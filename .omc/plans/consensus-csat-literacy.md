### Principles

1. **측정 없이 상수를 정하지 않는다** — 임계값 자체의 근거도 포함한다. rev2는 임베딩 선택을
   측정으로 옮기면서 그 합격선(ρ≥0.7)을 다시 논증으로 정해 위반을 한 층 아래로 옮겼다.

3. **판정의 국소성은 목적에 따라 다르게 적용한다.** 커버리지 매칭은 명제 단위가 유리하지만
   **모순 판정은 정의상 전역 맥락을 요구한다.**
4. **검증 가능한 것만 완료로 친다** — 검증 주장 자체가 실행된 것이어야 한다. rev2는 실행한

5. **웹 전환을 막지 않되, 지금 필요 없는 구조는 만들지 않는다.** 프로세스 경계는 예외다.

## 설계 확정 사항

### D1. Gate A — 2단 확인 (명제 단위 부산물이 아님)

**근거는 실측이다.** 예외 조항(`다만` / `경우에는`)을 포함한 지문이 상당수다. 다만
`경우에는`은 예외가 아니라 평범한 조건절인 경우가 많으므로, 정확한 유병률은 새 데이터셋에서
예외 마커 기준으로 재산출해야 한다 (미해결 항목). 골드 명제 하나만 놓고 보면 예외를 정확히 읽은 학생 응답이 contradict로 보인다.
rev2 설계는 **정확히 읽은 학생을 강제 교정**하며, 이는 Driver 1이 규정한 최악의 실패다.

| 단계 | 범위 | 출력 |
|---|---|---|
| 1차 | 골드 명제 1개 vs 학생 응답 명제 | entail / neutral / **contradict-suspect** |
| 2차 | **문단 원문 + 문단 전체 골드 집합** | 진짜 모순 / 예외 조항 반영 |

contradict-suspect는 **에스컬레이션 트리거**이고, 2차 통과 시에만 Gate A가 발동한다.

**미측정 항목으로 등록:** contradict-suspect 발생률. rev2는 "드문 경로이므로 p50 무영향"이라
단정했으나 이는 가설이다. 응답당 골드 명제 수십 건을 대조하므로 오탐률 5%만 되어도 상시
2차 호출이 발생한다. **K/E에서 실측하고, 응답당 2차 호출 ≥ 1.0이면 P3(슬롯 단위)로 전환한다.**

### D2. ablation — 부모-국소 정의, primary 간선 위에서만 계산

스펙의 "상위 의미"가 직속 부모인지 루트인지 모호해 순환처럼 보였다. **직속 부모로 확정한다.**

```
w(v) = 1 − cos( embed(text(parent(v))),
                embed(regenerate(parent(v) | children(parent(v)) \ {v})) )
```

**비용 정정 (Critic M2).** rev2는 "노드당 재생성 1회, O(n)"이라 했으나, primary parent를
"제거 시 손상이 최대인 부모"로 정하면 모든 부모 간선에 재생성이 필요해 O(|E|)가 된다.
→ **primary parent를 생성기가 직접 지정하도록 변경한다** (합성 시 "이 명제의 주 소속 상위
노드"를 함께 출력). ablation은 primary 간선에서만 수행되어 O(|V|)로 복귀한다. 생성기 지정의
품질은 K에서 인간 판단과 대조해 검증한다.

**W(v) 수식 정정 (Critic M3).** rev2는 할인을 슬롯까지만 적용해 **슬롯 자신의 중요도가
누락**됐다 — 사소한 슬롯의 잎과 핵심 슬롯의 잎이 같은 스케일로 보상에 기여한다.

```
W(v) = Π w(a)   for all a on the primary path from v up to root (inclusive of v)
```

**가법성은 가정하지 않고 측정한다.** one-at-a-time 손상도는 일반적으로 가법적이지 않다
(중복된 두 자식은 개별 제거 손상이 작지만 동시 제거 손상은 크다). K에서 자식 2개 동시 제거
손상 vs 개별 손상 합의 괴리를 실측하고, 괴리가 크면 보상 산출을 정규화한다.

### D3. 골드는 DAG — 트리 제약 없음

한 정의 명제가 두 상위 개념을 동시에 지지하는 구조는 수능 지문에 흔하다. 트리를 강제하면
생성기가 실제 관계를 지우고 가중치가 왜곡된다.

| 간선 | 생성 주체 | 용도 |
|---|---|---|
| **primary** (노드당 1개) | 합성 프롬프트가 지정 | 슬롯 배정, 보상 회계. 신장 트리 |
| secondary | 합성 프롬프트가 다중 부모 허용 | `HierarchyView` 렌더링, 힌트 |

`select-slots`는 primary 신장 트리 위에서 동작한다.

**폴백 정의 (Critic M7).** 크기 3~6의 안티체인 컷이 존재하지 않는 위계가 있다(루트 자식 2개,
그 자식들이 각각 4개 → 1, 2, 8로 진행). 실측상 문단 중앙값 312자·5문장이라 얕은 위계는 흔하다.
→ **혼합 깊이 안티체인**(서로 다른 레벨 노드의 조합)을 허용하고, 그래도 불가능하면 **크기 2를
허용하되 경고 로그**를 남긴다. property test는 "3~6 또는 명시된 폴백"으로 기술한다.

### D4. 웹 전환 가드

3패키지(`core` / `pipeline` / `app`) 유지. import 규칙 테스트 3종:
1. 파일시스템 접근이 리포지토리 구현체 밖에 없다
2. 클라이언트 번들이 `core/scoring`을 직접 import 하지 않는다 (프로세스 경계 강제)
3. LLM/임베딩 클라이언트가 클라이언트 번들에서 도달 불가하다

리포지토리 인터페이스는 처음부터 불투명한 `ownerId`를 받는다(로컬은 항상 `"local"`).

### D5. 검증 코퍼스 — 환언 소스 재설계 (Critic C2)

**rev2의 오류.** "`questions[].choices[].text`를 인간 저작 환언으로 쓴다"는 실행 불가능하다.
실측: 문항 731개에 **정답 키 필드가 없고**, 선택지의 80%가 오답이며, stem의 **349/731(48%)이
부정 발문**("적절하지 않은 것은")이라 극성이 문항마다 뒤집힌다. 다수 선택지는 명제 재진술이
아니라 메타 진술이고, 선택지는 지문 전체를 대상으로 하는데 골드는 문단 단위다.
그대로 쓰면 **오답을 "골드와 일치하는 환언"으로 라벨해 채점기가 거짓을 entail로 판정하도록
튜닝된다.**

**대체: 환언 코퍼스를 수작업 라벨 태스크로 승격한다.**

| 범주 | 출처 | 순환성 | 규모 |
|---|---|---|---|
| 완전 / 부분 / 모순 | **구성적** (명제 k를 지웠으니 k=neutral은 정의상 참) | 없음 | 자동 생성, 픽스처당 20건 |
| **환언** | **사람이 직접 작성** — 캘리브레이션 픽스처 2건의 명제를 다른 표현으로 재진술 | 없음 | **30쌍, 약 1시간 노동** (견적 반영) |
| 참이지만 문단 밖 | 같은 주제의 참인 사실을 사람이 작성 | 없음 | 10건 |
| 무관 | 다른 문단 내용 | 약함 | 자동 |

**임계값은 상대 기준으로 정의한다** (Principle 1):

| 범주 | 게이트 |
|---|---|
| 구성적 | 무작위 기준선(33%) 대비 유의미 초과 + 절대 오류 3건 이하 (n=20×2 픽스처) |
| 환언 | 구성적 범주 대비 저하폭 ≤ 15%p |
| 참이지만 문단 밖 | 오탐(entail) 건수 ≤ 1 (n=10) |

표본 수가 작으므로 **비율이 아니라 절대 오류 건수**로 게이트를 건다.

## K2 이전 단계 — 골드 재현성 측정 (2026-07-23 방침)

### 지표 우선순위 (2026-07-24 확정)

n=1(법인 문단) 측정에서 **단순 문장 일치율(82.9%)이 실제 의미 재현성을 과소평가**함이
드러났다. 불일치의 대부분이 슬롯 입도 차이(넓은 슬롯의 '부분' vs 좁은 슬롯의 '충족+누락')였고,
이를 제외하면 의미 일치율은 97.1%였다. 따라서 비교는 다음 우선순위를 따른다:

1. **모순 유무** — Gate A 발동 여부. 학습 경험을 근본적으로 가른다
2. **수정 필요 여부** — 첫 수정 종류가 '없음'인지
3. **첫 수정 종류** — 모순 교정 / 누락 보완 / 없음
4. **첫 수정의 의미적 대상** — 가리키는 문장 집합의 겹침
5. (참고) 의미 일치율 — granularity variance를 제외한 순수 의미 일치

**granularity variance는 semantic ambiguity와 별도 기록**한다 (`classifyDispute`). 모순이 끼거나
충족↔누락이 정면 충돌하면 semantic, 부분이 한쪽 끝과만 붙으면 granularity. semantic만 복수
골드로 다룰 진짜 애매성이고, granularity는 슬롯 입도 결정의 산물이라 규칙 변경 근거가 아니다.

**슬롯 개수 하한 상향과 부분 판정 제거는 추가 문단 결과를 본 뒤 결정한다.** n=1로 규칙을
바꾸면 과적합이다. K2는 이 측정이 끝날 때까지 보류.


D0 실행에서 **같은 문단·같은 프롬프트인데 실행마다 구조가 달라지는 것**이 관측됐다
(명제 10~11개, 위계 노드 14~16개, 한 번은 3개까지 붕괴). 완전성 검증이 최악의 경우는
막지만 구조 재현성은 보장하지 못한다.

**그러나 구조 재현성 자체는 목표가 아니다.** 학습자에게 중요한 것은 슬롯 경계가 아니라
자기 답이 어떻게 판정되는가다. 따라서 다음 순서로 진행한다:

1. 각 문단을 **3회 독립 생성**
2. **동일한 테스트 학생 응답**에 대한 판정을 비교
   - 슬롯 충족·누락·모순 판정
   - 첫 수정 타겟
3. **판정이 달라진 의미 구간에만** ambiguity bundle 생성
4. 전체 복수 골드 생성과 K2는 이 측정 **이후로 미룬다**

### 비교를 골드 독립적으로 만드는 축: 문장 번호

골드마다 슬롯 id와 경계가 다르므로 구조를 직접 비교하면 항상 "다르다"가 나온다.
슬롯 → traceability 명제 → `sourceSentences`로 환원하면 공통 좌표계가 생긴다.
한 문장이 여러 슬롯에 걸리면 가장 심각한 판정(모순 > 누락 > 부분 > 충족)을 택한다.

### 테스트 응답의 독립성

테스트 학생 응답은 **문단만 보고** 한 번 생성해 디스크에 고정한다. 골드별로 새로 만들면
각 골드에 유리한 응답이 나와 측정이 무의미해진다. 5개 품질 수준(완전·부분·모순·환언·문단 밖).

### 측정 지표

| 지표 | 의미 |
|---|---|
| 문장 판정 일치율 | 문장별 판정이 3개 골드에서 같은 비율 |
| 모순 유무 일치 | Gate A 발동 여부가 갈리면 학습 경험이 완전히 달라진다 |
| 첫 수정 종류 일치 | 모순 교정 / 누락 보완 / 없음 |
| 첫 수정 범위 겹침 | 첫 수정 타겟이 가리키는 문장 집합의 Jaccard |

### K의 인간 라벨 프로토콜 (Critic C3 — rev2는 형식조차 미정의였다)

rev2는 K에서 `핵심/장식`(이진)을 붙이고 K2에서 `순위`(Spearman)를 재려 했다 — **이진 라벨은
순위를 정의하지 않는다.** 그리고 문단 2건 × 부모당 자식 3~5개면 ρ=0.7은 n=5에서 p≈0.19로,
어떤 프로바이더든 우연히 통과하거나 탈락한다.

**변경: 쌍대 비교(pairwise).**
- 라벨 단위: 같은 부모 아래 자식 쌍 (A, B). 질문: **"A를 지우는 것과 B를 지우는 것 중 어느
  쪽이 부모의 의미를 더 크게 훼손하는가?"** (A / B / 구분 불가)
- 지표: 쌍대 정확도(구분 불가 쌍 제외), Kendall τ_b, 손상도 분포의 폭(IQR)
- 표본: 필요한 비교 쌍 수를 먼저 계산해 **문단 수를 역산한다.** 부모당 자식 4개면 쌍 6개,
  문단당 부모 3~4개면 쌍 20여 개. 2문단이면 40여 쌍 — 무작위 기준선 50% 대비 유의성 확보에
  최소한이다. **부족하면 문단을 늘린다. 2건은 결론이 아니라 표본 설계의 결과여야 한다.**
- 게이트: **절대 임계 없음.** 프로바이더 간 상대 비교 + 무작위 기준선(50%) 초과 유의성.
  손상도 IQR이 0.05 미만이면 "신호 없음"으로 판정한다.
- 편향 통제: 라벨러가 계획 작성자 본인이므로, **골드 작성 후 최소 1일 간격을 두고 블라인드로
  라벨**하고 일부 쌍을 재라벨해 자기 일치율을 함께 보고한다.

## Pre-mortem (Critic M11)

**시나리오 1 — 가중치가 노이즈였다.** K2에서 세 프로바이더 모두 쌍대 정확도가 기준선 근처다.
손상도 IQR이 0.03이다. 프로바이더 탓인지 표본 탓인지 구분되지 않아 판단이 마비된다.
- 조기 신호: K2 1차 실행에서 손상도 분포 폭이 좁게 나옴
- 분기: 표본을 4문단으로 확대해 재측정 → 여전히 미달이면 **ablation 기반 가중치를 포기하고,
  합성 시 LLM이 직접 중요도를 3단계로 라벨하게 한 뒤 그 라벨을 K의 쌍대 비교로 검증한다.**
  스펙의 "자의성 제거"는 조건부가 되며 이를 사용자에게 보고한다.

**시나리오 2 — 2차 확인이 예외 조항을 계속 오판한다.** 픽스처 1건에는 맞지만 31건 표본에서
오판이 20% 나온다.
- 조기 신호: B의 회귀 테스트가 픽스처 외 사례에서 실패
- 분기: 예외 조항을 **골드 스키마에 명시적 필드로 승격**한다(명제에 `exceptions[]`). 판정을
  LLM 추론에 맡기지 않고 구조로 해결한다. 골드 생성 비용이 오르지만 판정이 결정론이 된다.

**시나리오 3 — 보상 수치가 조용히 무의미해진다.** 가중치가 그럴듯하게 나와 아무도 가법성을
의심하지 않고, 학생이 받는 점수가 실제 이해도와 무관해진다. **가장 위험하다 — 실패가 눈에
띄지 않는다.**
- 조기 신호: K의 가법성 측정에서 동시 제거 손상 vs 개별 합의 괴리가 30% 초과
- 분기: 보상을 연속 점수로 표시하지 않고 **충족 명제 개수 + 위계 시각화**로만 표현한다.
  스펙의 `reward = Σ(충족 × 가중치)`는 내부 정렬용으로만 쓰고 학생에게 숫자를 보이지 않는다.

## 판정 규칙 (사용자 확정, 2026-07-23)

### R1. 명제 충족 판정 — **양끝 노드 규칙**

명제는 `시작개념 → 관계 → 끝개념` 형태다. 학생이 **시작개념과 끝개념을 모두 언급했고 관계
방향이 일치하면 충족**한다. 중간 표현의 차이나 어휘 선택은 묻지 않는다.

이 규칙은 관계의 **양끝**을 판정 단위로 삼으므로, 판정기가 "학생이 이 관계를 말했는가"를
개념 대조로 환원한다 — 세계 지식으로 빈칸을 메우는 미끄러짐(Architect 지적)을 억제한다.

**C2 예시의 기대값은 이미 확정되어 있다 — 재개방하지 않는다.**

스펙 `deep-interview-...md:76`은 확정 AC다: 학생 응답 "금리를 올리면 사람들이 돈을 덜 써서
물가가 내린다"는 **Gate A 통과 + p2 미충족의 부분 보상**으로 처리된다. 즉 p1·p3 충족이
사용자가 손으로 확정한 오라클이다.

rev3 초안은 이를 "K에서 정한다"로 미뤘으나 **오류였다.** Critic M8이 지적한 것은 "오라클을
추측으로 굳히지 말라"였는데, 이 오라클은 추측이 아니라 사용자가 이미 준 것이다.

→ **이 AC가 R1의 개념 동일성 판정을 구속한다.** "돈을 덜 쓴다"는 `화폐유통감소`와 동일 개념으로
읽는다. 다르게 결정하려면 스펙 변경으로 올린다.

**남는 긴장 (명시):** 이 느슨한 개념 동일성은 R1이 억제하려던 "세계 지식으로 빈칸을 메우는
미끄러짐"을 일부 허용한다. R1의 양끝 검사와 느슨한 동일성이 결합하면 판정기가 관대해진다.
E의 "참이지만 문단 밖" 적대 범주가 이 관대함의 상한을 재는 유일한 장치다.

### R2. 타이틀 채점 — **코어 슬롯 포괄 여부**

학생이 입력한 타이틀이 **충족된 코어 슬롯들을 아우르는가**로 판정한다. 골드 타이틀 문자열과의
유사도 비교가 아니다.

근거: 타이틀은 하위 내용의 상위 추상화이므로, "골드 타이틀과 얼마나 닮았나"가 아니라
"학생이 자기가 파악한 슬롯들을 하나로 묶어냈나"가 측정 대상이다. 이 방식은 슬롯 단계에서
일부를 놓친 학생에게도 **자기가 충족한 범위 안에서** 공정한 판정을 준다.

**반-게이밍 제약 3가지 (Critic C-3).** 소박한 구현은 유인을 세 방향으로 역전시킨다.

| 문제 | 소박한 구현의 귀결 | 제약 |
|---|---|---|
| **이중 계상** | 슬롯 단계에서 W를 받은 슬롯이 타이틀에서 또 W를 받아 `reward = Σ(충족 × W)` 스케일이 무너진다 | 타이틀 보상은 **별도 스케일**로 두고 슬롯 보상과 합산하지 않는다 |
| **연결 나열이 최적 전략** | 충족 슬롯을 그대로 이어 붙이면 포괄률 100%. 상위 추상화를 하면 오히려 포괄이 애매해져 손해 | **슬롯 문장의 표층 재사용은 포괄로 치지 않는다.** 판정 프롬프트와 AC에 명시 |
| **덜 맞출수록 쉬워짐** | 분모가 "충족 슬롯"이라 1개만 충족한 학생은 1개만 포괄하면 만점 비율 | 분모를 **코어 슬롯 전체**로 고정 |

이 셋을 넣지 않으면 스펙의 핵심 학습 설계(코어 슬롯 → 타이틀 상향식 추론 강제)가 정확히
뒤집히고, **학생은 점수를 받으며 잘못된 전략을 학습한다** — 실패가 조용하다.

구현: **코어 슬롯 전체**를 맥락으로 주고, 학생 타이틀이 각 슬롯을 포괄하는지 판정하되 표층
재사용은 배제한다. 타이틀 보상은 포괄률 기반의 독립 지표로 산출한다.
