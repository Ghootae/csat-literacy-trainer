# 문단 분석 지도 브레인스토밍 (2026-10-16)

[Q-0037](../../memory/OPEN_QUESTIONS.md)(학생 상태 모델의 분석 자료)에서 출발한 사용자–Claude 논의 기록이다. 구현과 무관한 아이디어 단계이며, API 호출·코드 변경은 없다. 사용자가 합의한 것과 Claude 제안(미합의)을 구분해 적는다. 합의 사항은 [D-0141](../../memory/decisions/D-0141-paragraph-analysis-map-direction.md).

## 1. 출발점

- 단순 형식([D-0139](../../memory/decisions/D-0139-paragraph-simple-format-question-rules.md))은 골드를 쓰지 않는다. 판정 결과가 "핵심 잡음 / 구멍 / 오류" 수준이라 *무엇이* 구멍이었는지가 누적되지 않는다.
- 예전 골드는 두 일을 함께 했다: (1) 대화를 이끄는 일(판정 기준·질문 재료), (2) 학생 상태를 재는 고정 눈금(`model.ts`의 `evidenceKey`가 축·MR ID). 단순 형식은 (1)만 대체했고 (2)는 비어 있다. (Claude 정리, 사용자 동의)
- 분석 자료는 대화 경로에 넣지 않고 뒤에서 주기적으로 돌리는 진단 단계([D-0115](../../memory/decisions/D-0115-thought-diagnosis-periodic-sol.md) 방식)에서만 쓴다. 분석 자료가 틀려도 학생 대화 품질은 흔들리지 않는다. (Claude 제안, 이후 논의의 전제로 이어짐)

## 2. 사용자 아이디어: 상향 지도 + 하향 확산

이전 골드는 학생의 홀리스틱 이해 판정이 목적이라 top-down이었다. 분석용 자료는 정보의 해상도가 관건이므로 bottom-up이 낫다(사용자).

지도 만들기(상향):

1. 문단을 명제로 분해
2. 명제 간 관계 파악
3. 명제로부터 층별 합성 명제를 위계적으로 조직
4. 최상위 층까지 위계 지도 합성

학생 응답 적용(하향 확산):

1. 학생 응답으로 위에서 아래까지 명제의 충족 정도를 판단. 실시간으로 보이지 않으므로 어느 정도의 일관성만 유지되면 된다.
2. 활성화된 명제와 관계를 누적 기록 → 반복 패턴 파악

## 3. 예전 명제 모델과의 관계 (Claude 조사)

- 최초 워크트리(`/Users/mac/Projects/csat-literacy-trainer`, 브랜치 `experiment/no-proposition-glyph`)의 `docs/DECOMPOSITION-PROCESS.md`, `docs/COMPOSITION-PROCESS.md`(2026-08-01)가 거의 같은 구조다: 명제 p1~p11(술어·측면·관계·근거 문장) → 1차 합성 노드 → 최상위 제목 노드.
- 실패해서 버린 것이 아니다. `docs/ROADMAP-PAUSE-2026-08-16.md`: Target-based 설계 후보 등장으로 동결.
- [D-0001](../../memory/decisions/D-0001-semantic-relation-verdict.md)은 명제 충족 개수를 *점수*로 쓰지 않기로 했다. 이유: 좋은 요약은 세부를 정당하게 생략함, 분해 방식에 따라 흔들림, 사람 이중 라벨링 불안정. 이번 용도(오프라인 분석)에서는 첫 이유가 약해지지만 둘째 이유(불안정)는 누적·패턴 파악에서 더 핵심이 된다.
- 예전 실측(`e45b42e` 커밋 메시지): 표시된 명제 상태의 55%가 ◐(추상화로 뒷받침). 학생 요약은 주로 위쪽 층에서 맞으므로 아래에서 명제를 하나씩 대조하면 "애매함"이 대량으로 생긴다. 하향 확산이 이 문제의 정면 해법이다.

## 4. 이 아이디어의 이득 (Claude 의견)

위계 지도는 문단이 달라도 비교되는 *깊이 분포*를 준다. 단순 형식의 전체 판정은 줄 수 없는 정보다.

- 아래층만 켜지고 위층이 빈 학생: 나열형 요약, 합성 실패
- 위층만 켜지고 아래가 비거나 모순인 학생: 그럴듯하지만 막연한 요지
- 특정 관계 유형에서만 반복해 끊기는 학생

## 6. 닫힌 소수 어휘 (Claude 설명, 목록은 초안 예시)

예전 술어(`consequence_of_violation_1`, `purpose_of_correspondence`)는 그 문단 안에서만 의미가 있어 문단을 넘어 묶을 수 없었다. 예전 `aspect`(definition, description, normative, result, intention)는 거의 닫힌 필드였고, `predicate`·`relation.kind`는 자유 문자열이었다. 문단 간 비교에는 닫힌 필드만 쓰고, 자유 문자열은 그 문단을 설명하는 데만 쓴다.

| 붙는 곳 | 라벨 예시(미확정) | 보는 패턴 |
|---|---|---|
| 관계(간선) | 인과, 조건, 대조, 목적, 전제→결론, 상위-하위, 예시, 시간 순서, 양보 | 어떤 종류의 연결을 반복해 놓치나 |
| 명제 역할(노드) | 정의, 주장, 근거, 결과, 사례, 평가 | 어떤 종류의 내용을 빠뜨리거나 왜곡하나 |
| 층 | 최하 / 중간 / 최상 (문단마다 층 수가 달라 정규화) | 합성 깊이가 어디서 끊기나 |

목록 기준: 짧을 것(관계 10개 안팎), 서로 겹치지 않을 것, 교육적 의미(진단 뒤 해 줄 지도가 있을 것), 검증 가능할 것(독립 2회 라벨 일치도).

## 7. 목록 작성 절차 (Claude 제안, 미합의)

1. 분야별(인문·사회·과학·기술·예술 등) 3~4지문, 연도 섞어 샘플링. 후보 풀: `/Users/mac/Projects/suneung_db`(내용 미확인)
2. 샘플 지문으로 지도를 먼저 만들고, 지도에 나온 관계에 자유 이름을 붙인다(열린 라벨링). 목록 재료와 지도 생성 가능성 점검을 함께 얻는다.
3. 비슷한 이름을 묶어 후보 목록. 담화 관계 이론(RST 등)·수능 문항이 묻는 관계 유형을 씨앗으로 대조
4. 목록 작성에 쓰지 않은 보류 지문에서 포괄도("기타" 비율)와 일치도 확인
5. 통과 시 v1 동결

분야별 분포 차이(가설): 과학·기술은 과정·인과·조건, 인문은 주장·비판·대조, 사회(법·경제)는 요건-효과·예외, 예술은 평가·관점 대비. 분야 전용 라벨이 필요해 보이면 먼저 공통 핵심 라벨의 하위 유형으로 둘 수 있는지 본다. 문단·분야 간 비교는 공통 핵심 라벨로만 한다.

## 8. 하향 확산 판정 설계

### 사용자 원안

학생 응답 + 상위 명제의 충족 정보 + 하위 명제 하나 → 응답이 타겟 명제를 얼마나 충족하는지 실수값(JEV). JEV를 고른 이유는 속도보다 실수값이었다.

### Claude 의견 (미합의 부분 포함)

- **상위 충족 정보를 판정 입력에 넣지 않는다.** 근거: [collision 단일 질문 대조](../experiments/jev-collision-single-question-ab-v1-2026-09-23/REPORT.md)에서 연결된 다른 MR의 명시적 오류가 표적 판정으로 0.45~0.63 번졌고, AX를 입력에 넣으면 0.77~0.86까지 올랐다. 상위 정보를 넣으면 "직접 언급"과 "상위 포섭"이 숫자 안에서 섞인다.
- **위계 결합은 코드 규칙으로.** 하위 명제의 직접 판정과 상위 노드 판정을 고정 규칙으로 합쳐 상태를 정한다(예: 직접 높음 → 직접 언급, 직접 낮음·상위 높음 → 상위 포섭, 둘 다 낮음 → 미활성).
- **하향 순서는 가지치기에 쓴다.** 상위가 확실히 미활성이고 모순도 없으면 아래는 묻지 않는다.
- **충족과 모순을 따로 본다.** 낮은 충족은 생략일 수도 반대 진술일 수도 있다.
- **포섭을 세부 이해의 증거로 승격하지 않는다.** 노드 상태: 직접 언급 / 상위 포섭(추정) / 미활성 / 모순.
- **"미활성"은 약한 증거다.** 응답은 요약 하나와 질문 답 최대 두 번이라 문단당 증거가 적고, 생략은 이해 부족이 아닐 수 있다. 패턴은 모순·층 분포·여러 문단에 걸친 반복에 기댄다.

### 모델 선택: 생성형 모델 (합의)

Claude 권고 이유:

1. 예전 MR coverage 실험에서 순위는 보존됐지만 백분율 점수는 통과하지 못했다. 어차피 구간으로 바꿔 쓸 것이므로 순서형 라벨(직접 충족 / 부분 / 없음 / 모순)과 차이가 작다.
2. 판정마다 학생 응답의 근거 구절을 인용하게 할 수 있다. 패턴이 학생 특성인지 판정·지도 결함인지 감사할 수 있고, "인용 없으면 직접 충족 불가" 규칙으로 포섭이 직접 언급으로 부풀려지는 것을 막는다.
3. 실수값이 필요하면 3~5회 반복 실행의 라벨 일치 비율로 얻는다. 판정 안정성 측정도 겸한다.

단서: 한 호출에 한 문단의 명제 여러 개를 함께 판정해도 되지만(collision 실험에서 묶음/분리 차이 작음) 상위 노드 판정 결과는 넣지 않는다. 모델·프롬프트를 바꾸면 기존 누적과 섞지 않도록 버전을 고정한다.

## 9. 함께 남긴 연결 아이디어 (Claude 제안, 미합의)

- **문제와의 다리:** 선지마다 근거 명제·관계를 지도에 걸어 두면 "문단에서 이 관계가 미활성·모순이던 학생이 그 관계에 걸린 선지에서 틀리는가"를 볼 수 있다. 맞으면 지도가 실제 사고 상태를 잡는다는 증거가 되고, 사고 진단([D-0111](../../memory/decisions/D-0111-thought-diagnosis-v0-experiment.md))과 합쳐진다.
- **구절 앵커:** 명제의 근거 문장 필드가 문단·문제 양쪽이 가리킬 수 있는 공통 좌표다. 단순 형식 개발자 모드 로그에 구멍·오류가 걸린 구절을 남기자는 제안도 했으나 사용자가 구현과 무관한 단계라고 해 진행하지 않았다.
- **머릿속 실험:** 예전 명실론 위계(p1~p11, c1~c5)에 기존 학생 응답 몇 개를 손으로 하향 확산시켜, 층 분포·활성 패턴이 단순 형식 판정보다 많은 정보를 주는지 본다.
