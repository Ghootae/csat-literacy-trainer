# JEV 선택 확률 이동 시험 설계 초안 — "근거가 선지를 얼마나 더 믿게 만드는가" (2026-10-29)

상태: 초안(사용자 검토 전). 출처: 사용자 아이디어(2026-10-29 대화: "선택한 선지가 정답일 확률 … 정답을 선택한 경우 근거가 근거로서 잘 기능하는지 실시간 확인"), [Q-0040](../../memory/OPEN_QUESTIONS.md)(근거 작성 중 충분성 신호, parked), [측정 6](../experiments/v58-conclusion-2026-10-29/REPORT-desktop.md)(JEV 충분성 탐색), [D-0036](../../memory/decisions/D-0036-jev-product-work-parked.md)(JEV 제품 적용 보류).

정책 위치: D-0036 보류 중 사용자 지시로 하는 탐색 실험이다(측정 6과 같은 성격). 결과가 좋아도 제품 적용은 별도 결정이다.

## 1. 문제

### 학생 화면에서 하려는 것

학생이 선지를 고르고 근거를 쓰는 동안, 근거가 "이 선지가 정답이다"를 얼마나 더 믿게 만드는지를 거의 실시간 그래프로 보여 준다. 판정이 아니라 보강 유도용 힌트다.

```
선지만 고름          0.70   (출발값, 화면에 안 보임)
+ 허점 있는 근거     0.72   → 그래프 거의 그대로
+ 충분한 근거        0.90   → 그래프 오름
```

### 측정 6의 방식이 이 용도에 안 맞는 이유

측정 6은 정답 번호를 넣고 "근거가 충분한가"를 물었다. 그 값을 실시간으로 보여 주면 오답을 고른 학생의 그래프는 아무리 써도 오르지 않는다. 선지를 바꿔 가며 떠보면 정답 키가 새어 나간다. 또 값이 0.29~0.68에 몰려 있어 확실히 충분한 근거(S12)도 0.67이었다.

### 새 방식에서 확인해야 할 것 (모두 아직 측정하지 않음)

| 물음 | 실패하면 생기는 일 |
|---|---|
| Q1. 충분한 근거와 허점 있는 근거가 출발값을 다르게 움직이는가 | 신호가 아무 정보도 주지 않음 |
| Q2. 단언·선지 베끼기처럼 추론 없는 글이 값을 올리는가 | 그래프 올리기 놀이로 흐름 |
| Q3. **오답 선지 + 그럴듯한 근거**가 그 오답의 확률을 올리는가 | 틀린 추론에 칭찬 신호(가장 위험) |
| Q4. "학생이 N번을 골랐다"는 사실만으로 값이 오르는가 | 근거 효과와 선택 효과가 섞임 |
| Q5. 쓰는 중인 미완성 글에서 값이 차례로 움직이는가 | 실시간 용도 불가 |
| Q6. 모델이 이미 확신하는 문항(출발값 0.97 이상)에서 신호가 남는가 | 쉬운 문항에서 그래프가 안 움직임 |

## 2. 전략

### 요청 형식

- JEV `type: choice`, 선택지 = 문항의 다섯 선지(C1~C5 문장 원문). 이전 [trap-map JEV 실험](../experiments/trap-map-jev-four-choice-2026-10-10/)과 같은 꼴.
- 지시문(모든 조건 같음): "아래 지문과 문항을 읽고, 이 문항의 정답일 가능성이 가장 높은 선지를 고르라."
- state = 지문·〈보기〉·그림 설명·발문·선지 + (조건에 따라) `[학생 풀이] 학생은 N번을 골랐다. 근거: …`. **정답 번호와 공식 해설은 넣지 않는다.**
- 지시문은 학생 근거를 언급하지 않는다. 학생 근거는 state 안의 자료로만 들어간다. 지시문이 "학생 근거를 참고하라"고 하면 설득 효과가 커질 수 있어서다.
- 반복 5회. 선지 제시 순서를 회마다 한 칸씩 돌려 각 선지가 각 자리에 한 번씩 놓이게 한다. 7초 간격.

### 지표

- 각 조건에서 고른 선지의 확률 P를 구한다. 0.001~0.999로 자른 뒤 로그 오즈로 바꾼다.
- **근거 기여 Δ** = logit P(근거 포함) − logit P(선택만). 화면 그래프에 쓸 값이다.
- **선택 효과** = logit P(선택만) − logit P(학생 정보 없음). 이 값이 크면 모델이 "학생이 골랐다"는 말에 끌린다는 뜻이다.
- 확률 차이 대신 로그 오즈를 쓰는 이유: 0.95→0.99와 0.70→0.90을 비슷한 크기로 잡아 천장 효과(Q6)를 줄이려고.

## 3. 위험

1. **API 형식 미확인.** 지금까지는 `jevplayground.com/api/evaluate`를 키 없이 썼다. `.env`의 `JEV_API_KEY`가 같은 엔드포인트의 인증 헤더인지, 다른 엔드포인트인지 확인하지 않았다. → 사전 점검 1요청(조건 19-0, 1회)으로 응답 형식이 측정 6과 같은지 보고 본 실행에 들어간다. 다르면 멈추고 보고한다.
2. **비용 미확인.** 요청당 입력 약 2,500토큰, 115요청이면 약 29만 토큰이다. 키 사용 요금을 모른다. → 사전 점검 응답의 사용량 필드로 추산해 본 실행 전에 알린다.
3. **새로 쓴 근거 4개(AS·CP 두 쌍, W5).** 실제 학생 글이 아니라 코드 에이전트가 썼다. 특히 W5는 설득력이 약하면 G3를 쉽게 통과해 버린다. → 위 표의 문구를 사용자가 실행 전에 확인한다. W5보다 더 그럴듯한 오답 근거가 떠오르면 바꾼다.
4. **2문항 표본.** 통과해도 "가능성 있음"까지만 말할 수 있다. 다른 문항 유형(어휘, 〈보기〉 없는 문항), 사람 판정과의 일치는 여전히 측정하지 않는다.
5. **19번 ⑤의 출발값이 이미 높을 수 있음.** 측정 6에서 이 문항의 출발값을 재지 않았다. 0.99면 G1이 천장에 막힌다. 그래서 16번을 함께 넣었다. 둘 다 천장이면 결과는 "판단 불가"로 보고하고, 모델이 어려워하는 문항으로 다시 시험할지 묻는다.
6. **지시문 하나만 시험함.** 중립 지시문에서 G3가 실패해도, "근거가 원문으로 뒷받침되는 만큼만 반영하라" 같은 지시문으로는 통과할 수 있다. 이번에는 시험하지 않고, G3 실패 시 다음 후보로만 적는다.
7. **외부 전송.** 수능 지문과 시뮬레이션 학생 글을 JEV로 보낸다. 측정 6과 같은 범위이고 실제 학생 개인정보는 없다.
