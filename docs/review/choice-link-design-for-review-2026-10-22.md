# 설계 검토 요청: 선지 연결 층 (수능 국어 독서)

- 날짜: 2026-10-22
- 작성: Claude Code (프로젝트 작업 세션)
- 검토 요청 대상: 이 문서만 보고 판단할 수 있게 썼다. 저장소 경로는 참고용이다.
- 상태: 설계 확정 직전. 생성 스크립트와 dry-run은 끝났고, 실제 생성(외부 API 6요청)은 아직 보내지 않았다.

## 1. 프로젝트 맥락 (짧게)

수능 국어 비문학(독서) 학습 도우미를 만들고 있다. 학생이 문단을 요약·대화하고 문항을 푼다.

- **분석 골드**: 지문마다 "분석 지도"를 한 장 만들어 동결한다. 지도는 상향 위계다.
  - 명제(`P1-3`): 원문 문장을 쪼갠 단위. 각각 원문 인용(`sourceQuote`)을 가진다.
  - 합성(`C1-2`): 명제를 묶은 상위 노드.
  - 요지(`G1`): 문단 요지. 최상위(`TOP`)와 문단 간 묶음(`X1`)도 있다.
  - 관계(`R5`): 노드 사이 연결. 18유형 닫힌 목록(인과·과정·조건·수단목적·대조·병렬·분류 / 근거·구체화·적용·정의·양보·문제대응 / 관점차이·공통·비판·해석 / 배경·전개)으로 분류해 둔다.
  - 입장 층: 명제마다 누구의 주장인지(필자 `AUTHOR` / 인물·학파 `FIGURE`+holder / 통념 `COMMON`).
  - 지도는 LLM(sol)이 3회 생성 → 점검표로 1회차 선택 → 수정 없이 동결. 층은 별도 파일로 얹고 지도는 고치지 않는다.
- **학생 이해 지문(fingerprint)**: 학생 요약을 지도 단위별로 판정(DIRECT/PARTIAL/ABSENT/CONTRADICTS)해 "층 × 관계 유형"별 포착률·정밀도·오류율로 모은다. 한계: ABSENT가 "모름"인지 "말 안 함"인지 가릴 수 없다.
- **이미 정한 원칙(D-0002)**: 문제 풀이 피드백 런타임에는 원문 직접 방식만 쓴다(원문·문항·정답·해설·학생 발화). 예전에 구조화 문제 골드(선지 주장·추론 경로·대표 오답 경로)를 런타임에 넣어 보니, 학생이 말하지 않은 오류를 골드에서 끌어와 채워 넣는 과잉 교정이 생겨 뺐다.

## 2. 이번 작업의 목적

**선지 연결 층**: 기출 문항의 선지마다 "지도(및 〈보기〉)의 어디를, 어떻게 다뤘나"를 동결해 둔다. 그러면 학생이 고른 선지가 지도 위의 좌표가 된다.

쓰임:
1. (먼저) **오프라인 진단**: 학생 이해 지문에 오류 유형 축을 더한다. 요약 판정과 합치면 "말 안 함 대 모름"을 가를 수 있다.

   | 요약 | 선지 | 해석 |
   |---|---|---|
   | 말 안 함 | 그 칸을 비튼 선지에 넘어감 | 모름(약점) |
   | 말 안 함 | 비튼 선지를 맞힘 | 알지만 말하지 않음 |
   | 정확히 말함 | 비튼 선지에 넘어감 | 풀이 중 실수 |
   | 틀리게 말함 | 비튼 선지에 넘어감 | 확실한 오개념 |
2. (나중, 별도 실험) 피드백 자료: 판정이 끝난 뒤에만 좌표를 쓰는 좁은 방식으로, 원문 직접 방식과 비교해 나을 때만 D-0002를 부분 수정한다. 이번 범위 아님.

## 3. 핵심 설계

### 3.1 선지 = 출처가 붙은 조각들

선지 문장을 내용 조각으로 나누고 조각마다 출처를 붙인다.

| source | 뜻 | 연결 |
|---|---|---|
| `PASSAGE` | 지문 내용 | `mapIds` (가장 작은 단위부터: 한 문장 내용→명제, 두 내용의 이어짐→관계+양 끝 명제, 요약 수준→합성·요지) |
| `SUPPLEMENT` | 〈보기〉·도표·그림 내용 | `supplementIds` (〈보기〉를 S1, S2…로 나눈 조각, 그림은 요소별 설명) |
| `APPLICATION` | 〈보기〉의 대상·사례를 지문의 원리에 대응시킨 판단 | `supplementIds` + `mapIds` |
| `OUTSIDE` | 지문·〈보기〉 어디에도 근거 없음 | 없음 |

조각마다 `twisted`(근거와 다르게 바뀌었나), `twistName`(바뀐 방식, 지금은 **자유 기술**), `twistDetail`("근거: … → 선지: …").

맞는 선지도 연결한다(비틂 없음). 학생이 맞는 선지를 틀렸다고 고르는 것도 진단 신호이기 때문이다.

### 3.2 예시 (2026년 3월 고3 교육청, 도파민 지문 13번)

> 윗글을 바탕으로 〈보기〉를 이해한 내용으로 적절하지 않은 것은?
> 〈보기〉 파킨슨병 약물: (가) 레보도파: 흑질의 도파민성 뉴런으로 흡수되어 도파민 합성 증가, 상당량이 말초에서 도파민으로 합성됨 / (나) 카르비도파: 레보도파→도파민 합성 효소 억제, 혈액-뇌 장벽을 통과 못 해 말초에서만 작용 / (다) 프라미펙솔: 선조체 뉴런의 도파민 수용체에 결합해 도파민처럼 기능
>
> ② (나)는 효소의 작용을 억제하여 흑질에서 합성된 도파민의 작용 기간을 연장할 수 있겠군. (정답)

예상 기록:

| 조각 | source | 연결 | 비틂 |
|---|---|---|---|
| (나)는 효소의 작용을 억제하여 | SUPPLEMENT | S(나) | 없음 |
| 흑질에서 합성된 도파민의 | APPLICATION | S(나) + 지문 합성 경로 명제 | 말초에서만 작용하는 약을 뇌 안 과정에 대응 |
| 작용 기간을 연장할 수 있겠군 | APPLICATION | S(나) + 지문 DAT 재흡수·분해 명제 | 근거 없는 효과 부여 |

### 3.3 비틂 종류 목록은 생성 결과에서 귀납

관계 18유형을 만든 방식과 같다.
1. v1: 비틂을 자유 기술로 받는다(이번 생성).
2. Claude가 자유 기술을 묶어 닫힌 목록 초안을 만든다. 갈래는 지문 비틂 / 〈보기〉 비틂 / 적용 비틂을 예상한다.
3. v2: 목록 중 하나를 고르게 바꾸고, 만들 때 쓰지 않은 문항 세트로 검증한다(기타 비율, Claude 블라인드 판정 일치).

표본 설계:
- 만들기: 앱(UI)에 연결된 6지문의 기출 문항(어휘 제외) 24문항·선지 120개. 〈보기〉 문항 8, 그림 2. 나중 피드백 실험이 이 문항들에서 돌기 때문이다.
- 검증: 별도로 만든 분석 골드 6지도(5세트)의 기출 문항 약 20개.

### 3.4 생성 입력·출력

입력(지문당 1요청, `gpt-6.1-sol` reasoning medium, strict JSON schema):
- 지문 문단 원문, 지문 표시(밑줄·㉠ 등 기호가 가리키는 구간)
- 동결 지도(명제 `id·paragraphId·text`, 노드 `id·kind·text·childIds`, 관계 `id·fromId·toId·name·note`), 명제별 입장
- 문항: 번호, 발문, 〈보기〉 글, 선지, **정답 번호**(EBSi 정답 및 해설로 확인한 값). 그림은 `[IMAGE q13 img_001]` 표지 뒤 이미지로.

출력 스키마:
```
{ passageId, questions: [{ number, stemPolarity: SELECT_INCORRECT|SELECT_CORRECT|OTHER,
    supplementSegments: [{ id, kind: TEXT|FIGURE, quote, description }],
    choices: [{ number, truth: TRUE|FALSE|UNDETERMINED, answerConflict, note,
      parts: [{ quote, source, mapIds[], supplementIds[], twisted, twistName, twistDetail }] }] }] }
```

코드 검증:
1. 문항·선지 번호가 입력과 같다.
2. `parts[].quote`는 선지 문장의 정확한 부분 문자열.
3. 〈보기〉 `TEXT` 조각 `quote`는 〈보기〉 글의 부분 문자열, `FIGURE`는 설명이 있다.
4. id가 실재하고 source별 연결 개수 규칙(PASSAGE는 mapIds≥1 등)을 지킨다.
5. `truth: FALSE`이면 비틂 조각 ≥1(이름·설명 필수), `TRUE`이면 0.
6. 정답 일관성: "적절하지 않은 것"이면 정답 선지만 FALSE, "가장 적절한 것"이면 정답 선지만 TRUE.

### 3.5 지시문 v1 본문 (모델에 그대로 보냄)

> 너는 수능 국어 독서 문항의 선지를 지문 분석 지도와 〈보기〉에 연결한다. 목적은 학생이 어떤 선지를 골랐을 때, 그 선지가 지문·〈보기〉의 어느 내용을 어떻게 다루었는지 좌표로 남기는 것이다. 지도는 고치지 않는다. 지문과 〈보기〉에 없는 내용을 지어내지 않는다.
>
> 문항마다: (1) 발문 극성. (2) 〈보기〉를 선지가 기대는 단위로 나눠 S1, S2… — 글은 정확한 부분 문자열, (가)·(나) 표지가 있으면 그 단위, 그림·표는 요소마다 설명. (3) 선지마다 truth(지문·〈보기〉에 비추어 맞음/틀림/판단 불가), answerConflict(정답과 어긋나면 표시하고 이유, 정답은 바꾸지 않음), parts(위 3.1 규칙; mapIds는 가장 작은 단위부터; twistName은 정해진 목록 없이 바뀐 방식이 드러나게 짧은 명사구; twistDetail은 "근거: … → 선지: …"). FALSE면 비틂 조각 ≥1, TRUE면 0. 선지의 주장 내용은 빠짐없이 조각에 넣고 조사·어미만 다른 부분은 나누지 않는다. 선지가 누구의 주장인지 말하면 명제별 입장과 대조하고, 주인이 바뀐 것도 비틂이다. (4) 지도에 알맞은 단위가 없으면 가장 가까운 단위를 넣고 note에 모자란 점을 적는다.

`twistName`에 예시 이름을 일부러 넣지 않았다(예시로 쏠리는 것을 막고 자유 기술에서 목록을 귀납하려고).

## 4. 검토 받고 싶은 점

1. **조각 단위**: 선지를 "내용 조각"으로 나누는 기준이 모델마다·회차마다 흔들릴 위험. 조각 경계를 더 기계적으로 정할 방법(예: 서술어 단위, 절 단위)이 필요한가?
2. **source 4분류**: `APPLICATION`과 `PASSAGE`/`SUPPLEMENT`의 경계가 분명한가? 추론 문항(지문 내용에서 한 단계 이끌어 낸 판단)은 어디에 두는 게 맞는가 — `PASSAGE`+비틂인가, 별도 `INFERENCE`인가?
3. **mapIds 단위 규칙**: "가장 작은 단위부터"가 진단에 적절한가? 관계를 다루는 선지에서 관계와 양 끝 명제를 모두 넣는 것이 집계를 부풀리지 않는가?
4. **비틂 목록을 생성 결과에서 귀납하는 방식**: 자유 기술 120선지(비틂 있는 조각은 대략 30~50개 예상)로 목록을 만들기에 표본이 충분한가? 수능 선지 오답 유형에 대한 기존 분류(교육학·출제 문헌)를 출발점으로 쓰는 편이 나은가?
5. **정답 번호를 입력으로 주는 것**: 정답을 알려 주면 모델이 정답 선지의 비틂을 억지로 찾아낼 위험(사후 합리화)이 있다. 정답을 주지 않고 먼저 판단하게 한 뒤 대조하는 2단계가 나은가? 대신 정답과 어긋난 판단이 섞이면 골드로 쓸 수 없다.
6. **〈보기〉·그림 조각화**: 〈보기〉를 모델이 직접 S1…로 나누게 했다. 코드로 미리 문장 단위로 나눠 고정하는 편이 회차 간 비교·집계에 낫지 않은가?
7. **진단 해석 표(2절)**: 요약 판정과 선지 선택을 합친 4칸 해석이 타당한가? 빠진 경우(예: 찍기, 선지 간 비교 실패)는?
8. 그 밖에 이 층을 학생 진단 자료로 쓸 때 놓친 위험.
