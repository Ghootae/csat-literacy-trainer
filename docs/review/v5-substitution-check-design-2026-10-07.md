# v5 기호 대상 주장의 원문 대입 확인 — 공손룡 12번 시험 설계안

작성 2026-10-07. 상태: **설계안(대조 응답 기대값 확정, 전체 승인 전)**. 프롬프트·코드·서버는 바꾸지 않았고 API 호출도 하지 않았다.

## 1. 배경과 가설

- 2단계 v5 비교([결과](../experiments/v5-marker-judgment-gongsun-2026-10-07/REVIEW-SUMMARY.json)): 판정 방법·해석본은 ⓓ=빨간 옷 오독을 4/24 → 0/24로 줄였지만
  S5("d는 '옷장에 있는 옷'") 과잉 교정을 0/3 → 2/3으로 늘렸다. 실패한 판정은 모두 학생 말에 없는 "만"을 덧붙여 "옷장 안의 옷만"으로 읽었다.
- 사용자 논의(2026-10-07): S5를 허용한 이유는 하위 범주이기 때문이 아니라, "ⓓ옷이 정말 없다는 게 아니라"의 문맥에서 ⓓ가 옷장 안의 옷으로
  해석될 수 있기 때문이다. 해석본이 ⓓ를 "옷 일반"(이름이 정하는 속성 층위)으로 못박아 이 문맥 층위의 답을 막았다고 본다.
- 사용자 제안: 해석본을 미리 주는 대신, 학생 응답을 분해하고 학생 표현을 원문의 기호 자리에 넣어 문맥상 성립하는지로 판단한다.
- **가설:** 학생 표현을 그대로 원문에 대입하고 세 가지(표시된 표현, 앞뒤 문맥, 선지가 따지는 구별)를 따로 확인하게 하면,
  (가) S5 과잉 교정이 줄고, (나) 판정 방법이 줄인 ⓓ=빨간 옷 오독 감소는 유지되며, (다) S2·S3·S7 같은 실제 오류는 계속 잡힌다.
- 이번 범위는 공손룡 12번(문맥이 대상을 정하는 명사구 기호)뿐이다. 개념 이름·사례 이름표·문장 기호·그림 문항은 효과가 확인되면 따로 설계한다.

## 2. 비교 조건

| 조건 | 구성 |
|---|---|
| `methods` | v5 + 학생 주장 분리 + 인용 형식 규칙(2단계의 `v5_methods`와 같은 지시·스키마) |
| `methods_subst` | `methods` + 원문 대입 확인 블록. 해석본 없음 |

- 해석본 조건은 넣지 않는다. 대입 확인이 해석본을 대신할 수 있는지가 질문이고, 해석본은 S5를 악화시켰다.
- 2단계 결과를 기준선으로 재사용하지 않고 두 조건을 같은 실행에서 새로 돌린다(대조 응답이 추가되고 실행 시점 변동을 맞추기 위해).
  2단계의 `v5`·`v5_methods_gloss` 결과는 참고로만 비교한다.

## 3. 원문 대입 확인 블록(초안, 문항 내용 없음)

```
## 기호 대상 주장의 원문 대입 확인
studentClaims 가운데 학생이 원문에 표시된 기호가 무엇을 가리키는지 말한 주장에는, sourceCheck를 정하기 전에 substitution을 기록한다. 그 밖의 주장은 substitution을 null로 둔다.
- substitutedText: 그 기호가 붙은 원문 문장을 그대로 옮기고, 기호가 표시한 표현 바로 뒤에 학생 표현을 괄호로 넣은 문장. 괄호 안에는 학생 발화의 해당 부분을 그대로 넣는다. 학생이 쓰지 않은 한정·강조(만, 오직, 모든, 전부 등)를 덧붙이거나 학생이 쓴 것을 빼지 않는다.
- markedTextCheck: 학생 표현이 기호가 표시한 원문 표현이 직접 정하는 내용(속성·조건)과 충돌하지 않는가.
- contextCheck: 대입한 문장이 그 문장 안에서뿐 아니라 앞뒤 발화·문단의 흐름과 함께 성립하는가.
- distinctionCheck: 학생 표현으로 읽어도 선택한 선지가 따지는 대상 사이의 구별이 유지되는가.
- 각 확인은 result(PASS, FAIL, UNCLEAR)와 근거(basis)를 가진다.
판정 규칙:
- 셋 중 하나라도 FAIL이면 sourceCheck는 CONTRADICTED다. FAIL은 원문에서 이유가 분명할 때만 쓴다.
- FAIL이 없고 UNCLEAR가 하나라도 있으면 UNDETERMINED다. 이때 그 주장을 내용 오류로 만들지 않는다.
- 모두 PASS이면 CONSISTENT다. 학생 표현이 원문·해설의 설명과 표현이나 층위(이름이 일반적으로 정하는 뜻과 이 자리에서 가리키는 대상)가 달라도, 세 확인을 통과하면 오류로 보지 않는다.
```

## 4. 출력 스키마와 코드 검사

- `studentClaims[]` 항목에 `substitution`을 더한다(필수 키, 값은 객체 또는 null):
  `{ substitutedText, markedTextCheck: {result, basis}, contextCheck: {result, basis}, distinctionCheck: {result, basis} }`.
- 코드 검사(어기면 2단계와 같이 `CLAIMS_CONTRACT` 오류 → 운영 평가기 재시도 1회):
  1. substitution이 있으면 sourceCheck가 판정 규칙과 일치한다(FAIL→CONTRADICTED, UNCLEAR만→UNDETERMINED, 모두 PASS→CONSISTENT).
  2. substitutedText의 괄호 안 문자열이 그 주장 quote의 부분 문자열이다(공백 정규화). **학생이 쓰지 않은 "만" 같은 한정을 넣으면 여기서 걸린다.**
  3. substitutedText에서 괄호 부분을 빼면 원문(보기·지문)의 연속 부분 문자열이다(공백·따옴표 정규화).
  4. 2단계의 주장 계약(인용이 발화에 있음, CONTRADICTED ↔ errors 대응, CONTRADICTED 없으면 ERROR 아님)을 그대로 유지한다.

## 5. 응답과 기대값

S1~S8은 2단계와 같다(`docs/experiments/gongsun-auto-gloss-formats-2026-10-07/FROZEN.json`). 대조 응답 3개를 더한다. 선택은 모두 ④(C4).

| ID | 응답 | 기대 | 확인하려는 것 |
|---|---|---|---|
| S1 | d는 색을 한정하지 않은 일반적인 옷, e는 빨간 옷… | SUPPORTED | 정상 |
| S2 | d는 빨간 옷만 가리키고, e는 색을 한정하지 않은 일반적인 옷… | ERROR(ⓓ·ⓔ 대응) | 표시된 표현 충돌(ⓔ)·문맥 충돌(ⓓ) |
| S3 | d는 일반적인 옷이고, e는 파란 옷… | ERROR(ⓔ 대응) | 표시된 표현 충돌 |
| S4 | d와 e는 서로 다른 대상… | SUPPORTED | 대입 대상 없음(D-0085) |
| S5 | d는 '옷장에 있는 옷', e는 '빨간 옷'을 지시 -> 다른 대상 지시. | SUPPORTED | 문맥 층위의 답 허용 |
| S6 | d는 갑이 들고 있는 옷도 포함하는 보통 옷… | SUPPORTED | 포함 관계 명시 |
| S7 | d는 갑이 가지고 있지 않은 옷이고 e는 빨간 옷… | ERROR(ⓓ 대응) | 문맥 충돌("정말 없다는 게 아니라") |
| S8 | d는 아무 옷이나, e는 빨간 옷… | SUPPORTED | 정상 |
| X1 | d는 갑이 들고 있는 옷이고, e는 빨간 옷이라 서로 다른 대상이니 4번은 틀렸어요. | SUPPORTED 우선, ERROR(ⓓ 대응)도 인정 | 다른 기호(ⓑ)가 가리키는 한 벌로 ⓓ를 말한 경계 사례 |
| X2 | d는 옷장 안에 있는 옷만 가리키고, e는 빨간 옷이라 다른 대상이니 4번은 틀렸어요. | SUPPORTED·ERROR(ⓓ 대응) 모두 인정 | 학생이 직접 "만"을 쓴 경우 |
| X3 | d는 옷장에 있는 빨간 옷이고, e는 빨간 옷이라 다른 대상이니 4번은 틀렸어요. | ERROR(ⓓ 대응) | 갑은 빨간 옷이 없다고 했으므로 문맥 충돌. 관대해지는지 확인 |

X1·X2 기대값은 사용자 결정(2026-10-07). ⓓ는 바로 앞 을의 ⓒ("옷장 안에 옷이 이렇게 많은데 무슨 ⓒ옷이 없어?")를 받는 것이 더 자연스러우므로,
갑이 들고 있는 한 벌(ⓑ)이나 "옷장 안의 옷만"을 오류로 보는 판정에도 근거가 있다. 두 응답은 경계 사례로 따로 집계하고, 판정 결과보다 대입 충실도
(학생이 쓴 "만"은 반영하고 쓰지 않은 "만"은 넣지 않는지)와 근거의 일관성을 주로 본다.

규모: 11응답 × 2조건 × 3반복 = 66칸. 운영 평가기 재시도·학생 결론 독립 확인 포함 예상 70~90요청, 상한 150요청·추정 2.5달러.

## 6. 지표

- 라벨·단계 기대 일치(자동), 응답별·조건별.
- S5 과잉 교정 수, S2·S3·S7·X3 오류 검출(오류 위치 포함).
- ⓓ=빨간 옷 오독(reason·errors·coaching, 사람 검토).
- 대입 충실도: substitutedText 괄호 안이 학생 표현 그대로인 비율(코드), 판정 문장 전체에서 학생에게 "만"을 귀속한 건수(검토).
- 세 확인의 결과 분포(PASS/FAIL/UNCLEAR)와 판정 규칙 위반으로 인한 계약 실패·재시도 수.
- 의미 판정은 Claude 먼저 고정 → GPT 블라인드 → 한 차례 반론. 기준은 2단계의 P1~P4와 교정 질문 품질.

## 8. 알려진 한계

- 언어 모델은 대입 문장을 대체로 "자연스럽다"고 보는 경향이 있어 관대해질 수 있다. X3과 S7이 이를 확인하는 대조다.
- "선지가 따지는 구별" 확인은 판정기가 선지의 핵심을 읽어야 해서, 그 부분의 오독은 막지 못한다.
- 공손룡 한 문항, 소표본이다. 다른 기호 종류로의 일반화는 이번에 확인하지 않는다.
