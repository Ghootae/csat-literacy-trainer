## 1. 사용자 코멘트별 대조

### 의식과 인지
- 14·16번: 앞 보고서(`REPORT-sns-diagnostic-judgment-strictness-2026-11-07-desktop.md`) 그대로. 사고 진단도 두 문항 모두 실패 없음.
- 12번 "근거를 쓰기엔 너무 명확": 기록상 근거 생략으로 처리됐고 `UNVERIFIED_CORRECT`. 근거 생략 버튼이 이 경우를 받는 장치다. 다만 결과 화면에서 "근거 생략 = 감으로 고름"처럼 읽히면 억울하다. 생략 문항을 "근거를 쓰지 않음"으로만 세고 부정적으로 표현하지 않는지 화면 문구를 확인할 것.

### 경마식 보도
- **5번**: 근거 "헌법재판소 논의는 언론의 자유와는 상관이 없음"은 원문(헌재가 알 권리와 언론의 자유 침해 여부를 다룸)과 실제로 어긋난다. **ERROR 판정 자체는 맞다.** 사용자 지적대로 교정 질문 "어떻게 다뤘어?"는 열린 질문이라 무겁다. "헌법재판소는 이 규정이 언론의 자유를 침해하는지 다뤘어, 다루지 않았어?"처럼 확인형이면 충분했다. 교정 질문 형식 규칙(답 표현 넣지 않기)과 부딪히는지 CLI 확인 필요.
- 5번 선지별 설명에서 "개발자 모드는 지문에 해당 영역을 표시하지 않나?": 기록의 말풍선에는 원문 표시 정보가 없다. 진단 화면이 판정의 `sourceEvidence`를 지문 표시로 연결하지 않았을 가능성. CLI 확인 필요.
- **6번**: 근거 "ⓐ는 제한이 합리적이라는 입장, ②의 사례는 제한으로 불합리가 생긴 경우 → ⓐ 약화"는 문항의 핵심을 짚었다. 판정기는 "어떤 일이 제한의 문제를 보여 주는지"를 원문 사실로 더 쓰라고 했다. 이건 선지 문장에 이미 적힌 상황이다(P1). 사고 진단은 전 단계 PASS. 사용자 판단이 맞다.

### 플라스틱
- **8번(부정 발문)**: 근거 "과산화물 개시제가 되면 안정적인 분자 구조가 불안정화됨"은 ④의 "안정해진다"를 반박한다. 거짓 선지는 한 지점 반박이면 충분하다(앞 보고서 3.4절, 13번이 SUPPORTED인 이유와 같은 원리). 그런데 판정은 UNKNOWN이고 M4는 "④의 '불안정한 원자를 가진 에틸렌'이라는 주장까지 판단한 건지 알기 어려워"라며 다른 주장까지 요구했다. **사용자 기억대로, 개발자 모드에서 정한 원리가 이 사례에서 적용되지 않았다.** 다만 근거 문장의 주어가 모호해서(무엇이 불안정화되는지) UNKNOWN이 나왔을 가능성도 있다. 사고 진단은 "④의 '안정해진다'를 반박"으로 읽고 PASS.
- **10번**: 근거 "(나)는 결정화 → 화학적으로 안정"에 대해 "㉮보다 ㉯가 더 적합한 이유까지 연결"을 요구. 비교 결론은 선지 문장에 이미 있다(P1). 사고 진단 PASS.
- 10번 코멘트 "근거가 불충분해도 정답 여부는 먼저 확인되어야 함": 기록상 정오는 M4 안에서 "③을 고른 건 맞아"로 처음 나온다. 그 앞에 "네 근거에서 맞는 부분은 살리고, 더 이어야 할 연결은 설명에서 같이 볼게"가 먼저 나와서, 학생은 맞았는지 틀렸는지 모르는 채 "부족하다"부터 듣는다. 진단 모드가 즉시 말풍선(`withoutInstantBubble`)을 끈 영향이다. **답 입력 중에는 정오를 숨기되, 피드백 차례에 문항에 들어갈 때는 코드로 정오를 먼저 보여야 한다**(오디오 B-1과 같은 문제).

### 오디오
- **16번**: 근거 "임계대역은 차폐가 일어나는 범위"에 대해 "주파수 차이와 폭의 비교 조건"을 요구. 이 조건은 선지에 적혀 있다(P1). 다만 여기서는 사고 진단도 INSUFFICIENT라서, 다섯 문항보다는 판단이 갈릴 수 있는 사례다.
- 16번 "개발자 모드보다 설명이 짧음, 같은 판정기인가": 같은 판정기(v5.8)·같은 M4(layout v2.2)다(앞 보고서 2.1). 짧게 느껴진 이유는 기록만으로 확정 못 함.
- **17번**: 원래 근거 "C의 차이가 더 큼 → 더 많은 비트"는 표 값과 다르고, ⑤(D에 더 많은 비트)를 고른 것과도 맞지 않는다. **ERROR 판정은 맞다.** 문제는 그 뒤다.
  - 교정 질문 "C와 D의 차이는 각각 얼마야?"에 학생이 "C: 26, D: 49"로 답해 방향(D가 더 큼)을 바로잡았다. 그런데 M4는 "C의 차이를 26dB라고 한 계산은 아직 맞지 않아(25dB)"라고 1dB 차이를 오류로 짚었다. 판정을 바꾸지 않는 차이를 오류로 본 것으로, **P2와 같은 문제**다.
  - "질문이 2단계": 두 번째 질문 "그러면 이 선지는 적절한 설명이야, 적절하지 않은 설명이야?"는 교정 뒤 선지 판단을 다시 묻는 단계로 보인다. 설계대로인지는 CLI 확인 필요. 학생은 여기서 "적절하지 않음"이라고 답했는데 발문이 "적절한 것은?"이라 헷갈리기 쉬운 질문이다.
- B-1 "개발자 모드는 응답 후 바로 정답 여부를 코드로 보여줬다": 맞다. 진단 모드는 그 즉시 말풍선을 끈 것만 다르다(`withoutInstantBubble: true`). 위 10번 항목 참고.
- A(문단 요약) 1~3: 요약 대화 원문이 참가자 파일에 없어 대조하지 못했다. "답이 정해진 질문은 그에 맞춰 질문", "필수적이지 않은 확인 질문"은 예전부터 지적한 과잉 질문 문제와 같은 줄기다.

### 최종 분석
- **"적절한 근거 4개"**: 기록과 맞다. SUPPORTED가 의식 13, 경마 7, 오디오 14·15 넷이다. 숫자가 틀린 게 아니라 판정이 엄격해서 적게 나온 것이다. 사고 진단 기준으로는 5개(의식 14·16, 경마 6, 플라 8·10)가 더 충분했다.
- **"근거를 살펴본 9문항"**: 근거를 쓴 13문항에서 SUPPORTED 4개를 뺀 9문항이다. 사고 진단은 SUPPORTED 정답에는 돌리지 않기로 했기 때문이다(인계 A (4)). 숫자는 맞지만 문구가 틀렸다. "근거를 살펴본"이 아니라 **"근거가 충분하지 않았던 9문항 중"**처럼 무엇을 센 것인지 밝혀야 한다. 9문항 중 근거 해석 단계 실패 3개는 경마 5, 플라 9, 오디오 17이다.

## 3. 우선순위 제안

1. **정답 판정 분리 + P1·P2**: 이번 자료에서 사고 진단과 판정기가 5문항에서 갈렸다. 이 5문항 + 오디오 16을 정답 판정 새 지시문의 첫 시험 세트로 쓴다. 오디오 17의 "26 vs 25"는 P2 시험 사례.
