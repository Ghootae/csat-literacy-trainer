## 1. 무엇을 위한 작업인가

### 1.1 제품 맥락

수능 국어 독서 문제를 푼 학생이 **선지 선택과 그 이유(자유 서술)** 를 입력하면, LLM 판정기가 원문·문제·정답·공식 해설을 보고
학생 근거를 판정한다. 판정 결과에 따라 서버가 다음 행동을 정한다.

- 근거가 원문과 맞음(SUPPORTED) → 근거 확인 완료(VERIFIED_CORRECT) 또는 선택 불일치 질문.
- 근거에 내용 오류(ERROR) → 오류 설명과 **교정 질문**을 보여 주고 학생의 수정 답변을 기다림(AWAITING_CORRECTION).
- 근거 부족·재구성 불가(INSUFFICIENT·UNKNOWN) → 코칭을 보여 주고 종료(정답을 맞혔으면 UNVERIFIED_CORRECT, 틀렸으면 정답 공개 후 COACHING_TERMINATED).

판정기 지시문은 v5(`packages/pipeline/experiments/problem-solving/source-direct-problem-feedback-v4-v3-based-candidate.md`,
sha256 98d36119…)다. 학생에게 보이는 칸은 errors.description·errors.question·selectionMismatchQuestion·coaching이고,
reason·reconstructedPath·studentClaims.sourceBasis는 내부 칸이다.

### 1.2 이번 시험의 질문

앞선 공손룡 12번(1문항, 응답 11개 × 3반복) 모델 비교에서 같은 기준(GPT 블라인드 검토, P1~P4 모두 통과)의 결과는 다음과 같았다.

| 모델 | P1~P4 모두 통과 |
|---|---|
| gpt-6.1-sol | 32/33 |
| gemini-3.8-flash (medium) | 32/33 |
| gpt-6-luna | 29/33 (라벨·오류 검출은 sol과 같고, 실패 4건은 설명 문장의 국소 오류) |
| gpt-5.6-terra | 28/33 |
| deepseek-flash low / high | 25/33 / 22/33(+판정 없음 1) |

사용자 판단(2026-10-08): luna는 비용이 매우 낮고(공손룡 33칸 약 0.06~0.09달러), gemini는 2027년부터 가격 인상 예정이다.
그래서 **luna를 운영 후보, sol을 정확도 기준선**으로 두고 다른 문항으로 넓혀 시험한다. gemini·DeepSeek은 이번에 뺐다.

이번 시험이 답하려는 질문:

- (가) luna의 판정 정확도가 다른 문항·다른 오류 유형에서도 sol과 비슷한가.
- (나) luna의 약점(설명 문장 오류)이 학생에게 보이는 칸에 얼마나 들어가는가. → 의미 검토 단계에서 답한다(아직 안 함).
- (다) 그림 문항(mRNA 19번)에서 luna가 그림을 읽고 판정할 수 있는가.

### 2.3 진행 순서

1. 설계안 작성 → 사용자 승인. mRNA 응답 6개 기대값 사용자 확인.
2. 인계 문서(`docs/handoffs/2026-10-08-v5-multi-item-luna-sol.md`)로 Codex가 실행기·검토 묶음 생성기·단위 시험을 구현.
   구현 중 Codex가 "운영 스키마가 media의 alt를 거부한다"는 설계 공백을 보고하고 멈췄다. 운영 앱이 alt를 빼고 보낸다는 것을 확인한 뒤
   실험도 같게 하도록 인계 문서를 고쳐 재개했다. Claude가 diff를 검토했고 단위 시험 10/10 통과.
3. 사전 점검(사용자 승인): 모델별 M1 1요청. 두 모델 모두 이미지 입력 포함·응답 완료·운영 검증 통과·라벨 SUPPORTED(기대와 일치).
   비용 luna 약 0.002달러, sol 약 0.03달러.
4. 본 실행(사용자 승인): 두 모델 병렬, 180칸.
5. 블라인드 검토 묶음 10개(A~J, 모델 × 문항, 묶음당 18칸, 모델 이름·반복 번호 가림) 생성 완료. **의미 검토는 아직 시작하지 않았다.**

### 2.4 앞으로의 의미 검토 방법(설계 확정)

- 기준: P1 판정(라벨·단계), P2 근거(원문 대조 정확성), P3 귀속(학생이 말하지 않은 것을 학생 것으로 돌리지 않음), P4 오류 위치.
- P2 실패는 학생에게 보이는 칸과 내부 칸으로 나눠 센다.
- 교정 질문 품질(양자택일·예/아니오·정답 노출)은 따로 나열한다.
- Claude가 180칸 전부를 코칭 끝까지 읽고 판정을 먼저 고정(sha 기록)한 뒤 GPT-6 Astra가 블라인드로 검토한다. 불일치는 원문 대조로 가리고 남는 이견은 그대로 기록한다.

### 3.4 자동 불일치 칸의 원출력 (luna)

**I1** — 학생: "실명 없이도 법 제정이 가능하다는 것을 근거로 소수파는 실명 확인을 주장할 수 없음."(선택 ④, 오답. 정답 ⑤)

- luna r1 reason(내부): "…이 근거는 소수 의견의 실명 확인 주장 여부를 말할 뿐, 게시자 이름을 달리한 글이 △△법 제정으로 이어진 경우가 소수 의견을 뒷받침하는지 직접 판단하지 않습니다. … 학생의 주장을 명시적으로 반박하거나 뒷받침하지는 않아 근거는 충분하지 않습니다." → INSUFFICIENT, 교정 질문 없이 정답 공개 후 종료. r3도 같고, r2는 재구성 불가(UNKNOWN)로 봤다.
- sol r1 reason(내부): "…소수 의견은 허위·왜곡 정보가 자율적으로 교정되기 어렵다는 점을 문제 삼는다. 게시자 이름을 달리한 글이 법 제정으로 이어졌다는 조건은 의사 결정 왜곡의 우려를 뒷받침할 수 있으므로, 이를 실명 확인을 주장할 수 없는 근거로 삼은 관계 판단은 원문과 어긋난다." → ERROR 1개, 교정 질문 후 대기. 세 번 모두 같다.

**D6** — 학생: "카르비도파는 뇌에 못 가니까요."(선택 ②, 정답)

- luna r1 reason: "…그 사실로부터 선지의 '흑질에서 합성된 도파민의 작용 기간을 연장할 수 있다'는 주장을 어떻게 판단했는지는 드러나지 않습니다." → UNKNOWN, UNVERIFIED_CORRECT. r2는 INSUFFICIENT. r3는 SUPPORTED(기대와 일치).
- sol r1~r3: SUPPORTED, VERIFIED_CORRECT.
- 참고: D-0085는 이런 "관계만 말한 짧은 근거"를 충분 근거로 보기로 한 결정이다. 기대값은 그 결정을 따른다.

## 4. 아직 모르는 것·한계

- **의미 검토 전이다.** 공손룡 시험에서 luna는 자동 기준을 통과한 칸에서도 설명 문장 오류가 있었다. 이번 85/90·90/90이 의미 기준에서 어떻게 바뀔지는 모른다.
- 기존 24응답의 기대값은 에이전트 작성이고 사람 독립 평가가 아니다. I1의 기대값 ERROR가 유일하게 타당한 판정인지 자체도 논의 대상이 될 수 있다.
- 반복 3회는 작다. 칸당 불일치율 추정에는 넓은 불확실성이 있다.
- 범위는 최초 선택 판정뿐이다. 교정 답변 판정(REPAIR)에서의 모델 차이는 시험하지 않았다.
- 비용은 캐시 할인을 적용하지 않은 보수적 값이다. 입력 토큰의 약 87~88%가 캐시 적중이었다.
- 해석본(gloss)을 붙인 조건은 시험하지 않았다.

## 5. 논의하고 싶은 질문

1. I1처럼 "학생이 틀린 관계를 근거로 댔지만, 그 관계가 선지 판단과 어떻게 이어지는지는 분명하지 않은" 응답을 ERROR(교정 질문)로 볼지,
   INSUFFICIENT(코칭 후 종료)로 볼지. 판정 기준을 어떻게 적어야 모델 간 차이가 줄어드는가.
2. D6처럼 짧은 관계 근거에서 판정이 반복마다 흔들리는 것(luna 1/3만 SUPPORTED)을 지시문 보강으로 줄일 수 있는가, 모델 한계로 봐야 하는가.
3. 운영 판단에서 "오류를 덜 잡는 쪽의 실패"(교정 기회 상실)와 "설명 문장의 국소 오류"(학생에게 틀린 설명 노출)의 무게를 어떻게 비교할 것인가.
4. 비용 차이(약 15배)를 고려할 때, luna 단독·sol 단독·혼합(예: 특정 판정만 sol로 재확인) 중 어떤 구조를 검토할 가치가 있는가.
5. 의미 검토에서 더 봐야 할 항목이 있는가(예: 오류 개수 차이의 타당성, 교정 질문의 정답 노출 여부).
