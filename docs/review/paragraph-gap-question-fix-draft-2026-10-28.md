# 설계 초안: 문단 요약 빈 곳 질문 — 담은 부분 되돌리지 않기(가)·이미 말한 것에서 출발하는 질문(나)

- 날짜: 2026-10-28 · 작성: Claude · 상태: **초안(사용자 검토 대기, 실행 전)**
- 근거: [3문단 10회 재판정](../experiments/paragraph-boundary-stability-2026-10-28/README.md), 사용자 화면 세션 85391e6c(3문단)·d6bb304e(5문단)
- 대상: 문단 지시문 `paragraph-simple-holistic-prompt-v4.7.md` → v4.8, `packages/pipeline/src/paragraph-simple/{schema,rules}.ts`, 서버 `dialogue-simple.ts`

## 1. 문제

**(가) 한 번 담았다고 본 부분이 다음 단계에서 '빠짐'으로 뒤집힌다.**
- 5문단 d6bb304e: 첫 요약 "…엔도솜이 터져서 mRNA가 방출 → 바이러스 단백질 합성 & 면역 반응" → INITIAL에서 2번 담음(true). 1번 바로잡기 답 뒤(AFTER_CORRECTION) 2번이 false로 뒤집혀 2번을 다시 물음 → 학생이 같은 말("바이러스 단백질 합성 → 면역 반응")을 또 하고 "아직 충분히 담기지 않았어"로 끝남.
- 원인: 판정기가 단계마다 담음 여부를 처음부터 다시 매기고, 앞 단계 결과를 입력으로 받지 않는다. 코드에도 막는 규칙이 없다.
- 빈도(저장 기록, 외부 호출 없음): 두 단계 이상인 시도 59개 중 1개(이 세션, 단계 2개). 드물지만 일어나면 학생 경험이 가장 나쁜 경우다.

**(나) 빈 곳 질문이 학생이 이미 말한 요소를 무시하고 부분 전체를 처음부터 묻는다.**
- 3문단 첫 요약 "꼬리(세포막 구성)와 인산기 머리(외부 수용액 접함)" → 10회 중 GAP 6회, 질문 6개 모두 배열 전체를 다시 물음(예: "인지질은 어떤 모습으로 배열되어 세포막을 이룰까?"). 학생이 말한 머리·꼬리 위치에서 출발해 빠진 고리(꼬리끼리 모임, 그 이유)만 묻는 질문 0/6.
- "인지질의 성질은 세포막을 이루는 배열에 어떻게 나타나?"(2/7회 모양)는 성질 이름만 대도 답처럼 보여 학생이 "양친매성 물질"로 답했고, 마무리가 "방금 답은 배열에 관한 설명과는 달라"로 맞는 방향의 답을 부정했다.
- 지시문 질문 작성 규칙(1~4)에 "학생이 이미 말한 것"에 관한 규칙이 없다.

## 2. 전략

**(가) 코드 규칙 + 입력 한 칸 (지시문은 설명 한 줄)**
1. 서버가 현재 시도의 앞 단계들에서 한 번이라도 true였던 부분을 `coveredBefore: boolean[] | null`로 판정 입력에 넣는다(INITIAL은 null; RETRY는 앞이 IRRELEVANT·COPY뿐이라 실제로 모두 false).
2. 검증 규칙(`validateSimpleOutput`): `coveredBefore[i]`가 true인데 출력 `corePartsCovered[i]`가 false이면, 그 부분을 가리키는 `errors[].corePartIndex`가 있을 때만 허용한다(학생이 나중 답에서 앞 말을 뒤집은 경우 = 오류 경로). 아니면 검증 실패 → 기존 재요청 1회(검증 사유를 알려 줌).
3. 지시문: 입력 설명에 "`coveredBefore`가 true인 부분은 학생이 그 부분을 뒤집는 말을 해 오류로 잡을 때가 아니면 true로 둔다" 한 줄.
- 서버가 출력을 덮어쓰지 않는 이유: 담음 여부가 category·action·message·gaps를 함께 정하므로, 한 칸만 바꾸면 "2번이 빠졌어"라는 말과 화면이 어긋난다. 재요청이면 모델이 앞뒤가 맞는 출력을 다시 쓴다.

**(나) 질문 작성 규칙 5번 추가 (지시문)**
- "그 부분에 대해 학생이 이미 말한 요소가 있으면 그것을 다시 묻지 않는다. 학생이 말한 것을 출발점으로 삼아 빠진 고리 하나만 묻는다."
- "개념의 이름 하나만 대도 답한 것처럼 보이는 질문(예: '그 성질은 …에 어떻게 나타나?')은 피하고, 빠진 관계(무엇이 어떻게 되는지)를 말해야 답이 되게 묻는다."
- 위 문장은 방향이다. 실제 문장은 기존 규칙 1~4와 문체를 맞춰 다듬는다(사례 문장을 지시문에 그대로 넣지 않는다).

**(가)·(나)를 함께 v4.8로 묶는다.** 지시문 버전 하나, 서버 코드 한 번 배포.

## 4. 위험

- **(가) 재요청 실패**: 모델이 두 번 다 뒤집으면 지금은 "판정 실패" 화면이 된다. V1에서 재요청 뒤에도 실패가 나오면, 그때만 서버가 그 부분을 true로 두고 나머지가 모두 true면 PRAISE로 정리하는 대안을 검토(이 초안에는 넣지 않음).
- **(가) 잘못 담음이 굳음**: 첫 판정이 너그럽게 true로 본 것이 끝까지 간다. 지금도 "애매하면 담은 것" 원칙이라 방향은 같다. 학생이 뒤집는 말을 하면 오류 경로가 남는다.
- **(나) 질문이 학생 말을 인용하며 길어짐 / 답을 흘림**: 규칙 2(답이 되는 개념어를 넣지 않는다)와 부딪힐 수 있다. 예: "머리는 수용액에 닿는다고 했는데, 꼬리는?"은 짧고 좋지만 "꼬리끼리 모인다"를 유도하는 정도가 커질 수 있다. V2에서 사용자 판단으로 확인.
- **(나) 판정 경계는 그대로**: 3문단 GAP 6/10 자체는 이 초안이 줄이지 않는다(질문만 나아짐). 질문을 고친 뒤 남으면 "부분 요소를 위치·관계로 말했으면 담음" 경계 규칙을 따로 다룬다.

## 범위 밖 (기록만)

- 5문단 첫 바로잡기 질문이 "산도↓ = pH↑" 방향 오류를 짚지 않은 문제(오류 설명 칸이 비어 무엇을 오류로 봤는지 불명). 별도 사례로 모은다.
- 마무리 문장이 같은 인과 줄 위의 덜 말한 답을 "다르다"고 부정하는 문제(3문단 CLOSE_GAP). (나)로 질문이 좁아지면 줄어드는지 V2 뒤 확인.
