## 6번 상세

사용자가 받은 최종 코칭(정보 비대칭 q13):

> 처음에 “갑은 ai를 이용해 서비스 제공. 따라서 규제 대상.”이라고 한 부분은 ⓐ의 적용 대상을 넓게 본 것이에요. … 그래서 플랫폼 A를 ⓐ로 제재하지 못한다는 ①은 적절해요.
>
> 다시 선택할 때 말한 “다수 의견은 실명확인이 필요하다고 보았으므로”는 원문과 달라요. 원문에서 다수 의견은 … ‘위헌’이라고 결정했어요.
>
> 따라서 적절하지 않은 선지는 ⑤예요. … ⑤는 헌법 재판소의 결론을 반대로 설명한 것이에요.
>
> 마지막으로 고른 ③은 적절한 설명이므로 답이 아니에요. … ③의 설명은 맞아요.
>
> (정답 카드) 정답 5번 …

사용자 수정 예시(각 번호는 개별 메시지 창):

1. 정답은 5번이에요. (코드 베이스)
2. 사용자님의 응답을 기반으로, 어디에 오류가 있었는지 하나씩 검토해볼까요? - 예/아니오 버튼(예: 계속, 아니오: 종료) (코드 베이스)
3. 처음에 사용자님이 1번을 선택한 것에 대해 살펴볼게요.
4. (첫 선택 ①에 대한 문단)
5. 이번엔 두 번째로 사용자님이 3번으로 선택한 것에 대해 살펴볼게요.
6. (다시 선택한 ③의 근거 오류 + ③이 답이 아닌 이유를 한 문단으로) — 사용자: "원본 피드백은 내용의 순서에 문제가 있어. 검토해줘"
7. 이번엔 5번이 정답인 이유를 살펴볼게요.
8. (⑤가 정답인 이유)
9. 충분히 이해가 되셨을까요? - 예(종료), 아니오(이 문제는 차후에 다시 검토할 수 있게 기록해두겠습니다.)

### 결정: 구조 (2026-10-13, 사용자 "6번은 내용대로 확정")

- 원인: sol 종료 지시문이 내용 종류 순서(① 처음 생각의 오류 → ② 맞는 내용 → ③ 정답 이유 → ④ 마지막 선지)로 쓰게 되어 있다. 그래서 재선택 세션에서 같은 선지의 이야기가 정답 설명을 사이에 두고 둘로 갈라진다.
- 구조:

| # | 말풍선 | 작성 |
|---|---|---|
| 1 | 정답은 ⑤번이야. | 코드 |
| 2 | 네 답을 하나씩 같이 볼까? [응] [아니] | 코드(아니 → 종료) |
| 3 | 처음에 고른 ①번부터 볼게. | 코드 |
| 4 | ①에 대한 이야기(네 생각, 틀린 곳, 답이 아닌 이유) | 모델 |
| 5 | 다음은 다시 고른 ③번이야. | 코드(재선택이 있을 때) |
| 6 | ③에 대한 이야기 | 모델(재선택이 있을 때) |
| 7 | 이제 ⑤번이 정답인 이유를 볼게. | 코드 |
| 8 | ⑤가 정답인 이유 | 모델 |
| 9 | 이해됐어? [응] [아니] | 코드(아니 → "이 문제는 나중에 다시 볼 수 있게 표시해 둘게.") |

- 모델은 처음부터 칸을 나눠 쓴다(첫 선택 / 재선택 또는 없음 / 정답). 긴 글을 코드가 자르지 않는다.
- 연결 문장과 버튼은 코드가 붙인다.
- 정답 세션(luna 설명)도 같은 틀이다: "정답이야." → 근거 이야기 → 정답 이유 → 이해 확인. 재선택으로 정답이 된 세션은 첫 선택 이야기가 앞에 붙는다.
- 표시 방식(2026-10-13, 사용자 "권고안으로 확정"):

포인트: 지금보다 좀 더 직접적인 질문이 필요하다(정답 정보나 오류 정보가 좀 더 직접적으로 드러나는 것을 감수).

관련(논의 때 볼 것, Claude 메모): 교정 질문 규칙 [D-0105](../../memory/decisions/D-0105-correction-question-covers-choice-deciding-relation.md), 판정기 지시문의 질문 작성 규칙, 서버의 정답 누출 검사(`validateQuestion`), 지문 강조 표시는 질문과 지문 위치를 연결하는 정보가 필요.


### 결정 A: 질문 작성 규칙 (2026-10-13, 7·12번)

- 원인: 판정 지시문의 질문 규칙이 정답을 흘리지 않는 쪽에 치우쳐 있다("올바른 결론을 모두 제시한 뒤 동의만 요구하지 않는다" 등). 그래서 모델이 한 단계 추상적인 분류로 묻는다.
- 방향(사용자 확정):
  1. 학생이 틀린 그 주장을 직접 겨냥한다. 학생이 말하지 않은 전제를 대신 묻지 않는다(12번 I-A1).
  2. 추상적인 분류 대신 지문에 나온 구체적인 사실과 낱말로 묻는다.
  3. 형식은 **학생 주장에 따라 두 갈래 질문 또는 짧은 직접 질문**이다(사용자: "열어 두는 안으로"). 두 갈래면 한쪽은 학생 생각, 다른 쪽은 원문의 사실이다.
  4. 유지: 정답 번호와 정답 선지 문장을 넣지 않는다. 다른 선지를 지워 정답을 좁혀 주지 않는다.
- 감수: 정답·오류 정보가 더 드러나고, 두 갈래는 찍어서 맞힐 수 있다. 교정 성공을 이해의 증거로 읽지 않는다.

### 결정 B: 지문에 근거 위치 표시 (2026-10-13, 사용자 "확정")

- 교정 질문 단계에서만, 지금 묻는 오류의 원문 근거 인용(`sourceEvidence`의 지문·보기 인용)을 미색으로 칠한다. 답을 보내면 표시가 사라진다.
- 그림 자료 근거는 칠하지 않는다.
- 지문 칸을 첫 표시 위치로 자동 스크롤한다.
- 탭 화면에서는 질문 말풍선 아래 [지문에서 보기] 링크를 둔다. 누르면 지문 탭으로 바꾸고 그 위치로 스크롤한다.
- 판정 지시문에 "근거 구절은 화면에 표시되므로 '표시한 부분'이라고 가리킬 수 있다"를 넣는다.
- 화면에는 표시할 위치(지문/보기, 시작·끝)만 보낸다. 오류 설명은 보내지 않는다.
- 실모델 확인 때 "칠한 곳이 질문과 맞는지"를 검사한다.
