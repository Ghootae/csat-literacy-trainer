# 분석 지도의 쓰임: 학생 이해 지문과 선지 연결 (논의 기록)

- 날짜: 2026-10-17~18
- 참여: 사용자, Claude
- 관련: [D-0141](../../memory/decisions/D-0141-paragraph-analysis-map-direction.md), [D-0143](../../memory/decisions/D-0143-analysis-map-gongsun-pilot.md), Q-0037
- 상태: 논의 중. 결정 아님.

## 1. 출발점: 공손룡 파일럿 기준선

사용자: 분석 지도 자료는 **오프라인 사고 상태 판정**용이다. 실시간으로 학생에게 노출하지 않으므로 적당한 완성도면 된다. 공손룡 파일럿 품질(판정 v3)이면 충분해 보인다.

Claude 의견: 동의. 근거는 원문 복사 대조군 모순 0, 지정 실제 오류 7개 v1~v3 모두 검출, 남은 오탐(오류 사건 17 중 약 4)은 오프라인 집계에서 감당 가능. 단서 두 가지.
- 학생 개인 판단에는 3회 판정 다수결 권고(1회 판정은 경계 사례에서 흔들림).
- 근거가 공손룡 한 지문·개발자 입력 위주라 다른 성격 지문에서 같은 흐름이 도는지 미확인.

기준선 구성: 동결 지도 r3 + 입장 확정본(`stance/stance-final.json`) + 판정 지시문 v3 + 오류 집계 규칙. 열린 항목: 상위 "부분" 패턴, 라운드 하락, 교차 관계(지문 단위 판정), 3회 판정.

## 2. 사용자 이미지 1: 학생의 문단 이해 지문

사용자: "한정된 관계 목록에서의 성공률 패턴, 즉 문단 이해의 지문을 파악하는 걸 생각하고 있어. 예를 들어, A라는 학생은 '사실 파악은 좋은데(명제는 잘 맞춤)', '논의 전환'을 파악하는 건 약하다."

Claude가 짚은 함의:
1. **닫힌 관계 목록이 필수.** 현재 관계 이름은 자유 라벨(공손룡 한 지문 26개, 같은 종류가 여러 이름). 유형별 성공률에는 소수 고정 목록이 필요하다 — D-0141의 "분야별 지문 표본 후 목록 작성"과 같은 작업.
2. **"논의 전환"은 현재 가장 비어 있는 곳.** 공손룡의 전환 관계(R16·R17·R20 반박, R27 대조)는 대부분 문단을 넘는다. 문단 대화 단위 판정에서 교차 관계 68건 중 52건이 "없음"이라, 그대로 두면 모든 학생이 전환에 약하게 나온다. 지문 단위 판정 층이 이 이미지의 핵심 부품이 된다.
3. **"안 말함"과 "모름"의 구별.** 자유 요약은 학생이 고른 것만 말한다. 질문 뒤 라운드나 문제 풀이 같은 다른 측정이 있어야 "약하다"고 말할 수 있다.

## 3. 사용자 이미지 2: 명제와 선지 연결

사용자: "명제를 문제 풀이의 선지와 연결시켜서, 문제 풀이에서의 사고 패턴을 고해상도로 복원해보고 싶은데, 이 부분은 더 이미지가 희미해."

Claude 정리: 선지는 대부분 지문 명제·관계의 바꿔 쓰기이고, 틀린 선지는 어딘가를 비튼다. 선지마다 "어느 노드·관계를, 어떻게 비틀었나(귀속 바꿈, 방향 뒤집기, 범위 과장 등)"를 한 번 표시해 동결하면, 학생이 고른 선지가 지도 위 좌표가 된다.

두 이미지는 같은 좌표계(지도 + 관계 유형 + 오류 유형)를 공유한다. 요약 판정은 학생이 스스로 말한 것, 선지 연결은 판단을 요구받았을 때 고른 것을 같은 지도에 찍는다. 둘을 합치면 "안 말함 대 모름"도 상당 부분 가를 수 있다(요약 없음 + 그 관계를 비튼 선지에 넘어감 → 약점, 요약 없음 + 선지 맞힘 → 알지만 말하지 않음).

## 4. 열린 질문 (하나씩 논의 예정)

1. 학생 지문의 축: (가) 관계 유형만 / (나) 관계 유형 + 층(명제·합성·요지) / (다) (나) + 오류 유형. **합의(2026-10-18, 사용자 "권고대로"): (나)로 시작, 오류 유형은 선지 연결 때 선지 비틂 분류와 같은 목록으로 더한다.**
2. 닫힌 관계 목록을 언제·어떻게 만들지.
3. 교차 관계·지문 단위 판정 층의 설계.
4. 선지 연결의 단위와 비틂 분류.

## 5. 우선순위 (사용자, 2026-10-18)

"일단 도파민 문단 4, 정보 비대칭 문단 중 하나를 타겟으로 품질이 유지되는지 테스트해보는게 우선일 거 같아. 품질 유지가 안되면 쓸데없는 이야기니까." → 위 논의는 다른 지문 품질 확인 뒤 이어간다.
