## 2. 2차: 함정 의도 제약 있음·없음 비교

### 2-1. 측정

- 자동 검사: 16/16이 형식·`evidenceQuotes`·`intentQuotes` 실재·금지어·존댓말을 통과했다. 비튼 조각의 `trapIntent`를 비운 출력은 constrained 조건에서도 0이었다.
- 글 안 따옴표 중 원문에 없는 구간은 대부분 요약 표현이었다('효소 억제', '수치가 커짐' 등). 공손룡 constrained r2는 원문의 안쪽 따옴표를 「」로 바꿔 인용했다.
- 웹 에이전트 블라인드 판정([질문](./trial-2/WEB-AGENT-QUESTION.md), [답변](./trial-2/WEB-AGENT-ANSWER.md)). 최고 글과 조건(키 `trial-2/USER-REVIEW-KEY.json`)은 다음과 같다.

| 선지 | 최고 글 | 조건 | 웹 에이전트 "4편 차이" |
|---|---|---|---|
| 법인 13번 ② | B | open r1 | 작은 편~중간 |
| 표면 장력 16번 ② | A | constrained r1 | 작음 |
| 공손룡 12번 ④ | B | open r2 | 작음 |
| 도파민 13번 ② | D | open r1 | 작음 |

- 사용자는 별도 판정 화면(`trial-2/USER-REVIEW.html`)을 쓰지 않고 웹 에이전트 의견에 동의했다(2026-10-23 "나는 웹앱의 의견에 동의해").

### 2-2. 해석

- 제약 없는 조건에서도 sol은 지문 밖 상식을 끌어오지 않았다. 두 조건의 차이는 지문의 어느 구절을 함정 근거로 끌어오느냐 정도다. 사용자가 open을 기준으로 정했다.
- 반복 약점(웹 에이전트 지적, 코드 에이전트 동의):
  - 함정 설명이 "…을 이용해 …처럼 읽히게"라는 공식에 갇혀, 바로 앞의 "X를 Y로 바꿨어"를 되풀이한다.
  - '맞는 부분' 문단이 16편 모두 비슷하다.
  - 결론 마지막 문장이 비튼 곳을 "…인지 확인해야 해"로 다시 나열한다. 사용자 지적도 같았다("그냥 잘 구분하라는 말이니까 하나마나한 말").

### 2-3. 정정

코드 에이전트는 처음에 "16편 모두 정확성 통과"라고 보고했다. 이 보고는 정정한다.

- **도파민 4편은 통과가 아니다.** 골드가 '흑질에서'를 작용 장소 비틂으로 떼어 냈다. 그런데 선지는 '흑질에서 합성된 도파민'으로 읽히고, 공식 해설도 "흑질에서 이미 합성된 도파민의 작용 기간을 연장한다는 설명은 맞지 않습니다"라고 한다. 4편 모두 "작용 범위를 흑질까지 넓혔어"라고 잘못 설명했다. 코드 에이전트 검토는 글을 골드·원문과만 대조해서, 골드 자체의 오류를 잡지 못했다.
- 공손룡 12번 ④에 대한 웹 에이전트 주장("뒷부분은 대화의 ⓐ에서 실제로 참이며, 이것이 진짜 함정")은 코드 에이전트가 처음에 지지했다가 철회했다. 사용자 지적대로 선지의 뒷부분은 "이 현상(ⓓ·ⓔ)"에 대한 말이라 ⓐ가 끼어들 자리가 없다. 학생이 ⓐ를 떠올린다는 것도 확인할 수 없는 추측이다. 공손룡 골드는 문제로 보지 않는다.

## 3. 3차: v3 (open 기준 + 형식 보완 + 결론 A안)

- v2-open에서 바꾼 것: 맞는 조각은 한 문장, 바뀐 내용은 한 번만, 함정은 학생 속말을 가능성으로, 상태 판단은 원인과 현상을 함께 인용, 「 」 인용 규칙, 결론 마지막 문장은 읽기 습관과 그 대신 할 읽는 동작.
- 측정: 자동 검사는 모두 통과했다. 법인 결론의 ‘부여한다’는 원문에 그대로 있는 말이 아니다(원문은 "부여된다"·"부여한"). 표면 장력은 '노즐에서 나오지 않았다'를 함께 인용했고, 함정 근거로 지문의 ‘얼마나 안정적으로 도착하는지의 정도’(실재 확인)를 짚었다.
- 웹 에이전트 지적(사용자가 전달·동의): 문단이 다시 뭉쳤다. 표면 장력은 비튼 곳 설명 한 문단이 9문장이고, 공손룡은 본문 전체가 한 문단이다. 내용은 좋아졌지만 이해 용이성은 내려갔다.

## 4. 4차: v4 (문단 나누기)

- v3에서 바꾼 것: 비튼 조각마다 원문 문단과 함정 문단으로 나누고, 판단 단계마다 문단을 나눌 수 있게 했다. 한 문단에는 한 가지 일만 담는다. 처음에 넣었던 "4문장 이하"는 사용자 지적(부자연스러워짐)으로 빼고 보냈다.
- 측정: 문단별 문장 수는 아래와 같고, 가장 긴 문단은 5문장이다(v3는 9문장).

| 선지 | 문단별 문장 수 |
|---|---|
| 법인 13번 ② | 1·1·3·2·3·2·3·2·2 |
| 표면 장력 16번 ② | 1·1·5·4·2·2 |
| 공손룡 12번 ④ | 1·5·3·2 |
| 도파민 13번 ② | 1·1·3·2·5·2·2 |

- 자동 검사는 모두 통과했다. 공손룡 결론의 ‘빨간 옷도 옷’은 학생의 생각인데 작은따옴표로 썼다(규칙상 큰따옴표).
- 같은 선지에서도 함정 설명이 회차마다 바뀐다. 공손룡은 v3에서 "뒷부분이 지문 설명과 닮음"이었고 v4에서 "빨간 옷도 당연히 옷이잖아"(일상적 포함 관계)다. 표면 장력은 v3에서 지문 구절이었고 v4에서 일상 상식("수치가 높을수록 성능이 좋다")이다.
- 사용자 판단(2026-10-23): "글 퀄리티는 이 정도에서 만족할 수 있을거 같아." → D-0170 보완에서 v4를 채택했다.

## 5. 제안과 열린 질문

> 정정(2026-10-23, 보고 뒤): 대상 선지는 61개가 아니라 57개다(D-0170 정정). 골드 검수는 별도 단계 대신 전체 생성 뒤 코드 에이전트 검토에서 공식 해설과 대조하기로 했다(사용자 "합치는 걸로 하자").

1. **골드 검수(Q-0039)를 61개 생성 전에 한다.** 코드 에이전트 제안: 스크립트로 골드 비튼 곳과 공식 해설을 나란히 놓은 표를 만들고, 코드 에이전트가 일치·어긋남·판단 불가로 나눈다. 사용자에게는 어긋남만 올리고, 고친 내용은 `overrides.json`에 기록한다.
2. 고정 글이므로 선지마다 여러 편을 생성해 하나를 고를지, 1편만 생성하고 검토에서 걸리면 다시 생성할지 정해야 한다. 함정 설명이 회차마다 바뀌는 것이 고를 거리가 될 수 있다. 다만 이해 용이성은 코드 에이전트가 판정하지 않으므로(D-0167), 고르는 기준은 정확성뿐이다.
3. 4차 형식 흠(학생 생각을 작은따옴표로 씀)이 61개에서 얼마나 나오는지 자동 검사로 셀 수 있다. 결론 문장 안의 작은따옴표 구간이 원문에 없으면 표시하면 된다.
