# B3 6세션 재확인 — 보고서

작성 2026-10-22. 논의용 상세본은 `REPORT-b3-recheck-desktop.md`에 있어요.

## 1. 개요

### 1) 작업의 목적

48세션 회귀 시험에서 버그 하나를 찾았어요. "B3" 학생은 근거 내용은 맞는데, 답을 발문과 반대로 고른 학생이에요. 예를 들어 "적절하지 않은 것을
고르라"는데 적절한 선지를 고르고, 근거로는 "이 선지는 맞아요"라고 쓴 경우예요.

이 학생에게 "그러면 이 선지는 적절한 설명이야, 적절하지 않은 설명이야?"라고 물으면, 학생은 "적절한 설명이에요"라고 맞게 답해요. 그런데
판정기가 학생의 원래 근거를 "근거가 충분하다"의 증거로 쓰려 하면, 서버가 "오류로 표시된 발화는 증거로 못 쓴다"며 막았어요. 서버가 선택 충돌을
표시할 때 학생 근거 전체를 오류 발화로 표시해 두었기 때문이에요. 이번 작업은 이 막힘을 고치고, B3 6개를 다시 돌려 확인하는 일이었어요.

### 2) 작업의 결과

- **고쳐졌어요.** 6개 모두 막힘 없이 한 번에 판정됐고, 모두 "다시 고르기 → 다시 고른 답도 오답 → 정답 공개 → 이해 확인"으로 끝났어요.
- 전에 "방금 답도 정확하지 않았어"라는 엉뚱한 말로 끝난 G-B3도 정상 경로로 돌아왔어요.
- 비용은 약 $0.59예요(30회 전송).
- **정정:** 처음 잡은 요청 상한(sol 20회)이 모자랐어요. 세션마다 sol을 4번 쓰는데 계산을 잘못했어요. 두 세션이 중간에 멈췄고, 승인을 받아 상한을
  26회로 올려 마저 돌렸어요. 막힌 요청은 실제로 보내지 않아 추가 비용은 없었어요.

### 3) 다음 스텝

1. 이 수정과 회귀 시험 자료를 커밋해요(승인 필요).
2. 실행기의 A2 재선택 버그(사례 이름 형식 문제)를 고쳐요. 외부 전송은 없어요.

## 2. 본문

### 1) 선택 충돌 학생의 맞는 근거가 막힘 (해결)

**문제.** G-B3(공손룡 12번)는 "적절하지 않은 것"을 고르는 문제에서 맞는 선지 ③을 골랐어요. 근거는 "ⓑ는 손에 든 한 벌만 가리키므로 유명을
사명으로 쓴 것이에요"였어요. 내용은 맞아요.

**과정.** 회귀 시험에서는 학생이 "적절한 설명이에요"라고 답한 뒤 판정기가 세 번 연달아 서버 검사에 막혔어요. 결국 판정기가 "교정 안 됨"으로
바꿔 통과했고, 화면은 "방금 답도 정확하지 않았어. 더 묻지 않고 정답을 먼저 알려 줄게."로 끝났어요. 학생은 맞게 답했는데 틀렸다고 들은 거예요.
나머지 5개도 같은 검사에 막혔고, "근거 부족"으로 바꿔서야 통과했어요.

선택 충돌 표시는 서버 검사에서 빼고, 진짜 내용 오류의 인용만 막도록 고쳤어요.

**결과.**

| | 전 | 후 |
|---|---|---|
| 검사에 막힌 세션 | 6개 모두 | 0개 |
| G-B3 끝 | 교정 실패, 엉뚱한 피드백 | 다시 고르기 → 정답 공개 |
| 근거 충분 판정 | 막혀서 모두 "부족" | 판정기가 직접 판단: 충분 3(G·I·M), 부족 3(C·D·S) |

"부족" 3개는 판정기가 "이번 답에는 판단 근거가 드러나지 않는다"고 본 경우예요. 검사가 강제한 게 아니에요.

### 2) 실행 중 요청 상한 초과 (해결)

**문제.** 상한을 sol 20회로 잡았는데 실제로는 24회가 필요했어요. M-B3와 S-B3의 다시 고른 답 판정이 막혔어요.

**과정.** 제가 쓴 실행 도구가 막힌 판정을 끝없이 "다시 시도"해서 쓸모없는 기록이 3천여 개 쌓였어요. 실제 전송은 없었어요. 쓸모없는 기록을 지우고,
상한 오류가 나면 바로 멈추게 도구를 고친 뒤 상한을 26회로 올려 마저 돌렸어요.

**결과.** 두 세션 모두 정상 종료했어요.
