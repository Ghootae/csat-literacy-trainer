# 드라이런 요청 수와 예상 비용 상한 (E1)

작성: 2026-11-06, 하위 에이전트(executor). 이번 단계는 외부 전송이 없다. 모든 숫자는 `--dry-run`(또는 가짜 transport 시험)으로 만든 요청 파일에서 센 값이다.

- 근거 인계 문서: `docs/handoffs/2026-11-06-e1-item-generation-implementation.md`, 결정 `memory/decisions/D-0206-gold-based-item-generation-experiment-design.md`.
- **입력 토큰 추정**은 기존 스크립트의 추정 함수(`reserveUsd`: 요청 JSON 바이트 수를 토큰 수로 보고 입력 단가를 곱함)를 그대로 쓴 **상한**이다. 한글은 바이트보다 토큰이 훨씬 적으므로(대략 1토큰 2~3바이트) 실제 입력 비용은 이보다 작다.
- **예상 비용 상한** = 요청마다 (요청 바이트 x 입력 단가 + 최대 출력 토큰 x 출력 단가) / 1,000,000. 응답이 최대 출력 토큰까지 가는 경우를 가정한 값이고, 실제 청구는 보통 이보다 훨씬 작다. 스크립트의 `--usd-cap`은 이 예약액 기준으로 요청 전에 멈춘다.
- 풀이·역연결 dry-run은 가짜 생성 결과로 만들었다. 가짜 문항 문장이 실제보다 짧아 입력 바이트가 약간 작게 잡힌다(문항 몇 개 분량, 상한 영향 $0.01 미만). 출력 상한이 비용의 대부분이다.
- 단가는 USD / 100만 토큰(입력 / 출력).

## 1단계 생성 (`scripts/run-item-generation.mjs`)

모델 `gpt-6.1-sol`, reasoning medium, 단가 $2 / $10, 요청마다 최대 출력 16,000토큰. 재시도 없음.

| 조건 | 요청 종류 | 요청 수 | 입력 바이트(=토큰 추정 상한) | 최대 출력 토큰 합 | 예상 비용 상한 |
|---|---|---:|---:|---:|---:|
| A | 문항 생성 | 4 | 36,567 | 64,000 | $0.713 |
| A2 | 설계(design) | 4 | 44,331 | 64,000 | $0.729 |
| A2 | 집필(write) | 4 | 49,482 | 64,000 | $0.739 |
| B | 설계(design) | 4 | 220,695 | 64,000 | $1.081 |
| B | 집필(write) | 4 | 48,306 | 64,000 | $0.737 |
| 합계 | | 20 | 399,381 | 320,000 | $3.999 (검토 수정 뒤 재생성 $4.038) |

- 지문 4개 x (A 1 + A′ 2 + B 2) = 20요청. 기본 상한(`LIMITS`): 20요청, $5.
- 집필 요청의 입력에는 설계 요청의 실제 출력이 들어가므로, dry-run에서는 가짜 설계표로 크기를 쟀다.
- 설계 요청이 파싱에 실패하면 그 (지문, 조건)의 집필 요청은 보내지 않는다(요청 수가 줄 수 있음).

외부로 나가는 자료(OpenAI, `gpt-6.1-sol`):

| 조건 | 나가는 자료 |
|---|---|
| A | 지문 원문(문단별), 문항 자리(극성·범위) |
| A′ 설계 | 지문 원문, 문항 자리 |
| B 설계 | 지문 원문, 문항 자리, 동결 지도(명제·합성·관계와 관계 유형), 명제별 입장, 다른 지문에서 센 비틂 종류별 개수·비율 |
| A′·B 집필 | 지문 원문, 설계표(설계 요청의 출력) |

기출 문항 텍스트·기출 번호(`realNumber`)·그 지문 자신의 선지 연결 동결본은 어떤 생성 요청에도 들어가지 않는다(시험으로 확인).

|---|---:|---:|---:|---:|
| A | 4 | 242,260 | 60,000 | $1.085 |
| A2 | 4 | 242,260 | 60,000 | $1.085 |
| B | 4 | 242,260 | 60,000 | $1.085 |
| 합계 | 12 | | | $3.254 |

외부로 나가는 자료(OpenAI, `gpt-6.1-sol`): 지문 원문, 지문 표시(밑줄·기호), 동결 지도·입장·관계 유형, **생성 문항**(발문·선지, 정답에서 계산한 truth 포함). 기출 문항은 없다. 이 단계의 실제 실행은 `run-choice-link.mjs`를 대상 파일(`choice-link/targets-<조건>.json`)로 따로 돌려야 하며, 생성이 끝나 `items.json`이 있어야 대상 파일을 만들 수 있다.

## 합계

| 단계 | 요청 수 | 예상 비용 상한 |
|---|---:|---:|
| 1 생성 | 20 | $3.999 |
| 2 풀이 | 96 | $6.584 |
| 3 역연결 | 12 | $3.254 |
| 합계 | 128 | $13.836 |

- 단계마다 따로 승인받는다(D-0206 15항). 풀이 단계는 1단계 결과(`runs/<조건>/<지문>/items.json`)가 있어야 실행되고, 없으면 요청 전에 멈춘다.
- 블라인드 검토지(`scripts/build-generation-blind-review.mjs`)는 외부 전송이 없다. dry-run 검토지는 `dry-run/review/`에 있고 가짜 생성 문항이 들어 있으므로 판정에 쓰지 않는다.

## 만든 파일 위치

- 대상: `targets.json`, 지시문 초안 4개(`BASELINE-PROMPT-v1.md`, `DESIGN-PROMPT-A2-v1.md`, `DESIGN-PROMPT-B-v1.md`, `WRITE-PROMPT-v1.md`), 지문별 비틂 분포 `inputs/<지문>.twist-distribution.json`.
- 생성 dry-run 요청: `dry-run/generation/<조건>/<지문>/{items|design}.request.json` (20개).
- 풀이 dry-run 요청: `dry-run/solve/<출처>/<지문>/<모델>.<모드>.request.json` (96개).
- 역연결 dry-run: `choice-link/dry-run/` (대상 파일 3, 문항 파일 12, 요청 12개).
- 검토지 dry-run: `dry-run/review/USER-REVIEW.html`, `USER-REVIEW-KEY.json`(판정 전 열지 않는다).

## 코드 에이전트 검토 수정 (2026-11-06)

- B 집필 요청: 설계표의 노드 id만 있고 지도가 없어 집필자가 id를 풀 수 없었다(인계 문서 공백). `writeInput(t, design, 'B')`가 `basis`·`twist.targets`를 `{ id, text }`로, 비틂 종류에 한국어 이름(`typeName`)을 붙여 넘긴다. `WRITE-PROMPT-v1.md`에 두 설계표 모양을 적었다. 시험 추가.
- A안 지시문: D-0170 매력 요인 규칙(품질 요구 10)을 넣었다(인계 문서는 세 조건 모두 요구).
- B 설계 지시문: 비틂 표의 예 가운데 E1 대상 지문 기출 선지에서 온 세 개(작은 기포→큰 기포, 자산 총액/자본금, 같은 압력/더 큰 압력)를 중립 예로 바꿨다.
- 생성 dry-run 재생성: 기출 10문항의 발문·선지 300개 문장 조각이 생성 요청 어디에도 없음을 확인했다.
