# 묵가 12번 헤드리스 자동 파일럿

일시: 2026-08-31

대상 문항: 고3 2023년 4월 교육청 모의평가 「공손룡과 후기 묵가의 명실론」 12번

정답: ④

구성: 중상·중·중하·하·최하위 각 2명, 총 10개 합성 학생 페르소나

## 1. 실행 범위

- 학생 역할과 문제 경로 evaluator 모두 실제 모델을 사용했다.
- 학생 역할에는 공개 `ProblemSessionView`만 제공했으며 정답, 골드, 대표 오답 경로와 evaluator 원출력은 제공하지 않았다.
- 최초 선택, 근거, 후속 답변과 재선택을 실제 문제 API로 제출했다.
- 문제별 세션 저장소, 5문단 대화 handoff와 12번 직접 URL 라우팅은 별도의 브라우저 회귀로 검증했다.

## 2. 결과

첫 10개 전체 재실행:

- 정상 완료: 7/10
- 학생이 정답 선택까지 해결: 6/10
- 상세 코칭·정답 공개 종료: 1/10
- evaluator 계약 오류로 중단: 3/10
- 완료 7건의 진단 질문: 0회
- 완료 7건의 교정 질문: 최소 0회, 최대 3회

보완 뒤 표적 재실행:

- 최하위 `LL-NAME-OBJECT-MERGE`는 두 번의 교정 질문과 직접 코칭 뒤 학생 미해결·정답 공개 상태로 정상 종료했다.
- `LL-GUESS-C1`은 외부 API 타임아웃이 반복되어 완료하지 못했다.
- `ML-WHITE-HORSE-REVERSAL`도 표적 재실행 시 외부 API 연결 오류로 완료하지 못했다.

따라서 실제 대화를 완료해 검토한 고유 페르소나는 8/10이며, 중상·중·중하·하·최하위의 모든 수준을 포함한다.

## 3. 확인된 교육적 동작

- 정확한 ④ 근거는 추가 질문 없이 `SUPPORTED_RATIONALE_CORRECT`로 종료했다.
- ④를 골랐지만 ⓓ와 ⓔ가 같은 대상을 지시한다고 설명한 경우, 정답 선택만으로 통과시키지 않고 두 표현의 지시 범위를 교정했다.
- 공손룡과 후기 묵가의 규칙을 바꿔 적용한 ① 오답은 공손룡의 일대일 대응만 다시 적용하게 했다.
- 유명을 단어의 고정 분류로 본 ③ 오답은 하나의 개체만 지시하는 상황 조건만 교정했다.
- 모든 학파가 일대일 대응을 요구한다고 본 ② 오답은 후기 묵가의 한 명–여러 실 관계만 교정했다.
- 새 오답을 선택하면 이전 교정을 반복하지 않고 새 선택의 경로를 별도로 다뤘다.
- 최하위 학생이 두 번의 교정 뒤에도 C5를 유지하자 추가 질문을 만들지 않고 직접 코칭과 정답 공개로 종료했다.

## 4. 발견하고 보완한 문제

### 정답 근거 evaluator 간 불일치

블라인드 근거 판정은 오류라고 했지만 후속 전체 진단은 `NO_ERROR_DETECTED`라고 본 한 사례에서, 허용 행동이 교정 질문뿐이라 존재하지 않는 오류를 질문하려 했다.

후속 전체 진단이 충분한 무오류 상태를 확인하면 `COMPLETE`할 수 있도록 행동 계약과 세션 경계를 보완했다. 정답 근거에 오류가 실제로 남아 있으면 기존처럼 교정 질문 한 번만 허용한다.

### 헤드리스 복구 경계

운영 UI는 evaluator 500 뒤 저장된 세션을 조회해 평가만 재개하지만, 기존 헤드리스 하네스는 첫 500에서 세션을 포기했다. 선택이나 답변 POST를 중복 제출하지 않고 `GET → resume`으로 최대 세 번 평가만 재개하도록 운영 UI와 같은 복구 규칙을 추가했다.

### evaluator 출력 계약 흔들림

실제 모델이 다음 계약 위반을 각각 한 번 생성했다.

- 학생 원문과 정확히 일치하지 않는 인용
- `SELECTED_CHOICE`·`MISSED_ANSWER` 대신 중복 타깃
- 질문 예산 소진 상태에서 잘못된 직접 코칭 사유

프롬프트의 출력 전 검사를 강화했고 복구 하네스를 추가했다. 계약을 완화하거나 잘못된 출력을 저장하지는 않았다.

## 5. 남은 제한

- 외부 API DNS·연결·60초 타임아웃이 간헐적으로 발생했다.
- 최하위 완료 사례 하나는 반복 재개 때문에 서버 처리 시간이 비정상적으로 길었다. 교육 로직 결과와 별개로 운영 지연 개선이 필요하다.
- 이번 파일럿의 `questionBudget`은 진단 질문만 세므로 0으로 표시되더라도 교정 질문은 존재할 수 있다. 실제 개입은 `interventionHistory`로 함께 분석해야 한다.
- 10개 전부가 동일 실행에서 완료된 것은 아니므로 10/10 안정성 통과로 해석하지 않는다.
