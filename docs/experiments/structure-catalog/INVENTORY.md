## 2. 지문 저장 형식

지문 하나 = `output/passages/{set_id}.json` 하나. 들여쓰기된 JSON(파일당 115~140줄 안팎). 문항은 같은 `set_id`의 `output/questions/{set_id}.json`.

대표 파일 2개:
- 단일 지문: `output/passages/69bbefa4a029f488d9e4e809.json` (2025 수능 10~13, 열팽창과 액추에이터, 문단 5)
- (가)(나) 세트: `output/passages/69bbef9a8937cf145518cb13.json` (2025 수능 4~9, 법 해석과 보증 계약, 2편 8문단)

필드 구조(문자열은 줄임):

```
{

  "set_id": "69bbef9a8937cf145518cb13",
  "source": { "detail_url": "https://gugeodat.com/products/…", "collected_at": "2026-07-23T07:08:26+00:00" },
  "exam": {
    "label": "고3 2025년(2026학년도) 11월 - 수능",
    "grade": 3, "year": 2025, "month": 11, "provider": "수능",
    "subject": "reading", "category": "social_culture",
    "question_range": "4~9", "title": "법 해석과 보증 계약",
    "exam_edit_id": "…", "reference_exam_id": "…"
  },
  "instruction": "다음 글을 읽고 물음에 답하시오.",
  "full_text": "법조문으로 구성된 …",          ← 전체 본문, 문단 사이는 \n
  "tags": ["법학", …],
  "sections": [
    { "section_id": "section_ga", "label": "(가)", "order": 1, "source_range": {start, end},
      "paragraphs": [
        { "paragraph_id": "ga_p1", "order": 1, "text": "법조문으로 …",
          "source_range": {"start": 0, "end": 144},
          "annotations": [ { "type": "underlined_phrase", "marker": "ⓐ", "start": 81, "end": 85, … } ],
          "image_ids": [] }, …
      ] },
    { "section_id": "section_na", "label": "(나)", … }
  ],
  "annotations": [ { "type": "section_block" | "labeled_block", "marker": "(가)" | "[A]", "start", "end", "paragraph_ids": […] } ],
```

## 5. PLAN.md 6절 확인 사항

### 문단 구분이 보존됐는가 → 보존됨

- 문단은 `sections[].paragraphs[]`에 하나씩 따로 있고, `order`와 원문 위치(`source_range`)가 붙어 있다. `full_text`에서도 문단 사이가 줄바꿈이다. 문단 글자 수를 더하면 158세트 모두 `full_text`와 맞는다.
- **주의 1: 낱말 풀이가 문단으로 들어가 있다.** "* 용어: 뜻" 형태의 각주가 40세트에 55개, 별도 문단으로 저장돼 있다. 문단 번호를 매기기 전에 `*`로 시작하는 문단을 빼야 한다. (1,047 − 55 = 실제 문단 약 992)
- **주의 2: 표·그림 제목이 문단으로 들어간 경우**가 있다(예: "<표>", "<…의 한계 효용>" 같은 짧은 문단 2개). 추출 입력에서 표시해 주거나 빼야 한다.
- 가장 짧은 본문 문단은 수십 자 수준의 결론 한 문장(1건)이다. 이것은 실제 문단으로 둔다.

### (가)(나)를 어떻게 저장했는가 → 글마다 section

- `sections[]` 하나가 글 한 편이다. `label`이 "(가)", "(나)", "(다)". 단일 지문은 section 1개에 `label`이 null.
- 158세트 중 단일 108, 2편 47, 3편 3.
- 위치 정보는 `annotations`의 `section_block`에도 중복 기록돼 있다.
- PLAN.md 4절의 출력 형식(`"paragraphs": { "가": [...], "나": [...] }`)과 바로 맞는다. 3편 세트 3개를 위해 "다"도 받게 해야 한다.

### 본문과 문항·〈보기〉가 섞였는가 → 섞이지 않음

- 지문 파일의 본문에는 문항 발문·선택지·〈보기〉가 없다(본문에서 "보기"로 잡힌 1건은 "알아보기"였다).
- 문항은 `questions/{set_id}.json`에 따로 있고, 〈보기〉는 `prompt_blocks`의 `supplement` 블록으로 분리돼 있다(752문항 중 223블록).
- 지문 안의 밑줄·기호(ⓐ, ㉠, [A])는 본문 텍스트에 기호로 남아 있다. 구조 추출에는 지장이 없지만, 원문을 옮기지 않는 규칙상 출력에 기호를 쓸지 정해 두면 좋다.
