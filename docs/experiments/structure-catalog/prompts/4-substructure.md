# 하위 구조 나누기

1차 유형 하나에 속한 기출 지문들의 구조 요약을 읽고, 그 유형 안에서 짜임이 다른 하위 구조를 나눈다. 결과는 새 지문을 설계할 때 "이 쟁점과 내용에는 이 짜임"을 고르는 구조 목록이 된다. 구조 목록은 문단 기능의 추상적 배열이다. 특정 기출의 배치나 문장을 따라 하게 하는 자료가 아니다.

## 입력
- 1차 유형: 코드, 이름, 하는 일, 가르는 기준
- 통일 어휘의 기능과 묶음 정의
- 지문마다: set_id, 목적·논리(화제어 없이), 문단 기능 배열(주된 기능, 두 번째 기능은 괄호), 중심 물음이 처음 드러나는 문단, 구조 특징(여는 방식, 깔아 두는 곳, 펼치는 순서, 규칙·식·범위, 사례, 끝맺음, 그 밖), 만나는 곳(문단 번호와 무엇이 어떻게 만나는지), 비워 둔 곳(문단 번호와 무엇). (가)(나) 세트는 글들의 관계와 글마다 종류·목적·배열도 있다.
- 구조 특징, 만나는 곳, 비워 둔 곳에는 화제어가 섞여 있다. 짜임을 읽는 데만 쓰고 출력에 옮기지 않는다.

## 규칙
1. 하위 구조는 문단 기능의 배열과 다음 축의 값으로 가른다. 축은 예이고 틀이 아니다. 유형에 맞는 축을 골라 쓴다.
   - 여는 방식: 문제·물음으로 / 대상·현상으로 / 배경·맥락으로 / 정의로 / 입장으로
   - 깔아 두는 곳: 앞에 몰아 둠 / 필요할 때마다 나눠 둠
   - 펼치는 순서: 한꺼번에 소개 / 차례로 소개 / 앞의 것을 반박하며 잇기 / 원리 → 경우들 / 문제 → 보완 → 남는 한계 …
   - 규칙·사례의 위치와 하는 일: 앞 / 중간 / 끝, 이해를 돕는가 / 판정을 가르는가
   - 끝맺는 방식: 종합 / 의의 / 남는 물음 / 판정 기준 / 실천 권고 / 새 정보 없이 끝
   - 만나는 곳과 비워 둔 곳이 어느 기능의 문단 사이에 놓이는가
2. 하위 구조는 2~5개로 나눈다. 지문이 5편 이하면 1~2개도 된다. 한 하위 구조에는 2편 이상이 들어가게 하고, 어디에도 맞지 않는 지문은 others에 넣는다.
3. 하위 구조마다 다음을 적는다. 모두 화제어 없이 쓰고, 특정 지문의 내용을 옮기지 않는다.
   - code: 1차 유형 코드에 -1, -2 …를 붙인다(예: S7-1).
   - name: 2~12자
   - array: 대표 문단 기능 배열(통일 어휘, 화살표로 잇는다). 문단 수가 달라도 같은 짜임이면 되풀이되는 부분을 "×n"이나 "…"로 줄인다.
   - axes: 위 축 가운데 이 하위 구조를 가르는 값
   - issue_logic: 이 짜임이 맞는 쟁점이나 내용의 논리. 한두 문장(예: "한 기준이 새 사례에서 흔들리는 문제")
   - choose_when: 지문을 설계할 때 이 짜임을 고를 조건. 한두 문장
   - hooks: 만나는 곳과 비워 둔 곳이 주로 놓이는 자리(기능 이름으로)
   - members: set_id 목록
   - examples: members 가운데 짜임이 가장 뚜렷한 set_id 2~3개
4. 지문마다 하나의 하위 구조나 others에만 넣는다.

## 출력 (JSON 하나만)
{
  "type": "S7",
  "substructures": [
    { "code": "", "name": "", "array": "", "axes": { "여는 방식": "", "펼치는 순서": "" },
      "issue_logic": "", "choose_when": "", "hooks": "", "members": [""], "examples": [""] }
  ],
  "others": [ { "set_id": "", "reason": "" } ],
  "notes": "나누며 망설인 점"
}
