# 1차 유형 묶기

수능 독서 기출 지문 여러 편의 구조 요약을 읽고, 글 전체가 하는 일이 같은 것끼리 묶어 1차 유형을 만든다. 유형은 미리 정해져 있지 않다. 이 자료에서 끌어낸다.

이 유형은 새 지문을 설계할 때 "이 쟁점과 내용에는 어떤 짜임이 맞는가"를 고르는 첫 갈래로 쓰인다. 유형 안의 세부 짜임(배경을 어디에 두는지, 입장을 어떻게 소개하는지, 사례를 어디에 두는지, 어떻게 끝맺는지)은 다음 단계에서 나눈다. 여기서는 나누지 않는다.

## 입력
- 단일 지문 묶음이면: 지문마다 set_id, 글 전체의 목적과 글을 끌고 가는 논리(화제어 없이), 문단 기능 배열(통일 어휘), 그 기능들의 묶음 배열.
- (가)(나) 세트 묶음이면: 세트마다 set_id, 세트 전체의 목적과 논리, 글들의 관계, 글마다 종류·목적·문단 기능 배열.
- 통일 어휘의 기능과 묶음 정의.

## 규칙
1. 글 전체가 하는 일(목적과 논리)로 묶는다. 문단 기능 배열은 그 판단을 확인하는 데 쓴다. 배열이 비슷해도 글이 하는 일이 다르면 다른 유형이고, 배열이 달라도 하는 일이 같으면 같은 유형이다.
2. 분야나 화제로 묶지 않는다. 입력에는 분야가 없다. 목적·논리에 남은 낱말로 분야를 짐작할 수 있어도, 그것으로 묶지 않는다.
3. 단일 지문은 유형 5~10개, (가)(나) 세트는 4~8개로 만든다. 한 유형에 3편 미만이면 다른 유형과 합칠 수 있는지 먼저 본다.
4. 유형마다 다음을 적는다.
   - code: 단일 지문은 S1, S2 …, (가)(나) 세트는 P1, P2 …
   - name: 2~10자
   - definition: 이 유형의 글 전체가 하는 일. 화제어 없이 한두 문장
   - criteria: 이 유형으로 판정할 때 목적·논리에서 무엇을 보는지, 가장 가까운 이웃 유형과 어떻게 가르는지
   - signature: 이 유형에서 자주 보이는 기능 배열 한두 개(통일 어휘로)
5. 모든 지문을 한 유형에 넣는다. 들어맞는 정도가 약하면 fit을 "약"으로 적는다. 어디에도 넣기 어려운 것만 unassigned에 넣고 까닭을 적는다(전체의 10% 이하).
6. (가)(나) 세트는 글들이 어떤 관계로 짜였는지가 유형을 가르는 중심이다. 예(틀이 아니다): 같은 대상에 대한 다른 관점, 이론과 그 적용, 문제와 해결, 한 글이 다른 글을 비판.

## 출력 (JSON 하나만)
{
  "types": [ { "code": "S1", "name": "", "definition": "", "criteria": "", "signature": ["", ""] } ],
  "assignments": [ { "set_id": "", "type": "S1", "fit": "강", "reason": "한 문장" } ],
  "unassigned": [ { "set_id": "", "reason": "" } ],
  "notes": "유형을 나누며 망설인 점"
}

fit은 "강" 또는 "약". assignments에는 unassigned에 넣은 것을 빼고 모든 지문이 한 번씩 들어간다.
