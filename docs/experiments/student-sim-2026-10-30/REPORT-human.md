# `/dialogue/lab` 학생 역할 시뮬레이션 — 검토 반영본 (사람용, 2026-10-30)

첫 보고: [`docs/review/dialogue-lab-student-sim-2026-10-30.md`](../../review/dialogue-lab-student-sim-2026-10-30.md)(코드 에이전트가 화면에서 직접 학생 역할로 실행). 이 문서는 그 보고를 메인 세션이 원기록·기존 결정과 대조해 고치고, 사용자 판정(2026-10-30)을 반영한 것이다. 가상 학생 답이므로 실제 학생 검증이 아니다.

## 1. 개요

**1) 목적.** 운영 후보 문단 요약 대화(단순 형식, 판정 지시문 v4.8)에 여러 수준의 학생 답을 넣어, 반복 질문·정답 누출·과잉 질문·판정기가 학생이 안 한 말을 채워 넣기·답할 수 없는 질문이 있는지 봤다. 지문 5편, 문단 19개, 모델 호출 약 30회.

**2) 결과.**

- 큰 흐름(칭찬·질문·교정·공개)은 설계대로 갈렸고, 반복 질문은 없었다. 충분한 답에 과잉 질문도 없었다.
- 실제로 고칠 거리는 **둘**이다.
  - 문제 1: 교정 질문이 오류 지점을 가리킨 뒤 학생이 **이미 맞힌 관계**를 물었고, 질문대로 답한 학생을 "바로잡히지 않았어"로 닫았다.
  - 문제 2(a): 교정 질문이 "서로 **바꾸어** 말한 부분"이라고 오류의 종류를 말해 버려, 학생이 "반대로 바꾸면 돼"만으로 통과했다.
- **정정.** 첫 보고가 "높음·중간"으로 올린 것 가운데 셋은 문제가 아니다.
  - 힌트 강조(교정 질문 때 정답 문장을 칠함)는 D-0175(문단 교정 질문 중 근거 문장 힌트, 베껴 써도 받아들임)로 정한 설계다.
  - 질문 전제가 관계를 알려 주는 것과 빈 곳 답을 너그럽게 충족으로 치는 것은 사용자 판정으로 문제 아님이 됐다(D-0191, 새 결정).
  - "질문 항목이 2개로 제한되는 것 같다(미확인)"는 지시문과 코드가 정한 설계다.
- 메모리의 현재 상태 문서가 문단 지시문을 v4.7로 적고 있었으나 실제는 v4.8이어서 고쳤다.

**3) 다음 스텝.** 문제 1·2(a)를 여러 지문에서 재현하는 고정 사례를 묶어 v4.10(다음 문단 지시문) 범위에 넣는다. 되묻기 처리(문제 4)와 요약 칸 정리(문제 5)는 사용자 판단 뒤 같이 묶을지 정한다.

## 2. 본문

표기: 학생 → 판정(CAPTURED 핵심 다 담음 / GAP 빈 곳 있음 / ONE_ERROR 오류 하나 / IRRELEVANT 관계없는 말 / COPY 옮겨 적기) → 튜터 말. `targetErrorResolved`(교정 질문이 겨냥한 오류를 학생이 고쳤는지)는 이하 tER.

### 문제 1. 교정 질문이 이미 맞힌 관계를 묻고, 질문대로 답한 학생을 실패로 닫음 (미해결)

- **사례 — 표면 장력 2문단.**
  - 학생: "계면 활성제가 표면 장력을 **높여서** 폐포가 잘 부풀게 해." (원문: 낮춘다)
  - 교정 질문: "계면 활성제가 표면 장력을 높인다고 한 부분을 다시 생각해 보자. 문단에서는 계면 활성제와 **폐포의 확장**이 어떤 관계라고 설명해?"
  - 학생: "계면 활성제 때문에 폐포가 확장이 쉬워진다고 해." — 물은 것에는 맞게 답했다.
  - 판정: tER=false → 닫기. 튜터: "폐포가 확장되기 쉽다는 점은 짚었어. 다만 1번의 표면 장력 변화 방향은 아직 바로잡히지 않았어."
- **왜 생겼나.** v4.8 질문 규칙 1은 "문단 전체 관계를 다시 보게 … 세부를 콕 찍지 않는다"이다. 모델은 이 규칙대로 질문을 넓게 던졌다. 그런데 교정 뒤 판정은 특정 오류(표면 장력의 방향)가 고쳐졌는지만 본다. **질문은 넓게, 판정은 좁게**라서 학생이 질문을 따르면 실패하는 구조다.
- **제안.** 교정 질문에서는 규칙 1의 예외로 "학생이 틀린 그 관계(여기서는 방향)를 답해야 답이 되게 묻는다"를 둔다. 다른 지문에서 같은 어긋남이 되풀이되는지 먼저 확인한다.

### 문제 2(a). 교정 질문이 오류의 종류를 말해 버림 (미해결)

- **사례 — 표면 장력 6문단.**
  - 학생: "점도가 커서 수가 더 커지면 위성 잉크 방울이 생겨 오염되고, 작으면 잉크가 안 나와." (두 결과를 뒤바꿈)
  - 교정 질문: "오네소르게 수가 범위보다 커질 때와 작아질 때의 결과를 **서로 바꾸어 말한 부분**을 다시 보자."
  - 학생: "반대로 바꾸면 돼. 커지면 안 나오고 작아지면 오염." → CAPTURED, "잘 정리했어."
- **왜 문제인가.** v4.8 질문 규칙 2("답이 되는 개념어나 관계를 질문에 넣지 않는다") 위반이다. 학생은 문단을 다시 읽지 않고 질문이 알려 준 대로 뒤집기만 했다.
- **제안.** 교정 질문에서 오류의 종류(반대·뒤바뀜 등)를 밝히지 않는다는 문장을 규칙 2에 덧붙인다.

### 문제 2(b). 힌트 강조가 정답 문장 그대로임 (문제 아님 — D-0175)

- 사례: 도파민 3문단. 교정 질문 동안 "…운동이 차단된다."가 칠해졌고, 학생은 "아 차단해."로 통과했다.
- 이것은 2026-10-22에 사용자가 정한 설계다(D-0175: 교정 질문 중 오류의 근거 문장 하나를 힌트로 칠하고, 베껴 답해도 받아들인다). 사용자가 2026-10-30에 다시 확인했다: "기존 규칙 그대로 두기."
- 첫 보고는 D-0175를 보지 못하고 문제로 올렸다(정정).

### 문제 3. 질문 전제가 관계를 알려 주고, 빈 곳 답을 너그럽게 충족으로 침 (문제 아님 — D-0191)

사용자 판정: "과도하게 힌트를 주는 것도 문제 없다고 봄", "문제 아님으로 정리해." 사례 셋을 모두 문제가 아닌 것으로 정리했다.

- **정보 비대칭 2문단 1번.** 질문 "생성형 인공지능의 활용은 온라인 광고 환경에 어떤 변화를 가져왔어?"에 학생이 "가짜 광고가 많아졌어"만 썼다. 원인은 질문이 줬지만, 빠진 결과는 학생이 직접 말했다.
- **정보 비대칭 2문단 2번.**
  - 판정기가 정한 핵심: "정부 개입의 **범위**를 두고 의견이 엇갈린다."
  - 학생: "개입해야 된다는 쪽이랑 하면 안 된다는 쪽이 있어."
  - 원문의 정리 문장은 "정부 개입에 관하여 엇갈리는 주장"이고, '범위'는 판정기가 핵심 설명에 덧붙인 말이다. 학생 답은 원문 정리 수준이며, 구체 쟁점(표시 의무를 정보 제공자·플랫폼까지 넓힐지)은 마무리 상자에 공개된다.
- **법인 2문단.** "관할 기관 허가." 두 단어로 '정관 기재·등기 + 허가' 핵심을 충족으로 쳤다. 틀린 말이 아니라 덜 말한 것이고, 마무리 상자에 전체가 나온다.
- **유지하는 것.** 빈 곳 질문에 원인·조건 같은 관계 요소를 넣지 않는 v4.9 질문 규칙 6은 그대로 진행한다. 질문이 답을 거의 다 줘서 낱말 하나로 통과하는 경우는 여전히 줄인다. 다만 학생이 빠진 결과를 직접 말한 경우는 문제로 치지 않는다.

### 문제 4. 되묻기와 근거 있는 반문을 무응답·오류로 처리하고 닫음 (판단 필요)

- **(a) 정보 비대칭 4문단.**
  - 학생 "비판론" 한 단어에 판정기가 질문 둘을 냈다. 그 가운데 1번: "**이 정보 공급 상황에서** 다양한 의견 간의 경쟁은 어떻게 된다고 비판론은 보는가?"
  - 학생은 그 상황을 말한 적이 없어 "이"가 가리킬 대상이 없다. 학생이 "이 정보 공급 상황이 뭔지 모르겠어요"라고 되묻자 "두 질문에는 아직 답이 없어"로 닫혔다.
  - 질문 말투도 이 문단만 "~보는가?"였다.
- **(b) mRNA 1문단.**
  - 학생: "백신은 진짜 바이러스를 넣는 거라 위험할 수 있어." → 오류로 판정. 1문단은 백신을 "바이러스를 인공적으로 흉내 낸 물질"이라고 적는다.
  - 학생 반문: "다음 문단에 기존 백신은 바이러스를 배양해서 접종한다던데?" 2문단은 실제로 "바이러스를 배양하여 접종하는 기존의 백신과 달리 mRNA 백신은 … 감염될 위험이 없으며"라고 적는다. 학생 말에 원문 근거가 있다.
  - 튜터는 반문에 답하지 않고 같은 교정을 되풀이하며 닫았다.
  - 같은 실행에서 표면 장력 3문단의 다른 문단 근거 추론(작은 기포→큰 기포)은 오류로 치지 않았다. 두 판정이 엇갈린다.
- **판단할 것.**
  1. 질문이 학생이 말하지 않은 대상을 "이·그"로 가리키지 않게 질문 규칙에 넣을지. 권고: 넣는다. 작은 문구 규칙이고 위험이 적다.
  2. 교정·빈 곳 질문 뒤 학생이 되묻거나 반문하면 따로 다룰지. 지금 상태표에는 이 분기가 없다. 권고: 지금은 기록만 하고, 실제 학생 기록에서 되풀이되면 다룬다.
  3. 다른 문단 원문과 맞는 주장을 오류로 칠지. 문단 경계 규칙(D-0133)과 얽혀 있어, 그 결정을 읽은 뒤 따로 논의한다.

### 문제 5. 요약 칸에 잡담·대화 설명이 남음 (판단 필요)

- 정보 비대칭 2문단: 종료 뒤 '지금까지 내 요약'에 "나도 속은 적이 있으며 유튜브 광고가 너무 많다"가 남았다. mRNA 1문단에는 "…아니냐고 물었어" 같은 대화 설명이 들어갔다. 표면 장력 2문단에는 바로잡히지 않은 "표면 장력을 높여"가 그대로 남았다.
- 정정: 첫 보고는 이 잡담이 IRRELEVANT가 아니라 GAP으로 간 것도 문제로 봤다. 하지만 "AI 광고에 속은 적 있음"은 문단 주제(생성형 AI 허위 광고)와 이어진 말이라 GAP 판정도 변호할 수 있다. 중요도를 낮춘다.
- 판단할 것: 요약 칸에서 잡담·되묻기·메타 설명을 뺄지(권고: 뺀다), 바로잡히지 않은 오류를 남길지(권고: 학생 말 보존 원칙상 남긴다).

### 문제 6. 핵심 3개 중 2개만 묻고 셋째는 공개 (확인된 설계)

- 법인 2문단의 핵심 3(기본 재산 외 자산의 제한된 수익 추구·보고)은 묻지 않고 종료 때 공개됐다.
- 정정: 첫 보고는 "제한되는 것 같다(미확인)"고 했다. 실제로는 v4.8 지시문 110행("최대 2개, 셋이면 가장 크게 빈 둘")과 `rules.ts:92-94` 검증이 정한 설계다. 남는 것은 공개 문구에서 묻지 않은 핵심을 구별할지 정도다(낮음).

### 문제 7·8. '모르겠어요' 다시 쓰기 요청, 문구 (낮음, 미해결)

- '모르겠어요'에 "네 말로 정리해서 다시 써 볼래?"만 되풀이해서 실마리가 없다. 도파민 4문단은 그대로 공개로 끝났다.
- "2번 부분은 아직 **답을 알 수 없어**"는 튜터가 모른다는 뜻으로 읽힌다. "아직 답하지 않았어"가 낫다.
- 화면 칭찬이 고정 문구("핵심 내용을 정확하게 잡아냈어!")라 힌트를 보고 고친 경우에도 같다. 모델이 쓴 구체 칭찬은 서랍(inspect)에만 있다.

### 잘 된 점

- 반복 질문 없음. 교정 → 빈 곳 질문 → 완료(mRNA 2문단) 경로에서 고친 내용을 다시 묻지 않았다.
- 충분한 답에 과잉 질문 없음(도파민 1, 법인 1, 표면 장력 3·4).
- 두 군데 반대 주장(정보 비대칭 5)은 바로 닫고 각각 정확히 바로잡았다.
- 서버 감지가 놓친 옮겨 적기(문장 일부 생략)를 모델이 COPY로 잡았다.
- 평가 실패·재시도 오류 0건.

# 문제 파트 (`/problem/lab`, 같은 날 추가 실행)

첫 보고의 부록 "`/problem/lab` 문제 풀이 학생 역할 시뮬레이션"을 메인 세션이 원기록·기존 결정과 대조했다. 원기록은 [`problem/logs/`](./problem/logs/)(9세션)에 있다.

## P-1. 개요

**1) 목적.** 문제 풀이 대화(판정 지시문 v5.8)에서 교정 질문이 답을 흘리는지, 고침을 제대로 가리는지, 약한 근거·모순·'모르겠어'를 어떻게 다루는지 봤다. 문항 3개, 세션 9개.

**2) 결과.**

- 부록이 높음·중간으로 올린 P1~P3은 모두 **이미 정한 설계**다. 고칠 것은 문구 두 건(P4·P5)뿐이었고, 이번에 고쳤다.
- 쓸모 있는 관찰: 문제 쪽 교정 질문은 매번 학생의 틀린 문장을 겨냥했다. 문제 쪽은 "사실 하나를 묻는 직접 질문"(D-0188)이고 문단 쪽 v4.8은 "넓게 묻기"(질문 규칙 1)다. 이 차이가 문단 문제 1의 원인 가설을 뒷받침한다.

**3) 다음 스텝.** v4.10에서 문단 교정 질문에 문제 쪽 직접 질문 방식을 참고한다. 문제 쪽에는 새로 할 일이 없다.

## P-2. 본문

### P1. 교정 질문이 한 단어 답을 요구하고, 칠한 문장에 답이 있음 (문제 아님 — D-0187·D-0188)

- 사례 — 도파민 13번 ④ 오답: Q1 "카르비도파가 효소의 작용을 억제하는 곳은 어디야?" → "말초 조직"(칠한 문장에 있음). Q2 → "늘어나?"(추측). 둘 다 REPAIRED(고쳐짐)였다.
- 이것이 설계인 이유:
  - "어디야/어떻게 변해" 같은 짧은 직접 질문은 D-0188(내용 오류는 사실 하나를 묻는 직접 질문)이 정한 형식이다.
  - 칠한 문장에 답이 있는 것도, 추측 답을 REPAIRED로 치는 것도 D-0187에서 사용자가 유지하기로 했다("너무 학생을 몰아세우는게 더 위험").
  - Q2가 방금 고친 사실을 전제로 이어받은 것은 D-0191과 같은 성격이다.

### P2. 고친 뒤 새로 밝힌 의문을 받아 주지 않음 (문제 아님 — D-0108, 관찰 중단)

- 사례 — 표면 장력 16번 ⑤ 오답: "커지네. 근데 커져도 위성 잉크 방울은 생길 수 있지 않아?" → "핵심 오류를 잘 고쳤어. … 다시 골라 볼래?"
- 교정 판정이 겨냥한 오류만 본다는 것은 D-0108의 설계다. 새 오류는 기록만 하는 것도 작동 순서 문서 199행대로다.
- 바로 뒤에 재선택 기회가 온다. 남은 의문은 재선택에서 드러나고, 다시 틀리면 마지막 설명이 짚는다. 시뮬레이션이 재선택 직전(`AWAITING_POST_REPAIR_CHOICE`)에 멈춰서, 부록의 "답 없이 지나간다"는 확인되지 않았다.

### P3. 근거 칸의 '모르겠어요'에 바로 정답 공개 (문제 아님 — D-0057)

- 사례 — 표면 장력 16번: ②를 고르고 "모르겠어요 그냥 찍었어요" → "정답은 ③번이야."
- 첫 오답에서 '모르겠어요/찍었어요'를 확인 불가로 보고 코칭 뒤 끝내는 것은 D-0057에서 사용자가 명시적으로 동의한 동작이다. 교정 질문에 "모르겠어"라고 답하면 공개되는 것은 교정 실패(REPAIR_FAILED) → 마지막 설명 경로다.

### P4. 근거 미확인 정답에 "같이 채워 볼게" (해결 — 문구만)

- 정답·약한 근거는 질문 없이 설명으로 간다. 이 동작은 D-0182에서 받아들였다. 그런데 문구 "빠진 연결을 같이 채워 볼게"는 질문이 올 것처럼 들렸다.
- 고침: "빠진 연결은 설명에서 같이 볼게", "더 이어야 할 연결은 설명에서 같이 볼게"(`packages/app/src/server/problem-feedback.ts`).

### P5. 재선택 오답의 첫 말풍선이 다음 말과 어긋남 (해결 — 문구만)

- 전: "정답이 아니야. 어디서 생각이 달라졌는지 살펴볼게." → "다시 고른 답도 정답이 아니야. 더 묻지 않고 정답을 먼저 알려 줄게."
- 후: "다시 고른 답도 정답이 아니야. 어떻게 생각했는지 읽어 볼게." → "더 묻지 않고 정답을 먼저 알려 줄게." 첫 선택의 문구는 그대로이고, 근거 없이 재선택한 경우의 안내도 그대로다.
- 교정 질문이 학생 말을 인용하기도 하고 안 하기도 하는 혼재는 모델 출력이라 이번에는 다루지 않는다(낮음).
