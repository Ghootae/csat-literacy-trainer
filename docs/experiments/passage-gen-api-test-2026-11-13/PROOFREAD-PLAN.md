# 교정 단계 시험 계획

작성: 2026-11-13. 결정(Ghootae): 초안 작성 뒤에 별도의 교정 호출을 붙인다. 지금 지문은 문법과 문체 문제가 많다.

## 질문

점검 단계(3-check)는 정확도만 보고, 지문마다 1~2문장만 고쳤다. 문장만 다듬는 교정 호출을 따로 붙이면 사람이 지적한 읽기 문제가 고쳐지는가? 그러면서 뜻은 그대로 남는가?

## 설계

| 항목 | 내용 |
|---|---|
| 대상 | API 지문 4개(가 B-2, 나 B-1, 다 C-2, 마 C-1)의 점검 후 최종 지문. 다시 생성하지 않는다 |
| 입력 | 최종 지문 + 최종 연결표 (3-check.md). 집필 규칙과 설계서는 넣지 않는다 |
| 지시문 | prompts/4-proofread.md. 우선순위: ① 한 문장에 너무 많이 담지 않기 ② 문장 사이 잇기 ③ 바로 이해되지 않는 문장 풀어 쓰기 ④ 문법 |
| 범위 밖 | 사실·주장·기준·입장 구분, 문단 구성, 용어 선택, 단서 문장 삭제, 입장 기호 지칭. 앞의 셋은 바꾸면 안 되는 것이고, 뒤의 둘은 집필 단계에서 다룬다 |
| 모델 | gpt-6.1-sol, effort high (생성과 같음). 4번 호출, 동시에 실행 |
| 출력 | out/{run}/4-proofread.md, out/{run}/proofread-passage.md, PROOFREAD-compare.md |

## 판정 기준 (미리 정함)

- **통과**: 아래 셋을 모두 충족한다.
  1. 범위 안 30개 중 20개 이상이 고쳐진다.
  2. 연결표 근거 문장의 뜻이 바뀐 곳과 새로 들어간 사실이 0건이다.
  3. Ghootae가 한 지문(가 권장, 지적이 가장 많음)을 교정 전후로 읽고 체감 개선이 있다고 본다.
- **부분 통과**: 20개 이상 고쳐졌지만 뜻이 바뀐 곳이 있다 → 바뀐 문장 유형을 보고 '바꾸지 않을 것'을 보강한다.
- **실패**: 15개 미만 → 문장 단위 교정으로는 부족하다. 집필 단계에서 해결하는 쪽(rules v2)으로 무게를 옮긴다.
- 기록만 하는 것: 길이 변화. 풀어 쓰기로 길어지는 것은 예상하지만, 15% 넘게 늘면 분량 문제로 적어 둔다.

## 셈하는 방법

Claude가 PROOFREAD-compare.md를 보고 체크리스트 항목마다 고쳐짐 / 일부 / 그대로 / 나빠짐으로 표시한다. '일부'는 0.5개로 센다. 뜻 보존은 연결표 근거 문장을 교정 전후로 대조해 확인한다. 결과는 PROOFREAD-RESULT.md에 쓴다.
