# API 지문 생성 검증 계획

작성: 2026-11-13 (웹 스레드 "수능형 지문 생성 방식 설계")
결정 (Ghootae, 2026-11-13): 실제 사용 전에 API에서 웹 파일럿과 같은 수준의 지문이 나오는지 먼저 검증한다. 문항 생성은 그다음.

## 질문

웹 파일럿 v4는 사람과 Codex의 피드백을 네 번 받아 고친 결과다. 그 피드백 없이, 규칙(W1~W14)과 점검 질문(C1~C7)만 받은 API가 쓸 만한 지문을 내는가?

## 설계

| 항목 | 내용 |
|---|---|
| 모델 | gpt-6.1-sol, effort high (문항 파이프라인과 같음) |
| 단계 | ① 설계 (노드 거르기, 쟁점 논리, 입장 설계표, 사실 목록) → ② 집필 (지문 + 연결표) → ③ 점검·수정 (C1~C7 적용, 찾은 문제만 고침) |
| 주제 | C = 인지 향상 약물 (웹 파일럿과 같은 주제), B = 의식적 결정에 앞서는 뇌 활동과 자유 의지 (새 주제) |
| 반복 | 주제당 2회 → API 지문 4개 |
| 기준 지문 | 웹 파일럿 v1(첫 생성), v4(피드백 4회) |
| 판정 | Ghootae 블라인드 판정. 6개 지문을 섞어 출처를 가림. 질문 = 실제 사용 가능 여부, 연결, 깊이, 기출 흉내, 오류 의심, 종합, 전체 순위 |

주제를 두 개로 한 이유: C만 쓰면 규칙이 작동한 건지, 모델이 비슷한 지문을 다시 쓴 건지 구분이 안 된다. B는 사람이 다듬은 기준 지문이 없으므로 "실제 사용 가능" 판정만으로 본다.

2회 반복한 이유: 한 번 잘 나온 것이 우연인지 보려고. 비용은 주제당 3호출 × 2회 × 2주제 = 12호출.

## 판정 기준 (미리 정함)

- **통과**: API 지문 4개 중 2개 이상이 "조금 고치면 쓸 수 있음" 이상이고, C 주제 API 지문 중 하나 이상이 v1보다 순위가 높다.
- **부분 통과**: B 또는 C 한쪽만 쓸 만함 → 주제에 따라 규칙이 덜 작동하는 지점을 찾아 지시문 보완.
- **실패**: 쓸 만한 것이 없음 → 단계 ③의 점검 결과와 ①의 설계서를 보고 어느 단계에서 무너졌는지 진단.

## 판정 후 할 일

- 사실 목록(3-check.md 끝)에서 "출처 모름"이나 확신 "낮음" 항목은 쓰기 전에 사람이 출처를 대조해야 한다. API는 출처를 검증하지 못한다.
- 통과한 지문만 문항 파이프라인(골드 지도 탐색 → 선별 → 〈보기〉 조립)으로 넘긴다.

## 파일

- prompts/1-design.md, 2-write.md, 3-check.md: 단계별 지시문
