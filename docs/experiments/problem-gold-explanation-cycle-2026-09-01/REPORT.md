# 공식 해설 참고자료 기반 B1-B2-B3-C 골드 자동화 실험

실행일: 2026-09-01

## 1. 목적

지문·문제·정답 키만 사용한 외삽 실험에서 골드 문제가 명확했던 네 문항과 기존에 강했던 대조 문항 하나를 선택해, EBSi 공식 배포 해설을 참고자료로 제공했을 때 다음 자동화 사이클이 실제로 작동하는지 검증했다.

```text
B1 최초 골드 생성
→ B2 정적 검수 기반 수정
→ B3 학생 응답 프로브 기반 수정
→ C 독립 의미 감사 에이전트
→ 최종 품질 게이트
```

EBSi 해설은 출제 기관이 집필한 공식 해설과 동일한 권위로 취급하지 않았다. 해설 문장은 추론 연결을 발견하는 참고자료로만 제공했고, 학생 런타임 평가에는 해설 원문을 전달하지 않았다.

## 2. 대상

| 문항 | 역할 | 기존 문제 |
|---|---|---|
| 수소 생산 12번 | 빠진 추론 다리 | 정확 근거가 0/6, 전체 6/12 |
| 보증 계약 8번 | 정답 키 경계 | 정확 근거 실패와 적용 조건 공백 |
| FTA 원산지 8번 | 양태 오류 | ‘가능’을 ‘보장’으로 강화한 최초 생성 오류 |
| 확산 모델 13번 | 시각·최소 전제 | 전제 과잉과 일부 평가 실패 |
| 열팽창·액추에이터 12번 | 대조군 | 기존 12/12, 전제 과잉 경고만 존재 |

## 3. 실행 계약

- B1-B3: `gpt-5.6-terra`, reasoning `medium`
- C: `gpt-5.6-sol`, reasoning `high`
- 생성 프롬프트: `problem-gold-generation-prompt-v1` + `problem-gold-generation-prompt-v2-explanation-reference`
- 스키마: `problem-solving-gold-v1`
- 학생 프로브: 정확, 부정형 정확, 대표 오답, 통제 저정보를 각각 3회
- B1 최초 공급자 응답은 수정 전에 별도 저장
- B2는 최대 3회 정적 수정
- B3는 실패 원인을 `GOLD_DEFECT`와 `EVALUATOR_DEFECT`로 분류하고 골드 결함일 때만 수정
- C는 독립 의미 감사 후 `PASS`, `REPAIR_GOLD`, `HUMAN_REVIEW` 중 하나를 선택하고, 수정 시 정적 검수·프로브·2차 감사를 다시 수행
- 최종 자동 승인은 정적 계약, 원본 무결성, 프로브, 해설 배치, 역수입, 의미 감사 조건을 모두 통과할 때만 허용

## 4. 실행 중 발견하고 교정한 오케스트레이터 결함

첫 시각 문항 실행에서는 이미지 URL을 JSON에만 넣고 실제 `input_image`로 전달하지 않았다. 이 때문에 FTA의 선택 ID가 `choice1` 형식으로 생성되어 기존 `C1` 학생 fixture와 연결되지 않았고, 시각 근거 감사도 불완전했다.

다음과 같이 수정했다.

- 시각 자료를 B1, B2, B3 수정, C 감사·수정 호출에 고해상도 이미지 입력으로 전달
- `C1`~`C5` 식별자 정책을 B1 생성 계약에 명시
- 원본 미디어 URL·해시·크기와 최종 골드를 비교하는 source fidelity 게이트 추가
- 장시간 C 호출을 Responses background 실행과 5초 상태 조회로 전환
- C 수정본을 프로브에 전달하기 전에 교차 필드 정규화와 스키마 검증 수행
- 유효하지 않은 첫 시각 실행은 `*-run1-without-image` 디렉터리에 보존하고 최종 수치에서 제외

## 5. 단계별 결과

### 5.1 구조적 결과

| 단계 | 통과 |
|---|---:|
| B1 무수정 전체 스키마 | 0/5 |
| B2 후 전체 스키마 | 5/5 |
| 최종 정적 오류 0건 | 5/5 |
| 최종 정적 warning 0건 | 5/5 |
| 최종 공식 정답 일치 | 5/5 |
| 최종 자동 승인 | 0/5 |
| 인간 검토 라우팅 | 5/5 |

B1 실패는 결정 단계와 결론 단계의 중복, 대표 오답 경로 scope, 정답 키 제약 같은 기존 교차 필드 오류가 중심이었다. B2가 모두 수정했지만, 정적 계약 통과만으로 의미 품질을 보장하지는 못했다.

### 5.2 학생 프로브 비교

| 문항 | 해설 미제공 기존 | 해설 참고 사이클 | 변화 |
|---|---:|---:|---:|
| 수소 생산 | 6/12 | 12/12 | +6 |
| 보증 계약 | 9/12 | 9/12 | 0 |
| FTA 원산지 | 12/12 | 12/12 | 0 |
| 확산 모델 | 11/12 | 10/12 | -1 |
| 열팽창 | 12/12 | 12/12 | 0 |
| 합계 | 50/60 | 55/60 | +5 |

수소 문항에서는 해설의 `전환율 → 반응량 → 몰비 → 수소 생성량` 연결이 정확 근거 검증 공백을 직접 보완했다. 그러나 보증 계약과 확산 모델의 실패는 주로 빠른 평가기의 부정 표현 처리 문제로 분류되어 해설 추가만으로 개선되지 않았다.

### 5.3 C 의미 감사 결과

| 문항 | 역수입 | 프로브 | C 최종 조치 | 주요 검토 사유 |
|---|---|---:|---|---|
| 수소 생산 | 감지 | 12/12 | HUMAN_REVIEW | B의 총 전환량에 2:1:3 몰비를 그대로 적용할 전제 공백 |
| 보증 계약 | 감지 | 9/12 | HUMAN_REVIEW | 원문의 충분조건을 필요조건으로 바꾼 `경우에만`, 사례의 선행 조건 누락 |
| FTA 원산지 | 없음 | 12/12 | REPAIR_GOLD 후 검토 | `NOT_JUSTIFIED` 결론을 직접 `CONTRADICTS`로 표시 |
| 확산 모델 | 없음 | 10/12 | REPAIR_GOLD 후 검토 | 비정당화와 직접 모순의 효과 강도 불일치, 평가기 부정 표현 문제 |
| 열팽창 | 없음 | 12/12 | REPAIR_GOLD 후 검토 | 곡률 정의 전제 누락, 비정당화 효과, 미디어 해시 불일치 |

C의 지적은 자동 확정 사실이 아니라 인간 검토를 위한 감사 가설이다. 다만 수소·보증 계약에서는 공식 해설 자체가 생략하거나 강화한 연결이 기본 골드로 유입되는 위험을 구체적으로 포착했다.

## 6. 핵심 해석

### 공식 해설은 빠진 연결을 찾는 데 실제로 도움이 됐다

수소 문항의 프로브가 6/12에서 12/12로 회복됐다. 기존 `ANSWER_KEY_CONSTRAINED` 공백을 줄이는 데 공식 해설이 유효했다.

### 공식 해설은 안전한 근거의 보증서가 아니다

수소와 보증 계약에서 해설이 사용한 연결 일부는 원문 전제만으로 엄밀하게 재구성되지 않았다. B 생성기는 이를 모두 보충 층에 격리하지 못했고 `supplementalExplanationInferences`는 다섯 문항 모두 0개였다.

즉 “해설은 참고자료”라는 프롬프트만으로는 부족하며, 해설의 각 문장을 먼저 독립적인 claim으로 분해한 뒤 출처 등급과 배치 결정을 구조적으로 강제해야 한다.

### 현재 `targetClaimEffect`의 두 값은 부족하다

FTA·확산·열팽창에서 반복적으로 다음 문제가 발생했다.

```text
원문으로 선지 주장을 정당화할 수 없음
≠
원문이 선지 주장의 반대를 직접 입증함
```

현재 `SUPPORTS | CONTRADICTS`만으로는 `DOES_NOT_JUSTIFY` 또는 `INSUFFICIENT_SUPPORT`를 표현하지 못한다. 이로 인해 결론 문장은 비정당화인데 효과는 직접 모순으로 기록되는 문제가 반복됐다.

### C 자동화는 가능하지만 전 문항 상시 실행은 비효율적이다

골드 생성·수정·감사 API 호출은 23회였고, 이 중 C의 `gpt-5.6-sol/high` 호출은 11회였다. C 호출 누적 시간은 약 1,010초였다. 학생 evaluator는 실제 96회 호출됐다.

- 골드 생성·수정·감사 입력: 226,109 tokens
- 골드 생성·수정·감사 출력: 138,745 tokens
- 학생 evaluator 입력: 1,154,773 tokens
- 학생 evaluator 출력: 71,155 tokens
- 전체 실제 API 호출: 119회

따라서 대량 처리에서는 B2·B3의 위험 점수로 C 호출 대상을 좁히는 편이 현실적이다.

## 7. 결론

자동화 사이클 자체는 실제로 작동했다. B1의 구조 오류를 B2가 5/5 복구했고, B3는 평가기 결함을 골드 결함과 구분했으며, C는 해설 역수입과 의미 강도 문제를 찾아 자동 승인을 차단했다.

그러나 현재 구성은 자동 승인 파이프라인이 아니라 자동 분류·감사 파이프라인에 가깝다. 5개 중 자동 승인은 없었지만, 이는 해설을 넣었으니 통과시키는 대신 남은 위험을 인간에게 올렸다는 의미다.

다음 우선순위는 다음과 같다.

1. 공식 해설을 먼저 claim 단위로 분해하는 `ExplanationAudit` 계약 추가
2. `targetClaimEffect`에 비정당화 효과 추가
3. 원본 식별자·미디어 메타데이터를 모델 출력이 아니라 코드로 강제 주입
4. 빠른 평가기의 부정·거부 표현 일반화 수정
5. C를 전체 문항이 아니라 위험 점수 기반으로 선택 실행
