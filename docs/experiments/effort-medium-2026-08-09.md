# 채점 effort를 `high` → `medium`으로 — 회귀 3세트 재측정

- 날짜: 2026-08-09 / 모델: `claude-opus-4-8` (유지)
- 코드: `62d8b02` (측정 도구), `28d494a` (접두부 캐싱), `885d91b` (캐시 키 수정)
- 원시 출력: `effort-medium-2026-08-09-base.log` / `-new.log` / `-n2.log`
- 대조 기준선: `n2e-full-sweep-2026-08-02.md` (`high`, evidenceRole 도입 직후)
- 오라클·프로브·기대값·생성 fixture: **전부 미수정** (단일 변수 비교)

## 왜 쟀나

접두부 캐싱(`28d494a`)을 넣은 뒤 채점 1건의 비용 구조가 이렇게 바뀌었다:

```
입력  7,320토큰 중 7,236이 캐시 읽기  →  $0.0040   (5%)
출력  약 3,300토큰                    →  $0.0825  (95%)
```

**입력은 더 짜낼 것이 없다.** 그리고 지연은 출력 토큰에 거의 선형이다 — 계측 640건에서
일관되게 약 12ms/토큰이었다.

```
 1,080토큰 → 13.5s        2,892토큰 → 33.2s
 1,955토큰 → 21.5s        3,656토큰 → 42.5s
 2,607토큰 → 30.2s        5,245토큰 → 67.8s
```

즉 **effort 하나가 비용과 지연을 동시에 정한다.** 그리고 그 출력 토큰의 대부분은 판정
JSON(질의 11개 ≈ 900토큰)이 아니라 사고 토큰이다.

계기는 실사용 불만이었다. 코덱스가 터널로 테스트하다 요청이 끊겼고(실제 원인은 터널이었지만),
사람이 직접 써 보고도 "너무 느리다"고 했다. `high`의 실측 지연은 68.5s였다.

## 방법

`EVAL_EFFORT` 환경변수를 붙여 같은 코드 경로로 effort만 바꿔 돌렸다(`62d8b02`). 지문에
effort가 들어가므로 캐시가 갈려 서로 오염되지 않는다.

**측정 직전에 결함을 하나 잡았다.** 지문을 상수에서 함수로 바꾸면서 호출부 두 곳이 함수를
호출하지 않고 넘기고 있었다 — `JSON.stringify`가 함수를 지우므로 모델·effort가 캐시 키에서
통째로 빠진 상태였다. 그대로 돌렸다면 **다른 설정을 쟀다고 믿으면서 같은 캐시를 다시 읽는**
실험이 됐다. 타입을 좁혀 컴파일이 깨지게 고쳤다(`885d91b`).

### 1단계 — 니체 p1로 방향 확인 (프로브 3개)

```
effort   불일치(vs high)   출력토큰    지연     채점 1건
high            —           5,577   68.5s   $0.1435
medium         1/9          2,213   25.0s   $0.0594
low            1/9          1,550   18.1s   $0.0428
```

불일치 1/9는 **둘 다 같은 칸**이었다 — `혼합` 프로브의 `r2`, 부분관계 ↔ 주제만 경계.
이 자리는 반복 안정성 측정(`repeat-stability-nietzsche-2026-08-08.md`)에서 변동이 집중되던
바로 그곳이다.

갈라내려고 `medium`으로 반복 측정을 돌렸다:

```
medium 반복 3회  →  변동 1/9
high  반복 5회   →  변동 2/9   (이전 측정)
```

**`medium`의 자체 변동폭이 `high`보다 오히려 작다.** 스윕의 1/9는 effort가 판정을 바꾼
것이 아니라 원래 흔들리던 경계가 흔들린 것으로 본다.

### 과대평가 — 유지 (핵심 지표)

이 시스템에서 가장 위험한 오류는 미달 응답에 `관계보존`을 주는 것이다. **새로 생긴
과대평가는 없다.** 유일한 1건은 `base`의 인문 `Bd1`으로, 기준선(2026-07-25)부터 있던
것이고 분해 4종 중 비율이 **2/4 → 1/4로 오히려 줄었다.**

```
[Bd1(경계)]  기대 주제만
   오라클 | gen1 | gen2 | gen3
   주제만 | 미포착 | 주제만 | 관계보존   ← gen3만
```

### N2-e 본체 — 완전 통과

`evidenceRole` 축이 존재하는 이유인 케이스. 이름만 나열한 응답에 관계 점수가 가면 안 된다.

```
[주제만]  "C4 식물의 광합성 / 엽육 세포와 유관속초 세포"
   기대 주제만  →  주제만 | 주제만 | 주제만 | 주제만   4종 전부 일치
```

반대 방향(`한쪽공간만` — 대상 하나지만 역할 있음 → 부분관계)도 3/4에서 유지됐다.

### `new` — 완전히 동일

evidenceRole 도입 때도 기준선과 완전 동일했던 세트이고, `medium`에서도 12프로브가 전부
그대로다. 특히 **`암묵적` 프로브가 두 문단 모두 4종 전부 `관계보존`**이다 —
"공모는 신고서 제출, 사모는 불요"처럼 병치만으로 조건 분기를 나타낸 응답을 관계로
인정한다. 병치 인정 규칙이 살아 있다.

### 늘어난 불안정 2건

`4/37 → 6/37`. **전부 `주제만 ↔ 미포착` 경계**다. 학생 화면에서 이 둘은 같은 회색·같은
`○` 기호로 나가고 힌트만 다르다 — 등급이 눈에 띄게 바뀌는 자리가 아니다. 그리고 반복
변동이 별도로 1~2/9 있으므로 **2/37 차이는 잡음과 구분되지 않는다.**

## 함께 검토한 것 — Sonnet 5

같은 n2 세트를 `claude-sonnet-5` / `medium`으로 돌렸다. 기술적으로는 드롭인이다
(구조화 출력·캐싱·adaptive thinking 전부 그대로 동작).

```
                과대평가  오라클≠기대  불안정   채점 1건
opus-4-8           0건      0/13      2/13    $0.0546
sonnet-5           0건      1/13      2/13    $0.0331
```

**과대평가는 Sonnet도 0건이고 N2-e 본체도 막았다.** 그런데 opus에 없던 실패가 나왔다:

```
[순환중간생략]  기대 부분관계
   opus    : 부분관계 | 부분관계 | 부분관계 | 부분관계
   sonnet  : 부분관계 | 부분관계 | 부분관계 | 모순      ← 거짓 모순
```

`모순`은 학생 루프의 **하드 게이트**다 — 붉은 박스, 강제 확인, "관계 방향이 원문과
어긋납니다" 문구. 순환의 중간을 생략했을 뿐인 학생에게 틀렸다고 말하는 것이라,
`부분관계 ↔ 주제만` 같은 인접 등급 미끄러짐과 성격이 다르다.

Sonnet은 전반적으로 더 박했다 — `조직만`도 4종 전부 `미포착`으로 내렸다(opus는 오라클에서
`주제만` 유지).

**채택하지 않는다.** 추가 절감은 $0.0215/건인데, 그걸 얻자고 하드 게이트 방향의 새 실패
유형을 안는 것은 프로브 13개짜리 표본에서 맞바꿈이 나쁘다. 다만 **기각이 아니라 보류**다 —
거짓 모순 1건은 52개 판정 중 1건이라 반복 변동일 수 있고, 그 프로브만 반복해 보면 갈린다.

## 결정

**채점 기본 effort를 `medium`으로 확정한다.** 모델은 `claude-opus-4-8` 유지.

## 미결 / 한계

- **각 설정당 1회 측정이다.** 반복 변동을 감안하면 ±2/37은 흔들릴 수 있다.
- `오라클≠기대` 3/37은 `medium` 탓이 아니라 **기대값 자체가 의심스러운 항목**이다
  (`n2e-full-sweep`도 같은 판단을 남겼다). 판정이 안 맞는다고 기대값을 손보면 기준선이
  사라지므로 미결로 둔다. N2-c(P5 `조직만`)가 대표 사례다.
- Sonnet 5의 거짓 모순이 재현되는지 안 재봤다.
- `low`는 니체 프로브에서 판정 차이가 없었지만 **반복 변동을 재보지 않았고**, 회귀 3세트도
  안 돌렸다. `medium`이 이미 지연 문제를 해결하므로 더 내릴 유인이 약하다.
