작성 2026-10-23. 근거 결정: D-0167(+보완 1), D-0168, D-0163. 인계: `docs/handoffs/2026-10-23-choice-link-end-explanation-compare.md`. 측정은 결과 파일 기준이고, 판정과 해석은 Claude 메인 세션이 했다. **사용자 6쌍 확인 전 중간 보고다.**

## 1. 설계 (요약)

- 대상은 v5 회귀 시험(2026-10-22) 42세션이다.
  - 오답 종료 30세션: 6문항 × A1·A3·B1·B2·B3. 마지막 설명은 sol이 쓴다.
  - 정답·근거 미확인 12세션: CT·CP. 마지막 설명은 luna가 쓴다.
- 조건
  - BASE: 회귀 시험에서 저장된 마지막 설명 출력을 그대로 다시 쓴다(D-0168). 저장된 지시문과 모델은 현재 운영 상수와 일치함을 확인했다.
  - LINK: 같은 요청에 두 가지를 더한다. `choiceLinks`(처음·다시 고른 선지와 정답 선지의 statement, twists 또는 support)와 사용 규칙 문단이다.
  - 사용 규칙 문단에는 다음이 들어 있다.
    - 비튼 곳을 한두 문장으로 짚는다.
    - 걸러내는 법을 한 문장으로 쓴다.
    - 학생 생각을 단정하지 않는다.
    - 분류 이름을 노출하지 않는다.
  - 두 요청의 차이는 이 두 곳뿐이다(42세션 깊은 비교로 확인).
- 판정
  - X·Y 배정은 seed 20261023으로 무작위로 했다.
  - Claude가 블라인드로 판정하고 결과를 `run/CLAUDE-BLIND-JUDGMENT.json`에 기록한 뒤 열쇠를 열었다.
  - 사용자 6쌍(`run/USER-PAIRS.md`)은 아직 판정 전이다.

## 3. 블라인드 판정 결과 (해석, 열쇠 연 뒤 집계)

| | LINK 우세 | BASE 우세 | 비슷 |

| 오답 종료 29쌍 | 27 | 0 | 2 |
| 정답 종료 12쌍 | 8 | 1 | 3 |

- 비튼 방식 + 걸러내는 법 문장: LINK 34/41에 있었다. BASE에는 0이었다.
- 문장이 없던 LINK 7쌍과 그 판정은 다음과 같다.
  - D-B2: 비튼 방식만 명명해서 LINK 우세로 봤다.
  - G-B1, G-CP, I-A1, I-CT, S-CT: 비슷.
  - S-CP: BASE 우세(아래 안전 기준).
- 안전 기준
  - ① 원문 정확성: 문제 1건이다. **S-CP의 LINK(luna)**가 "오네소르게 수가 점도에 비례하고"라고 썼다. 원문 "점도가 클수록 크고"보다 강한 관계로, 지시문이 금지한 것이다. 좌표 support 문장은 원문 그대로였으므로 좌표가 원인은 아니고 luna의 실수로 본다. 다만 표본 1건이다.
  - ③ 학생 생각 단정: 0건이다. 근거가 막연한 세션(A1·B1)에서도 LINK는 비틂을 선지에 대한 사실로만 썼다. 학생 생각 추정은 기존 v5 규칙의 "내 짐작으로는" 형식 그대로였다.
  - ④ 형식: 0건(자동·수동).

## 4. 해석의 한계 (중요)

1. **블라인드가 약했다.** LINK의 "이런 선지는 …확인하면 걸러낼 수 있어" 문장 때문에 조건이 거의 드러났다. Claude의 우세 판정은 이 문장 유무와 거의 겹친다(우세 35 중 34가 문장 쪽). 판정의 실질은 "이 문장이 학생에게 도움이 되는가"이고, Claude는 도움이 된다고 봤다. 이 판단이 맞는지는 사용자 6쌍 확인이 가려 준다.
2. **나머지 내용 차이는 작다.** BASE도 정답 선지의 틀린 곳을 원문으로 이미 정확히 짚는다. 특히 법인·도파민·mRNA처럼 "적절하지 않은 것" 문항의 정답 설명이 그렇다. 좌표가 더한 것은 주로 다음 둘이다.
   - "어떻게 바꿨는지" 명명: 범위를 넓힘, 원문에 없는 효과를 덧붙임, 방향을 반대로 바꿈 등.
   - 걸러내는 법 한 문장.
3. 표본은 세션당 1회 생성이다. 출력 변동은 따로 보지 않았다.
4. 정답 세션 12쌍은 짧은 설명이라 차이가 작았다(비슷 3).

## 5. 제안

1. 사용자 6쌍 판정을 받아 Claude 판정과 맞춰 본다.
2. 일치하면 운영 반영안을 설계한다. 범위는 운영 v5 마지막 설명(오답 sol, 정답 luna)에 `choiceLinks`와 규칙 문단을 넣는 것이다.
   - 운영 반영은 D-0002 범위 안이다. 판정 이후 설명에만 쓰기 때문이다.
   - 골드가 있는 문항에만 적용된다. 현재는 UI 6문항이다.
3. 반영 전 보완을 검토한다.
   - luna 정답 설명의 관계 강화 1건을 막기 위해, 기존 금지 문장을 덧붙임 문단에도 되풀이할지 정한다.
   - 실패한 I-B3 1건을 재전송할지 정한다(sol 1요청, 약 $0.02). 지금 결론에는 영향이 없다.
4. 걸러내는 법 문장의 품질 자체도 사용자 판단 대상이다. 너무 일반적인 경우가 있다. 예: "각각 원문에서 확인하면 돼".

  - 사용자는 6쌍 중 5쌍에서 오른쪽(Y)을 골랐다. 위치 효과일 가능성도 배제할 수 없다. 차이가 "조금"이라는 사용자 표현과 합치면, 두 조건의 차이는 작다고 보는 것이 맞다.
- D-0167 5항 기준("비슷하면 v5 유지")에 따라 잠정 결론은 **운영 반영 근거 없음**이다. 판단 전에 사용자가 Y를 고른 이유를 확인한다.

## 8. 사용자 41쌍 판정 (추가, 2026-10-23, 기준: 이해가 잘 되는가)

사용자가 `run/ALL-PAIRS.html`로 41쌍을 블라인드로 판정했다. 쌍마다 이유 한 줄을 달았다(`run/USER-JUDGMENT-ALL.json`, 이유 원문은 대화 기록). 열쇠로 바꾼 결과는 다음과 같다.

|---|---:|---:|---:|
| 전체 41 | 20 | 18 | 3 |
| 오답 종료 29 | 14 | 14 | 1 |

- 위치: X 18, Y 20이다. 6쌍 때 보인 Y 쏠림은 전체에서는 없다.
- Claude와의 일치는 20/41이다. 우연 수준이다. Claude 블라인드 판정은 "이해 용이성" 기준으로 쓸 수 없다.
- "걸러내는 법" 문장이 있는 쪽을 고른 쌍은 18, 다른 쪽을 고른 쌍은 20, 비슷은 3이다. 이 문장은 결정 요인이 아니었다.
- 사용자 이유를 유형별로 세면 다음과 같다(Claude 분류, 중복 있음).

  | 유형 | 수 | 해당 쌍 |

  | 문단을 나눠 읽기 쉬움 | 9 | 03·04·05·17·18·24·29·36·37 |
  | 비튼 곳(함정)을 한 문장으로 바로 짚음 | 6 | 04·06·07·09·22·38 |
  | 결론을 분명히 닫음("그래서 답이 아니야") | 6 | 02·10·11·19·25·30 |
  | 간결함 | 6 | 13·14·20·39·41·42 |
  | 판별 팁이 쓸모 있음 | 6 | 19·20·28·29·34·37 |

  | 정확성·불필요 정보 | 2 | 42(관계 강화)·34(불필요 정보) |

- 해석
  - 좌표는 평균적으로 이해 용이성을 높이지 않았다. 사용자가 본 차이는 대부분 좌표와 무관한 서술 품질이었다: 문단 나눔, 결론 닫기, 간결함, 시작 방식.
  - "비튼 곳 바로 짚기"와 "판별 팁"은 좋은 점으로 꼽혔지만(합 12), 반대쪽 장점(문단·결론·간결)에 밀린 쌍이 비슷하게 많다.
  - 사용자는 "왜 의심했는지 알기 어려워"로 시작하는 설명을 맥이 끊긴다고 봤다(01). 근거가 막연할 때의 시작 문장 규칙도 다시 볼 대상이다.
- **결론: D-0167 5항에 따라 좌표를 운영 v5에 넣지 않는다.** 대신 사용자 이유에서 마지막 설명의 이해 용이성 규칙 후보가 나왔다.
  - 문단 나눔
  - 선지 칸 끝에서 판정을 분명히 닫기
  - 학생 말에서 바로 시작
  - 발문 조건 혼동이면 그 원인을 직접 말하기
  - 함정을 한 문장으로 요약하기
