## 4. eval-repair.mjs (RULES_V=6일 때)

### 4-1. e3 지시에 칸 둘 추가 (선지마다)
- `task`: "내용 확인 / 짝짓기 / 원리 적용 중 하나. 내용 확인 = 선지 진술이 지문(또는 〈보기〉)의 진술과 같은지 대조하면 끝. 짝짓기 = 〈보기〉의 대상·사례가 지문의 어느 개념·범주·관점에 해당하는지 정하면 끝. 원리 적용 = 지문의 원리·인과·규칙을 상황에 돌려 지문에 직접 적히지 않은 결과를 끌어내야 함. 셋이 섞이면 가장 뒤의 것(원리 적용 > 짝짓기 > 내용 확인)을 고른다." (MARKING-SCHEMA-v2 F4 그대로)
- `bogi_only`: "지문을 보지 않고 〈보기〉와 선지만으로 이 선지의 정오가 확정되는가 (true/false)."
- e3 JSON 예시에 두 칸을 넣는다.

### 4-2. 판정(서버) 다시 나눔
- 선지 n의 '지문 되묻기' = `one_fact_shortcut.possible`이고 `minimum_evidence.bogi`가 비었고 `task`가 "내용 확인".
- **결함 (defect)**: 정답 유일성 문제(지금 규칙 그대로: valid_answers가 [정답] 하나가 아니고, '후보 비움 + 답 일치' 경고 경우가 아님). → `defect: true`. 수리하지 않고 보고서에 "다시 생성" 표시.
- **방식 위반 (methodViolations)**:
  - M2: `bogi_only`가 true인 선지가 하나라도 있음.
  - M3: 내용상 참인 선지 중 `task`가 "내용 확인"인 것이 있음. 내용상 참 = 부정 발문이면 정답이 아닌 선지, 긍정 발문이면 정답.
  - M4: 지문 되묻기 선지가 2개 이상.
  - M5: `mirror_pair.exists`(정답 포함 여부와 상관없이).
- **수리 대상 (repair)**: methodViolations가 2개 이상이고 defect가 아님. 하나면 warnings에 "방식 위반 M?"으로만.
- **경고로 내림**: 핵심 관찰 없음, 가려도 정답만 남음, 정답이 지문 한 사실, 정답 steps ≤ 1, 오답 넷/셋이 지문 한 사실, 정답 〈보기〉 관찰 하나, 경쟁 선지 판단 다름.
- **고른 전략 못 지킴 (전략 경고)**: 항목에 strategies가 있으면
  - S3을 골랐는데 (핵심 관찰 없음 또는 가려도 정답만 남음 또는 정답이 지문 한 사실) → "고른 전략 못 지킴: S3".
  - S1을 골랐는데 (정답 steps ≤ 1 또는 정답 〈보기〉 관찰 하나) → "고른 전략 못 지킴: S1".
  - S4를 골랐는데 오답 셋 이상이 지문 한 사실로 지워짐 → "고른 전략 못 지킴: S4".
- **지움**: "정답이 가장 긴 선지" 경고.
- diag에 `defect`, `methodViolations`, `strategyWarnings`, 선지별 `task`·`bogi_only`를 더한다.

### 4-3. e4 수리 지시
- v6에서는 수리 사유로 방식 위반(M2~M5) 목록만 넘긴다. 지시문의 "사유만 고치는 최소 수정. 정답 번호·발문·갈래 유지"는 그대로. strategies·strategyUse는 그대로 옮기게 한다.
- 수리 뒤 다시 검사(e1r~e3r)도 같은 v6 판정을 쓴다.

### 4-4. 판정 함수 분리와 시험 (API 비용 없음)
- 위 판정을 순수 함수 `classifyV6(item, mask, e2, e3)`로 떼어 낸다(API 호출 없음).
- 가짜 e1·e2·e3 출력으로 만든 시험 사례 6개로 확인한다: (1) 유일성 문제 → defect, (2) M4만 → 경고, (3) M2+M5 → repair, (4) 정답 지문 한 사실 + S3 고름 → 전략 경고, repair 아님, (5) 아무 문제 없음, (6) 거울 짝이 오답끼리 → M5 위반.
- v5 경로(RULES_V 없음)의 결과가 바뀌지 않는지, 기존 out 폴더 하나의 e1~e3 저장 파일이 있으면 그것으로 v5 판정을 다시 계산해 같은지 본다(API 호출 없음, 저장 파일이 없으면 건너뛰고 적는다).
