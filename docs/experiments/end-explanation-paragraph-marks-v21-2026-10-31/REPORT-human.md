# 판정 반영한 마지막 설명 v2.1 — 사람용 보고

날짜: 2026-10-31. 자세한 수치: [REPORT-desktop.md](./REPORT-desktop.md). 나란히 보기: [COMPARE.md](./COMPARE.md)(지적 사례를 앞에 둠).

## 1. 개요

### 1) 작업의 목적

지난 판정(글 품질 부분 퇴보, 결론만 있는 짧은 문단, 같은 문장 연속 칠하기 등)을 고친다. 판정 항목 중 모델이 어겨도 결과가 정해져야 하는 것은 서버 처리로 막았다. 나머지는 지시문 v2.1에 넣었다. 생성마다 흔들림이 있는지 보려고 12건을 두 번씩 생성했다.

### 2) 작업의 결과

- **형식 문제는 거의 사라졌다.**
  - 결론만 있는 짧은 문단 0개(지난번 3개).
  - "될 수 있어" 같은 흐린 결론 0개.
  - 오네소르게 문항은 4번 모두 "오네소르게 수는 변하지 않아"로 결론을 말한다.
  - 각주 표시 ‘정관*’ 0개.
- **같은 문장 연속 칠하기**는 지시문만으로는 7건 남았다. 서버가 자동으로 지운다.
- **칠할 곳 87곳**은 모두 원문에서 정확히 찾아졌다. 서버가 문장 단위로 넓혀 칠한다. 잘린 칠하기는 없다.
- **새 검사로 2건이 생성 실패**했다. 새 검사는 "따옴표 안 말이 선지·원문에 실제로 있는가"를 본다. 모델이 바꿔 쓴 말이나 학생 말을 따옴표로 감싼 경우다. 선지를 바꿔 말하고 반박하는 실수를 막으려고 넣은 검사다.
- **아직 남은 것(판단 필요)**: C-B3 정답 칸이 두 번 모두 "지문은 주주들이 갑에게 법인격을 부여했다고 말하지 않아"라고 쓴다(2-2).
- 비용 $0.20.

### 3) 다음 스텝

1. 사용자 판정: 미리보기 22건, 특히 지적했던 사례가 나아졌는지.
2. C-B3 읽기 문제를 어떻게 볼지(2-2).
3. 통과하면 실제 마지막 설명 생성에 v2.1과 서버 처리를 연결한다(인계 문서 → 하위 에이전트).

## 2. 본문

### 2-1. 지난 판정 지적 항목 (대부분 해결, 판정 필요)

| 지적 | 이번 결과(2회) |
|---|---|
| 결론만 있는 20~27자 문단 | 0개(서버 합치기도 0건 필요) |
| QP "될 수 있어", 결론 흐림 | 0/4, 결론 문장 4/4 |
| KC-r1 ‘정관*’ | 0/2 |
| K4-r3 논리 비약 | r1 "지문은 주주들이 법인격을 부여한다고 말하지 않아" 있음, r2는 보셔야 함 |
| XS-r1 효소 구별 누락 | 두 번 모두 '분해 효소' 문장 있음. 구별이 제대로 됐는지 보셔야 함 |
| 같은 문장 연속 칠하기 | 모델이 7건 냄 → 서버가 지움 |
| 잘린 칠하기(C-CT) | 서버가 문장 단위로 넓힘 |

### 2-2. C-B3: 법인격을 누구에게 줬다고 읽는가 (판단 필요)

선지 ②: "갑에게 자산 운용의 권한이 주어진 것은 A를 설립할 당시 개인의 재산을 출연하여 주주들에 의해 법인격이 부여되었기 때문이겠군."

v2.1 r2 정답 칸 2번째 문단:

> 법인격은 법적으로 권리와 의무를 가질 수 있는 자격이야. 지문은 주식회사의 법인격이 ‘주식회사의 구성원 단체에 부여된다’고 설명해. 이는 갑 개인이 아니라 주식회사를 이루는 단체에 그 자격이 주어진다는 뜻이야. 지문은 갑이 재산을 내놓아서 주주들이 갑에게 법인격을 부여했다고 말하지 않아.

- 선지를 그대로 인용한 뒤 반박하는 것은 지켜졌다. 그런데 모델은 선지의 "법인격이 부여"된 대상을 갑으로 읽는다. 지난 판정은 대상을 A(회사)로 봤다.
- 이 차이는 K4(회사법 13번 ②) 판정 때 사람과 판정기가 선지를 달리 읽었던 지점과 같다. 당시에는 현재 동작을 수용했다(D-0182).

| 방안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| **(ㄱ) 이번 작업에서는 수용 — 권고** | K4와 같은 읽기 차이로 보고 지시문은 그대로 | K4 결정과 일관, 지시문이 한 문항에 맞춰지지 않음 | 이 문항 설명에 어색한 문장이 남음 |
| (ㄴ) 이 문항만 손보기 | 선지 읽기 규칙을 지시문에 추가 | 이 사례는 나아질 수 있음 | 한 문항 맞춤 규칙(과적합 위험), 재시험 필요 |

권고는 (ㄱ)이다. 이 문제는 문단·칠하기 형식이 아니라 선지 읽기 문제다. 그래서 판정기 쪽 선지 읽기(K4)와 함께 다루는 게 맞다.

### 2-3. 따옴표 인용 검사로 생긴 생성 실패 (판단 필요, 운영 적용 때)

- 24번 중 2번(XA-r1, C-CT)은 두 번 시도해도 검사에 걸려 설명을 만들지 못했다.
- 운영에서 이러면 학생은 설명을 못 받는다. 운영에 연결할 때 처리 방식을 정해야 한다.

| 방안 | 장점 | 단점 |
|---|---|---|
| **(ㄱ) 검사 실패 시 그 따옴표만 지우고 통과 — 권고** | 설명이 항상 나옴, 비용 없음 | 바꿔 말한 문장 자체는 남음 |
| (ㄴ) 재시도 3회 | 정확한 인용으로 다시 쓸 기회 | 지연·비용 증가, 그래도 실패 가능 |
