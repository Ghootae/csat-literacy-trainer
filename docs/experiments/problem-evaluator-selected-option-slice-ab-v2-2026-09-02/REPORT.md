# 선택 선지 완전 슬라이스 A/B 보고서

실행일: 2026-09-02

## 목적

4방향 판정 프로필과 기존 골드는 유지하면서, 판정 모델에 전체 기본 골드 대신 선택 선지의 승인 근거만 전달해도 판정 품질이 유지되는지 검증한다. 첫 단계에서는 절대 최소 입력이 아니라 선택 선지의 모든 claim, 승인 추론, 전제·원문·보기·시각 의존성을 닫은 `SELECTED_OPTION_COMPLETE` 슬라이스를 사용한다.

## 수행 작업

- 선택 선지의 모든 claim과 연결된 모든 기본 `itemInference`를 수집하고, 지문 명제·보기 사실·시각 assertion·미디어까지 참조 closure를 구성했다.
- `ACCEPTED / REJECTED` 결정에 필요한 충분 근거 집합을 `ANY_OF(ALL_OF(...))`로 명시했다. 기존 골드에 `decisionCritical`이 없는 2개 선지는 같은 실제 결정과 근거를 가진 모든 claim을 사용하는 `CONSERVATIVE_FROM_ALL_DECIDED_CLAIMS`로 명시적으로 파생했다.
- 정규화 명제와 함께 실제 지문 인용, 전체 보기 원문 또는 검증된 시각 자료 메타데이터를 제공했다.
- `DOES_NOT_JUSTIFY`에는 source evidence, dependency graph, 전체 골드의 서로 다른 해시와 감사 ID를 가진 coverage certificate를 요구했다. 이번 5문항 골드는 `candidate`이므로 인증 상태는 `EXPERIMENT_ONLY`이며 운영 승인으로 사용할 수 없다.
- 모델 입력에는 included manifest만 넣고, 다른 선지·claim·추론·대표 오답 경로·보충 해설·무관 출처의 excluded manifest는 별도 감사 산출물로 분리했다.
- 대표 오답 경로와 `supplementalExplanationInferences`는 전체 골드 기준군에서도 제거해 진단 유도와 공식 해설 노출을 통제했다.
- 모델 출력에 `DECISIVE / NON_DECISIVE`를 추가했다. 결정적 일치와 비결정적 오류가 섞이면 인정할 수 있지만, 결정적 충돌은 인정 결과를 덮도록 구조 검증했다.
- 학생 인용의 원문 존재, 골드 참조 ID의 허용 범위, finding과 최종 판정의 구조 일치를 코드로 검증했다. 자연어를 정규식으로 다시 판정하는 후처리는 추가하지 않았다.
- 기존 5문항의 `accurate` 15회와 `representativeWrong` 15회를 전체 골드와 슬라이스에 각각 실행했다. 모델은 `gpt-5.6-terra`, effort는 `medium`이다.

첫 실행에서는 모든 대표 오답의 기대값을 `CONTRADICTED`로 둔 채점 오류를 발견했다. `DOES_NOT_JUSTIFY` 대상 주장을 근거 없이 단정한 경우는 그 부정도 도출되지 않으므로 `INSUFFICIENT / NOT_ESTABLISHED`가 맞다. 첫 실행 산출물은 `docs/experiments/problem-evaluator-selected-option-slice-ab-2026-09-02/`에 보존하고, v2에서는 이 관계를 프롬프트와 기대 라벨에 명시해 동일 60회를 다시 실행했다.

## 결과

| 지표 | 전체 골드 | 선택 선지 슬라이스 |
|---|---:|---:|
| 전체 판정 | 30/30 | 30/30 |
| `CORRECT_ACCEPTED` | 9/9 | 9/9 |
| `CORRECT_REJECTED` | 6/6 | 6/6 |
| `WRONG_ACCEPTED` | 6/6 | 6/6 |
| `WRONG_REJECTED` | 9/9 | 9/9 |
| 평균 입력 토큰 | 6,683.7 | 2,673.3 |
| 총 입력 토큰 | 200,511 | 80,199 |
| 평균 입력 JSON 바이트 | 21,373.4 | 6,016.2 |
| 평균 응답 시간 | 4,454 ms | 4,481 ms |
| 오류 | 0 | 0 |

- 슬라이스는 판정 손실 없이 평균 입력 토큰을 60.0%, JSON 바이트를 71.9% 줄였다.
- 동일 사례·반복 번호로 짝지은 판정은 30/30이 완전히 같았다.
- `DOES_NOT_JUSTIFY` 대표 오답 2문항 × 3회 × 2입력군의 12회는 모두 `INSUFFICIENT`였다. 모든 호출에서 결정적 학생 주장은 `NOT_ESTABLISHED`로 포착됐다.
- 슬라이스 생성 실패와 암묵적 전체 골드 폴백은 0건이었다.
- 지연 시간은 사실상 유지됐다. 이번 결과는 입력 비용 절감과 판정 동등성을 입증하지만 지연 개선을 입증하지는 않는다.
- 관련 계약·회귀 58/58과 전체 타입 검사가 통과했다. 전체 회귀는 645/646이 통과했고, 유일한 실패는 기존부터 누락된 Hegel `.omc` 실험 산출물을 직접 읽는 무관한 테스트다.

이 결과는 기존 30개 응답 범위의 성공이다. 골드와 다른 표현의 유효 근거, 맞는 핵심 근거와 틀린 부가 설명의 혼합, 복수 전제 일부 누락, 슬라이스 밖의 새로운 유효 근거 등에는 아직 일반화되지 않았다. 또한 충분 근거 집합은 현재 골드 필드에서 보수적으로 파생했을 뿐, 사람이 검토한 명시적 대안 경로 계약은 아니다.

## 다음 작업 추천

운영 evaluator의 전체 골드 입력을 바로 교체하지 말고, 다음 위험 프로브를 전체 골드와 슬라이스에 먼저 추가하는 것을 권장한다.

1. 골드 대표 표현과 다른 유효한 정답 근거
2. 핵심 근거는 맞지만 부가 설명이 틀린 응답
3. 관련 있지만 결정적이지 않은 사실만 제시한 응답
4. 두 전제가 모두 필요한데 하나만 제시한 응답
5. `CONTRADICTS`와 `DOES_NOT_JUSTIFY`를 혼동하는 응답
6. 현재 슬라이스 밖의 새로운 유효 근거

이 프로브에서도 판정 동등성과 참조 무결성이 유지되면, 그다음에 운영 provider projection을 `SELECTED_OPTION_COMPLETE`로 교체하고 실패 시 `SLICE_UNAVAILABLE → BASELINE_FULL_GOLD`가 감사 로그에 명시되는 폴백을 연결하는 편이 안전하다. 장기적으로는 골드에 사람이 검토한 `sufficientGroundSets`를 직접 저장해 현재의 보수 파생을 제거해야 한다.
