# 코덱스와 논의 2차: 감사에 쓸 재료 (2026-11-23)

이 파일과 아래 '읽을 파일' 가운데 필요한 것만 읽고 답해 줘. 파일을 고치거나 새로 만들지 마. 인터넷·API도 쓰지 마. 답은 대화창(표준 출력)으로만 내 줘.

## 1차 정리

- 1차 답(`CODEX-REPLY-1.md`)의 결론인 **섞은 길**을 받기로 했다. 기출을 넓게 다시 분석하고, 그 결과로 지금 규칙을 유지·고침·삭제·추가로 감사한다. 감사하는 동안 칸별 규칙 덧붙이기는 멈춘다.
- 웹 Claude도 1차 전부터 같은 방향이었다. 일부러 알리지 않았는데 따로 같은 결론에 닿았다.
- 그대로 받는 것:
  - 규칙을 **보편 기준 / 갈래별 방식 / 선택 전략**의 세 층으로 나눈다.
  - 검사에 걸리면 곧바로 수리하는 연결을 끊는다.
  - 목표는 짧은 기준이다.
  - '세부 비틀기' 가설도 성급하다고 본다(세부 암기 위험).
  - 수능다움, 풀이 깊이, 학생을 가르는 힘은 별개다.

이번에는 찬반이 아니라 감사에 바로 쓸 재료를 묻는다.

## 지켜야 할 작업 규칙 (WORKING-RULES.md)

- 사람 판정 대신 코덱스 평가자의 블라인드 판정을 쓴다. 생성·감사 절차에 사람이 중간에 끼어드는 단계는 넣지 않는다.
- 규칙은 원칙과 점검 질문으로 쓴다. 예시는 시험 지문과 다른 소재로 든다.
- 한 번 본 실패로 문구 규칙을 더하지 않는다(과적합 경계).
- 규칙을 고칠 때는 함께 읽히는 규칙 묶음 전체와 대조 기출로 충돌을 검토한다.

## 질문 1. 지금 규칙의 세 층 분류 초안

다음 규칙을 하나씩 **보편 기준 / 갈래별 방식 / 선택 전략**으로 나눠 줘.

- `rules-common.md`의 C1~C23
- `kind-case.md`의 K-S1~K-S10
- `kind-view.md`의 원칙들
- `rules-A.md`·`rules-B.md`는 위 규칙과 겹치거나 부딪치는 항목만

뜻은 이렇게 쓴다.
- 보편 기준: 모든 3점 〈보기〉 문항이 지켜야 한다. 기출 대부분이 지킨다고 예상된다.
- 갈래별 방식: 그 갈래 기출에서 흔한 짜임이다.
- 선택 전략: 좋은 문항을 만드는 여러 방법 가운데 하나다. 기출이 늘 쓰지는 않는다.

출력은 표 하나로 해 줘. 칸: 규칙 번호 | 한 줄 요약 | 층 | 판단 근거 | 기출과 어긋난 기록(파일·위치, 없으면 '없음') | 기출로 확인할 방법(무엇을 세면 되나).

판단이 어려우면 '애매'로 두고 이유를 적어 줘.

## 질문 2. 웹이 고친 실행안 다섯 곳에 대한 반론

1차 답의 '가장 작은 시험'과 '지킬 것·버릴 것'을 우리 작업 규칙에 맞추려고 다음과 같이 고쳤다. 각각 동의·반대와 이유를 적어 줘.

1. **판정자:** "사람이 확인"을 다음으로 바꾼다. CLI(Claude)가 1차로 표시하고, 코덱스 평가자 2명이 같은 표로 따로 표시한다. 일치율을 재고, 갈린 곳만 웹 Claude가 판정한다. 일치율이 낮으면 규칙보다 표시 항목부터 고친다.
2. **시험의 자리:** 6+6 시험을 감사 앞의 관문으로 두지 않고 **감사의 1단계(시범)**로 돌린다. 감사를 넓게 해야 할 근거는 이미 있다고 본다(사례에서 C4·C9·C11·K-S10·C23이, 관점에서 C23과 수리 검사기가 기출과 어긋남). 발문 방향(A형·B형)을 나눠 짝짓는 1차 제안은 받는다.
3. **'핵심 규칙'의 정의:** 핵심 규칙 = 보편 기준. 규칙마다 "기출 n개 중 몇 개가 지키는가"를 센다. 보편 기준인데 기출 다수가 어기면 철회 후보로 본다. 숫자 문턱은 실행 전에 정한다(예: 3분의 1 이상이 어기면 철회 후보).
4. **걸린 문항의 처리:** 사람이 검토하는 단계가 없으므로 셋 중에서 고른다. 경고만 기록하고 통과 / 다시 생성 / 버림. 생성 규칙을 바꾼 뒤 새 문항의 걸림 비율을 보고 정한다.
5. **자료:** 규칙을 만들 때 쓰지 않은 평가원·수능 문항을 우선한다. 이미 쓴 것은 해부 9개, 태깅의 평가원·수능 10개, 보정 4개이고 서로 겹친다. 남은 것이 갈래마다 모자라면 교육청 고3으로 채우고, 출처를 칸으로 따로 적는다.

## 질문 3. 선지 표시 항목(코딩표) 초안

시범과 감사에서 선지마다 다음을 표시하려 한다. **빠진 칸, 판정이 흔들릴 칸, 줄여도 될 칸**을 짚어 줘. 고친 안이 있으면 그 문안도 적어 줘.

| 칸 | 값 |
|---|---|
| ① 정오를 가르는 근거의 자리 | 〈보기〉만 / 지문만 / 둘 다 |
| ② 지문 근거의 층위(지문이 관여할 때) | 중심 주장·정의 / 적용의 경계(단서·예외·범위·조건) / 이유·비교(누가 왜, 무엇과 다른가) / 외우면 되는 세부 |
| ③ 비튼 방식(거짓 선지) | `rules-common` C5의 목록 + '해당 없음' |
| ④ 선지가 〈보기〉 내용을 담는 방식 | 그대로 옮김 / 가정을 덧붙임 / 담지 않음(〈보기〉를 봐야 함) |
| ⑤ 지문 요지만 아는 사람이 바로 판정할 수 있나 | 예 / 아니오 |
| ⑥ 참·거짓, 정답 여부 | |
| 문항 단위 | 갈래, 발문 방향, 정답의 근거 구조(①~②를 정답 선지에 대해 한 줄로), 쉬운 선지 수(⑤가 '예'인 선지) |

②의 '적용의 경계'와 '외우면 되는 세부'를 나눈 것은 1차에서 네가 짚은 '세부 암기' 위험을 가르려는 것이다.

## 질문 4. 목표

"기출 재현"인가, "기출보다 엄격한 문항"인가? 웹 Claude는 이렇게 제안했다. 동의·반대와 이유, 고친 안이 있으면 그것까지 적어 줘.

> 규칙의 바닥은 기출이 모두 통과하는 수준으로 둔다(보편 기준은 기출 대부분이 지키는 것만). 지향점은 좋은 평가원·수능 기출로 둔다(갈래별 방식과 선택 전략은 '수능 같음'을 받는 평가원·수능 3점 문항의 모양을 따른다).
