## 2. Codex가 짚지 않은 발견

### A. 정답을 골랐지만 근거가 약하면 한 줄로 끝난다 (12/48)

- **정정(2026-10-12, 사용자 지적):** 계획된 동작이다. D-0104(정답 세션은 과도한 개입보다 관대함)·D-0106 32행, 합의된 운영 규칙 수형도("정답 + 근거 부족 → 정답·근거 미확인")에 이미 있다. 아래 "결정 기록이 없다"는 틀렸다. 남는 것은 이 한 줄 종료에 luna 설명을 붙일지에 대한 선택 사항뿐이다.

- 정답 사례 12개(CT 6, CP 6)가 모두 질문도 설명도 없이 "정답입니다. 다만 근거는 검증되지 않았습니다." 한 줄로 끝났다.
- 원인은 설계 그대로의 동작이다(`feedback-v4.ts` `unknown()`, SELECTION 정답·INSUFFICIENT 분기). 버그가 아니다.
- 근거가 부분적으로 맞는 학생도 같은 처리를 받는다. 예: D-CP "카르비도파는 레보도파가 도파민으로 바뀌는 효소를 억제해요." 는 정답 판단의 절반이다.
- 반대로 오답 학생은 코칭을 평균 약 650자 받는다(507~762자). 실제 운영에서는 정답·약한 근거 학생이 가장 흔할 가능성이 높아, 학습 효과의 공백이 가장 큰 곳이다.
- D-0112는 정답·교정 실패만 다뤘고 이 분기는 결정 기록이 없다. 사용자 논의가 필요하다.

### B. 오답에 막연한 근거를 쓰면 되묻지 않고 바로 끝난다 (5/6)

- **정정(2026-10-12, 사용자 확인):** 계획된 규칙대로다. 합의된 운영 규칙 수형도에서 "근거를 재구성할 수 없음 → 오답 → sol 종료 코칭 [RATIONALE_UNVERIFIABLE]", D-0112 2항. 결함이 아니라, 바꿀지 논의할 거리다.

- A1 사례 6개 중 5개는 확인 질문 없이 곧바로 RATIONALE_UNVERIFIABLE 코칭으로 끝났다. I-A1만 ERROR로 판정돼 질문이 나갔다.
- 근거를 아예 내지 않은 학생(B1)에게는 한 번 더 근거를 요청한다. 그래서 막연하게라도 쓴 학생이 덜 묻는 비대칭이 생긴다.
- UI 메모장 2번(판단 불가 안내 멘트)과 함께 논의할 거리다.

### C. 공개 코칭에 내부 용어 "교정 질문" (6/30)

- 해당 칸: C-B3, D-B3, G-B3, I-B3, M-B3, M-B2. 예: "이 점은 교정 질문에 '아니요.'라고 답하면서 바로잡았어요."
- 정적 검사가 잡지 못한다. D-B2의 3인칭 "학생이 고친 답변"(1/30)보다 더 많다.

### D. 서버 고정 문구의 말투와 조사

- 서버 고정 문구는 합쇼체인데("오답입니다…", "확인된 오류의 수정이 확인됐습니다.", "정답과 근거가 확인됐습니다."), 모델 코칭은 해요체다. 한 대화 안에서 말투가 바뀐다.
- "확인된 오류의 수정이 확인됐습니다"는 '확인'이 겹쳐 어색하다.
- 교정 성공 문구에서 "①를", "③를"은 읽는 소리(일, 삼)로 보면 '을'이 맞다. '를' 고정 규칙(D-0112)을 다시 볼 필요가 있다.

### E. 코칭의 순서와 중복

- 순서가 칸마다 다르다. "학생 생각 → 정답 → 고른 선지"와 "학생 생각 → 고른 선지 → 정답"이 섞여 있다.
- 같은 내용이 되풀이되는 칸이 있다. G-A1은 정답 ④를 처음과 끝에 두 번 말하고, D-B2는 ④ 설명을 두 번 한다.
- UI 메모장 6번에 이미 기록된 문제와 같다.

## 4. 내용 정확성

- 종료 코칭 30개에서 원문과 어긋나는 내용은 찾지 못했다. 원문을 직접 대조한 곳: 법인(배당의 주주 총회 의결, 무상 증자는 이사회 결정만), mRNA(<보기>의 에탄올 pH 7 단서).
- 교정 질문 35개는 대부분 "A인가요, B인가요?" 식의 두 갈래 질문이었다. 정답 정보가 드러나는 것을 감수하고 직접 묻자는 사용자 방향과 맞는다.
