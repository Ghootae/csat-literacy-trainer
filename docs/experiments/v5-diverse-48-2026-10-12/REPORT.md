## 기록을 읽을 때 구별할 것

- `correctionSucceeded=true`는 19개다. 이 중 최종 정답·근거 검증까지 간 것은 6개이고, 코칭 요청 또는 재선택 오답으로 끝난 것은 13개다. 국소 수정 성공을 전체 해결로 바꾸어 집계하지 않았다.
- `resolvedByStudent=true`는 18개다. **여기에는 최초 정답·근거 미확인 12개도 포함된다.** 현재 `packages/pipeline/src/problem-solving/feedback-v4.ts`의 `finish()`는 이 값을 `!answerRevealed`로 설정한다. 따라서 이 필드를 이해 교정 완료 수로 읽으면 안 된다. 근거 검증은 `rationaleVerified`와 outcome을 따로 보아야 한다.
- 학생 답변은 Codex가 실제 질문과 원문을 보고 작성했다. 실제 학생 회복률·학습 효과·운영 정확도 측정이 아니라, 서로 다른 수준에서 발생하는 대화 과정을 기록한 합성 실행이다.

## 검토 항목

1. **D-A2, REPAIR 충분성 기록:** 레보도파가 장벽을 통과할 수 있다고 수정한 답은 REPAIRED로 인정했지만, `rationaleSufficient=false`의 이유를 “선택한 선지가 부적절하다는 판단을 뒷받침하지 않는다”고 썼다. 옛 오답 선택을 충분성 판단의 기준으로 다시 사용하는 것으로 보인다. 국소 수정·재선택을 막지는 않았고 최종 재선택은 VERIFIED_CORRECT다. 사용자 검토가 필요한 기록 문제로 남긴다.
2. **D-B2, 공개 코칭 형식:** “학생이 고친 답변”이라는 3인칭 표현 1건. 직접 말하라는 종료 지시문과 어긋난다. 자동 정적 검사도 `noThirdPerson=false`로 잡았다. 원응답은 교체하지 않았다.
3. **I-A1, 해석 경계:** “과장 광고니까 걸릴 것 같아요”를 플랫폼 제재 판단으로 읽고 교정 질문을 만들었다. 선택 선지 문맥으로 복원 가능한 생략인지 판단 관계를 더한 것인지 사용자 검토가 필요하다. 과잉 교정이라고 확정하지 않는다.

`I-A3`는 구성자가 복합 경로를 의도했지만 실제 판정은 표시 의무 적용 범위만 명시적 오류로 보았다. “AI로 만든 광고는 모두 허위”는 UNDETERMINED로 보존했고, 마지막 코칭이 자료에 근거 없는 일반화로 짚었다. 실제 판정에 없는 두 번째 질문을 만들지 않았다.

이 검토는 사례를 작성한 Codex의 원문 대조이며 독립 블라인드 사람 검토가 아니다. 전체 48개에 검토 기록을 남겼으나 이를 운영 품질 비율로 환산하지 않는다. 정책·프롬프트 수정은 이번 작업에 포함하지 않았다.
