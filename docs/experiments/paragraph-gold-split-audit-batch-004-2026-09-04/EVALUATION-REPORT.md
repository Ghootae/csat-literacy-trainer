# 배치004 Local/Global 분리 감사 실험 보고서

## 1. 전체 맥락

배치004의 기존 단일 감사는 최초 수리 뒤 재감사에서 새 문제를 발견하는 경우가 있었다. 특히
협업 수리로 확정한 다섯 문제점(PGC-016~PGC-020) 중 상당수가 최초 감사와 자동 수리에서
누락됐다. 이를 개선하기 위해 최초 감사를 개별 명제·간선 중심의 Local 감사와 중심 이야기·축·
핵심 관계 중심의 Global 감사로 나눠, 호출 한 번을 추가하는 운영 방침을 시험했다.

## 2. 수행한 작업에 대한 목적

새 2단계 감사가 다음 두 조건을 동시에 만족하는지 확인했다.

- 기존 최초 감사가 놓친 알려진 문제를 수리 전에 더 잘 찾는가?
- 정상적으로 승인된 문단에 불필요한 수리 요구를 크게 늘리지 않는가?

둘을 함께 만족할 때만 기본 운영 방침을 변경하기로 했다.

## 3. 작업 과정

배치004의 3지문·18문단에 대해 수정 전 최초 후보를 동결하여 사용했다. 기존 승인본과 기존
수리 결과는 입력하지 않았다.

각 문단은 다음 순서로 처리했다.

1. Terra Medium Local 감사
2. 같은 최초 후보에 대한 독립 Terra Medium Global 감사
3. 코드로 두 결과 병합
4. `REPAIR_REQUIRED`인 경우에만 자동 수리 1회
5. 수리본에 Local·Global 재감사

모든 호출은 `service_tier=default`, 자동 재시도 0회로 실행했다. 원본 배치004와 승인본은
수정하지 않았고 별도 실험 폴더에 전 과정을 저장했다.

## 4. 작업 결과

| 지표 | 기존 단일 감사 | Local+Global v1 |
|---|---:|---:|
| 최초 PASS | 6/18 (33.3%) | 3/18 (16.7%) |
| 최초 수리 대상 | 12/18 | 15/18 |
| 수리 후 최종 PASS | 14/18 (77.8%) | 10/18 (55.6%) |
| 감사·수리 API 호출 | 42회 | 81회 |
| 계산 비용 | 약 $1.1254 | 약 $2.3254 |

알려진 다섯 문제점 중 최초 감사에서 직접 찾은 것은 PGC-018 한 건뿐이었다.

- PGC-016: E1·E6 목적-수단 확대를 최초에는 놓치고 재감사에서야 발견
- PGC-017: `차례로`라는 근거 없는 시간 순서를 끝까지 발견하지 못함
- PGC-018: 계약 원칙과 보호 예외의 중심 구조 누락을 최초에 발견하고 복원
- PGC-019: P6의 필수 조건 양상 약화를 끝까지 발견하지 못함
- PGC-020: 조건 분기 간선 누락을 발견하지 못하고, 수리 과정에서 관련 구조를 더 삭제

따라서 알려진 문제점 기준 최초 검출률과 전체 과정 해결률은 각각 1/5(20%)였다. 문단 단위로
보면 네 회귀 문단 중 한 문단만 핵심 문제를 최초에 잡았다.

또한 기존 최초 PASS 대조군 6개 중 4개에 새 수리 요구가 발생했다. 이 4개를 모두 의미적
오탐이라고 단정할 수는 없지만, Global 감사가 도입 설명·구체적 사례·보조 정의까지
centralStory·centralAxes·coreRelations에 모두 넣도록 요구하는 경향이 확인됐다. 이는 중요한
내용을 선별·압축하는 현재 문단 골드 계약보다 넓은 기준이다.

## 5. 결과 해석

Local/Global 분리라는 형식만으로 최초 감사의 핵심 문제가 개선되지는 않았다. 호출 수는
42회에서 81회로 92.9% 늘고 계산 비용은 약 106.6% 늘었지만, 알려진 회귀 문제 검출은 20%에
그쳤고 자동 완결률은 오히려 77.8%에서 55.6%로 낮아졌다.

따라서 **Local+Global v1을 기본 운영 방침으로 채택하지 않는다.** 다음 배치에는 현재의
`단일 감사 → 수리 1회 → 재감사 → 예외 협업 수리` 방침을 유지한다.

이번 결과가 뜻하는 바는 감사 호출 수가 부족하다는 것보다 감사 기준이 정확하지 않다는 것이다.
Global 감사는 원문의 모든 사실을 진단 구조에 넣는 검사가 아니라, `centralStory가 선별한 독립
중심 의미`가 축과 핵심 관계에 보존됐는지를 검사해야 한다. Local 감사 역시 조건문을 별도
명제로 나누지 않았다는 이유만으로 존재 주장을 읽어 내는 식의 과도한 문자 검사를 피해야 한다.

향후 감사 개선을 다시 시도한다면 별도 호출을 기본 추가하기보다, PGC-016~PGC-020을 고정
회귀 세트로 두고 기존 단일 감사 프롬프트의 검출 기준을 먼저 교정한 뒤 같은 배치004에서 무료
채점 가능한 변이 검사부터 통과시키는 편이 타당하다.
