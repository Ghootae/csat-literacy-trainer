# 충실도 검사기 보정 결과 (2026-11-16)

CLI가 out/r3a, out/r3b, out/r2를 한 번씩 돌렸다. 코드는 고치지 않았다. 비용은 r3a 0.077달러, r3b 0.087달러, r2 0.057달러(비교 없음)다. 따라서 목표가 있는 지문 한 편에 0.08달러 안팎이 든다.

## 1. 판정: 사람 판단과 맞는가

| 이름 | 목표 | 사람 판단 | 검사기 판정 | 맞음? |
|---|---|---|---|---|
| r3a | S7-1 사례 재대조 | 대체로 따른다 | 따름 | 맞음 (기준: 따름 또는 대체로 따름) |
| r3b | S7-2 복수 논거 재검토 | 절반쯤 따른다 | 절반 | 맞음 |
| r2 | 없음 | — | 가장 가까운 구조 S7-2 | 참고 |

두 편 모두 판정 단계에서는 사람 판단과 맞았다. 코드 대조도 두 편 모두 목표를 37개 중 1위로 찾았다.

## 2. r3b: 판정은 같지만 까닭이 다른 부분

| 사람이 본 것 | 검사기가 본 것 |
|---|---|
| 입장을 차례로 쌓는 부분은 따른다 | 같음. 2~4문단이 "입장 제시(조건 명시) ×n"에 맞음 |
| 끝의 수치 사례를 덧붙였다 | 같은 곳을 잡았다. 다만 덧붙음이 아니라 "귀결 제시 자리가 사례로 바뀜"으로 판정했다 |
| 설계도에 없는 "공통 조건" 문단을 덧붙였다 | 덧붙음으로 잡았지만 "짜임을 바꾸지 않음"으로 봤다. r3b에서는 공통 조건이 따로 된 문단이 아니라 2문단 앞부분에 있어서다 |
| (사람 판단에 없음) | 빠짐: 마지막 입장(㉰)이 앞선 논거들을 함께 되짚어 수용·거부·수정하지 않는다. S7-2를 S7의 다른 하위 구조와 가르는 핵심 요소다 |
| S6(요건 → 판정) 방식이 섞였다 | S4(유형·방식 대조)를 닮았다고 했다. S6은 코드 대조의 가장 가까운 구조 3위(S6-1 요건 누적 심사)에만 나왔다 |

Claude 판단:
- **빠짐 판정은 맞다.** r3b의 ㉰는 새 기준(산정 근거의 독립성)을 하나 더 얹을 뿐 ㉮·㉯의 논거를 되짚지 않는다. 사람 판단의 "절반"을 구조 쪽 말로 더 정확히 짚었다.
- **S6을 놓친 것은 한계로 남긴다.** 검사기는 "목표대로 썼는가"를 재는 도구라서, 어긋난 부분이 어느 유형에서 왔는지는 약하게만 잡는다. 입장마다 "승인 조건"을 다는 짜임은 평면도에서 "입장 제시(조건 명시)"로 그려진다. 그런데 S7-2 배열에도 바로 그 라벨이 있어서, 요건처럼 보이는 문체가 구조 차이로 드러나지 않는다.
- 이 차이 때문에 비교 지시문을 고치지는 않는다(한 번 본 어긋남으로 문구를 더하지 않는다는 원칙).

## 3. 그 밖에 나온 것

- **겹침**: 세 편 모두 기출과 연속 15자 이상 겹친 곳이 0곳이다.
- **분량**:
  - r2는 2,731자, 54문장으로 기출 최대(2,639자, 36문장)를 넘는다.
  - r3a·r3b는 35문장으로 범위 안이지만, 모든 문단이 7문장으로 똑같다.
  - 보고서에 이런 것이 자동으로 표시되게 고쳤다("기출 범위 밖" 줄). API 호출은 더 들지 않고, 다시 돌리면 보고서만 새로 써진다.
- **r2**: 구조 목록 없이 쓴 글인데 S7-2에 가장 가깝게 나왔다(점수 0.13). 큰 전개가 "입장을 차례로 쌓기"였다는 뜻이다.

## 4. 결론

- 3.2(구조를 주고 생성하기)에 이 검사기를 쓴다.
- 판정이 경계에 걸리는 지문은 FORCE_COMPARE=1로 한 번 더 돌려 같은 판정이 나오는지 본다.
- 이번 보정은 한 번씩만 돌린 결과라 판정이 얼마나 안정적인지는 아직 모른다.
- 검사기가 재는 것은 "고른 설계도대로 썼는가"다. 그 설계도가 수능다운지, 다른 유형이 섞였는지는 사람이 본다. 이 부분은 블라인드 판정으로 보완한다.
