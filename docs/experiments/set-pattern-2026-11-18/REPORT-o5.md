## 3. 그래프 읽기 판 수리 (B5)

### 3-1. 원인
o5a 첫 실행에서 두 그래프 문항이 "정답 유일성 결함"이었다. 검사 모델은 SVG가 아니라 읽기 판(글)만 보는데, 읽기 판이 (a) 눈금별 높이·기준선 위아래, (b) 기준선과 만나는 곳, (c) 표시점 가로 위치를 적지 않았고 (d) 내부 좌표 `x=3`이 노출됐다.

### 3-2. 바꾼 것 (`graph/render.mjs`의 readingText, `render.test.mjs`)
- a. 이름 있는 가로 눈금마다 계열 높이: 세로 눈금 값이 있으면 "눈금 v 높이 / 눈금 a~b 사이 / 눈금 a보다 위", 수평 기준선이 있으면 "P보다 위·아래·P 높이", 계열이 둘 이상이면 "높은 쪽부터 ㉡ > ㉠".
- b. 기준선과 만나는 곳: "㉠: t₀~t₁ 사이에서 P 아래로 내려간다." 만나지 않으면 "㉡: t₀~t₂ 내내 P 위."
- c. "표시점의 가로 위치: ⓐ: t₁ 이전, ⓑ: t₁~t₂ 사이 …", 높이가 같으면 "표시점 ⓑ, ⓓ의 높이가 같다."
- d. `x=N`을 "ⓑ와 가로축 t₂ 사이 지점"처럼 이름 있는 표시·눈금 기준으로. (지시문은 "t₂와 t₃ 사이"처럼 눈금 기준 예를 들었는데, 표시점까지 함께 쓰는 기존 where 규칙을 그대로 써 더 잘게 나뉜다. 이 점은 지시문과 다르다.)
- e. 비교는 graphSpec 원래 숫자로(허용오차 1e-9). 계산한 숫자 값은 읽기 판에 적지 않는다.
- 조사(은/는·와/과)가 숫자·기호에 따라 틀리지 않게 "㉠: …" 꼴과 "~ 사이"를 썼다.
- SVG 그리는 코드, run.mjs, eval-repair, leak-fix, 규칙·갈래 파일은 건드리지 않았다.

### 3-3. 시험
- 변경 전 43/43 통과 → 변경 후 **49/49 통과**(새 시험 6개: a 2, b 1, c 1, d 1, e 1).
- 회귀 9개(graphD 기준): 읽기 판이 바뀐 줄은 모두 a~d 범위였다(`o5/graph-fix/regression-changed-lines.txt`). a~d와 무관한 줄 변경 0 → 멈춤 조건 해당 없음.
- 회귀 시험 규칙을 고쳤다: 기존 시험은 "줄 수가 같고 바뀐 줄은 '같은 가로 위치' 줄뿐"을 검사해 줄이 늘어나는 변경과 맞지 않았다. "추가 줄은 a~c 꼴, 사라진 줄은 `x=N` 줄뿐, 읽기 판에 `x=N`이 남지 않음"으로 바꿨다. 기준 파일(regress-before/after)은 바꾸지 않았다.
- svg→png: playwright 전용 브라우저가 없어 시스템 Chrome으로 변환(`o5/graph-fix/svg2png.mjs`).

## 4. 해석 (측정과 분리, 미확정)
- 생성 문항이 대부분 평균 1.0(8회 모두 '중') 근처에 몰렸고, 가장 흔한 결함은 ㉲(정답이 지문 한 문장으로 정해짐)·㉯(〈보기〉 없이 풀리는 선지 2개↑)였다. 표·사례·관점에서 반복된다.
- 과학 실험은 BL-B-exp 1.500이 칸 최고인데 TW-B-exp가 0.250이다. TW-B-exp 평가자는 8회 모두 ㉳를 표시하고 이유를 같다고 썼다: "⑤가 적절하지만 ①도 A의 모노클로라민이 조사 구간 이후에도 작용한다는 뜻으로 읽혀 정답의 유일성이 확보되지 않는다." 생성기 검사(정답 유일성 통과)와 평가자 판정이 갈렸다. 문항 하나 때문에 칸이 "바닥 미달"이 된 구조다.
- 그래프: 기출 열팽창(KG, 2.000)이 높아 M이 올랐고(1.583) 생성 두 문항은 1.0 안팎이다. 평가자 그래프 평에 새 읽기 판의 "가로축 위" 표현이 "축선 위 vs 축 위쪽"으로 헷갈리고 설명이 장황하다는 지적(TW-A-graph), 그림에서 ㉠ 표시가 가로축 제목과 겹쳐 빽빽하다는 지적(TW-B-graph)이 있다. 둘 다 이번 수정 범위 밖(읽기 판 기호 표현, SVG 이름 배치)이다.
- 앵커 점수가 같은 칸 안에서 0.000~2.000으로 퍼져 M 자체가 불안정하다(예: 과학 실험 M 1.344는 연소 1.000·압전 1.000과 수소 1.875의 평균).
