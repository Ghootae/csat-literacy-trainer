## 1. 방법과 한계

- **블라인드 문항과 생성 문항의 연결**: `KEY-*.md` 표기만 믿지 않고, 블라인드의 선지 5개와 〈보기〉를 `out-*/<지문>-<형>/`의 `items.json`(수리 전)·`repair/items-final.json`(e4 최종)·`leakfix/items-leakfix.json`(노출 수리 채택본)과 글자 단위(공백·기호 제거)로 대조했다. 일치한 판만 표에 썼고 일치하지 않은 문항은 기출(KEY가 기출로 적은 것과 일치)이다.
- **검사 판정 파일**: e4 최종본이면 `e1-maskr`·`e2-maskedr`·`e3-shortcutr`와 `eval.json`의 `after`, 수리 전·원본이면 `e1-mask`·`e2-masked`·`e3-shortcut`와 `before`. 노출 수리 채택본은 e4 최종본(수리가 없었으면 원본)을 검사한 결과라 검사한 판과 본 판이 다르다.
- **평가자 지적 부호화**: 평가 보고서의 "이유"·"결함" 칸을 읽고 사람이 정리했다. 선지 번호를 들어 "〈보기〉·사례 없이 배제된다"고 쓴 것은 해당 선지의 지적(c), 정답이 규칙·문장 하나의 직접 적용이라는 지적(㉲ 포함)은 정답 선지의 지적(a), ㉯ 표시만 있고 번호가 없는 것은 선지 지정이 안 되는 항목 단위 지적(u)으로 적었다. 그래프 블라인드 `graph-r3`는 "보기 없이 풀리는 선지" 열을 그대로 썼다. 부호화는 문장 해석이라 표 B의 "애매"와 모호한 지적(아래 "애매로 둔 지적")에 재검토 여지가 있다.
  - 애매로 둔 지적 leakfix|1|다: e1 「답이 쉽게 정해져」(정답 규칙 하나 적용으로 읽었으나 문장이 모호)
  - 애매로 둔 지적 cell5|2|자: e3 「비교적 곧바로 적용하는 수준」(곧바로≠한 사실이라 애매)
  - 애매로 둔 지적 gen62|4|나: e1·e2 「쉽게 끝난다/쉽게 드러난다」(정답 한 단계 지적으로 읽음, e3·e4는 명시)
- **같은 판 확인**: 표 C는 두 블라인드의 선지 5개와 〈보기〉가 모두 같은 항목만 같은 판으로 쳤다(글자 단위).
- **한계**: (1) 평가자는 코덱스 `gpt-6.1-sol` 세션이고 블라인드마다 새 세션이라 같은 번호의 평가자(e1~e4)가 같은 사람이 아니다. (2) 노출 수리·그래프 블라인드는 평가자가 2명(leakfix)이거나 평가 기준이 약간 다르다(graph 계열은 그래프 열 추가). (3) 수리 기준 같음 판정은 git 커밋 시각 기준이며 커밋하지 않은 작업본은 알 수 없다. (4) 점수는 평가자 기준 문장 해석이라 사람 판정과 같다고 보장하지 않는다.

## 6. 후보 (규칙·기준에 대해 떠오른 것, 고치지 않음)

규칙·기준 파일은 이번에 읽기만 했다. 아래는 웹 스레드가 WORKING-RULES 3절 절차(충돌 검토 → 논의 → Ghootae 결정)로 다룰 후보다.

1. **W 측정을 보강할지**: W = 0.25는 4대4 같은 판 쌍 6개(그중 기출 12번 3평가 포함)에서 나왔다. 평가가 쉬운 문항이 많아 실제 흔들림보다 작을 수 있다. 2단계 블록에서 같은 판 한두 개를 다른 순서로 반복 평가하면 W를 다시 잴 수 있다(예: 수리 전 판 1개를 두 번 넣기). 비용: 코덱스 계정이라 과금 없음.
2. **e3 오탐(정답 지문 한 사실 판정) 완화 가능성**: 청약 A-V2 수리 전(`cell5` 카)은 e3가 정답 ②를 "〈보기〉 없이 지문 한 사실로 판정"이라 했는데 평가자 4명 모두 수능 같음(2.00)이었고 아무도 지름길을 지적하지 않았다. 수리 전 정답은 "비용을 누가 냈는지로 철회 이유를 거꾸로 짐작할 수 없다"를 묻는 선지다. e3의 `one_fact_shortcut.possible` 판정이 '결과만으로 원인을 역추론할 수 없음' 형태 선지에 반응하는지 다른 문항에서도 볼 필요가 있다(표 D에서 e3 사유 문항: 13개).
3. **e3 정답형 놓침 vs 정의 차이**: 평가자는 "정답이 규정 하나의 직접 적용으로 정해진다"(㉲)를 지름길로 봤다. e3는 "〈보기〉 근거 없이 지문 한 사실로 판정"이거나 "추론 단계 수 ≤ 1"일 때만 수리한다. 수리 후 청약 A-V2(`cell5` 사)는 e3r가 정답 ②를 4단계로 세어 통과시켰지만 평가자 4명이 모두 "방문판매 분류 후 규칙 하나 적용"을 지적했다. 단계 수를 세는 정의가 평가자의 "한 규칙 대입" 느낌과 다르다. e3 단계 수 정의나 정답형 지름길 검사 항목을 논의할 후보다.
4. **오답형 놓침의 반복 패턴**: 평가자가 가장 자주 지적하는 오답은 "일반 원칙·개념 확인만으로 배제되는 쉬운 오답"(③·⑤가 대표)이고 평가자가 선지를 지적한 줄 32개 중 e3도 지름길로 본 것은 11개다. 선지 단위 검사를 오답 4개 모두 지름길일 때만 수리(오답 넷)·3개는 경고로 두는 현재 기준이 평가자 눈과 맞는지 볼 후보.
5. **e4가 좋은 선지를 단순하게 만들 수 있다**: `cell5` 청약 A-V2는 수리 전 정답 ②("비용 부담으로 철회 이유를 거꾸로 짐작할 수 없다")가 e4 수리로 "일반 철회 기간 안에서 단순 변심이면 비용을 을이 부담한다"로 바뀌었다(`repair/e4-repair.md`). 평가자 4명이 수리 뒤 판을 "규칙 직접 적용"이라 평가했다. e4 프롬프트에 "정답의 구조(역추론 불가 형태)를 바꾸지 않는다"를 넣을지는 2단계 결과(낮춤 쌍이 더 있는가)를 보고 판단할 후보다.
6. **수리 후에도 "수리 필요"인 문항**: 표 D에서 수리 후 검사가 다시 걸린 문항이 있다(표 D "수리 뒤 검사" 칸). 그 문항이 최종본으로 블라인드에 들어갔는지, 수리를 한 번만 하는 규칙(REPAIR 1회)이 맞는지 볼 후보.
7. **⑤ 보고서 7절 후보 2개**(e4 뒤 안 쓰이는 〈보기〉 사실 정리, K-S10 범위를 B형으로 넓힐지)는 PLAN 6절대로 웹 스레드에서 따로 논의한다. 이 1단계에서 새로 찾은 것은 없다.

## 7. 열린 질문

- 2단계에서 어떤 표 D 문항을 수리 쌍으로 쓸지는 웹이 목록을 확정한다. 표 D에는 그래프 2개, cell5 3개, 수리 기준이 첫 커밋 이전인 `out-v52`·`out-v53` 16개(v52 13, v53 3), 수리가 여러 번 바뀐 규칙 전 시기 문항이 섞여 있다.
