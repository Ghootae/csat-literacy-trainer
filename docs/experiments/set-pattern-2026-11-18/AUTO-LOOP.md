# 고난도 칸 자동 실행 절차 (CLI용, 2026-11-20)

Ghootae 결정(2026-11-20): 생성 → 블라인드 → 코덱스 판정 → 집계 → 규칙 수정 → 재실행을 CLI가 이어서 한다. 사람은 아래 "멈춤 지점"에서만 본다. 웹 스레드는 칸이 끝날 때 보고서를 읽고 다음 칸·방향을 논의한다.

기본 자료: PROGRESS-hard.md(진척), STRATEGY-hard-cells.md(칸별 전략·순서), REVIEW-*.md(칸별 기록), deep-item-v5-2026-11-18/(생성기·kind 규칙).

## 0. 공통 규칙
- 파일을 git checkout·stash·restore로 되돌리지 않는다. 실행 전 kind 파일에 필요한 원칙이 있는지 grep으로 확인하고, 없으면 멈춘다.
- 사람 판정은 쓰지 않는다. 평가는 코덱스 두 평가자만.
- 생성한 쪽(gpt-6.1-sol 파이프라인)과 평가하는 쪽(codex)은 늘 다르게 둔다. 규칙을 고친 사람(CLI)이 평가하지 않는다.
- 비용: 단계마다 호출 수 × 단가로 미리 추산하고, 끝나면 usage.json 합산으로 실제 비용을 기록한다. 최소 실행이 기본(필요한 지문·버전만, ONLY=V1|V2 + KEEP_OUT 재사용).

## 1. 한 칸 루프
1) 준비: 지문(passages/<id>)과 대조용 기출 〈보기〉 문항(같은 지문)을 확인. 없으면 만들고, 지도가 없으면 멈춤 지점 ①.
2) 생성: run.mjs (MODE=A 다음 MODE=B, B는 같은 회차 A를 피하게), eval-repair.mjs REPAIR=1.
3) 검사기 보정: 같은 지문 기출을 eval-repair.mjs로 검사만. 기출이 "수리 필요"로 잡히면 그 갈래는 검사기 결과를 참고만 한다(관점 갈래가 그랬음, 2026-11-20).
4) 블라인드: 지문마다 생성 문항 + 기출 1문항, 순서 무작위, 출처 표시 없음. 발문은 통일하되 기출 선지가 원래 발문에 묶여 있으면(비판형 등) 원래 발문 유지. 결함 목록 ㉮~㉴는 BLIND-view-hs.md와 같게. 단 ㉴는 "학생이 내려야 할 판정(누가 긍정·부정하는지, 어느 쪽과 같은지)까지 〈보기〉가 말함"으로 적는다. 비판형 발문에서 비판의 전제를 주는 것은 ㉴가 아니다.
5) 평가: 코덱스를 비대화형으로 두 번 따로 실행(각각 새 세션, 이전 맥락 없음). 각자 답·등급(수능 같음/중/수능 아님)·한 줄 이유·결함 표시를 고정한 뒤 KEY와 대조. 결과 REPORT-<칸>-eval1.md, -eval2.md.
6) 집계: 정답 일치 수, 문항별 두 등급, 결함 표시 빈도, 기출 등급. 기출이 둘 다 '수능 같음'이 아니면 평가가 이상한 것 → 멈춤 지점 ②.
7) 판정:
   - **L2 통과** = 생성 문항이 모두 두 평가자에게 '중' 이상 + 두 평가자가 모두 '수능 같음'을 준 생성 문항이 1개 이상.
   - **거의 통과** = 모두 '중' 이상이지만 둘 다 '수능 같음'인 문항 없음.
   - **미달** = '수능 아님'이 하나라도 있음.
8) 미달·거의 통과면 개정: 결함 빈도 상위 1~2개만 kind 파일에 원칙 + 점검 질문 + 다른 소재 예로 추가(기존 원칙과 겹치면 기존 원칙을 고친다). 그다음 V1만 최소 재실행 → 4)부터 다시. 개정은 칸당 최대 2회.
9) 기록: PROGRESS-hard.md 해당 칸(단계·근거·다음), REVIEW-<칸>.md에 회차별 결과, 실제 비용. 칸이 끝나면 커밋·푸시(메시지에 칸 이름·결과 등급·바꾼 규칙).

## 2. 멈춤 지점 (Ghootae에게 묻고 기다림)
① 새 지문이나 새 지도가 필요할 때(비용 추가) ② 기출이 '수능 같음'을 못 받아 평가 자체가 의심될 때 ③ 한 칸 비용이 상한을 넘을 때(칸당 기본 $6) ④ 개정 2회 뒤에도 '거의 통과'에 못 미칠 때 ⑤ 공통 규칙(rules-common)이나 생성기 코드를 바꿔야 할 때
'거의 통과'에서 2회가 끝나면 멈추지 말고 그 상태로 기록하고 다음 칸으로 간다.

## 3. 칸 순서 (STRATEGY 3절)
② 관점 L2(진행 중, 블라인드 BLIND-view-hs.md 판정부터) → ③ 그래프(명세 JSON → SVG, 코드 작업 있음 → 멈춤 지점 ⑤로 먼저 보고) → ④ 사회 A형 시험 → ⑤ 생성 지문 L3 → ⑥ 경제 표·그래프 → ⑦ 과학 관점·실험.

## 4. 칸이 끝날 때 보고 (웹 스레드로 가져갈 것)
REPORT-cell-<칸>.md 5~10줄: 결과 등급, 회차별 변화, 남은 결함, 바꾼 규칙, 실제 비용, 다음 칸.
