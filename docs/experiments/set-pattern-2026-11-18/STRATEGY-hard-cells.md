# 고난도(〈보기〉 3점) 11칸 진행 전략 (2026-11-19 밤)

함께 보는 문서: PROGRESS-hard.md(진척표), MATRIX.md(기출 비율), BOGI-ANATOMY.md(기출 3점 9문항 해부), REVIEW-case-humanities-social.md(사례 칸 재검토).

## 0. 전체 판단 먼저

### 0-1. 칸을 막는 것은 세 종류뿐이다
| 막힘 | 뜻 | 해당 칸 |
|---|---|---|
| 규칙 | 갈래 규칙 파일이 없거나 그 지문 유형에서 한 번도 안 돌림 | 과학 실험, 모든 관점 칸, 사회 표 |
| 출력 형식 | 생성기가 글·표만 낸다. 그림을 못 만든다 | 과학 그래프, 사회 그래프 |
| 지문 | 그 갈래가 붙는 지문이 생성기로 아직 안 나온다 | 관점 3칸(입장형 지문), 사회 표·그래프(경제 지문), 인문 사례(S7 v3.1) |

그래서 순서는 "막힘이 규칙뿐인 칸 → 형식 → 지문" 쪽이 싸고 빠르다.

### 0-2. 모든 칸에 같은 사다리를 쓴다
칸마다 아래 단계를 밟는다. PROGRESS-hard.md의 "진척 단계"도 이 이름으로 맞춘다.

| 단계 | 끝났다는 기준 |
|---|---|
| L0 없음 | - |
| L1 규칙 | 갈래 규칙 파일이 있고 run.mjs로 돌릴 수 있다 |
| L2 기출 지문 검증 | 기출 지문 1편에서 A·B 생성 + eval-repair, 코덱스 두 평가자 블라인드(같은 지문 기출 문항 섞음)에서 결함표가 바닥 수준 |
| L3 생성 지문 검증 | v3.1 생성 지문 1편에서 같은 실행, 기출 지문 결과와 차이가 작다 |
| L4 기준 확정 | 결정 기록(D-xxxx) + 세트 조립기에 넣을 수 있음 |

- 기출 지문을 먼저 쓰는 이유: 지문 결함과 문항 결함이 섞이지 않는다. 기출 지문에는 같은 지문의 실제 3점 문항이 있어 블라인드 대조군이 공짜로 생긴다.
- 사람 판정은 쓰지 않는다(Ghootae 11/19). 코덱스 두 평가자 + 결함표(REVIEW-case 2절 형식)로 본다.

### 0-3. 칸과 상관없이 걸리는 공통 문제 셋
1. **A형(적절하지 않은 것)의 깊이.** 기출 고난도는 부정 발문이 68~81%다. 세트를 조립하면 A형이 다수인데, A형 정답이 "거짓 진술 하나 + 지문 한 문장"으로 풀리는 약점이 과학·인문·사회 모두에서 나왔다. v5.3 규칙은 B형에서만 효과가 났다.
   - 전략: 지금은 바닥(v5.2)으로 두고 칸 확장을 먼저 한다. 단, 기출 해부 A1(재판매)이 보여 준 방식 하나만 사회 사례 칸에서 시험한다. A1은 다섯 선지 모두 〈보기〉에 새 가정을 하나씩 얹고, 정답을 상식과 갈리는 면제 범위에 두었다. 정답이 "〈보기〉 사실 + 선지의 새 가정 + 지문 예외" 셋을 합쳐야 거짓이 되는 구조다. 법 지문에서는 이것이 자연스럽다. 같은 지문에서 버전만 올리는 실험은 하지 않는다는 규칙과도 부딪치지 않는다(새 칸, 새 지문이라서).
2. **검사기 보정이 과학 지문뿐이다.** eval-repair의 '가린 판 풀이'는 도플러·mRNA와 기출 12·19번으로만 맞췄다. 인문 문항은 "개념으로 옮기기"가 깊이의 대부분이라, 과학 기준이면 좋은 문항을 수리 대상으로 잘못 잡을 수 있다(공손룡 A-V1이 그 예로 보인다).
   - 전략: 칸마다 L2 실행 때 같은 지문 기출 3점 문항 1개를 eval-repair에 같이 넣는다(문항당 약 $0.25). 기출이 '수리 필요'로 나오면 그 칸에서는 해당 수리 사유를 경고로 낮춘다.
3. **분량·문체 편차.** 기출 해부 기준 선지 길이는 표·도식 33~58자, 사례 40~84자, 관점·실험 81~98자다. 갈래별 길이 목표가 이미 kind 파일에 있으니, 세트 조립 때 checks.json 경고만 본다. 따로 실험하지 않는다.

## 1. 칸별 전략

### 과학 · 표 (기출: 그림 든 〈보기〉 66% 중 일부) — L3, 기준 버전

- 남은 일: A형 표의 깊이(한 행만 보고 풀림, v5.3 A형 표가 나빠짐). L4 결정 기록.
- 전략: 더 다듬지 않는다. 그래프 칸을 만들 때 표와 그래프가 같은 "자료 해석" 축을 공유하므로, 그래프 칸 결과를 보고 표를 다시 볼지 정한다. L4 결정은 다음 결정 기록에 묶는다.

### 과학 · 사례 (12%) — L3, 기준 버전, 수준 중

- 남은 일: A형 사례가 한 단계로 풀림.
- 전략: 과학 쪽은 손대지 않는다. 사회 사례에서 A형 시험(0-3의 1)이 효과를 보면 그 원칙을 과학 사례 A형에 옮겨 한 번만 확인한다.

### 과학 · 실험 (8%) — L1 직전(옛 버전만)

- 남은 일: kind-experiment.md가 없다.
- 전략: 방침대로 우선 v4.1로 채워 두고, 나중에 kind-experiment.md를 D1 모양으로 쓴다. 원칙 셋이면 충분하다. ① 비교 대상 둘 이상과 바뀐 조건 하나 ② 관찰은 변화 모양·대소까지, 목적·가설은 쓰지 않음 ③ 변인 고정은 괄호 한 줄. 시험은 도플러나 혈액 응고처럼 이미 있는 과학 지문 1편에서 A·B 1회(약 $2). 비중이 8%라 순서는 뒤쪽이다.

### 과학 · 외부 글·관점 (12%) — L1(규칙만)
- 준비됨: kind-view.md(예시는 인문 문화재뿐).
- 막힘: 과학 이론 대립 지문이 손에 없다.
- 전략: 인문·사회 관점 칸(아래)에서 kind-view를 먼저 L2로 올린 뒤 들어온다. 기출에서 "두 이론·모형이 같은 현상을 다르게 설명하는" 과학 지문 1편을 고른다(CLI로 structure-catalog에서 검색, 비용 없음). 금광 지도 생성(1편, 추정 약 $1, 3.3 때 지도 3회 실행 기준) 뒤 A·B 실행(약 $2). 과학 관점 〈보기〉는 기출에서 "새 실험 결과를 두 이론이 어떻게 해석하나" 형태가 많을 것으로 예상하므로 kind-view에 사례형 하위 형태로 "새 관찰"을 추가한다.

### 과학 · 그래프 (그림 66% 중 일부) — L0, 출력 형식이 막힘
- 준비됨: 기출 도플러 12번(그래프)을 글로 옮긴 calib-gold/doppler-12.json. 판단은 "데이터 JSON → SVG"로 가능.
- 전략(세 부분으로 나눈다).
  1. **그래프 명세 형식(코드, API 비용 없음).** 모델은 그림이 아니라 명세 JSON만 낸다: 축 이름·단위, 구간 경계(t1, t2…), 계열별 점 또는 "증가/감소/일정" 구간 모양, 표시할 기호(㉠, A). 렌더러(작은 node 스크립트)가 SVG로 그린다. 검사용으로 같은 명세를 글로 옮긴 "그래프 읽기 판"도 자동으로 만든다.
  2. **kind-graph.md(웹에서 작성).** 기출 그래프는 숫자보다 모양(기울기, 꺾임, 교차, 부호)을 읽게 한다. 원칙: 선지 셋 이상은 구간 두 개를 비교해야 판정, 축에 판정어 금지(표의 결과 행 금지와 같음), 기울기·넓이처럼 한 번 더 넘기는 읽기를 정답 축으로(C20).
  3. **검사.** eval-repair는 "그래프 읽기 판"을 〈보기〉로 받아 그대로 돌린다. 코덱스 평가는 SVG 이미지를 같이 본다.
- 시범: 도플러(기출) B형 1회만(약 $1). 코덱스가 도플러 12번과 섞어 본다. 통과하면 사회 그래프로 넘긴다.

### 인문 · 사례 (35%) — L1+, 재검토 끝
- 준비됨: kind-case.md + K-S4~K-S6(오늘 추가). 옛 결과는 깊이 충분, 결함은 지문 예시 복제.
- 진행 중: 공손룡(기출 12번 사례 〈보기〉 대조) A·B 실행 지시문 대기(약 $2, 공시와 합쳐 $4).
- 남은 일: L2 판정 → L3에는 인문 v3.1 생성 지문이 필요(S7-1 계열, 지금은 v2뿐).
- 전략: L2는 공손룡 실행 결과로 본다. 볼 것은 K-S4가 듣는지(〈보기〉가 흰 말 예를 떠나는지)와 0-3의 2(검사기가 공손룡 기출 12번을 잘못 잡는지). L3은 S7-1을 v3.1로 1편 생성(약 $0.6 + 충실도 $0.08) 후 같은 실행(약 $2). 인문 사례만을 위해 지문을 따로 만들지 말고, 아래 관점 칸에 쓸 입장형 지문과 한 번에 계획한다.
- 범위 밖 메모: 인문 고난도의 10%인 '학습 활동' 〈보기〉는 세팅에 없다. 세트 조립 때 필요하면 그때 본다.

### 인문 · 외부 글·관점 (34%) — L1(규칙만)
- 준비됨: kind-view.md(인문 문화재 예시), 기출 해부 C1(공공 저널리즘: 학자 이름 없이 사례 둘, 481자)·C2(노자: 새 평가자 관점, 294자). **두 입장 지문과 금광 지도가 이미 있다**: 의미 내재주의·외재주의(배치2). 지도 생성 비용이 들지 않는다.
- 남은 일: kind-view 첫 실행.
- 전략: 의미 지문에 KIND=view로 A·B 1회(약 $2). 사례형(새 사례를 두 관점이 평가)과 새 관점형 중 V1·V2에 하나씩 두면 한 번에 두 하위 형태를 본다. 볼 것: K-E1(〈보기〉에 평가자 이름·입장이 새지 않는가), 정답 오류가 귀속·묶음·평가 방향에 있는가(K-E2), 선지가 70~100자인가. 이 지문은 옛 사례 문항이 쌍둥이 지구를 복제했던 지문이라 K-S4도 같이 확인된다.
- 다음: 복합 (가)(나) 지문은 인문 문항의 34%가 매트릭스 밖인 이유다. 세트 조립 단계에서 따로 다룬다.

### 사회 · 사례 (44%) — L1+, 재검토 끝, 가장 비중 큼
- 준비됨: kind-case.md + K-S6·경계값 보충. 모범형 공시 B-V1. 옛 법인·공시 결과.
- 진행 중: 공시 의무 A·B 실행(위 $4 지시문에 포함).
- 남은 일: L2 판정 → A형 시험(0-3의 1) → L3(청약 철회 v3.1).
- 전략: ① 공시 실행으로 L2. ② 결과에서 A형이 여전히 한 단계면, A형 전용 원칙 한 줄("정답 거짓은 〈보기〉 사실 + 선지의 새 가정 + 지문 예외를 합쳐야 드러난다")을 rules-A가 아니라 kind-case의 법·제도 항목에 넣고 공시 A형만 다시 돌린다(약 $1). ③ 청약 철회 S6-2를 v3.1로 다시 생성(약 $0.6, 끝 문단 미완결 해결 확인) → 같은 실행(약 $2). 사회 사례는 비중이 가장 크고 생성 지문에서도 문항이 얕아지지 않았던 칸(3.3 결과)이라 L4에 가장 먼저 도달할 후보다.

### 사회 · 외부 글·관점 (24%) — L1(규칙만)
- 준비됨: kind-view.md. **입장 지문과 지도가 이미 있다**: 정보 비대칭과 사상의 자유 시장(사상의 자유 시장 이론 vs 비판론, 헌재 다수 vs 소수 의견). 옛 사례 문항(갑·을 운영자 의견)이 사실상 관점 문항이었다.
- 남은 일: kind-view에 법·제도 예시 추가, 첫 실행.
- 전략: kind-view에 "법 조항·학설·판결 의견"을 평가자로 쓰는 예시 하나를 다른 화제로 추가(웹, 비용 없음). 정보 비대칭 지문에 KIND=view로 A·B 1회(약 $2). 인문 관점과 같은 CLI 지시문에 묶는다. 볼 것은 인문과 같고, 추가로 K-S5(인물 발언에 지문 핵심어 금지)가 관점 갈래에서도 지켜지는지.

### 사회 · 표 (그림 든 〈보기〉 27% 중 일부) — L1(규칙만, 과학 기준)
- 막힘: 경제 지문이 없다(생성 S2·S3 미착수, 기출 경제 지문도 손에 없음).
- 전략: 기출 먼저. CLI로 suneung_db에서 "경제 + 그림 〈보기〉" 기출 1편(원가·조세·수요 공급 등)을 골라 금광 지도를 만든다(추정 약 $1). KIND=table로 A·B 1회(약 $2). 사회 표는 대개 "조건별 값(가격·세율·수량)"이라 kind-table의 '같은 행 = 같은 변수' 규칙이 그대로 맞을 것으로 본다. 다른 점이 보이면 그때만 kind-table에 경제 예시를 더한다. L3은 S2/S3 v3.1 생성 뒤.

### 사회 · 그래프 (그림 27% 중 일부) — L0, 출력 형식이 막힘
- 전략: 과학 그래프 시범이 통과한 뒤, 사회 표에 쓴 같은 경제 기출 지문에 KIND=graph로 1회(약 $1~2). 경제 그래프(수요·공급 곡선 이동, 세금 쐐기)는 "두 선의 교점이 어디로 움직이나"가 핵심이라, 명세 형식에 "곡선 이동 전·후" 계열을 넣어 두면 된다. 지문과 지도를 사회 표와 같이 쓰므로 추가 준비 비용이 없다.

## 2. 지문 생성 쪽 전략
