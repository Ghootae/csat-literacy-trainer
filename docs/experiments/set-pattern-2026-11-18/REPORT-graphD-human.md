# 그래프 D — 쉬운 설명 (2026-11-25)

## 1. 개요
1) **목적:** 지난번 B형 그래프 점수(0.88)가 낮았던 이유가 "그림 옆 글(읽기 판)의 버그" 때문인지 "문항 자체" 때문인지 가르고, 규칙대로 B형을 한 번 다시 만들어 보는 것.
2) **결과:** 버그가 맞았다. 읽기 판의 버그 한 줄만 고쳐서 옛 B를 다시 평가했더니 0.88에서 **2.00**(8명 모두 '수능 같음')이 됐다. 그런데 새로 만든 B는 **0.00**이었다. 이번에는 그림이 아니라 수리 단계가 〈보기〉의 조건 문장을 지워서, 정답을 정할 수 없는 문항이 되었다. 새 B로 계산한 칸 평균은 0.81, 고친 옛 B로 계산하면 1.81이다.
3) **다음 스텝:** 웹이 4-3 기준으로 판정한다. 알아낸 것 두 가지: ① 읽기 판 버그는 고쳤다. ② 수리 단계가 〈보기〉 조건을 지우는 문제가 새로 나왔다.

## 2. 본문
### 문제 1. 읽기 판이 그림과 다름 (해결)
- **어떤 문제가:** 옛 B의 읽기 판이 "병: ⓔ(100) → ⓑ: 증가"라고 적었다. ⓑ는 갑의 끝점인데 병의 끝점 이름처럼 쓴 것.
- **과정:** 끝점에 표시가 없으면 같은 가로 위치의 다른 선 기호를 가져다 쓰던 코드를 고쳤다. 이제 "가로축 1(ⓑ와 같은 가로 위치)"처럼 쓴다. 다른 기출 그림 9개로 확인했더니 바뀐 줄은 같은 종류 줄뿐이었다(그림은 하나도 안 바뀜).
- **결과:** 고친 읽기 판으로 옛 B를 다시 평가: 8명 모두 '수능 같음', 그림 탓 이유 0건(지난번엔 8건 전부 그림 탓). 문항 자체는 그대로인데 점수가 0.88에서 2.00이 되었다.

### 문제 2. 새로 만든 B가 정답을 못 정함 (미해결)
- **어떤 문제가:** 규칙대로 B형을 한 번 다시 만들었다. 서버 확인은 통과했는데 평가자 8명 모두 정답을 못 골랐다.
- **과정:** 처음 만든 문항은 〈보기〉에 "공급의 가격 탄력성은 세 시장 모두 1, 균형 거래량은 A와 B가 같고 C는 두 배"라는 조건이 있었다. 수리 검사가 "〈보기〉만으로 정오가 정해지는 선지가 있다"고 해서 고쳤는데, 고치는 과정에서 이 조건 문장을 통째로 지워 버렸다. 남은 것은 그림과 읽기 판뿐이라 ②와 ⑤ 중 무엇이 맞는지 알 수 없다.
- **결과:** 8명 모두 '수능 아님', 이유는 전부 "조건이 없다". 4-3에 따라 더 다시 만들지 않고 기록만 했다.

### 판단 필요
| 방안 | 내용 | 비고 |
|---|---|---|
| 1. 수리 단계 점검 추가 | 수리가 〈보기〉 조건을 지웠는지 확인하는 규칙 | 수리 코드·규칙을 고쳐야 함 |
| 2. 수리 전 문항 평가 | 수리 전 새 B(조건이 남은 판)를 같은 방식으로 평가해 보기 | 수리 단계 탓인지 갈림 |
| 3. 이대로 기록 | 칸 평균 0.81(새 B)과 1.81(고친 옛 B)을 나란히 웹에 올림 | 코드 변경 없음 |
추천: 2를 먼저, 그 다음 1. 이유: 점수를 깎은 것이 수리 단계의 조건 삭제인지 생성 설계인지 아직 갈리지 않았다.
