# 칸 보고: ③ 그래프 갈래 시범 (과학·그래프, L0→L2 시범) — 2026-11-21

생성 gpt-6.2-sol, 판정 codex gpt-6.1-sol 4회(ChatGPT 계정, 새 세션·정답표 격리, 그림 PNG + 읽기 판 같이 줌). 커밋·푸시 없음.

## 1. 결과 한눈에
- **등급: 거의 통과**(생성 1문항이 4/4 평가자에게 '중', '수능 아님' 0, 둘 다 '수능 같음' 0). 기출 도플러 12번은 4/4 '수능 같음'이라 평가는 정상(멈춤 지점 ② 아님).
- 표본은 문항 1개다. 갈래가 통과한다는 증거가 아니라 "파이프라인이 돌고, 어디가 약한지 보인다"는 시범 결과다.
- 1차 시범은 실패(풀이자 답 `null`)였고, 읽기 판 결함을 고친 뒤 2차(r2)를 돌렸다. 아래 등급표는 r2.

## 2. 등급표 (코덱스 4회, 블라인드 BLIND-graph.md)
| 문항 | 출처 | 정답 | 평가자 답 | 판정 (4회) | 결함 표시 |
|---|---|---|---|---|---|
| 가 | 기출 도플러 12번 | ② | ② 4/4 | 수능 같음 4 | ㉰ 4/4 |
| 나 | 생성 r2 B-V1 | ⑤ | ⑤ 4/4 | 중 4 | ㉰ 4/4, ㉯ 1/4 |

- 더 수능다운 문항: 4/4 모두 **기출(가)**.
- ㉰("〈보기〉에 쓰이지 않는 사실") 표시는 기출에도 같은 4/4로 붙었고, 이유가 "읽기 판의 기울기 크기 순위가 풀이에 불필요"였다. 문항 결함이 아니라 **읽기 판 설계의 흔적**이다. 문항 결함으로 세지 않는다.

## 3. 반복된 결함 (2문항 이상이 아니라 표본이 1문항이므로 평가자 4명 중 일치 기준으로 적음)
1. **정답이 쉽게 서는 구조는 맞지만 선지 ②·③이 그래프를 안 쓴다**(4/4). ②는 단계 이름, ③은 젤의 역할이라 〈보기〉 없이 배제된다(평가자 3은 ㉯로 표시). 다섯 선지 중 그래프 값을 써서 판정하는 것은 ④·⑤ 둘뿐이다. kind-graph G1(셋 이상이 구간 비교)·G4(그래프만/지문만으로 풀리는 선지 제한)를 생성이 어겼다.
2. **가로축이 각도(°)인데 눈금 값이 없고 구간 경계 `t1~t3`만 있다**(4/4, "어색"·"①은 각도 범위를 판단할 근거 없음"). 생성 명세의 ticks에 id(t1~t3)만 쓰고 의미를 안 줬다. 렌더가 그 id를 그대로 그림에 찍는다.
3. **읽기 판에 풀이에 안 쓰이는 정보가 붙는다**(8/8, 기출 포함): 기울기 크기 순위, 가로축 구간 경계. 읽기 판이 〈보기〉로 취급되므로 ㉰를 부른다.

## 4. 왜 이렇게 됐나 (무엇이 정답을 쉽게/어색하게 만들었나)
- 〈보기〉 그래프가 `㉠ 두 점, ㉡ 세 점`뿐이라 읽을 구간이 거의 없다. 두 계열을 같은 각도에서 견주는 한 가지 읽기(절댓값 → 속도 → 밝기)만 남았고, 나머지 선지는 지문 사실 확인으로 흩어졌다. 정답의 읽기 단계(부호·절댓값 한 번 더 넘기기, C20)는 좋다.
- 읽기 판은 "자동으로 계산할 수 있는 것을 전부" 적는 방식이라, 실제 선지가 쓰지 않는 항목이 늘 붙는다.

## 5. 1차 실패 정정과 렌더 수리
- 정정: 처음에 "읽기 판의 가로축 이름이 명세(시간)와 다르다"고 한 것은 내 오독이다. 1차 시범 명세 자체가 "송신 주파수(MHz)"였고, 렌더 결함이 아니었다. 이 점은 3절의 "생성이 가로축 의미를 임의로 정함"과 같은 갈래의 문제다.
- 실제 렌더 결함 두 가지를 `graph/render.mjs`에서 고쳤다: (a) 다른 곡선의 표시 기호와 가로 좌표가 같으면 그 기호의 점으로 읽히던 문제("ⓑ와 같은 가로 위치"로 표기), (b) 곡선이 한쪽 부호뿐이면 부호 줄이 없어 ⓒ가 0선 위인지 알 수 없던 문제("전 구간 음(−)", 표시 기호마다 가로축 위·아래 표기). (c) 판정 전 그림에서 가로축 이름이 `t3`와 겹쳐 위치를 옮겼다(두 문항 모두 같은 방식).
- 1차 풀이 결과: 풀이자 답 null, 장면-정의 문제 2곳 → 2차: 풀이자 답 5 일치, 장면-정의 문제 2곳(각도 눈금 없음, 절댓값 순서가 속도 순서와 일치한다는 보장 없음).
- 수리(eval-repair)와 노출 수리(leak-fix)는 r2에서 모두 "원본 유지"였다. 즉 사후 수리 단계가 그래프 갈래의 약점(선지 구조, 가로축 의미)을 못 잡는다.
