# CLI-o5b — 그래프 글 설명 고치기 + 나머지 실행 (2026-11-28, 웹 작성)

- 근거: o5a 첫 실행(수돗물 A·B형)에서 그래프 문제 2개가 모두 "정답 유일성 결함"으로 멈춤. 웹이 산출물을 읽어 본 진단:
  - 그림(SVG)에는 필요한 정보가 있다. 예: B형 그래프에서 ㉠은 t₁ 전에 기준선 P 아래로 내려가고 ㉡은 t₁ 뒤까지 P 위에 있다.
  - 그런데 그림을 글로 옮긴 "그래프 읽기 판"이 그 정보를 빠뜨린다. B형 읽기 판은 "㉠: t₀ → t₂ 감소, ㉡: t₀ → t₂ 감소"뿐이라, 어느 쪽이 P 위인지·t₁에서 어느 쪽이 높은지가 없다. A형 읽기 판은 표시점(ⓑ·ⓓ)이 t₂·t₃의 어디쯤인지가 없고, 내부 좌표 "x=3"이 그대로 찍혔다.
  - 검사 모델은 읽기 판만 보므로 "정보가 없어 정답을 못 정함"이 나왔다. 문제 자체의 결함인지는 아직 모른다.
- 그래서: 읽기 판을 만드는 코드(render.mjs의 readingText)만 고치고, 두 그래프 문제를 다시 검사한다. 문제는 새로 만들지 않는다. 다시 검사해도 결함이면 그 문제만 한 번 새로 만든다.
- 동시에 그래프와 상관없는 나머지 실행(혈액 응고 A·B형, 청약 철회 A·B형)과 블라인드는 o5a 계획 그대로 진행한다.
- **추정 비용: 약 $3 (상한 $5).** 나머지 4실행 × 약 $0.5 × 2문항 ≈ $2.0~2.5, 그래프 두 문제 다시 검사 약 $0.4, 새로 만들기가 생기면 1회당 약 $0.5. 블라인드는 0원.
- **최소 실행:** 그래프 문제는 새로 만들지 않고 글 설명만 고쳐 다시 검사한다.

## 쉬운 설명

- **무엇이 문제였나:** 그래프 문제 두 개가 "정답이 하나로 안 정해진다"는 검사에 걸려 CLI가 지시대로 멈췄습니다. 살펴보니 그림 자체는 괜찮은데, 그림을 글로 옮긴 설명이 핵심(어느 선이 기준선 위에 있는지, 어느 선이 더 높은지)을 빠뜨렸어요. 검사 모델은 그 글만 읽기 때문에 "정보가 없다"고 한 것입니다.
- **무엇을:** 그 글 설명을 만드는 코드만 고쳐서, 눈금마다 선의 높이, 기준선과 만나는 곳, 표시점의 위치를 적게 합니다. 그다음 두 그래프 문제를 새로 만들지 않고 다시 검사합니다.
- **나머지:** 혈액 응고와 청약 철회 문제 8개는 그래프와 상관없어 바로 만들고, 다 모이면 원래 계획대로 하나씩 따로 채점합니다.
- **비용:** 약 $3(상한 $5). 첫 실행에 쓴 비용과 합쳐도 처음 추정(약 $6) 안쪽일 것으로 봅니다.
