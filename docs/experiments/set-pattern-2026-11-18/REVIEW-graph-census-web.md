## 1. 집계에서 알게 된 것

1. **그래프 〈보기〉는 드물다.** 158세트 문항 752개 중 그래프 〈보기〉 14개(1.9%), 3점은 10개. 이미지 〈보기〉 80개 중 표 23·도식 27·삽화 9·글 상자 7. PROGRESS의 '그림 든 〈보기〉 66%/27% 중 일부'에서 그래프 몫은 작다.
2. 종류는 두 가지뿐: 두 양의 관계 평면 8, 시간·위치 진행 6. 변수 짝이 종류를 거의 정한다(시간-지표 6/6 진행, 조건값-반응값 4/4 관계 평면).
3. 개형: 직선 7, 봉우리 7, 그 밖(구간마다 다름·불규칙) 6, 지수 감소·U자·주기·계단 각 1. 포화·S자·반비례 0.
4. 표시 도구: **기준선 10, 교점 8, 기호 눈금 9**(숫자 눈금 5). 이동 1, 구간 화살표 1, 곡선 사이 색칠 0.
5. **지금 형식으로 기출과 똑같이 그릴 수 있는 그래프 0/14.** 막는 것: 기호 기준선·눈금(P₁·M₁ 등), 점 없는 곳의 수직선, 곡선 이름 잘림·겹침, 점 계열, 격자.
6. 모양 성질(보충 2)로 적기: 됨 5 / 성질 더해야 됨 7(값 수준·기준값, 계열 사이 관계 = 같은 시작점·기울기 배수·합·같은 x 정렬) / 못 적음 2(선 없는 점 집합).
7. graphPlan은 기출에서 대체로 채워졌다. 어려운 곳: 계열마다 모양이 달라 shape 한 칸으로 부족(3/4), 모양을 말한 문장이 지문이 아니라 〈보기〉에 있음(1/4).
8. **인용 확인이 필요하다는 측정:** 하위 에이전트가 쓴 관계 문장 인용 14개 중 4개가 지문에 그대로 없었다(줄이거나 풀이를 붙임). 서버의 '인용 실재' 확인이 실제로 걸러 낼 것이 있다.
9. 버그: 가로 눈금 뒤에 단위가 붙어 "M₁M", "t₁t"로 읽힘.

## 2. 해석

- 그래프가 곡선형으로 안 나온 원인은 '축 고르기'(graphPlan이 맡음)와 '그리기 도구 부족'(기준선·기호 눈금·교점) 둘이다. 집계는 뒤쪽이 생각보다 크다는 것을 보여 준다(기출조차 0/14).
- 모양을 서버가 계산하는 일(shape → 점)은 계열 사이 관계까지 넣으면 코드가 커진다. 그래프 〈보기〉가 1.9%인 것을 생각하면 한 번에 다 만드는 것은 과하다.
- 그래서 **효과가 큰 것부터 나눠 한다.** 기출 빈도 순: 기준선·기호 눈금(10·9) → 교점 자동 표시(8) → 곡선 이름 배치 → 모양 계산.

## 3. 최종안 (가)(관계 모양 + graphPlan 칸 + 서버 확인)을 두 단계로

**3-1. 그래프 1차(이번, ④ 2단계 전) — API 비용 없음**
- run.mjs: graph 문항에 **graphPlan** 칸. 칸을 바꿈: `shape`는 **계열마다**(`series[].shape`), `relation`은 인용 **1~2개**, 모양이 지문에 없고 〈보기〉가 주면 `shapeFrom:"보기"`(그 모양은 판정에 안 씀, G3 보충·P2와 같음).
- 서버 확인: 축 이름 = variables.x·y, 인용이 지문에 그대로 있음(공백 정리 후 부분 문자열), series 수·이름 = graphPlan 계열과 같음. 어긋나면 결함 → 1회 재생성.
- render.mjs 도구: ① 기준선(수평·수직, 위치는 값 또는 다른 점에 맞춤, 기호 라벨) ② 기호 눈금(가로·세로) ③ 교점 자동 표시(analyze의 cross에서, 기호는 선택) ④ 곡선 이름 배치(겹침·잘림 피하기) ⑤ 단위 이어붙임 버그. 기존 명세는 출력 바이트 동일.
- 좌표는 지금처럼 points로 쓴다. 다만 '같은 x 정렬'을 쉽게: 기준선이 다른 점에 맞출 수 있게(예: `"at":{"series":"b","point":"peak"}`).
- kind-graph-v6 문안(웹 최종안, 3절 규칙 절차 4단계 결정 대상):
  > 그래프를 쓰기 전에 graphPlan을 먼저 쓴다. 축은 지문이 관계를 말한 두 양이다. 계열의 모양은 지문의 관계 말(방향, 변화 빠르기, 최댓값·최솟값, 어떤 값에 가까워짐, 다른 계열과의 만남·순서)에서 옮긴다. 지문이 모양을 정하지 않았으면 그 모양은 〈보기〉가 주는 측정 결과이고(shapeFrom "보기") 판정에 쓰지 않는다. 기준선·교점은 선지가 부르는 곳에만 둔다.
  - 참고 후보(강제 아님): 시간에 따라 변하는 양은 시간 진행형, 조건값에 따른 반응은 관계 평면에서 봉우리가 흔하다, 가격·수량은 관계 평면의 직선 교점형이 흔하다(집계 1-b).
- 시험: ④ 2단계의 경제 V2(graph). 따로 돌리지 않는다.

**3-2. 그래프 2차(나중, 필요할 때)**
- 서버가 모양 성질에서 점을 만드는 계산(계열 사이 관계·값 수준 포함), 점 계열, 격자, 선 굵기.
- 시작 조건: 3-1 뒤에도 생성 그래프의 모양 결함(손으로 맞춘 좌표 오류, 교점 어긋남)이 평가에서 반복될 때.
