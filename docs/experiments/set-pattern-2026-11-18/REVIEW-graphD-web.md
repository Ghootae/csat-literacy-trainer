## 2. 무엇을 알게 됐나

1. **그래프 쪽(생성 + 그리기)은 됐다.** 옛 B는 문항·그림·선지를 그대로 두고 읽기 판 한 줄("병: ⓔ → ⓑ")만 고쳤는데 0.88 → 2.00(8명 모두 '수능 같음')이 됐다. graphC 때 B의 감점은 전부 렌더러 버그였다. A도 두 번 연속 1.6~1.75. 좌표·교점 결함은 두 실행 모두 0 → **그래프 2차(서버가 모양에서 점 계산)는 필요 없다.**
2. **새 B의 0점은 그래프 문제가 아니라 수리 단계(e4) 문제다.** 수리가 선지 ⑤를 고치면서 발문의 〈보기〉 조건(공급 탄력성 세 시장 모두 1, 균형 거래량 A=B·C=A의 2배 등)을 모두 지웠다. 정답 ②를 정하는 조건이 문항에서 사라져 8명 모두 "정답 확정 불가". 평가 이유 중 그림 탓 0건.
   - 함께 드러난 것: 수리 뒤 재판정이 "결함(다시 생성)"을 냈는데도 최종본이 그대로 남는다(4-3이 재생성을 1회로 막아서 평가에 들어감). 실제 서비스에서는 이 판정이 난 문항이 나가면 안 된다.
   - 이 문제는 그래프 갈래에만 있는 게 아닐 수 있다(수리 단계는 모든 갈래 공통). 그래서 그래프 스레드에서 고치지 않고 따로 넘긴다.
3. **설계 관찰(가로축 탄력성, 점 두 개짜리 직선, 인용은 정의뿐인데 shapeFrom '지문')은 옛 B·새 B 두 번 나왔다.** 하지만 같은 설계의 옛 B가 2.00을 받았다. 평가자는 이것을 깎지 않는다 → **kind-graph 점검 질문은 넣지 않는다.**
