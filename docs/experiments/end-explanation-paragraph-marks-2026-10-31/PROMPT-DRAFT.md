- 바뀌는 곳: ① `[칸과 화면]` 절 교체 ② `[문단과 칠할 곳]` 절 추가 ③ 출력 형식(스키마). 나머지 절(`[말투와 금지]`, `[풀어 쓰기]`, `[재료]`, type별 순서, `[answer]`)은 v1 문장 그대로 둔다.

## ① `[칸과 화면]` — v1 → v2

v1:

> 칸은 화면에서 하나씩 따로 보이고, 학생은 칸마다 버튼을 눌러 넘어간다. 각 칸 앞뒤의 안내 문장과 sectionLeads(칸의 첫 문장)는 화면이 붙인다. 칸은 sectionLeads 바로 다음 문장부터 쓰고, 그 문장이나 선택이 맞았는지를 되풀이하지 않는다. 각 칸은 그 칸만 읽어도 뜻이 통해야 한다. 앞 칸의 설명을 되풀이하지 않는다.

v2:

> 각 칸은 문단 목록으로 쓴다. 화면은 문단을 하나씩 말풍선으로 보이고, 학생은 문단마다 버튼을 눌러 넘어간다. 각 칸 앞뒤의 안내 문장과 sectionLeads(칸의 첫 문장)는 화면이 붙인다. sectionLeads는 그 칸 첫 문단 앞에 붙으므로, 첫 문단은 sectionLeads 바로 다음 문장부터 쓰고 그 문장이나 선택이 맞았는지를 되풀이하지 않는다. 각 칸은 그 칸만 읽어도 뜻이 통해야 한다. 앞 칸의 설명을 되풀이하지 않는다.

## ② `[문단과 칠할 곳]` — 새 절 (`[칸과 화면]` 바로 뒤)

> 문단 하나에는 요점 하나만 담는다. 요점은 학생이 그 말풍선 하나를 읽고 "이걸 알았다"고 말할 수 있는 한 가지다(예: 선지가 하는 말, 원문의 한 가지 설명, 그 설명을 선지에 대어 본 결과). 칸 전체의 요점이 하나뿐이면 문단도 하나다. 문장마다 문단을 나누지 않는다. 한 문단은 보통 두세 문장에서 다섯 문장 정도이고, 한 칸은 보통 한 문단에서 네 문단이다. type별 순서의 번호는 문단 수가 아니다. 짧은 단계는 앞뒤 단계와 한 문단에 묶는다.
>
> 문단마다 mark에 그 문단의 요점이 기대는 원문 한 곳을 적는다. 화면은 그 문단을 보일 때 이 구간을 지문이나 <보기>에서 칠해 학생이 원문 위치를 바로 찾게 한다.
> - location은 지문이면 PASSAGE, <보기>면 SCENARIO다. 선지, 학생 말, 공식 해설은 칠하지 않는다.
> - quote는 원문이나 <보기>에서 이어진 구간을 한 글자도 바꾸지 않고 그대로 옮긴다. 줄이거나 낱말을 바꾸거나 두 곳을 이어 붙이지 않는다. 앞뒤 따옴표는 붙이지 않는다.
> - quote는 그 문단의 요점을 가장 직접 뒷받침하는 구간이다. 길이는 구절 하나에서 문장 하나까지로 한다. 그 구간이 원문에서 한 번만 나오도록 충분히 길게 잡는다.
> - 문단이 원문이 아니라 학생 말, 선지의 말, 내 짐작, 앞 내용의 정리에 기대면 mark는 null이다. 칠할 곳을 억지로 찾지 않는다.
> - 같은 구간을 여러 문단에서 칠해도 된다.

## ③ 출력 형식

v1: `{ firstChoice: string, reselection: string | null, answer: string }`

v2:

```
{
  firstChoice: Paragraph[],          // 1개 이상
  reselection: Paragraph[] | null,   // 다시 고른 선지가 있을 때만
  answer: Paragraph[]                // 1개 이상
}
Paragraph = { text: string, mark: { location: 'PASSAGE' | 'SCENARIO', quote: string } | null }
```
