# 1단계 mRNA 19번 문제 시뮬레이션 결과 (2026-10-29)

- 12세션(계획 10 + 재확인 2), 호출 29(luna 19, sol 10), 비용 $0.4139. 판정 v5.6, 마지막 설명 레이아웃 v1. 세션별 기록: [SESSIONS.md](./SESSIONS.md).
- 학생 역할·검토: Opus 하위 에이전트(이 파일은 에이전트 보고를 Claude가 옮겨 적음, 에이전트가 파일 쓰기 규칙에 막힘). prob-1·prob-11의 `holds` 차이(false/true)와 학생이 받은 문장 차이는 Claude가 원기록으로 재확인.

## 요지

판정기의 판단은 대체로 원문과 맞고, 마지막 설명 9개 모두 학생이 실제 쓴 오해를 다뤘다. 문제는 그 사이: 교정 질문이 정답 표현을 보기로 주는 양자택일이고, 판정 뒤 코드 문장과 서버 재계산 결론이 판정기와 어긋난다.

## 가장 중요한 발견

1. **같은 근거가 세션마다 "정확"과 "연결 부족"으로 갈린다(prob-1 vs prob-11).** 근거 "ph 높이면 … 중성됨 -> 전하 없어지니까 소수성은 오히려 강해짐 …". 판정기 출력은 둘 다 INSUFFICIENT, 다른 칸은 `judgment.holds`(false/true)뿐. 서버 `settleConclusion`(`feedback-claims.ts`)이 prob-11에서 holds로 SUPPORTED로 바꿔 "근거도 정확해. 잘 풀었어."가 나갔고(재확인), prob-1은 "더 이어야 할 연결을 같이 채워 볼게"(재확인). 저장 reason은 "충분하다고 볼 수 없다"로 남아 기록 안에서도 모순. 서버는 중간 추론 2개의 UNDETERMINED를 보지 않는다. 원문 3문단이 "전하를 띠는 물질, 즉 친수성 물질"이라 정의하므로 이 추론은 원문상 맞다고 봄 → prob-1의 "알 수 없어 … 글은 소수성 변화를 설명하지 않아"를 A1·D2(확신 중간). 반면 "지문에 없음" 근거는 3번 모두 "근거도 정확해".
2. **교정 질문 6/6이 "A야, B야?" 양자택일.** prob-10: 학생이 "완전 중성까진 모르겠음"이라 했는데 질문 "양전하를 유지해, 전기적으로 중성이 돼?" → "중성 되나 봄" → "핵심 오류를 잘 고쳤어". prob-5 "중성 됨" 세 글자로 통과.
3. **게이트 문장이 판정기 구분을 버린다(`problem-feedback.ts` 222~233행 분기).** prob-7(② 오답): 판정기 "판단 경로 확인됨"인데 화면 "어떻게 판단했는지 다 알기 어려웠어 … 짐작하지 않고". prob-9: 학생 "잘 모르겠음", 판정기 UNCONFIRMED인데 화면은 틀린 답과 같은 "방금 답도 정확하지 않았어". prob-2~4: 짐작 근거에도 "맞는 부분은 살리고, 더 이어야 할 연결".

## 일반 규칙 수정 후보 (에이전트 제안, Claude 검토 전)

1. 교정 질문에 정답 표현을 보기로 주지 않는다. 지문을 다시 읽어야 답할 수 있는 열린 질문. 질문의 보기 하나만 고른 답을 '고침'으로 인정할지 함께 검토.
2. 게이트 문장이 판정기 구분을 따른다(코드 분기): 오답도 경로 파악 여부로 나눔, 교정 실패는 '모름'·'고집' 구분, 부족한 정답은 '판단 방법'·'연결 부족' 구분.
3. 서버가 판정기 결론을 뒤집을 때: 중간 추론에 UNDETERMINED가 있으면 holds 하나로 SUPPORTED 주지 않음, 뒤집으면 검토 표시, reason도 맞춤.
4. 원문 정의를 한 단계 적용한 추론을 '원문과 맞음'으로 볼지 하나로 정함(설계 판단, 확신 중간). q19 해설 보강 여부 확인.
5. 오류 가설을 하나로 못 정해도 학생 문장에 오해가 드러나면 교정 질문(prob-7).
