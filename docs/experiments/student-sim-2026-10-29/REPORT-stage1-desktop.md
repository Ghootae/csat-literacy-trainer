## 해석
1. 0단계 발견 중 '질문 흘림'이 두 화면 모두에서 가장 크고 흔하다. 문단은 v4.8 질문 규칙 5번("학생 말에서 출발해 빠진 고리만")과 판정의 합쳐 읽기("답을 질문과 합쳐 읽는다")가 겹쳐, 질문이 준 관계 요소를 학생 몫으로 센다. v4.7에서도 흘림 사례가 있었으므로(0단계) v4.8만의 원인은 아니나, 규칙 5번이 질문 안에 학생 말+단서를 넣게 만들어 늘렸을 가능성(미검증).
2. 어제(10-28) 고친 방향(너무 엄격 → 재질문)과 반대 방향(질문 뒤 너무 너그러움)이 더 흔하다. 두 방향을 함께 다루는 기준이 필요: "학생이 쓴 것은 다시 묻지 않는다" + "질문이 준 것은 학생 몫으로 세지 않는다".
3. 문제 쪽 판정기 판단은 대체로 맞고, 어긋남은 코드 층(게이트 문장 분기 `problem-feedback.ts` 222~233, 결론 재계산 `settleConclusion`)에 몰려 있다. 코드 수정 범위.
4. 외국어 출력은 빈도 1/104지만 치명적이고 코드 검사로 확실히 막을 수 있다.

## 수정 후보와 권고 순서
1. (코드, 확실) 학생에게 나가는 모델 문장 한글 검사 → 실패면 재요청. 문단·문제 공통.
2. (코드, 확실) 문제 게이트 문장 분기가 판정기 구분(경로 파악 여부, 모름·고집, 판단 방법·연결 부족)을 따르게.
3. (지시문, 주 과제) 질문 흘림: 문단 v4.9(질문이 준 내용은 학생 몫 아님, 합쳐 읽기는 생략된 주어·대상 이어받기만, 질문에 학생이 쓰지 않은 관계 요소 금지, 개념어 하나로 답 가능한지 자기 점검), 문제 v5.7(교정 질문 양자택일·정답 표현 금지). 검증은 이번 도구로 같은 유형 재실행(전후 비교).
4. (설계 판단 필요) `settleConclusion`: 중간 추론 UNDETERMINED일 때 holds만으로 SUPPORTED 금지 여부 + "원문 정의를 한 단계 적용한 추론"을 맞음으로 볼지.
5. (설계 판단, 나중) 같은 문단 핵심 부분 세션 간 고정(컨트롤러가 골드를 일부러 읽지 않는 설계와 충돌).
