# 문단 전체 판정 그림자 실험 — 목적, 과정, 결과 (토론용 정리)

작성: 2026-10-08, Claude. 이 프로젝트의 이전 대화를 모르는 독자도 읽을 수 있도록 맥락을 모두 담았다.

- **사실과 의견의 구분:** 측정값과 사람 판정은 저장소 기록에서 옮겼다. 해석은 "Claude 의견"으로 표시했다.
- **원자료:** `docs/experiments/holistic-verdict-shadow-2026-10-08/`의 `REPORT.md`, `summary.json`, `comparisons.json`, `REVIEW.md`, `PROBE-REVIEW.md`

## 1. 배경

### 제품

수능 국어 독서 지문을 문단 단위로 읽고, 학생이 각 문단을 요약하면 AI가 판정해 필요할 때만 질문하는 학습 도구다. 학생이 충분히 이해했는데 질문을 받는 일(FA, false alarm)은 이탈의 원인이 된다. 그래서 **FA 회피를 miss(이해가 부족한데 통과) 회피보다 우선**한다.

### 현재 운영 판정기 V4 (`axis-dialogue-selective-v4`)

- 문단마다 사람이 검토한 골드(gold-v2)에 **중심축**(AX1, AX2, …)이 1~3개 있다. 각 축은 문단의 핵심 관계 하나를 한 문장으로 쓴 것이다.
- V4는 학생의 누적 응답을 **축마다** 판정한다.

| 상태 | 뜻 | 행동 |
|---|---|---|
| PASS | 그 축의 의미를 확인 | 없음 |
| UNCLEAR_OK | 중심 관계는 드러났고 일부만 미확인 | 질문하지 않는다. PASS로도 기록하지 않는다 |
| UNCLEAR_SERIOUS | 소재만 있거나 중심 관계의 근거가 크게 부족 | 질문 |
| ERROR | 학생이 유지하는 명시적 왜곡 | 질문 |

- 축이 하나라도 SERIOUS나 ERROR면 질문 후보가 된다.

### 문제 제기

- **축 경계가 불안정하다.** 축을 자동으로 생성·감사하는 실험을 여러 번 했는데, 같은 입력에서도 실행마다 축 경계가 흔들렸다. 사례별로 규칙을 고치다 보니 같은 25문단에 과적합하는 문제도 생겼다(그 작업은 중단했다).
- **문제 풀이 쪽은 이미 축 없이 판정한다.** 문제 풀이 피드백은 2026-09-08부터 구조화 골드 없이 원문, 정답, 공식 해설만으로 판정한다.
- **가설:** 축마다 coverage를 끝까지 확인하려는 구조가 "이해했는데 확인이 안 끝나는 학생"을 만들어 FA를 낳는다.
- **제안:** Codex, GPT, Claude와의 논의에서 "축을 채점 좌표계에서 내리고, 문단 전체를 한 번 판정하자"는 제안이 나왔다.
  - 정확한 가설은 "골드 없이"가 아니라 **"구조화된 분절 없이"**다.
  - 반론으로 나온 위험은 네 가지였다.
    - 포섭 판정의 불안정이 응답마다 옮겨 간다.
    - 기준점이 없으면 모델이 학생 답에 맞춰 핵심을 재정의한다.
    - 유창한 답을 과대 인정한다.
    - 다회 대화에서 기준이 움직인다.

## 2. 목적

**질문: 축별 확인을 통과의 필수 조건으로 두지 않아도 판정이 잘 되는가?**

- V4는 그대로 둔다.
- 같은 학생 응답에 **문단 전체 판정**(그림자)을 오프라인으로 덧붙여 실행한다.
- 두 판정이 갈리는 시점을 사람이 판정한다.
- 운영, UI, 학생 기록은 바꾸지 않는다.

실험 설계 도중, 실데이터로 잴 수 있는 범위가 생각보다 좁다는 것을 알게 됐다.

- **실데이터 → 비열등성:** 실제 응답 72시점 가운데 V4가 질문 후보로 본 시점이 8개뿐이다. 그래서 실데이터로는 "그림자가 V4보다 더 많이 묻지 않고, 오류를 놓치지 않는가"만 볼 수 있다.
- **탐침 → FA 감소 여부:** FA 감소(V4는 묻는데 그림자는 통과시키고, 그 판단이 옳은 경우)는 주로 일부러 만든 탐침 응답으로 본다.

## 3. 설계

### 그림자 판정의 두 변형

| 변형 | 입력 |
|---|---|
| H0 (순수) | 문단 원문, 지문 전체, 학생 발화 |
| H1 (참조 해석) | H0에 **참조 해석**을 더함. gold-v2 축 설명을 축 번호 없이 이어 붙인 2~4문장 산문 |

- 축 정보는 전체 판정에 넣지 않는다. 그림자가 미해결로 판정한 경우에만, 별도 호출로 공백을 축 ID에 귀속한다(기록용).
- 판정 질문: "학생의 발화 전체만 읽은 사람이 대상 문단의 중심 관계를 재구성할 수 있는가?"
- 지시문의 핵심:
  - 세부가 빠지거나 압축·상위어로 묶여도 핵심을 이해했으면 충분하다.
  - 순서와 표현은 묻지 않는다.
  - 유창함이나 핵심 단어 수만으로 충분하다고 보지 않는다. 관계의 방향·주체·조건을 본다.
  - 소재 나열은 불충분하다.
  - 애매하면 resolved로 판정한다(FA 회피).
  - 학생이 받은 교사 질문은 대화 맥락일 뿐 판정 기준이 아니다.
- 출력: `overall`(resolved/unresolved), `understoodRelations`, `brokenRelation`(설명, 학생 발화의 정확한 인용, 종류: missing / incorrect / inter-axis-relation), `unconfirmed`, `questionWorthy`, `question`, `confidence`
- 코드 계약:
  - 인용은 학생 발화의 정확한 부분 문자열이어야 한다.
  - resolved이면 brokenRelation과 question이 없어야 한다.
  - incorrect이면 인용이 있어야 한다.
  - 위반하면 재시도 없이 실패로 기록한다.
- **철회 규칙:** V4는 해결로 봤는데 그림자만 미해결로 봤고, 인용할 학생 발화가 없으면 그림자 판정을 해결로 바꾼다(FA 회피 정책).

### 비교 단위

- V4는 문단 수준으로 요약한다. 모든 축이 PASS 또는 UNCLEAR_OK면 "해결", 하나라도 SERIOUS나 ERROR면 "미해결(질문 후보)"이다.
- 시점마다 네 칸으로 나눈다: V4 해결/미해결 × 그림자 해결/미해결.

### 데이터

| 출처 | 시점 | 최초 / 후속 | V4 판정 |
|---|---:|---|---|
| A: 09-21 실험의 실제 입력 | 45 | 31 / 14 | 09-21에 같은 골드·모델로 재판정 |
| B: 운영 로그의 V4 세션(9-22, 9-29) | 27 | 14 / 13 | 당시 운영 실시간 판정 |
| 탐침 | 13 | 13 / 0 | 이번에 고정 V4 요청으로 새로 판정 |

- **응답자:** 모두 **개발자 1인**이다. 골드와 지문에 익숙하다.
- **문단 분포:** 공손룡 지문이 실데이터 72시점 중 28시점이다.
- **같은 기준:** A와 B 모두 gold-v2와 `gpt-5.6-terra` medium을 썼다. B의 골드 해시가 A와 같은 것을 확인했다.
- **후속 시점의 입력:** 최초 응답 → 학생이 받은 V4 질문 원문 → 학생 답을 순서대로 넣었다. 질문에는 "대화 맥락, 판정 기준 아님"이라고 표시했다. V4가 합성한 누적 응답은 넣지 않았다. V4 판정이 섞여 있기 때문이다.
- **후속 시점의 한계:** V4 질문이 V4가 본 공백을 드러내므로, 그림자 판정이 V4 쪽으로 끌릴 수 있다. 그래서 후속 시점은 진단용으로만 썼다.
- **독립 판정:** 모든 시점을 독립적으로 판정했다. 이전 그림자 판정은 다음 시점에 넘기지 않았다. 학생의 실제 후속 답은 V4 질문에 대한 답이기 때문이다.

### 탐침 13개

- Claude가 쓰고, 사용자가 **원문만 보고 블라인드로** 판정한 뒤 해시로 고정했다. 유형과 의도는 별도 파일에 숨겼다.
- **문단:** 공손룡2, 법인2, 도파민2, 정보 비대칭1, 표면 장력5
- **FA 표적 8개:** 축 기반이면 SERIOUS가 날 법하지만 충분할 수 있는 답이다.
  - 배경 축을 빼고 중심 주장만 쓴 답
  - 여러 축을 압축하거나 상위어로 묶은 답
  - 축 순서와 다른 구조로 쓴 답
- **대조 5개:** 관계가 뒤집힌 답 3개, 소재만 나열한 답 1개, 막연한 답 1개
- **고정 전 정정:** 사용자의 판정 두 개가 원문과 어긋나 보여 Claude가 짚었고, 사용자가 고쳤다. T13 충분→오류(방향을 뒤집은 답), T05 오류→충분. 이 두 탐침은 블라인드가 일부 깨졌다.

### 사람 판정

- **대상:** 실데이터에서 H0나 H1이 V4와 갈린 시점 전체(11개)와, 일치한 시점에서 고른 표본 9개. 모두 20시점이다.
- **블라인드:** 원문과 학생 발화만 보여 주는 순서로 만들었다. 모델 결과, 축, 출처는 판정 뒤에 공개했다.
- **판정 칸:** 충분 / 미확인 / 오류, "질문 필요 여부", 메모
- **동의의 정의:** 갈린 시점에서 사람의 "질문 필요"가 어느 판정기의 행동과 같은가로 정한다.

### 사전에 고정한 성공 판정 규칙 (실행 전 확정)

- **V4 유지:** 실데이터 최초 45시점에서 다음 중 하나면 V4를 유지한다.
  - 갈림이 5개 미만이다. 단, 탐침에서 FA 감소가 "뚜렷"하면 보류한다.
  - 갈린 시점에서 사람이 V4 쪽에 더 자주 동의한다.
- **운영 후보:** 다음 네 조건을 모두 넘어야 한다.
  1. 갈린 시점에서 사람이 그림자 쪽에 3분의 2 이상 동의한다.
  2. 사람이 오류로 본 시점 가운데, V4는 잡았는데 그림자가 놓친 경우가 0건이다.
  3. FA 방향 갈림(V4 미해결, 그림자 해결, 사람이 질문 불필요로 판정)이 6개 이상이다.
  4. 3회 반복 실행에서 그림자 판정이 90% 이상 일치한다.
- **"뚜렷하다":** 사람이 충분·질문 불필요로 본 FA 탐침 7개 중 V4 미해결·그림자 해결이 4개 이상이고, 오류 탐침 3개를 그림자가 모두 잡는 경우다.
- **최대 결론:** 조건 3을 못 채우면 최대 결론은 "비열등 확인, FA 효과 미확인"이다.
- **1회 실행의 한계:** 1회 실행 뒤에는 조건 4를 볼 수 없다.
- 이 기준은 통계 검정이 아니라 방향을 정하는 기준이다.

## 4. 과정 (시간순, 주요 판단과 정정 포함)

1. **지시서 해석 정정:** 지시서의 "V4"를 사용자는 처음에 축 생성 실험(두 단계 생성 v3)으로 봤다. Claude가 확인해 보니 운영 판정기였다. 축은 V4 판정이 쓴 gold-v2를 쓰기로 했다. 다른 축을 쓰면 판정 방식의 차이와 축의 차이가 섞이기 때문이다.
2. **데이터 확정:** 지시서는 운영 로그를 지정했지만, 로그에서 V4 판정이 담긴 세션은 15개뿐이었다. 09-21 재판정 45시점과, 그 이후의 14세션을 합쳤다. Claude가 14세션을 처음에 41시점으로 잘못 셌다가 27시점으로 바로잡았다(합계 86 → 72).
3. **1차 실행 범위:** 처음 설계는 3회 반복이었다. 사용자가 "1회 먼저, 나머지 2회는 결과를 보고"로 정했다.
4. **독립 검토 반영:** 다른 Claude 인스턴스가 계획을 검토했다. 반영한 의견은 다음과 같다.
   - 탐침에도 V4 판정을 돌린다.
   - 실데이터로는 FA 감소를 거의 못 잰다는 점을 목적에 명시한다.
   - 임계값은 최초 시점에만 적용한다.
   - FA 방향 갈림 최소 6개 조건을 둔다.
   - 며칠 뒤 사람 재판정으로 경계 사례를 분리한다.
   - H1은 기계적 연결을 유지한다.
   - 검토안의 "탐침을 실데이터와 같은 분모에 넣는다"는 받아들이지 않았다. FA 표적으로 만든 답이라 비율이 부풀기 때문이다.
5. **탐침:** 사용자가 한 번 뺐다가 다시 넣었다. 작성 주체도 "사용자 작성"에서 "Claude 작성, 사용자 블라인드 판정"으로 바꿨다. 사용자가 축을 알고 쓰면 판정이 오염되기 때문이다.
6. **구현:** Codex가 했다. Codex는 계획서와 인계 문서의 출력 스키마가 다른 것을 발견하고 구현 전에 멈췄다. Claude가 계획서를 맞춘 뒤 다시 실행했다. Claude 검토에서 실행을 막을 수 있는 고정 범위 문제 두 가지를 고쳤다.
   - 운영 로그 전체 해시를 고정하던 것을 선택한 줄의 해시로 바꿨다.
   - 결과 기록용인 계획서를 고정 대상에서 뺐다.
7. **실행:** 사용자 전송 승인 뒤 1회 실행했다.
8. **사람 판정:** 사용자가 20시점을 판정했다. "충분이면서 질문 필요: 예"였던 두 시점(R006, R012)은 입력 실수로 확인돼 "질문 불필요"로 정정했다.

## 5. 결과

### 실행

- **호출:** 220회. 그림자 170, 탐침 V4 13, 축 귀속 37.
- **계약 실패:** 0건, 재시도 0회
- **비용:** 약 $1.54
- **지연:** 그림자 1회 중앙값 약 3.4초. V4 판정은 1회 약 7.5초였다(09-21 기록).

## 6. 해석 (Claude 의견)

1. **이 데이터에서 V4는 이미 조용했다.** 실데이터 72시점 중 V4가 질문 후보로 본 시점이 8개다. UNCLEAR_OK가 "묻지 않음"을 이미 구현하고 있어서, 전체 판정으로 바꿔도 줄일 FA가 많지 않다. "축 coverage 확인이 FA를 낳는다"는 가설은 적어도 이 응답자의 데이터에서는 크게 드러나지 않았다. 다만 응답자가 골드 구조에 익숙한 개발자라서 FA가 원래 적게 나올 조건이었다.
2. **V4의 FA는 ERROR 쪽에서도 나왔다.** 사람 기준으로 V4의 불필요한 질문 4개 가운데 2개(R011, R012)가 ERROR였다. 사소한 표현 오류나 부수적 세부 오류를 명시적 왜곡으로 격상한 사례다. FA를 줄이려면 판정 구조보다 ERROR 문턱이 더 직접적인 대상일 수 있다.
3. **참조 해석(H1)은 FA를 늘렸다.** H1은 FA가 6개로 가장 많았다(R009, R012, R014, R017, R018, R019). 축 문장을 산문으로 주면 모델이 그 문장들을 사실상 체크리스트로 쓰는 것으로 보인다. 지시문에 "체크리스트로 쓰지 말라"고 했는데도 그랬다. "골드를 산문 참조로만 유지한다"는 대안은 이 결과로는 지지되지 않는다. 1회 실행이라 변동일 가능성도 있다.
4. **그림자는 막연한 답에 관대했다.** 탐침 T02와 T04는 사람이 "질문 필요"로 봤는데 그림자(H0·H1 모두)는 통과시켰다. "애매하면 resolved" 지시와 축이라는 기준점이 없는 구조가 겹친 결과로 보인다. 위험 목록의 "핵심 재정의"와 "과대 인정"이 일부 나타난 것이다. 반대로 R015와 R016(후속)에서는 V4가 놓친 막연한 답을 그림자가 잡았다. 방향이 일관되지 않다.
5. **명백한 오류는 둘 다 잡았지만, 오류 탐지의 안전성은 확인되지 않았다.** 관계를 뒤집은 탐침 3개는 모두 잡았다. 하지만 실데이터에서는 "원문과 다른 주장"과 "질문할 만큼 중요함"을 따로 판정하지 않았다. R012(허가와 보고의 혼동)처럼 부수적 오류가 섞인 답에서 그림자가 오류를 인식하고도 질문하지 않은 것인지, 인식하지 못한 것인지 구분할 수 없다.
6. **표본이 결론을 받치기에는 작다.** 갈린 시점이 3~5개이고, 사람 판정자가 1명(재판정 전)이며, 1회 실행이다. 방향을 보는 데이터지 효과 크기를 재는 데이터가 아니다.
