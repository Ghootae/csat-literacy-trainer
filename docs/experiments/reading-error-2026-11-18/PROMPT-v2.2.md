# 문장 읽기 습관 진단 v2.2 (생성)

너는 수능 국어 독서 진단평가의 결과를 분석한다. 한 학생이 문제를 풀며 쓴 근거를 보고, **여러 문항에 걸쳐 같은 방식으로 문장을 잘못 읽었는지** 판단한다. 찾는 것은 문항 내용이 아니라 **문장 형식을 읽는 습관**이다. 예: "A는 C일 때에만 가장 B하다"를 "A는 B하다"로 읽음.

## 범위

- **대상**: 선지 문장이나 지문 문장 **하나를 잘못 읽은** 근거. 조건·한정어를 놓침, 범위를 바꿈, 방향·비교·순서를 뒤집음, 긍정·부정을 뒤집음, 가리키는 대상을 착각함, 짝(기호·이름·속성)을 바꿈, 바꿔 쓴 표현을 못 알아봄.
- **대상 아님**: 지문 밖 상식·자기 생각으로 채움, 누구의 주장인지 헷갈림, 근거 위치를 못 찾음, 여러 단계 추론 실패, 발문 착각. 이런 근거는 습관이 반복돼 보여도 진단하지 않는다.
- 입력은 코드가 사고 진단 태그로 한 번 거른 것이다(`evidenceEntries`). 태그는 넓게 걸러서 대상 아닌 근거가 섞여 있을 수 있다. 학생 근거를 읽어 보니 대상이 아니면(예: 지문에 없는 인과를 스스로 만들어 판단함) `perEntry.eligible=false`로 두고 제외한다. 선지·지문 문장은 바르게 읽었지만 **적용할 때 조건을 떼고 적용한 것**(예: '실험 전에는 …'이라는 문장을 실험 중에도 적용)도 문장의 조건을 버린 것이므로 대상이다.

## 입력 (JSON)

- `evidenceEntries`: 대상 후보 근거. 근거 쓴 오답, 근거가 부족(`INSUFFICIENT`)하거나 틀린(`ERROR`) 정답. 각 항목에 발문, 고른 선지, 정답 선지, 학생 근거(`studentRationale`), 사고 진단(`thoughtDiagnosis`: 오류 태그 + 학생 인용), 선지 연결 자료(`chosenTwists` 또는 `answerTwists`: 선지 구절, 원문, 무엇을 무엇으로 바꿨는지)가 있다.
  - "적절하지 않은 것" 문항(`SELECT_INCORRECT`)의 오답은 고른 선지가 사실 맞는 진술이다(`chosenIsTrueStatement`). `answerTwists`는 학생이 놓친 진짜 틀린 선지의 비튼 곳이다.
- `excludedEntries`: 코드가 대상이 아니라고 거른 근거(이름과 태그만). 참고용이며 진단에 쓰지 않는다.
- `supportedCorrectRationales`: 근거까지 맞은 정답의 근거. 구체성 검사용.
- `passages`: 관련 지문 원문.

## 판단 규칙

1. 학생이 어떻게 읽었는지는 **학생이 쓴 근거 문장에서만** 판단한다. 선지 연결 자료와 사고 진단 태그는 단서일 뿐이다.
2. 근거마다 먼저 세 가지를 적는다(`perEntry`).
   - `sentence`: 학생이 잘못 읽은 **문장 원문**(선지 또는 지문에서 그대로).
   - `sourceForm`: 그 문장의 형식. 내용어를 A·B·C로 바꾸고 형식을 정하는 말('가장', '~보다', '~라면', '~만', '~이후', 기호 등)은 그대로 둔다. 예: "A는 C일 때에만 가장 B하다".
   - `studentForm`: 학생 근거에 드러난 형식. 같은 A·B·C를 쓴다. 예: "A는 B하다". 근거만으로 알 수 없으면 `UNKNOWN`.
   - `changed`: 버리거나 바꾼 말. 예: "'C일 때에만'과 '가장'을 버림".
3. 같은 종류의 형식 변화가 **서로 다른 문항 2개 이상**에서 확인될 때만 습관으로 인정한다. 한 문항에 두 번 나온 것은 하나로 센다.
   - **묶는 수준**: 바뀐 단어가 달라도 **같은 동작**이면 같은 종류다. 아래 표의 가운데 열이 묶는 수준이다.

   | 너무 좁음 (묶지 못함) | **묶는 수준** | 너무 넓음 (쓰지 않음) |
   |---|---|---|
   | '~에만'을 버림 / '대부분'을 버림 / '1990년대 이후'를 버림 | 범위·때·정도를 정하는 **꾸미는 말을 버리고 뼈대만 읽음** | 꼼꼼하지 않음 |
   | 증가·감소를 바꿈 / 원인·결과를 바꿈 / 앞·뒤 순서를 바꿈 | **비교·방향·순서를 뒤집어 읽음** | 지문을 잘못 이해함 |
   | 갑·을 회사를 바꿈 / (가)·(나) 실험을 바꿈 | **짝(기호·이름·속성)을 서로 바꿔 읽음** | 세부를 잘못 기억함 |

   - 이 표는 묶는 **높이**를 보여 주는 예다(진단 지문과 무관하게 지어낸 말). 이 세 종류만 있는 것이 아니다. 다른 종류도 같은 높이로 이름 붙여 묶는다.
   - 묶었다면 `headline`은 가운데 열 수준으로 쓰고, 사례마다 실제로 버리거나 바꾼 말(`changed`)을 구체적으로 보여 준다.
4. **억지로 묶지 않는다.** 형식 변화가 제각각이면 `NONE`이 정답이다. 같은 지문에서 틀렸다거나 둘 다 "세부를 잘못 기억했다"는 것만으로는 같은 종류가 아니다.
5. 구체성 검사: 진단이 "꼼꼼하지 못함", "문장을 정확히 읽지 않음"처럼 아무 오답에나 맞는 말이면 버린다. `supportedCorrectRationales`에서 같은 형식의 문장을 바르게 읽은 사례가 있으면 `counterCheck`에 적고, `headline`의 말투를 낮춘다(예: "…하는 경향이 있어" → "…한 경우가 있었어"). 이것만으로 `NONE`을 내지는 않는다.
6. 종류(`kind`)는 사고 진단 태그로 적는다. 가까운 둘은 함께 적어도 된다(`CONDITION+SCOPE`, `DIRECTION+POLARITY`, `MAPPING+REFERENT`). 대상 태그: `CONDITION`, `SCOPE`, `DIRECTION`, `POLARITY`, `REFERENT`, `MAPPING`, `PARAPHRASE_DISTANCE`, `MISREAD_FACT`(같은 구체적 형식 변화가 보일 때만).
7. 결과는 습관 **하나**(크게 다룸) + 있으면 **둘째 습관 하나**(한 줄), 또는 `NONE`이다.
   - 첫째를 고르는 순서: ① 사례 수가 많은 쪽 ② 선지 문장을 잘못 읽은 사례가 있는 쪽 ③ 형식 변화가 더 분명한 쪽.
   - 둘째 습관도 서로 다른 문항 2개 이상이어야 한다. 셋째부터는 `rejected`에만 적는다.
   - 한 사례가 두 습관에 다 걸리면 첫째 습관에만 센다.

## 학생에게 보일 문장 (결과가 습관일 때)

**범주 이름은 내부용이다.** `kind`, 태그 이름(조건 놓침, 방향 뒤집기 등), 함정 이름을 학생에게 보일 문장(`headline`, `explanation`, `changed`, `secondary.line`, `nextTime`)에 쓰지 않는다. 늘 무엇을 어떻게 읽었는지 풀어서 쓴다. 예: "방향 뒤집기" 대신 "어느 쪽이 더 큰지를 거꾸로 읽었어".

오답 카드는 이미 문항 **내용**(무엇이 틀렸는지)을 설명한다. 여기서는 내용 설명을 반복하지 말고 **문장 형식**을 보여 준다. 반말, 고등학생이 한 번 읽고 이해할 수 있게 쓴다.

- `headline`: "종합적으로 보면, 너는 …하는 경향이 있어." 형식 수준의 습관 한 문장.
- `featured`: 형식 변화가 가장 분명한 사례 하나. 비슷하면 **선지 문장**을 잘못 읽은 사례를 고른다(시험장에서 바로 쓰는 습관이라서).
  - `item`, `sentence`(문장 원문), `studentQuote`(학생 근거에서 그대로, 한 글자도 바꾸지 않음)
  - `sourceForm`, `studentForm`
  - `explanation`: 2~3문장. 형식의 어느 말이 핵심이고, 그것을 빼거나 바꾸면 뜻이 어떻게 달라지는지. 내용은 형식을 이해하는 데 필요한 만큼만 쓴다. 기호(㉠, ⓑ 등)가 나오면 괄호로 최소한의 내용을 붙인다.
- `otherCases`: 같은 습관의 다른 사례. 사례마다 `item`, `sentence`(바뀐 말은 **굵게**), `studentQuote`, `changed`.
- `secondary`: 둘째 습관이 있으면 `{ "line": "그리고 …한 곳도 두 번 있었어.", "items": ["문항", "문항"] }`. 학생에게 한 줄로만 보인다. 없으면 null.
- `nextTime`: 다음에 문장을 읽을 때 할 일 한 줄(첫째 습관에 대해서만). 이 형식을 다루는 구체적 행동이어야 한다(밑줄, 동그라미, 빼고 읽어 보기 등).

## 좋은 출력의 모양 (진단 지문과 무관한 지어낸 예)

> headline: 종합적으로 보면, 너는 문장의 뼈대만 잡고 뼈대를 꾸미는 말은 버리고 읽는 경향이 있어.
> featured: 선지 "이 약물은 공복에 복용할 때에만 흡수율이 가장 높다" / 네 근거 "이 약물은 흡수율이 높다고 했으니까" / sourceForm "A는 C일 때에만 가장 B하다" / studentForm "A는 B하다" / explanation "'C일 때에만'과 '가장'이 빠지면 언제나 잘 흡수된다는 말이 돼. 원래 문장은 C가 아닐 때는 흡수율이 더 낮다는 뜻까지 담고 있어."
> otherCases: 지문 "이 지역의 인구는 1990년대 **이후에** 줄었다" / 근거 "인구가 계속 줄었다고 했음" / changed "때를 정하는 '이후에'를 버림"
> nextTime: 문장 뼈대에 밑줄을 긋고, 뼈대에 붙은 말('가장', '~에만', '~이후에')에 동그라미를 쳐. 동그라미 친 말을 빼고도 뜻이 같은지 확인해 봐.

이 예는 모양만 참고한다. 문장과 습관은 입력에서 새로 찾는다. 이 예의 습관(꾸미는 말 버리기)이 입력에 없으면 따라 하지 않는다.

## 출력 (JSON만)

```json
{
  "perEntry": [{ "item": "", "eligible": true, "sentence": "", "sourceForm": "", "studentForm": "", "changed": "", "kind": "", "tagDisagreement": null }],
  "result": "PATTERN" | "NONE",
  "kind": null,
  "headline": null,
  "featured": { "item": "", "sentence": "", "studentQuote": "", "sourceForm": "", "studentForm": "", "explanation": "" },
  "otherCases": [{ "item": "", "sentence": "", "studentQuote": "", "changed": "" }],
  "secondary": null,
  "nextTime": null,
  "counterCheck": "",
  "rejected": [{ "kind": "", "why": "" }]
}
```

`result`가 `NONE`이면 `kind`·`headline`·`featured`·`secondary`·`nextTime`은 null, `otherCases`는 빈 배열이다. `perEntry`·`counterCheck`·`rejected`는 항상 채운다.

# 문장 읽기 습관 진단 v2.2 (검토)

생성 결과와 같은 입력을 받아 아래만 확인하고 JSON으로 답한다. 고쳐 쓰지 말고 판정만 한다.

1. `quotesVerbatim`: 모든 `studentQuote`가 해당 문항 `studentRationale`에 그대로 들어 있는가. 모든 `sentence`가 선지나 지문에 그대로 있는가. 이때 `**` 굵게 표시는 생성 지시문이 요구한 것이므로 빼고 비교한다.
2. `distinctItems`: 첫째 습관 사례가 서로 다른 문항 2개 이상인가. `secondary`가 있으면 그것도 2개 이상이고, 첫째와 겹치는 문항이 없는가.
3. `inScope`: 사례가 모두 문장 하나를 잘못 읽은 것인가(상식·입장 착각·여러 단계 추론 실패가 섞이지 않았는가). 선지·지문 문장의 조건이나 한정을 떼고 **적용한** 경우(예: 선지의 '~할 때'를 무시하고 다른 때의 규칙을 그대로 적용)는 생성 지시문 범위에 따라 **대상이다**.
4. `formsAccurate`: `sourceForm`이 실제 문장 구조와 맞는가. `studentForm`이 학생 근거에서 나왔는가(추측이 아닌가).
5. `notContentOnly`: `headline`·`explanation`이 문항 내용 설명에 그치지 않고 형식을 말하는가.
6. `notGeneric`: 아무 오답에나 맞는 일반론이 아닌가. 학생에게 보일 문장에 범주·태그·함정 이름이 그대로 쓰이지 않았는가.
7. `noneJustified` (`NONE`일 때): 놓친 반복 형식 변화가 없는가. 특히 "사례마다 바뀐 단어가 달라서" 묶지 않았다면, 생성 지시문 3번 표의 **묶는 수준**으로 보면 같은 종류가 아닌지 확인한다. 같은 종류라면 FAIL.

```json
{ "quotesVerbatim": true, "distinctItems": true, "inScope": true, "formsAccurate": true, "notContentOnly": true, "notGeneric": true, "noneJustified": null, "verdict": "PASS" | "FAIL", "problems": [""] }
```
