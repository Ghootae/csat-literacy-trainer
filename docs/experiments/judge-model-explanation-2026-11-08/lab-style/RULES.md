# lab식 해설 쓰기 규칙 v2 (실행 전 고정, 2026-11-08)

- v1 결과: `output-v1.json`(규칙 1~5). v2는 규칙 6을 더해 16문항 전부를 새로 쓴 것이다(사용자 지시 2026-11-08). 쓰는 사람은 v1 결과를 보지 않는다.

근거: `../DESIGN-DRAFT.md` 2.3절.

## 입력

- `input.json`의 `targets` 16문항: 지문(`passage`), 발문(`stem`), <보기>(`scenario`, 이미지가 있으면 `scenarioImages`), 선지, 정답 번호(`answerPosition`), 지금 해설(`currentExplanation`).
- `input.json`의 `examples` 6개: 다른 문항의 lab 해설(`labExplanation`). **모양의 본보기로만** 쓴다.

## 쓰는 규칙

1. 첫 문장은 "정답은 ⓧ입니다."이다. ⓧ는 원문자 ①~⑤로, `answerPosition`과 같아야 한다.
2. 정답을 가르는 원문(지문·<보기>) 사실을 1~2문장으로 쓴다. 원문과 지금 해설에 없는 내용은 더하지 않는다.
3. 마지막 문장은 "따라서 ~"로 선지 판단을 쓴다.
   - `stemPolarity = SELECT_CORRECT`(발문 "적절한 것"): 정답 선지는 참인 선지다. "따라서 ⓧ는 적절한 설명입니다." 꼴로 끝맺는다. 발문에 맞게 "적절한 반응입니다", "적절한 이해입니다"처럼 바꿔 써도 된다.
   - `stemPolarity = SELECT_INCORRECT`(발문 "적절하지 않은 것"): 정답 선지는 거짓 선지다. 원문과 어긋나는 한 지점을 밝히고 "따라서 ⓧ는 적절하지 않습니다." 꼴로 끝맺는다.
4. 합니다체로 쓴다. 공백을 포함해 100~160자로 쓴다.
5. 16문항을 모두 쓴다.
6. 선지가 비교나 조건을 말하면, 해설도 그 비교·조건까지 이어서 정답 이유를 쓴다. 예: 선지가 "A보다 B가 적합하다"면 B가 왜 A보다 나은지까지 쓰고, 선지가 "X가 Y보다 크면 Z"이면 X와 Y의 관계에서 Z가 나오는 이유까지 쓴다. 이 규칙 때문에 160자를 넘어야 하면 넘겨도 된다. 그때는 넘긴 이유를 보고한다.

## 출력

`output.json`(v2):

```json
{ "schemaVersion": "lab-style-explanation-output-v1",
  "explanations": [ { "questionId": "...", "text": "정답은 ①입니다. ... 따라서 ..." } ] }
```
