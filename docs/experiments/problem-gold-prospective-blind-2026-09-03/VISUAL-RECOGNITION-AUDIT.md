# 신규 24문항 시각 자료 인식 감사

감사일: 2026-09-03

감사 대상: `prospective-gold-sample-v1.json`에서 `VISUAL`로 표시된 10문항, 입력 이미지
15개, 최초 생성본과 정규화 후 후보 골드

## 1. 결론

이번 표본은 “이미지가 모델에 전달되지 않았다”거나 “작은 해상도 때문에 모든 그림을 읽지
못했다”는 가설을 지지하지 않는다. 15개 이미지가 모두 원본 바이트와 같은 해시로 저장됐고,
생성 호출에는 `detail: high`로 전달됐다. 수치표 2개와 단순 도식 2개에서는 숫자, 레이블,
패널 구분을 정확히 추출했다.

확인된 핵심 문제는 **복잡한 그림의 정밀 관계를 충분히 명제화하고, 텍스트 해석과 교차
검증하는 단계가 없다**는 것이다. 볼록 렌즈 문항에서 모델은 광선 흐름과 C·E·D의 대략적인
배치는 보았지만 P0·P1·P2의 상대 거리처럼 판정에 중요한 공간 관계를 visual assertion으로
만들지 않았다. 이어 보기 문장의 비율을 반대로 정규화했고, 그림은 이 오류를 교정하는
근거로 사용되지 않았다.

또 다른 구조적 문제는 시각 근거의 계보다. 옥신 문항은 그림 내용을 정확히 읽었지만 그것을
`visualAssertionIds`가 아니라 `scenarioFactIds`로 판정 경로에 연결했다. 그 결과 실제로는
그림이 필수인 문항이 시각 위험 없음, `LOW`로 분류됐다.

따라서 현재 증거가 말하는 것은 다음과 같다.

- 단순 OCR·표 판독·패널 식별은 이 표본에서 대체로 작동한다.
- 복잡한 공간 관계는 **완전 오독보다 불완전 추출** 위험이 크다.
- 시각 사실과 텍스트 사실 사이의 모순을 잡는 독립 검사가 없다.
- 그림에서 읽은 사실을 SF로 옮기면 시각 의존성 검사를 우회할 수 있다.
- 현재 `VISUAL` 표본 수 10은 실제 시각 필수 문항 수가 아니다.

## 2. 표본과 입력 전달

| 항목 | 결과 |
|---|---:|
| manifest의 `VISUAL` 문항 | 10 |
| 실제 이미지 | 15 |
| 로컬 입력 파일 존재 | 15/15 |
| 원천 메타데이터와 SHA-256 일치 | 15/15 |
| 생성 호출의 이미지 상세도 | `high` |
| 사람이 재판정한 풀이 필수 시각 문항 | **5/10** |
| 풀이와 무관하거나 텍스트로 대체 가능한 이미지 문항 | **5/10** |
| 풀이 필수 이미지 문항 중 후보 골드 생성 | 4/5 |
| 풀이 필수 이미지 문항 중 의미 충돌로 차단 | 1/5 |

렌즈 그림은 787×481이고 다른 필수 이미지도 505×381~739×531 범위다. 이번 실패를 입력
파일 누락이나 극단적인 저해상도로 설명하기 어렵다.

`VISUAL` 10개가 실제 시각 필수 5개로 줄어드는 이유는 표본 분류기가 선택 문항과 관계없이
지문에 이미지 URL이 하나라도 있으면 `VISUAL`을 붙이기 때문이다. 블록체인·준거가격·섀플리
값·니체 문항의 이미지는 선택 문항 풀이에 필요하지 않았다. 나미브 문항도 선택 문항의 표
정보가 텍스트로 구조화되어 있어 두 지문 그림이 필수는 아니었다.

### 3.3 볼록 렌즈

[입력 그림](/Users/mac/Projects/csat-literacy-problem-solving-mvp/docs/experiments/problem-gold-prospective-blind-2026-09-03/gold-production/artifacts/prospective-69fd388386fd308968e0b9f4-q11/input-media/MEDIA1.png)은
이번 표본에서 유일하게 복잡한 3차원 공간 관계를 요구한다. 생성본은 다음 두 VA만 만들었다.

1. 광선 다발이 P0에서 렌즈를 지나 C·E·D 영역으로 진행한다.
2. C와 D는 서로 다른 선분상이고 E는 그 사이의 원형상이다.

둘 다 맞지만 다음 결정적 관계는 시각 명제로 남기지 않았다.

- P1은 P0보다 광축에 가깝다.
- P2는 P0보다 광축에서 멀다.
- 그림의 상대 배치는 `d(P2) > d(P0) > d(P1)`이다.
- C와 D는 비점 격차의 양 끝이고 E는 그 사이에 있다.

보기 문장은 `d(P0) = 2d(P1)`이고 `d(P0) = ½d(P2)`라는 뜻이다. 따라서
`d(P2) = 2d(P0)`이다. 비점 격차가 광축 거리의 제곱에 비례하므로 P2로 옮기면 C~D 거리는
P0일 때의 4배가 되어 C2는 참이다.

그러나 최초 생성본은 SF7을 “P2의 거리는 P0의 절반”으로 반대로 만들었다. 이 잘못된 SF7을
근거로 C2를 1/4배라고 판정했고, 원래 거짓인 C3과 함께 거짓 선지가 두 개가 됐다. 정답 키로
`answerChoiceId: C3`을 기록한 것과 별개로 선택지 진리값은 일관되지 않았다.

오류의 최초 위치는 B1의 `scenario.facts` 생성이다. 이미지 입력이나 코드 정규화 과정에서
생긴 오류가 아니다. 정규화기는 ID와 교차 필드만 고쳤고 SF7의 의미는 변경하지 않았다.
“부정 발문의 거짓 선지가 정확히 하나”라는 게이트가 결과를 차단했지만, 이것은 시각 오류를
직접 검출한 것이 아니라 그 오류가 우연히 유일성 위반까지 일으켰기 때문이다.

이 사례는 **텍스트 관계 방향 반전 + 그림의 불완전 명제화 + 교차 모순 검사 부재**가 합쳐진
실패다. 따라서 순수한 OCR 실패로 분류하는 것은 정확하지 않다.

## 4. 최초 오류 단계

```text
원본 이미지 수집·저장       15/15 정상
        ↓
모델 입력(detail: high)      정상
        ↓
B1 시각 사실 추출            단순 표·도식 정상 / 렌즈 coverage 부족
        ↓
B1 텍스트·그림 결합          렌즈 비율 반전, 교차 검증 없음
        ↓
근거 계보 구성               옥신 VA→SF 우회
        ↓
코드 정규화·스키마 검사      의미·coverage는 검사하지 않음
        ↓
위험도 계산                  옥신을 LOW로 과소평가
```

정적 정규화는 네 필수 후보 문항에서 시각 의미를 변경하지 않았다. 최초 출력과 후보의
`mediaAssets`, `visualAssertions`, `scenario` 차이는 SCENARIO 배치에 누락된
`supplementIndex: 0`을 코드가 복원한 것뿐이다. 따라서 시각 의미의 성공과 실패 모두 B1
출력에서 이미 결정됐다.

## 5. 현재 계약의 취약점

### 5.1 `VISUAL` 표본 정의가 너무 넓다

표본 준비기는 `result.image_urls`가 하나라도 있으면 선택 문항과의 관련성에 관계없이
`VISUAL`로 분류한다. 이 때문에 실제 시각 필수율은 5/10이었다. 현재 보고서의 “시각 문항
10개”를 모델의 시각 추론 성능 분모로 사용하면 성능이 과대평가된다.

필요한 구분은 최소한 다음 세 가지다.

- `HAS_MEDIA`: 지문 또는 문항에 이미지가 존재
- `VISUAL_RELEVANT`: 선택 문항 판정과 관련됨
- `VISUAL_REQUIRED`: 이미지 없이는 정답 판정에 필요한 사실을 얻을 수 없음

### 5.2 시각 assertion의 완전성 계약이 없다

현재 스키마는 VA ID가 존재하고 media ID를 올바르게 가리키는지만 검사한다. 해당 이미지에서
풀이에 필요한 레이블, 수치, 방향, 거리, 포함 관계를 모두 추출했는지는 검사하지 않는다.
렌즈처럼 두 개의 참인 VA만 있어도 구조적으로는 문제가 없다.

### 5.3 시각·텍스트 모순 검사가 없다

렌즈의 SF7은 그림의 상대 배치와 충돌하지만 이를 대조하는 단계가 없다. 동일 사실이 텍스트와
이미지에 모두 나타날 때 다음 중 하나를 요구할 필요가 있다.

- 두 모달리티의 정규화된 관계가 일치함
- 불일치하면 `UNRESOLVED_VISUAL_CONFLICT`로 자동 차단

### 5.4 시각 근거를 SF로 우회할 수 있다

이미지에서만 얻은 사실을 SF에 기록하면 이후 위험 계산은 그것을 텍스트 보기 사실처럼
취급한다. `requiredForSolving: true`인 미디어가 있는데 결정 경로에 VA가 하나도 없는 옥신
문항을 현재 게이트가 허용했다.

### 5.5 정답 키가 시각 이해 성공처럼 보일 수 있다

생성 입력에는 정답 키가 포함된다. 렌즈 생성본도 `answerChoiceId`는 공식 정답 C3이지만 실제
진리 판단은 C2와 C3을 모두 거짓으로 만들었다. 따라서 정답 ID 일치율은 시각 이해 평가
지표가 될 수 없다. 선지별 진리값과 근거 재구성까지 독립적으로 봐야 한다.

## 6. 다음 파이프라인에 필요한 시각 감사 구조

복잡한 그림은 B1 생성 에이전트가 한 번에 보고 바로 골드로 옮기게 하기보다, 공식 해설의 A
감사와 비슷한 독립 시각 감사 계층이 필요하다.

```text
V0 문항-이미지 관련성 판정
→ V1 원자 시각 사실 추출
   (텍스트/OCR, 수치, 레이블, 방향, 순서, 거리, 포함, 패널 대응)
→ V2 텍스트·시각 동일 관계 교차 검사
→ A 공식 해설 감사
→ B1 골드 생성
→ B2 정적 수정
→ B3 프로브
→ C 독립 의미·시각 감사
→ 품질 게이트
```

최소 품질 게이트는 다음 조건을 확인해야 한다.

1. `VISUAL_REQUIRED` 미디어마다 결정 경로에 VA가 하나 이상 있다.
2. 원자료의 텍스트가 비어 있는데 이미지에서 복원한 사실은 SF 단독 근거가 될 수 없다.
3. 시각 필수 선지 claim마다 이를 판정하는 시각 assertion 또는 검수된 시각-텍스트 등가 관계가
   있다.
4. 수치·비율·방향·순서 관계는 원자 단위로 정규화한다.
5. 텍스트와 그림이 같은 대상을 표현하면 관계 방향을 대조한다.
6. C 감사자는 B1의 VA를 신뢰하지 않고 원본 이미지를 다시 본다.

## 7. 감사 범위

이번에는 승인된 범위대로 기존 이미지, 최초 생성본, 후보 골드와 정적 검증 결과만 읽기
전용으로 감사했다. 골드, 코드, 검수 상태를 수정하지 않았고 모델 재호출이나 재생성도 하지
않았다. 보고서 이외의 산출물은 추가하지 않았다.
