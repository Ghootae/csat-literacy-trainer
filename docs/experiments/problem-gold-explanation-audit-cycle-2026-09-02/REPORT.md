# ExplanationAudit 방화벽·삼원 효과 5문항 재실행 보고서

실행일: 2026-09-02

## 1. 목적

공식 해설을 `ExplanationAudit`으로 먼저 분해·검증한 뒤 승인된 claim만 골드 생성에 제공하는 구조가 실제 모델 출력에서도 해설 역수입을 줄이는지 검증한다. 동시에 `targetClaimEffect` 삼원 관계, 원본 메타데이터 코드 주입, 빠른 평가기의 부정 표현 보정을 같은 5문항에서 재검증한다.

이번 실행은 다음 순서로 수행했다.

```text
A 해설 claim 분해·원문 대조·등급/배치 결정
→ B1 최초 골드 생성
→ B2 정적 계약 수정
→ B3 학생 프로브
→ C 독립 의미 감사
→ 품질 게이트
```

## 2. 이번에 구현한 계약

- `problem-solving-gold-v2`에서 `targetClaimEffect`를 `SUPPORTS | CONTRADICTS | DOES_NOT_JUSTIFY`로 확장했다.
- `DOES_NOT_JUSTIFY`는 주장과 그 부정 모두 승인 근거에서 도출되지 않는 비함의 관계로 고정했다.
- 운영 골드 6개와 에피소드의 스키마 참조를 v2로 마이그레이션했다.
- 원본 `sourceId`, 시험·문항 번호, 선지 ID, 정답 ID, 미디어 URL·해시·크기·배치를 코드로 다시 주입한다.
- 명시적인 평가 대상이 있는 한국어 부정 표현만 선택 태도로 정규화하고, 사실 명제 내부의 부정·거부 표현은 뒤집지 않는다.
- A단계 공급자 구조 스키마와 최종 교차 필드 계약을 분리해, 잘못된 첫 출력도 자동 수정 루프가 회수할 수 있게 했다.
- 품질 게이트가 캐시된 프로브의 과거 `passed` 값을 신뢰하지 않고 현재 삼원 효과 기준으로 다시 채점한다.
- 실행 요약에 아래 효능 지표를 자동 집계한다.

## 3. 5문항 결과

### 3.1 핵심 지표

| 지표 | 결과 | 해석 |
|---|---:|---|
| ExplanationAudit claim 누락률 | 0/31, 0% | 후보 벤치마크의 모든 claim 구간을 찾음 |
| 출처 등급 정확도 | 25/31, 80.6% | 6개 claim 등급 불일치 |
| 배치 정확도 | 31/31, 100% | 후보 벤치마크와 배치 일치 |
| 해설 역수입 감지 | 2/5문항 | 수소·보증 계약 |
| 잘못 배치된 해설 claim | 5건 | 수소 2건, 보증 계약 3건 |
| 의심 passage proposition | 2건 | 보증 계약에서 감지 |
| SUPPLEMENTAL 계보 보존율 | 산출 불가 | 허용 claim과 실제 항목이 모두 0건 |
| 삼원 효과 전체 일치 | 20/26, 76.9% | C 기대 효과와 최종 골드 비교 |

| B1 구조 무수정 통과 | 3/5 | 이전 0/5에서 개선 |

ExplanationAudit 벤치마크는 아직 `candidate`다. 따라서 누락률·등급·배치 수치는 구현자가 만든 후보 정답과의 일치율이며, 인간 검토로 확정된 효과 수치가 아니다.

### 3.2 문항별 결과

| 문항 | B1 | B2 | C 조치 | 역수입 없음 | 효과 일치 | 프로브 | 최종 |
|---|---:|---:|---|---:|---:|---:|---|
| 수소 생산 | 통과 | 통과 | HUMAN_REVIEW | 실패 | 1/5 | 6/12 | HUMAN_REVIEW |
| 보증 계약 | 실패 | 통과 | HUMAN_REVIEW | 실패 | 3/5 | 10/12 | HUMAN_REVIEW |
| FTA 원산지 | 통과 | 통과 | REPAIR_GOLD | 통과 | 5/5 | 10/12 | HUMAN_REVIEW |
| 확산 모델 | 통과 | 통과 | PASS | 통과 | 5/5 | 10/12 | HUMAN_REVIEW |
| 열팽창 구동기 | 실패 | 통과 | PASS | 통과 | 6/6 | 11/12 | HUMAN_REVIEW |

수소 문항에서는 A 감사가 미해결 전제 공백을 찾았지만, B 골드가 동일 공급량의 수소 생성량 비교를 다시 필수 경로에 포함했다. C가 이를 해설 역수입으로 감지하고 자동 승인을 차단했다.

보증 계약에서는 해설이 생략한 청구 순서 조건과 충분조건을 필요조건으로 바꾼 관계가 다시 후보 골드에 나타났다. C는 세 해설 claim의 기본 골드 사용을 부적절하다고 판단했다.

FTA에서는 삼원 관계 도입으로 I2·I3·I4가 `DOES_NOT_JUSTIFY`로 표현되었다. 다만 같은 대표 오답 3회 중 2회에서 평가기가 이를 `CLEAR_ERROR`로 과단정해 삼원 관계의 런타임 일관성 문제가 남았다.

열팽창에서는 공식 해설의 “물체를 잡음 → 힘이 소멸되지 않음” 연결을 A가 `UNRESOLVED / HUMAN_REVIEW`로 격리했다. 후보 골드는 이 연결 없이 온도 변화량 규칙으로 정답을 독립 도출했고 C도 골드 자체는 PASS로 판정했다.

|---|---:|

실패 13건 중 열팽창 1건은 요청 시간 초과, 확산 저정보 1건은 evaluator 출력 계약 오류였다. 나머지는 실제 의미 판정 또는 삼원 효과 일관성 실패다. 이번 대표 오답 점수는 `DOES_NOT_JUSTIFY` 선지를 `CLEAR_ERROR`로 단정하면 실패로 세는 더 엄격한 기준이 적용되어 이전 55/60과 완전히 동일한 채점 기준은 아니다.

## 4. 입증된 것과 미입증된 것

입증된 것:

- 삼원 효과 계약과 운영 골드 마이그레이션이 정적 계약에서 작동한다.
- 원본 식별자·미디어 메타데이터 코드 주입이 5/5에서 통과한다.
- A단계 claim 분해, 계약 오류 자동 수정, B·C 연결, 계보 검사가 실제 호출 경로에서 완료된다.
- `ANSWER_KEY_CONSTRAINED`, `UNRESOLVED` 관계가 남은 문항은 자동 승인되지 않는다.
- C가 수소·보증 계약의 의미적 역수입을 감지해 자동 승인을 차단한다.

미입증되거나 실패한 것:

- 후보 벤치마크가 아직 인간 검토되지 않아 ExplanationAudit의 실제 등급 정확도는 확정되지 않았다.
- A 감사가 해설 claim을 빠짐없이 정확하게 분해한다는 일반화 성능은 입증되지 않았다.
- B 생성 단계의 의미적 해설 역수입 자체는 2/5문항에서 여전히 발생했다.
- `DOES_NOT_JUSTIFY` 구분은 5/11에 그쳐 실제 모델 출력에서 안정적이지 않다.
- SUPPLEMENTAL 항목이 한 건도 생성되지 않아 계보 보존율을 시험할 분모가 없다.
- 인간 검토율과 자동 승인율은 개선되지 않았다.

## 5. 결론과 다음 우선순위

이번 결과는 방화벽이 “잘못된 골드를 자동 승인하지 않는” 마지막 차단선으로는 작동했음을 보여 준다. 그러나 “승인되지 않은 해설 의미가 B 골드에 전혀 들어가지 않게 한다”는 생성 전 예방 효과는 아직 달성하지 못했다.

다음 순서는 다음과 같다.

1. 후보 ExplanationAudit 벤치마크 31개 claim을 사람이 검토해 기준을 확정한다.
2. B 골드의 각 해설 유래 관계에 `explanationClaimId` 계보를 의무화하고, `BASE_GOLD` 미승인 claim 참조를 생성 직후 코드에서 제거하거나 거부한다.
3. `DOES_NOT_JUSTIFY` 대상의 평가기 출력 계약과 재시도 규칙을 강화하고 수소·보증·FTA 회귀를 추가한다.
4. 실제 `SUPPLEMENTAL` claim을 포함한 통제 문항을 추가해 계보 보존율을 측정한다.
5. 같은 5문항을 다시 실행해 역수입 0건, 삼원 효과 구분, 60회 프로브와 자동 승인율을 비교한다.

원본 호출, 단계별 검증, 프로브, C 감사와 최종 게이트는 `artifacts/`에, 기계 집계는 `summary.json`에 보존했다.

## 6. 후속 판정기 재검증

같은 날 골드는 유지하고 버튼 선택과 근거 역할을 분리한 4방향 판정기로 대표 오답만 다시 실행했다. 기존 9/15는 당시 삼원 효과 채점 규칙의 영향을 받은 수치이며, 새 실험의 엄격 기준인 `SUFFICIENT + CLEAR_ERROR + ASK_CORRECTIVE`로 과거 원출력을 다시 채점하면 13/15다. 수정 판정기는 같은 오답·같은 근거 15회에서 15/15를 기록했다.

이 후속 결과는 대표 오답 진단의 국소 개선만 의미한다. 정답 근거와 저정보 응답을 포함한 전체 60회 재실행 및 ExplanationAudit 효능 검증은 아직 완료되지 않았다. 상세 내용은 `docs/experiments/problem-evaluator-four-route-wrong-probes-2026-09-02/REPORT.md`에 기록했다.

이어 같은 5문항의 기존 정확 근거를 3회씩 실행한 결과, 모델의 마지막 원출력은 15/15였지만 런타임 반환은 10/15였다. `CORRECT_REJECTED`에서 `부적절하다` 내부의 `적절하`를 긍정 태도로 중복 인식하는 의미 모순 방어기 위양성이 확인됐다. 상세 내용은 `docs/experiments/problem-evaluator-four-route-correct-probes-2026-09-02/REPORT.md`에 기록했다.

후속 수정에서는 자연어 태도 정규화와 의미 모순 재판정을 제거하고, 모델 근거 finding과 코드 파생 라벨을 분리했다. 같은 정답 근거 15회 재실행에서 런타임까지 15/15가 되었고 의미 모순 재시도는 0건이었다. 상세 내용은 `docs/experiments/problem-evaluator-four-route-correct-probes-postprocessor-fix-2026-09-02/REPORT.md`에 기록했다.
