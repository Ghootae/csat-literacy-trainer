# 타이틀 질의를 생성기가 쓸 수 있는가

- 날짜: 2026-08-10 / 모델: `claude-opus-4-8` / 생성 effort `high`, 채점 effort `medium`
- 선행: `title-compression-2026-08-10.md` (손으로 쓴 질의로 판정 가능성을 먼저 확인)
- 코드: `packages/pipeline/src/llm/title-gen.ts`, `npm run title:gen`
- 원시 출력: `-gen-vs-hand.log`, `-variants.log`

## 왜 별도 생성기인가

기존 생성기(`query-gen.ts`)를 확장하지 않았다. 두 가지 이유다.

1. **기존 프롬프트를 건드리면 `GENERATOR_VERSION`을 올려야 한다.** 그러면 fixture를 다시 만들고
   회귀 3세트를 통째로 재야 한다 (실측 약 $7, 40분). 타이틀 때문에 그럴 이유가 없다.
2. **입력이 다르다.** 타이틀 질의는 슬롯 목록과 타이틀 노드가 핵심 입력인데, 기존 생성기는
   명제·관계 간선을 받는다.

출력은 `GeneratedQuerySet` 모양 그대로(영역 하나)라 `evaluateResponse`가 손대지 않고 돈다.

## 1차 — 생성 질의 vs 손 오라클 (프로브 14개 × 3회)

같은 프로브를 두 출처에 각각 돌렸다.

```
                       손 오라클        생성 질의
반복 변동               1/28            1/28
기대 불일치             1/28            3/28
```

핵심 프로브는 **전부 일치**했다.

```
압축         O O O    O O O
경계         O O O    O O O
연결         · · ·    · · ·
나열-관계없음  · · ·    · · ·
```

### 갈린 셋 — 전부 생성 질의 쪽이 같거나 낫다

**① 모순 응답의 `qT3`.** 손 오라클은 보존(조직만 보라고 썼으므로), 생성 질의는 미보존.
생성기가 수용 기준에 중심 서술을 **내용으로 특정**했기 때문이다. 손 오라클 기준으로는
"보상은 관계보존일 때만"이라는 게이트를 따로 걸어야 했는데, 생성 질의는 스스로 걸러낸다.
**게이트는 그대로 둔다** — 생성기가 매번 그렇게 쓴다는 보장이 없고, 이중 방어는 비용이 0이다.

**② P5 `나열-관계있음`.** 프로브 결함이었다. "그렇게 → 그래서"로 인과가 이어져 병렬이
아니었다. 니체 쪽(`~이다. ~이다. ~이다.`)은 양쪽 출처 모두 미보존으로 정확히 나왔다.

**③ P5 `과대추상`의 영역 판정.** 손 오라클 `미포착`, 생성 `주제만`. **생성이 더 맞다** —
"C4 식물의 광합성"은 화제를 짚었다.

## 2차 — 중심 서술 변형 (프로브 22개 × 2회, 생성 질의)

생성기는 수용 기준에 **중심 서술의 예를 박아 넣는다**:

```
"'니체가 ~에 반대한다'는 하나의 중심 서술에 … 종속되면 인정한다"
```

예시를 규칙으로 착각해 다른 표현을 쓴 학생을 막는지 봤다.

```
니체 변형 4개 — 전부 통과
  명사중심(비판)  "…를 근거로 한 니체의 전통 형이상학 비판"          O O
  이유중심       "…을 니체가 거부한 이유"                        O O
  도치          "…형이상학, 니체는 이를 받아들이지 않았다"          O O
  콜론          "니체가 맞선 지점: 삶은 수단이 아니라 목적이다"      O O
```

**과잉 구속은 없다.** 생성기가 예를 적어도 그것을 규칙으로 삼지 않는다.

### P5에서 둘이 걸렸다

**`변형-이유중심` → 실패.** 프로브 결함이다.

```
"C4 식물의 광합성이 C3보다 효율적인 까닭"
```

결과(효율)만 있고 **원인(두 공간 분업·농축)이 없다.** "까닭"이라고 말만 했지 그 까닭을 쓰지
않았다. 니체의 같은 유형은 양쪽 항이 다 있어서 통과했다. `qT2` 수용 기준이 "한쪽 항만
제시하면 미보존"이고 정확히 그대로 작동했다 — **형식만 보고 통과시키지 않고 내용을 봤다.**

**`변형-명사구병렬(짧음)` → 압축으로 판정** (기대는 미보존).

```
"엽육과 유관속초로 나뉜 광합성, 그리고 그 결과인 높은 효율"
```

"그 결과인"이 인과 종속을 만드는가, 두 명사구가 대등한가 — **사람도 갈릴 자리다.** 기대값이
확실했다고 말하기 어렵다.

## 판단

```
반복 변동    1/44
불일치      6건 중 4건은 프로브 결함이거나 생성 질의가 더 정확한 경우
            나머지 2건은 원래 애매한 경계(연결↔압축)
```

**생성기를 쓸 수 있다.** 8문단에 넣을 수 있다는 뜻이다.

중심 서술을 어떻게 쓰든 조직만 맞으면 통과하고, 관계가 빠지면 형식이 그럴듯해도 걸러낸다.
애매함은 원래 애매한 자리에만 남으며, 압축은 **보상이라 학생의 진행을 막지 않는다.**

## 한계

- 문단 2개다. 나머지 6문단에서도 같은 구조가 나오는지 **안 쟀다.**
- 생성 1회씩이다. 기존 회귀가 생성 3회(gen1/2/3)를 비교하는 것과 대비된다 — 생성기의
  실행 간 변동은 안 봤다.
- 프로브 기대값 2건이 이번에도 틀렸다(`변형-이유중심`, `변형-명사구병렬`). 프로브를 쓰는
  것 자체가 어렵다는 뜻이고, 기대값을 고칠 때는 **판정에 맞추는 것이 아니라 왜 틀렸는지를
  먼저 밝힌 뒤** 고쳐야 한다.
- 3단계 UI는 여전히 미구현이다. 이 실험은 판정과 생성만 검증했다.
