## 4. 해석 (가설 포함)

1. **가설 확인 (기출):** 원리 적용 선지가 모이는 문항은 주로 〈보기〉 문항이다(7/10). 〈보기〉 없는 문항에서는 드물다(2~3/21). 모인 문항은 모두 `SHARED`(상황 하나 공유)였다(정보 비대칭 13의 `PER_CHOICE` 제외).
2. **P1은 구조 조건을 넘었다.** 생성기가 "규칙 → 상황·계산표 → 단계를 비튼 오답"으로 상황 하나 위에 APPLIED 선지를 모으는 데 성공했다. E1(0/100)과 대비된다.
3. **그러나 P1은 기출보다 단조로울 수 있다.**
   - 기출의 원리 적용 문항도 〈보기〉형(16·17·10)은 AAAAA다. 그러나 〈보기〉 없는 15번과 법인 13은 A·S·C가 섞인다.
   - P1 7문항은 모두 AAAAA다.
   - P1의 상당수는 수치 계산이다. 법인 a·b(주식 수 × 액면가), 표면 장력 a(104·100·절반), 오디오 b(소리 크기 − 문턱값)가 그렇다. 기출 15번은 수치 없이 정성적 대소 비교다.
   - 다만 기출 17번(오디오, 표 수치)과 16번(잉크 조건)도 수치·조건형이다.
4. **P1 a의 형식 이탈:** 법인 a와 표면 장력 a는 발문 "(단, …)"에 지문에 없는 수치를 넣었다. 지문이 깐 상황(무상 증자, 폐포)을 쓰긴 했지만, 실질은 발문 안 〈보기〉다.
   - 플라스틱 a(20%→40%)도 수치를 새로 넣었다.
   - 기출 15번처럼 "지문이 준 상황만으로 추론"하는 형태는 아니다.
   - 원인(확인함): SITUATION 지시문 11행이 "규칙에 그 상황의 값을 넣어 결과를 구하는 계산표"를 요구한다. 그런데 IN_PASSAGE(15행)에는 지문 밖 값을 넣지 말라는 제한이 없다.
5. **판정 기준의 한계:** APPLIED 판정은 "값을 넣어 결과를 냄"만 본다. 계산 단계 수나 함정의 정교함(깊이)은 재지 않는다. 그래서 (나)·(다) 통과가 곧 "기출만큼 깊다"는 뜻은 아니다. 이 판단은 (라)의 몫이다.

## 5. 열린 질문 (웹 에이전트와 논의)

1. P1의 "AAAAA 계산형" 수렴을 문제로 볼 것인가?
   - 다음 판으로 갈 때 "선지 일부는 지문 확인·연결(S·C) 함정으로 둔다"는 혼합 구성을 넣을지
2. P1 a에 지문 밖 수치를 허용할 것인가?
   - 허용하면 a와 b의 차이가 "〈보기〉 칸이 있느냐"뿐이다.
   - 금지하면 기출 15번형(정성적, 지문 상황만)으로 좁혀지고, 재료가 더 줄어든다(오디오는 이미 0).
3. 기출 원리 적용이 〈보기〉에 몰린다(7/10 대 2~3/21)는 결과에 따라, 본설계를 b(〈보기〉형) 중심으로 둘 것인가(D-0224 5)?
4. (라)를 어떻게 할 것인가?
   - 사용자가 7문항을 기출 15·16·17과 나란히 놓고 볼 때, 비교 축을 "생각하게 만드는가" 하나로 둘지
   - 또는 "계산만 하면 풀리는가 / 지문 이해가 필요한가"를 따로 볼지
