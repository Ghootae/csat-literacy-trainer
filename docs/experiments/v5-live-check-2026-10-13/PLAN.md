# v5 실모델 확인 시험 설계 (2026-10-13)

상태: 설계안. 사용자 승인 전에는 외부 API를 호출하지 않는다.

## 목적

D-0116 이후 바뀐 것은 모두 mock 평가기로만 확인했다. 한 번의 시험으로 실제 모델에서 다음을 확인한다.

| 확인 대상 | 결정 |
|---|---|
| 결론을 생략한 근거를 재구성하는가, 진짜 모호한 근거는 그대로 확인 불가인가 | D-0120 |
| 교정 질문이 반말이고, 학생 주장을 직접 겨냥하며, 두 갈래 또는 짧은 직접 질문인가 | D-0116, D-0118 |
| 지문·보기에 칠한 곳이 질문이 가리키는 구절과 맞는가 | D-0118 |
| 마지막 설명이 칸(첫 선택 / 재선택 / 정답)으로 나뉘고, 칸끼리 내용이 겹치지 않는가 | D-0117 |
| 정답이지만 근거가 확인되지 않을 때 학생을 틀렸다고 단정하지 않는가 | D-0112 6항 (CORRECT_UNVERIFIED) |

## 사례 (총 26세션, 6문항)

학생 발화는 모두 사람이 쓴 고정 문장이다. 모델이 학생 답을 만들지 않는다.

### V군: 진짜 모호한 근거, 대조군 (6세션)

48세션 A1 문장을 그대로 쓴다(예: "①이 틀린 것 같아요. 이익 잉여금이라는 말이 걸려요."). 기대 결과: 지난번과 같이 확인 불가이고, I-A1만 교정 질문이 나온다. I-A1과 S-A1 두 세션은 마지막 설명까지 진행해 확인 불가 안내와 칸 설명을 본다.

### F군: 전체 흐름 (12세션, 2문항 × 6유형)

정보 비대칭 q13과 표면 장력 q16에서 48세션의 같은 첫 문장을 쓰고, 대화를 끝까지 진행한다.

| 유형 | 지나가는 길 | 주로 보는 것 |
|---|---|---|
| CT | 정답 + 소재만 언급 → CORRECT_UNVERIFIED | 틀렸다고 단정하지 않는 luna 설명 |
| CP | 정답 + 관련 사실만 언급 → CORRECT_UNVERIFIED | 위와 같음, 빠진 연결을 채우는 설명 |
| A2 | 오답 → 교정 질문 → 고침 → 정답 재선택 | 질문·칠한 곳, 재선택 칸 |
| A3 | 오답·복합 오류 → 첫 오류만 고침 | 다음 오류 질문, REPAIR_FAILED 설명 |
| B1 | 근거 미제출 오답 | 근거 미제출 안내, 칸 설명 |
| B2 | 오답 → 교정 질문 → 고침 → 설명 요청 | 질문·칠한 곳, COACHING_REQUESTED 설명 |

- 질문 뒤의 학생 답은 질문을 본 뒤 유형 의도(48세션 `behaviors`)에 맞춰 클로드가 쓴다. 지난 실험처럼 단계마다 답을 파일로 고정한 뒤 보낸다.
- 마지막 설명 시작은 [응]을 누른다. 이해 확인은 세션마다 [응]·[아니]를 번갈아 누른다.

## 검사

### 자동 검사 (코드)

학생에게 보이는 모든 글(질문, 안내, 설명 칸)에서:

1. 존댓말 어미(…요. …습니다 …세요)가 없다.
2. 내부 용어("교정 질문", "판정", "종료 사유")와 내부 식별자(C1, E1 등)가 없다.
3. 학생을 3인칭("학생은", "학생이")으로 부르지 않는다.
4. 칠한 곳은 지문·보기의 실제 구절과 정확히 일치하고, 질문이 나갈 때 비어 있지 않다.
5. 칸 구성: 첫 선택과 정답 칸이 있고, 재선택 칸은 재선택이 있을 때만 있다. 칸 안에 코드 연결 문장("처음에 고른 …부터 볼게" 등)이 되풀이되지 않는다.

### 의미 검토 (클로드 → 사용자)

- R군: 학생이 밝힌 사실만으로 결론을 만들었는가. 말하지 않은 전제를 끼워 넣지 않았는가.
- 질문: 학생 주장을 직접 겨냥하는가, 지문의 구체적 사실과 낱말로 묻는가, 칠한 곳이 질문과 맞는가.
- 설명: 칸끼리 겹치지 않는가, CORRECT_UNVERIFIED에서 학생을 틀렸다고 단정하지 않는가.

## 실행 방식

- 새 실행기 `scripts/run-v5-live-check.mjs`: 지금의 비동기 흐름(제출 즉시 반환, 백그라운드 평가, `settled()`로 대기)과 [응]·[아니] 명령을 따른다. 지난 실행기를 재사용하지 않는다(새 흐름과 맞지 않음).
- 지난 실험과 같은 장치를 쓴다: 실행 전 입력·코드 해시 고정(FROZEN), 요청·응답 원본 저장, 비용 원장, 요청 수·금액 상한 도달 시 즉시 중단.
- 순차 실행, 세션별 기록. 중간에 끊겨도 같은 단계를 두 번 보내지 않는다.
- 모델 경로는 지금 운영 경로 그대로다(오답 판정 gpt-6.1-sol, 정답 판정·교정 응답·설명 gpt-6-luna).

## 비용 추정

- 48세션 실험의 유형별 평균 세션 비용(0.0015~0.079달러, 평균 0.034달러)을 기준으로 잡으면 약 0.6~1.0달러다.
- 상한: sol 2.5달러, luna 0.5달러, 요청 120건. 상한에 닿으면 멈추고 보고한다.
