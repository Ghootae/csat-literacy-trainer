# 24개 지문 문단 골드 선행 생산 준비

## 1. 전체 맥락

24개 문제 골드를 원래 생산 파이프라인으로 다시 만들기 전에, 각 문제에 연결된 지문의 문단
골드를 먼저 생성하기로 했다. 문단 분석 중간에 생성되는 명제와 명제 간선도 별도 보존해 이후
문제 골드가 참고할 수 있게 한다. 기존 골드는 변경하지 않는다.

## 2. 수행한 작업에 대한 목적

실제 API를 호출하기 전에 대상 지문과 문단 수를 확정하고, 기존 문단 골드 생성 방식과 독립
의미 감사를 중단·재개 가능한 하나의 생산선으로 연결하는 것이 목적이다.

## 3. 작업 과정

문제 골드 표본 24개를 원자료와 생산 당시 스냅샷에 다시 연결했다. 비어 있지 않은 원문 줄을
문단으로 보되 `*`, `＊`, `※`로 시작하는 각주는 바로 앞 문단에 붙였다. 그 결과를 입력
manifest로 저장했다.

실행기는 각 문단에 대해 다음 단계를 수행하도록 구현했다.

1. v3.1 문단 분석
2. 중심 이야기의 중심축 분해
3. 중심축과 핵심 관계 매핑
4. 문단 진단 골드와 명제 Bundle 별도 저장
5. 독립 의미 감사
6. 필요한 경우 1회 부분 수리와 재감사

이번 실행은 `dry-run`으로만 수행해 API 요청을 보내지 않았다.

## 4. 작업 결과

- 지문: 24개
- 분석 대상 문단: 140개
- 앞 문단에 연결한 각주: 8개
- 생성 최대 호출: 420회
- 독립 감사 최대 호출: 140회
- 수리 전 기본 최대: 560회
- 모든 문단이 1회 수리되는 극단적 절대 최대: 840회
- 실제 API 호출: 0회
- 기존 골드 변경: 0건

기계 판독 가능한 상세 계획은 [execution-plan.json](./execution-plan.json)에 있다.

## 5. 결과 해석

24문항이 24개 서로 다른 지문에 연결된다는 점과 실제 생성 단위가 140개 문단이라는 점을
확정했다. 생성·명제 보존·감사·예외 분류를 실행할 준비는 됐지만, 아직 문단 골드 자체가 만들어진
것은 아니다. 다음 단계는 모델 설정과 비용을 산정한 유료 실행 계획을 검토하고 승인하는 것이다.
