# 문제 풀이 MVP 첫 결정

기준일: 2026-08-26

## 1. 첫 실험 문항

첫 수직 슬라이스는 `dopamine-motor-control-q13`으로 고정한다.

- 출처: 고3 2026년 3월 교육청 모의평가 국어 13번
- 유형: 파킨슨병 치료 약물에 대한 보기 적용, 복합 추론, 부정 발문
- 선택 이유: 문단 사실 인출만으로 풀리지 않고, 보기의 약물별 작용 위치와 지문의 혈액-뇌 장벽·도파민 합성 관계를 결합해야 한다. 내용 표상, 보기 표상, 조건 적용, 추론 변환, 선지 판단, 발문 극성을 한 문항에서 구별할 수 있다.
- 정답: 2번. 현재 fixture는 스키마와 기준 경로를 구현하기 위한 `candidate`이며 사람 검토 뒤에만 `human_reviewed`로 승격한다.

원문은 기존 로컬 정본 `69c28579d58cf540a9bc25eb`에서 가져온다. 문항 fixture는 `packages/pipeline/fixtures/experiments/problem-solving/dopamine-motor-control-q13.json`에 둔다.

## 2. 최소 골드 경계

문단 요약 골드를 확장하지 않는다. 문제 풀이 골드는 다음 두 층을 별도로 가진다.

1. `PassageDetailGold`: 명제 ID, 문단 ID, 극성, 조건, 예외, 범위, 원문 근거
2. `ProblemQuestionGold`: 출제 출처, 발문 극성, 보기 사실, 선지별 참·거짓과 근거, 정답 기준 경로, 대표 오답 경로 후보

선지와 기준 경로는 문단·명제·관계 ID를 함께 참조한다. 대표 오답 경로는 열린 후보이며 실제 학생 경로를 제한하지 않는다.

## 3. 소유 패키지와 세션 경계

`ParagraphUnderstandingHandoff`는 어느 한 하위 엔진의 내부 타입이 아니다. 두 엔진이 공유하는 경계이므로 `packages/pipeline/src/learning-session/handoff.ts`가 소유한다.

문제 풀이 골드와 이후 evaluator/session은 `packages/pipeline/src/problem-solving/`이 소유한다. 앱 서버는 최종적으로 다음 집계를 소유한다.

```text
LearningSession
  ├─ ParagraphDialogueSession[]
  ├─ ParagraphUnderstandingHandoff
  └─ ProblemSolvingSession
       └─ ProblemDiagnosticEpisode[]
```

클라이언트 DTO는 `packages/app/src/shared/contract.ts`에 별도로 두며 모델 내부 표상을 그대로 노출하지 않는다. 현재 인메모리 `DialogueController`를 별도 앱으로 복제하지 않고, 후속 단계에서 상위 `LearningSessionController`로 확장한다.

## 4. 현재 구현 범위

- 완료 세션과 미시도 문단을 handoff로 바꾸는 순수 변환 함수
- PASS, UNRESOLVED, NOT_ATTEMPTED 및 관계 교정 궤적 테스트
- 질문 문장이 학생 근거로 새로 승격되지 않는 회귀 테스트
- 첫 실제 문항의 상세 골드·문항 골드 후보와 구조 검증

다음 단계는 학생 선택·근거를 관찰로 저장하고, 사고 경로 가설과 네 가지 충분성 판정을 추론 층에 별도로 저장하는 evaluator/session 수직 슬라이스다.

## 5. 선택·피드백·종료 흐름

확정일: 2026-08-28

문항당 선택은 최초 선택을 포함해 최대 3회, 재선택은 최대 2회로 제한한다. 3차 선택 이후에는 추가 재선택을 허용하지 않는다.

모든 선택 차수에 공통으로 다음 규칙을 적용한다.

- 정답 선택에서 근거를 제시하지 않으면 종료한다. 최초 정답은 독립 정답, 재선택 정답은 근거 미검증 정답으로 구분한다.
- 정답 선택에서 근거를 제시하면 선택 차수와 무관하게 반드시 평가한다.
- 정답 근거가 타당하면 근거 검증 정답으로 종료한다.
- 정답 선택과 근거 또는 발문 극성이 충돌하면 타당한 근거로 통과시킬 수 없다.
- 모든 오답 선택에는 해당 선택에 대한 새 근거가 필요하다. 이전 선택의 근거로 새 오답 경로를 추정하지 않는다.
- 질문은 한 번에 하나만 제시하고, 이미 확인된 내용을 다시 묻지 않는다.

`valid`는 질문에 문법적으로 응답했는지가 아니라 교정 목표가 실제로 수정되었음을 뜻한다. 질문 답변은 다음처럼 구분한다.

- `PATH_CLARIFIED`: 진단 자료는 충분해졌지만 오류는 아직 수정되지 않음
- `CORRECTED`: 학생이 목표 관계를 수정함
- `NOT_CORRECTED`: 기존 오류를 유지함
- `INCONCLUSIVE`: 여전히 판단할 수 없음

진단 질문의 답이 사고 경로만 명확하게 했다면 재선택으로 이동하지 않고 교정 질문으로 이동한다. `CORRECTED`일 때만 정답 근거 진단을 종료하거나 다음 선택으로 이동한다.

### 5.1 1차·2차 선택이 정답인 경우

```text
근거 없음
→ 즉시 종료

근거 있음
→ 근거 평가
   ├─ 타당함 → 근거 검증 정답으로 종료
   ├─ 불확실함 → 근거 미검증 정답으로 종료
   └─ 명백한 오류 또는 선택·근거 충돌
       → 교정 질문 1회
          ├─ CORRECTED → 근거 교정 정답으로 종료
          └─ NOT_CORRECTED / INCONCLUSIVE
              → 상세 코칭과 정답 설명 후 종료
```

정답을 이미 선택했으므로 교정 질문에 성공한 뒤 다시 선택하게 하지 않는다. 수정된 관계를 학생이 설명한 관찰을 검증 근거로 남긴다.

### 5.2 1차·2차 선택이 오답인 경우

해당 선택의 근거를 받은 뒤 최대 두 번의 학생 대상 질문 기회를 허용한다.

```text
선택 근거 평가
→ 경로 불충분: 진단 질문
→ 경로 충분 + 명백한 오류: 교정 질문
→ 합리적 대안 또는 문항 한계: 문항 경계 설명

질문 답변
├─ CORRECTED → 다음 선택으로 이동
├─ PATH_CLARIFIED → 남은 질문 기회에서 교정 질문
└─ NOT_CORRECTED / INCONCLUSIVE
    ├─ 질문 기회가 남음 → 더 직접적인 질문
    └─ 질문 기회 소진 → 상세 코칭과 정답 설명 후 종료
```

문항 경계 설명은 학생 오류 교정과 별도 결과로 기록한다. 경계가 해소되면 다음 선택으로 이동한다.

### 5.3 3차 선택

3차에서는 새로운 진단·교정 질문을 시작하지 않는다.

```text
3차 정답
├─ 근거 없음 → 근거 미검증 3차 정답으로 종료
└─ 근거 있음 → 평가
   ├─ 타당함 → 근거 검증 3차 정답으로 종료
   └─ 오류·충돌 → 상세 코칭과 정답 설명 후 종료

3차 오답
→ 상세 코칭과 정답 설명 후 종료
```

### 5.4 상세 코칭 종료의 성과 기록

시스템이 정답을 알려준 것은 학생이 정답을 맞힌 것과 구분한다.

```text
studentFinalChoiceId: 학생의 마지막 선택
answerRevealed: true
resolvedByStudent: false
outcome: DETAILED_COACHING_REQUIRED
```

향후 세션 계약은 최소한 `selectionAttempt`, 차수별 질문 사용량, `answerRevealed`, `resolvedByStudent`, 정답 근거 검증 수준을 보존해야 한다.
