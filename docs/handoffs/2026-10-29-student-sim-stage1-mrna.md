- 날짜: 2026-10-29
- 작성: Claude
- 사용자 승인: 시뮬레이션 계획(문단당 약 12세션, 문항당 약 10세션), 상한 넉넉히(1단계 $10), 학생 응답 견본 "이대로 진행해도 괜찮을거 같아".
- 도구: `scripts/student-sim.mjs` ([도구 인계](./2026-10-29-student-sim-harness.md) 사용법 절). 실행은 `node --env-file-if-exists=.env scripts/student-sim.mjs ...`.

## 학생 말투 (사용자 확인한 견본 기준)

짧고 메모식. 화살표(`->`), 괄호 메모, `o/x`, 소문자 `mrna`·`ph`, 문장 끝 "~함/~됨". 지나치게 정돈하지 않는다. 실제 사용자 응답 예: "낮은 산도에서 지질과 mRNA 결합 후 산도를 높여 복합체 -> 세포 내 진입. 세포 내부에서 엔도솜이 터져서 mRNA가 방출 -> 바이러스 단백질 합성 & 면역 반응".

## A. 문단 (run `docs/experiments/student-sim-2026-10-29/mrna-para/`, `--cap-usd 3`)

문단 1~5 각각 약 12세션(한 세션 = `para-start` 한 번, 그 문단 끝까지).

1. 첫 요약 7종 각 1세션: 정확 / 경계(압축·괄호 메모, 결론으로 이어지는 관계는 있으나 원문 세부 생략) / 한 부분 빠짐 / 관계 뒤집힘(방향·주체 바꿈) / 상위어로 묶음 / 원문 베끼기 / 엉뚱(소재만, 무관).
2. 경계 유형은 같은 글로 2세션 더(총 3).
3. 질문(빈 곳·바로잡기)이 나오면 답하는 방식 4종을 세션에 나눠 맡긴다: 정확(빠진 고리를 말함) / 이름만(개념어 하나) / 되풀이(이미 한 말 반복) / 모름·틀림. 문단마다 4종이 최소 한 번씩 나오도록, 모자라면 질문이 나올 만한 첫 요약(한 부분 빠짐·뒤집힘·경계)으로 세션을 더 연다(문단당 최대 15세션).
4. 다시 써 보기(RETRY)가 나오면: 엉뚱 세션은 한 번은 제대로 다시 쓰고, 베끼기 세션은 자기 말로 다시 쓴다.
5. 세션마다 `show`로 전체 대화를 확인하고 체크리스트로 검토한다.

## B. 문제 19번 (run `docs/experiments/student-sim-2026-10-29/mrna-prob/`, `--cap-usd 7`)

정답 ⑤(적절하지 않은 것). <보기>는 그림이지만 문항의 `scenario` 글과 그림 설명(alt)으로 내용을 안다(Y자 미세관에서 산성 용액의 mRNA와 에탄올의 이온화 지질을 섞고, 투석으로 pH를 높이고, 에탄올을 뺌).

약 10세션:
- ⑤ + 정확한 근거 1 / ⑤ + 짐작(근거 부실) 3(같은 글) / ⑤ + 틀린 말 섞인 근거 1
- 오답 ①·②·③·④ 각 1, 각자 그럴듯한 오해 근거(견본: ④ "ph 높이면 수소 이온 농도도 높아지는 거 아님?", ① "에탄올은 물에 잘 섞이니까 친수성", ③ "에탄올에 녹아 있으면 이온화 안 될 듯"; ②는 새로 만든다)
- 다시 고를 때 또 틀리는 1(오답 → 교정 → 다른 오답 → 끝까지)
- 교정 질문 답 4종(정확히 고침 / 반만 / 고집 / 모르겠어)을 오답 세션들에 나눠 맡긴다. 마지막 설명의 "이해됐어?"에는 응·아니를 섞는다.
- 세션마다 끝까지(마지막 설명, 이해 확인) 간다.

## 산출물 (각 run 폴더)

- `SESSIONS.md`: 세션마다 한 덩어리 — 키, 유형, 학생이 쓴 말 전부, 받은 피드백 요지(질문·마무리는 원문 그대로), 판정(action·category·corePartsCovered 또는 문제 판정), 체크리스트 코드(없으면 "문제 없음"), 한 줄 이유. 원문 근거 인용.
