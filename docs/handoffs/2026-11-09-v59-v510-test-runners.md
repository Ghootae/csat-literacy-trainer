## 목표

외부 호출 없이 selftest가 통과하는 실행기를 만든다. 실제 실행(외부 전송)은 이 작업에 포함하지 않는다. 사용자 전송 승인 뒤 메인 세션이 실행한다.

1. `scripts/run-judgment-rules-test.mjs`: 묶음(set) 이름으로 칸을 만들어 선택 판정(필요하면 교정 판정 1회)만 실행하고 칸마다 파일로 남긴다.
2. `scripts/judgment-rules-test-cases.mjs`: 묶음 정의(사례·근거 글·기대 판정·조건).
3. `scripts/summarize-judgment-rules-test.mjs`: 결과를 기대 판정·통과 기준과 대조하고 질문 목록을 뽑는다.
4. `scripts/run-v5-regression-replay.mjs`에 `--judgment-rules <v5.8|v5.10>` 인자 추가(기본 없음 = 지금과 같음).

## 공통 계약 (실행기)

11-08 실행기 `scripts/run-judge-model-explanation.mjs`의 구조를 따른다: 칸 단위 파일 `<out>/<label>.json`, 요청 장부 `<out>/requests.jsonl`, 새 칸 시작 전 비용 상한 확인, 이미 있는 칸 건너뜀, 동시 4칸, `timeoutMs 240000`, `maxRetries 1`, 단가 `sol {2,10}`·`luna {0.1,0.5}` USD/1M, `reasoning.effort medium`(평가기 기본).

- 사용법: `node --env-file-if-exists=.env scripts/run-judgment-rules-test.mjs <set> [--cap-usd n] [--dry]` / `... selftest`.
- 평가기: `new OpenAIFeedbackEvaluator({ model, promptPath, promptVersion, judgmentRules, timeoutMs, maxRetries, transport })`. `model`을 지정하면 교정 판정도 그 모델이 되므로, 교정 판정 칸(T2 prob-10)은 교정용 평가기를 따로 만든다(`model: 'gpt-6-luna'` = `FEEDBACK_REPAIR_MODEL`).
- 조건 이름: `<ver>-<모델>`. 지시문 경로·버전:
  - v5.8: `packages/pipeline/experiments/problem-solving/source-direct-problem-feedback-v5.8.md`, `problem-feedback-v5.8`, `judgmentRules` 생략
  - v5.9: `...-v5.9.md`, `problem-feedback-v5.9`, `judgmentRules` 생략
  - v5.10: `...-v5.10.md`, `problem-feedback-v5.10`, `judgmentRules: 'v5.10'`
- v5.10 조건에서만 문항 자료에 `runtime-reference.json`(`packages/pipeline/fixtures/experiments/sns-diagnostic/runtime-reference.json`)의 `lenientCorrect`를 붙인다(있는 문항만: 경마 4·오디오 15). v5.8·v5.9 조건에는 붙이지 않는다. `SourceDirectProblemBundleSchema.parse`로 다시 검사.
- 세션: `submitFeedbackCommand(createFeedbackSession(id, source), { type: 'SELECT', choiceId, rationale: { mode: 'PROVIDED', text } }, ...)` 뒤 `judge.evaluate` → `applyFeedbackAssessment`(11-08 `runCell`과 같음).
- 칸 파일 필드: `set, caseId, questionId, condition, model, promptVersion, judgmentRules, replicate, choiceId, rationaleText, expected`(사례에 있으면), `status`(VALID/EVALUATION_ERROR), `error`, 그리고
  - `judge`: 서버를 거친 최종 `contentAssessment, insufficiencyKind, boundary, reason, rationaleImpliedVerdict`
  - `modelJudge`: 마지막 ASSESSMENT 시도의 판정기 원출력에서 `contentAssessment, insufficiencyKind, ground.kind, ground.locatedSource`(없으면 null)
  - `normalizedNotes`: 마지막 ASSESSMENT 시도의 `normalized` 배열(서버 올림 `contentAssessment raised to SUPPORTED: lenient item` 확인용)
  - `errors`: `errorId, errorType, basis, description, question`
  - `phaseAfterSelection`, `attempts`(kind·outcome·error 300자), `rawOutput`, `requests`
  - 교정 칸이면 `repair: { answerText, judge, errors, phaseAfter }` 추가
- `--dry`: 칸 목록(label·조건·근거 글 앞 40자)과 칸 수·추정 비용(호출당 sol $0.055, luna $0.003)을 출력하고 끝.
