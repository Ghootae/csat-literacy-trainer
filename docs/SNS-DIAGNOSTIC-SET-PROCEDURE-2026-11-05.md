# SNS 진단평가 세트 제작 절차

- 작성: 2026-11-05, 코드 에이전트. 근거 결정: D-0200(모드 방향), D-0201(세트 E), D-0202(지금의 학생용 폐기), D-0151(분석 골드), D-0162(선지 연결).
- 쓰임: 진단평가 기본 세트, 확장 시험, 학생이 원해서 더 푸는 추가 문항 세트를 새 지문으로 만들 때.
- 상태: ①~⑤는 기존 절차·도구가 있다. ③′는 도구가 없어 설계 중이다. ⑥은 D-0200 "설계 확정 전에 풀 조건"이 남아 있다.

## 한눈에 보기

```
① 후보 추리기 → ② 세트 확정 → ③′ 판정용 원자료 묶음 → ③ 분석 골드 → ④ 선지 연결 → ⑤ 품질 확인 → ⑥ 진단평가 연결
```

- **③′는 판정에 필요하다.** 판정(문단 단순 형식, 문제 v5)은 골드를 쓰지 않고 원자료만 읽는다(D-0202 근거 절). ③′만 있으면
  판정까지 도는 최소 진단평가가 된다.
- **③·④는 결과 화면 분석에 필요하다.** 분석 지도는 독해 패턴(결과 화면 ③), 선지 연결은 걸린 함정(결과 화면 ②)의 재료다.
  판정 입력에는 쓰지 않는다(D-0002·D-0003·D-0162).

## ① 후보 추리기

외부 전송은 메가스터디 조회뿐이다. 판단은 코드 에이전트가 한다.

1. 수능 DB(`/Users/mac/Projects/suneung_db/output/`)에서 대상 시험만 남긴다. 기본 세트는 고3 수능·평가원(30세트).
2. 분야를 인문(예술·복합 포함)·사회·과학·기술로 나눈다. DB `category`는 비어 있거나 과학·기술을 나누지 않으므로 제목으로 나눈다(`fields.json`).
3. 어휘 문항(꼬리표 "어휘"·"문맥" 또는 발문 "문맥상")을 빼고 쓸 수 있는 문항 수를 센다.
4. 메가스터디 정답률을 붙인다. 세트–회차 대응은 `docs/experiments/megastudy-rate-coverage-2026-11-05/match.json`(158세트 전부).
   고3은 화법과작문(1004)·언어와매체(1005) 두 탭을 받아 평균한다. 정답 번호를 trainer 정답(`csat-literacy-trainer/data/enrichment/records/`)과 대조한다.
5. 분야마다 한 지문, 목표 문항 수(기본 15~17)가 되는 조합을 모두 따진다. 기준:
   - 쉬운 문항부터 어려운 문항까지 넓게(정답률 구간 <40·40~55·55~70·70~85·≥85).
   - **지문 안에서도 난이도가 퍼질 것.** 지문 하나가 통째로 어렵거나 쉬우면 분야별 결과가 지문 난이도와 섞인다.

도구·본보기: `docs/experiments/sns-diagnostic-candidates-2026-11-05/`(`build_candidates.py`, `spread_search_within.py`, 보고서 두 개).

## ② 세트 확정 (사용자)

조합 비교표(문항 수, 구간 분포, 지문별 범위, 새로 동결할 지문 수)를 보이고 사용자가 고른다. 결정 기록으로 남긴다(예: D-0201).

## ③′ 판정용 원자료 묶음 (외부 전송 없음)

개발자 경로가 판정에 쓰는 원자료를 새 지문·문항마다 만든다. **지금은 만드는 도구가 없다**(기존 6문항 묶음은 손으로 만들었다). 설계 확정 뒤 인계 문서로 실행한다.

| 산출물 | 위치(현행) | 내용 |
|---|---|---|
| 문항 묶음 | `packages/pipeline/fixtures/experiments/problem-solving/public/<questionId>.json` | 지문, 발문, 〈보기〉, 선지, 기호 표지 위치(`textAnnotations`), 이미지(`media`) |
| 정답·극성·해설 | `.../problem-solving/source-direct-runtime-v1.json`의 `questions[]` | `answerChoiceId`, `stemPolarity`, `officialExplanation` |
| 문단 요약용 지문 | `.../dialogue/passages/<passageId>.json` | 문단 목록, 출처, 연결 문항 |

확인: 기호 표지는 `scripts/audit-problem-source-markers.mjs`로 원문 대조, 정답은 trainer 정답 대조.

## ③ 분석 골드 (D-0151, `docs/ANALYSIS-GOLD-PROCEDURE-2026-10-20.md`)

| 단계 | 누가 | 외부 전송 |

## ⑤ 품질 확인과 교체

동결된 선지 연결로 결함 문항(예: D-0196 회사법 13번 ②)과 비틂 분포 쏠림을 본다. 문제가 있으면 같은 분야 다음 후보
(`spread-within-top.json`)로 바꾸고 ③′·③·④를 그 지문만 다시 한다.

## ⑥ 진단평가 연결 (미정, D-0200 설계 단계)

정답률 일괄 수집과 이용 범위(Q-0042), 문항 난이도 근사(Rasch)와 집단 보정, 학생용 표현(비틂 14종·관계 4갈래), 추천 대응표,
판정 연결(v5 판정만·사고 진단 즉시 실행·문단 1회 판정), 지문당 여러 문항 흐름(현행 문단 지문 파일은 연결 문항 하나,
`problemQuestionId`), 추천 최소 근거, 비용·대기 시간, 개인정보.
