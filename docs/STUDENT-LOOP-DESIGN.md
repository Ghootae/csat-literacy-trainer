# 학생 루프 설계

문단을 읽은 학생이 **서술형으로 요약 → 판정 → 피드백 → 재제출**하는 상호작용의 스펙.
평가 엔진(질의 보존 평가)이 무엇을 판정하는지는 `docs/ARCHITECTURE.md`가 다루고, 이 문서는
**그 판정을 학생에게 어떻게 돌려줄 것인가**를 다룬다.

> **상태 (2026-08-07):** 스펙 확정. **UI는 여전히 미구현**(`apps/` 없음) — 게이트·결과 화면·
> 재제출 루프는 화면이 없으므로 스펙으로만 존재한다.
>
> 코드에 반영된 것은 **평가·피드백 계층 5건**이다: S7 참고 세부 상한, 원칙 B(관계 증거 가드),
> N2-e `evidenceRole`, scope 증거 가드, S2 힌트 문구 4종.
> 화면 설계(§4.1.1~4.1.3 — 영역 주도·색 체계·3단 레이아웃)는 **확정됐으나 구현 전**이다.
> 항목별 상태는 §6 표를 본다.

## 근거

세 번의 조사에서 나왔다. 셋 다 **API 콜 없이** 또는 동결된 오라클 위에서 수행돼, 프롬프트를
건드리지 않고 설계 결정만 뽑아내도록 통제했다.

| 조사 | 대상 | 성격 |
|---|---|---|
| 1차 시뮬레이션 (2026-07-26) | 명실론 — 공손룡 vs 후기 묵가 | **반론·대립형**. 손 시뮬레이션, 기록은 `docs/NEXT.md`에 요약 |
| 교차검증 (2026-07-27) | 광합성 — C3/C4 | **과정형 + 문제-해결형**. `docs/experiments/student-loop-photosynthesis-2026-07-27.md` |
| N2 실험 (2026-07-29) | 광합성 P3(순환)·P5(분업) | 실제 골드·생성기 대조. `docs/experiments/n2-compression-2026-07-29.md` |

1차에서 가설 8개를 세우고, 2차에서 지문 유형을 바꿔 교차검증했다(6개 유지 / 1개 부분 반증 /
1개 위치 확정). 3차는 2차가 남긴 위험 가설(N2)을 실측으로 검증했고 — **반증됐다**(§5).

## 1. 상호작용 단위 — 2단 구조 고정

```
1단계  문단별 요약    문단 i를 읽고 핵심을 서술 → 문단 i의 영역별 판정
2단계  지문 전체 표제  지문 전체의 최상위 조직 관계를 한 문장으로 → 표제 판정
```

**양자택일이 아니다.** 과정형 지문(광합성 P2·P3·P5)은 문단이 조밀해 문단별 요약이 없으면
과정 세부가 통째로 날아가고, 반론형(명실론)은 전체 종합이 자연스럽다. 둘 다 필요하므로
2단 구조를 **모든 지문에 고정**하고, 지문 유형은 2단계 focal 후보 도출(§4)에만 반영한다.

2단계는 **별도 평가기가 아니다.** `regionSemanticVerdict`를 지문 최상위 조직 관계에 적용한
것이며 1단계와 동형이다. 실제로 같은 5값이 그대로 나온다:

> "광합성의 과정과 C3·C4 식물" → 주제만
> "C3 식물은 고온에서 효율이 떨어지는 한계가 있어 C4 식물이 대안으로 연구된다" → 관계보존
> "C4 식물의 효율이 낮아 C3 식물이 대안으로 연구된다" → 모순

## 2. 완료 게이트 (S1)

판정값이 다음 단계 진행을 막는지 여부. **모순만 막는다.**

| 판정 | 게이트 | 동작 |
|---|---|---|
| `contradicted` | **하드** | 다음 단계 차단 + 해당 항목 재제출 필수 |
| `region_not_evidenced` / `topic_only` / 불명확 | **소프트** | 넛지 제안, 학생이 무시하고 진행 가능 |
| `partial_relation_preservation` | **소프트** | 〃 |
| `relation_preserved` | 없음 | 참고 세부만 제시 |

- 하드 게이트는 **벌이 아니라 집중 교정 장치**다 — "여기만 고치면 통과". 재제출 범위는
  차단된 항목 하나로 좁힌다.
- **부분 정답 보존 (S5).** 하드 게이트는 모순 판정을 받은 **영역에만** 걸린다. 같은 응답의
  다른 영역이 관계보존이면 그 ●는 유지된다. (광합성 P3 경로 F: `dark_reaction` ● 유지 +
  `calvin_cycle` ✗ 차단.) 좌절 방지이자 국소 교정 유도다.
- 2단계 표제도 같은 규칙 — 단, 모순은 **focal 후보와 무관하게** 하드다(§4).

### 2.1 수정 흐름 (2026-08-07 확정)

```
결과 화면 표시
   │
   ├─ 모순 영역이 있으면 ──▶ 강제 수정. 해소해야 다음 문단으로 진행
   │
   └─ 나머지 ──▶ 학생이 고를 영역을 선택. **미달 영역마다 1회씩** (선택)
                    │
                    ├─ 성공 ──▶ 채움색 상승 + 간략 정답 공개 + 명제 표시
                    └─ 실패 ──▶ celeste 테두리 + 간략 정답 공개 (명제는 미표시)
```

- **영역당 1회다** (2026-08-07 개정 — 이전에는 문단당 1회). 각 미달 박스에 "다듬기" 버튼이
  하나씩 있다가 쓰면 사라진다. 남은 횟수를 세는 UI가 필요 없고, 같은 영역을 반복 시도하는
  **정답 맞히기 게임**이 구조적으로 막힌다.
- **문단당 1회로 묶었던 것을 되돌린 이유**: 니체 실행에서 수정 후 화면에 `r1`(주제만)과
  `r2`(부분관계)가 힌트를 단 채 남았는데 **고칠 방법이 없었다.** 넛지의 목적이 재독 유도인데
  재독할 길을 막는 것은 앞뒤가 맞지 않는다.
- 원래 우려("영역 분해 입도가 학습 부담을 결정한다")는 **수정이 선택이므로 상한일 뿐 부담이
  아니다.** 3개가 열려 있어도 학생은 0회를 고를 수 있다.
- **전체 영역을 순서대로 고치게 하지는 않는다.** 결과 지도를 먼저 보여주고 학생이 고를 영역을
  선택한다. 모든 미달 영역을 강제로 채우게 하면 학생은 결국 **원문을 최대한 재현하는 답**을
  쓰게 되고, 이는 요약 훈련의 반대 방향이다.
- 실패해도 진행을 막지 않는다. 정답을 확인했다는 것 자체가 획득이며 celeste 테두리로 남는다.
- 힌트는 **정답을 주지 않는다**(§3.1). 예: "삶과 가치라는 주요 개념을 잘 포착했어요.
  두 개념 사이의 관계가 드러나도록 수정해 보세요."

#### 재평가는 **전체**로 하고, 판정값은 그대로 표시한다 (2026-08-07 확정)

로그: `docs/experiments/student-loop-nietzsche-2026-08-07.md` (실제 골드·평가로 사이클 2회 실행)

| | 결정 |
|---|---|
| 재평가 범위 | **전체 응답 · 전체 질의**. 선택 영역만 다시 보지 않는다 |
| 판정값 표시 | **그대로**. 단조 유지(내려간 것을 가림)를 하지 않는다 |
| 직전 결과 | **보관** — 값을 바꾸려는 게 아니라 **변화를 알리려고** |
| 상승 | `○ → ●` 축하 표시 (S8 교정 이력) |
| 강등 | "이전에 있던 내용이 빠졌어요" 사유 표시 |

**부분 재평가를 쓰지 않는 이유.** `evaluateQueries`는 질의 개수와 무관하게 **1회 호출**이므로
비용이 절감되지 않는다. 반면 (a) 수정이 만든 **새 모순을 놓쳐** 하드 게이트가 조용히 실패하고,
(b) 한 섹션이 여러 영역을 뒷받침하므로 판정이 **이전 응답 기준으로 남고**, (c) 최종 화면이
서로 다른 시점의 혼합이 되어 "내 최종 답안에 대한 평가"라고 말할 수 없다.

**단조 유지를 쓰지 않는 이유.** 실험에서 **부당한 강등이 관찰되지 않았다.** 모든 변화가 내용
변화로 설명됐다 — 상승은 증거가 실제로 유입돼서, 강등은 학생이 그 내용을 지워서였고, 건드리지
않은 영역(`r1`)은 세 번 내내 불변이었다. 뒷받침: 3축 실험의 `regionSemanticVerdict` 반복
안정성 **100%**, 그리고 구조화 섹션 UI가 편집을 국소화한다.

없는 문제를 막으려다 **화면이 답안과 어긋나는 상태**를 만든다 — 학생이 내용을 지웠는데
화면은 ●와 정답·명제를 공개하게 되어, **"내 답안이 이걸 담고 있다"고 잘못 배운다.**

**강등을 보여주는 것이 오히려 학습적이다.** 칸이 나뉘어 있으면 학생은 "섹션 = 독립된 답"으로
착각하기 쉬운데, 3번을 고쳐 2번이 내려가는 것을 보면 **요약이 하나로 연결된 글**임을 배운다.
단조 유지로 가리면 이 학습 기회가 사라진다.

**관찰 대상**: 부당한 강등(편집이 그 영역의 증거를 건드리지 않았는데 판정만 흔들리는 것).
표본이 수정 2회·문단 1개뿐이라 단정할 수 없다. 실제로 나오면 그때 단조 유지를 도입한다.

## 3. 피드백 (S2)

### 3.1 오블리크성 스펙트럼

정답을 직접 주지 않는다는 원칙은 전 판정에 공통이고, **얼마나 우회하는지가 판정별로 다르다.**

| 판정 | 오블리크성 | 형태 |
|---|---|---|
| 모순 | 가장 낮음 | 어긋남을 지목 + **하이라이트된 원문에서** 핵심 질의를 되물음 |
| 부분관계 | 높음 | 한 축을 잡았음을 인정 + **미보존 축의 질의**를 되물음 |
| 주제만 | 높음 | 화제 포착을 인정 + **핵심 관계 질의**를 되물음 |
| 미포착 | 높음 | 인정할 것이 없다 — **위치만** 가리킴 |
| 불명확 | 중간 | 짚은 것을 인정 + 무엇을 덧붙이면 확정되는지 (미구현, §3.3) |
| 관계보존 | — | 포착한 관계 확인 + 참고 세부(감점 아님) |

#### 확정 문구 (2026-08-07 반영) — `buildFeedback`

```
관계보존   핵심 관계 「{expectedAnswer}」를 잘 포착했습니다. [+ 참고 세부 최대 3개]
부분관계   관계의 한 축은 잡았어요. "{미보존 핵심 질의}"도 함께 드러나도록 다듬어 보세요.
주제만     화제는 짚었어요. "{핵심 관계 질의}"에 답해 보세요.
미포착     이 부분은 요약에 나타나지 않았어요. 하이라이트된 문장을 다시 읽어 보세요.
모순       관계 방향이 원문과 어긋납니다. 하이라이트된 문장에서 "{어긋난 질의}"를
           다시 확인해 보세요.
```

**미달 4종은 골드를 노출하지 않는다.** 문구는 **안전한 필드만** 쓸 수 있다:

| 필드 | 미달 영역에서 |
|---|---|
| `expectedAnswer` · 영역 `label` · 명제 `shortForm` | ❌ 정답 노출 |
| 질의 `question` | ✅ **질문 형태라 답을 주지 않는다** |
| `sourceSentences` | ✅ 위치만 (하이라이트가 지목) |
| 학생 자신의 `evidence`·`viaItem` | ✅ 학생이 쓴 것 |

**구체성 수준은 B(템플릿 + 안전 필드)다.** A(판정별 고정 문구)는 문단이 바뀌어도 같은 문구가
나와 무의미해지고, C(LLM 생성)는 비결정적인 데다 **정답 노출을 구조적으로 통제할 수 없다.**
B는 노출 통제가 **필드 선택으로** 보장된다.

> **이전 결함 (2026-08-07 수정).** `topic_only` 문구가 `critical.expectedAnswer`를 그대로 끼워
> 넣어 정답을 공개했다 — *"…핵심 관계 「법인은 자산의 법적 권리·소유 주체이고, 실제 운용은
> 권한을 부여받은 사람이 수행한다 (역할 분리)」가 아직…"*. 위 원칙과 §4.1.3에 위배되고,
> 무엇보다 **학생이 수정할 이유를 없앤다.** 답을 이미 봤기 때문이다.

**되물을 질의를 고르는 규칙이 있다.** 모순이면 어긋난 질의를, 그 외에는 **아직 보존되지 않은**
핵심 관계 질의를 고른다. 이미 보존된 질의를 되물으면 학생이 무엇을 더 해야 할지 알 수 없다.

모순에서 오블리크성이 낮은 것은 의도적이다. 방향이 뒤집힌 이해는 넛지로 교정되지 않는다.
다만 **원문을 문구로 인용하지 않는다** — 3단 레이아웃(§4.1.3)에서 원문이 왼쪽에 있고
해당 문장이 하이라이트되므로, 인용은 중복이고 화면이 좁아진다. 하이라이트가 지목을 맡고
문구는 되물음만 맡는다.

교차검증에서 확인된 것: **과정형은 모순 되물음이 대립형보다 쉽다.** 대립형에서는 논지를
건드리지 않는 우회 질문을 짜내야 했지만("몇 개인가?"), 과정형은 원문의 방향 표현(…에서
생성된, …로 이동한 후, 다시)이 그대로 근거가 되어 정답 노출 없이 교정이 유도된다.

### 3.2 참고 세부 상한 (S7 · N1) — **반영 완료**

관계보존 피드백에 붙는 참고 세부는 **최대 3개**(`REFERENCE_DETAIL_CAP`, `assessment.ts`).

상한이 없으면 명제가 10개 넘는 과정형 문단에서 우수 응답에 5~7개가 붙어, "감점 요소는
아닙니다"라는 문구에도 불구하고 결손표로 읽힌다. **잘한 응답에 가장 긴 텍스트가 붙는
역전**이라 시각적 보상(S4)과 정면으로 충돌한다.

- 잘린 나머지는 **사라지지 않는다** — 결과 화면 오버레이의 ○(참고·미확인)로만 표시된다.
  `propositionEvidence`는 전량 그대로 유지되므로 오버레이 입력은 변하지 않는다.
- 선정 기준: `assess()`의 선택 인자 `propWeight`(명제 id → 전역 가중치 W) 상위.
  **채점이 아니라 무엇을 남길지 고르는 데만** 쓴다. 동률·부재 시 골드 순서로 폴백해 항상
  결정적이다.
- 잔여 개수("외 N개")는 **표기하지 않는다.** 개수 표기는 결손표 인상을 되살린다. 재검토 여지 있음.
- **잔여 작업**: 실제 W를 넘기는 호출자가 없다. `weights.ts`의 `globalWeight`는
  `GoldNode`/`NodeWeight` 위에서 동작하는데 질의 보존 파이프라인의 `Gold.propositions`에는
  가중치 필드가 없다. 두 구조를 잇기 전까지 기본 경로는 골드 순서다.

### 3.3 불명확(unclear) (S6)

> 학생: "암반응은 여러 물질이 관여하는 복잡한 순환 과정을 거쳐 포도당을 만든다."

원문 용어("순환")를 복창했으나 **무엇이 순환하는지 확인 불가**. 부분관계와 다르다 —
부분관계는 관계의 한 축이 실제로 보존된 것이고, 불명확은 보존 여부 자체를 판정할 수 없다.
지문 유형과 무관하게 재현됐다(명실론 P3 항목② ≡ 광합성 P3 경로 E).

**위치 결정: 판정축을 확장하지 않는다.**

- ✗ `regionSemanticVerdict`의 6번째 값 — 게이트 규칙·점수 롤업·`overallCategory`가 전부
  갈라진다(모순도 미포착도 아닌 값에 대해 차단 여부를 새로 정의해야 함).
- ✓ **질의 층위 evidence의 5번째 상태 + 피드백 레이어의 `clarify` 신호.**
  영역 판정은 `topic_only`로 접히고 게이트는 소프트(미포착과 동일).

> 「캘빈 회로의 순환」에서 "순환"을 짚었습니다. **무엇이 무엇으로 되돌아가는지** 써 보면
> 관계가 분명해집니다.

현재 코드에는 없다. `SemanticState`는 3값(`preserved`/`not_evidenced`/`contradicted`)이고
`PropositionEvidenceState`는 4값이다. 어느 쪽에 5번째 상태를 붙일지는 구현 시 결정한다.

## 4. 결과 화면 (S3 · S4 · N3)

### 4.1 위계 수형도 + 커버리지 오버레이

학생이 요약할 때는 골드를 보지 못하고, **결과 화면에서 처음 본다.** 정독 훈련 철학과 맞다 —
먼저 스스로 조직하고, 그다음 원문의 조직과 대조한다.

| 기호 | 의미 |
|---|---|
| ● | 직접 진술로 확인 (`evidenced`) |
| ◐ | 병치·함축으로 뒷받침 (`supported_by_abstraction`) |
| ○ | 참고·미확인 (`not_evidenced` — **결손 아님**) |
| ✗ | 모순 (`contradicted`) |
| ■ | 영역 판정 (`regionSemanticVerdict`) |

○이 "결손 아님"인 것은 평가 엔진의 정의와 같다 — 좋은 추상은 세부를 버린다.

**scope 증거는 명제를 뒷받침하지 않는다 (2026-08-05 반영).** 화제 이름표만 쓴 응답이
scope 질의를 통과시키면, 그 질의에 앵커된 명제들이 ◐로 칠해져 **오버레이가 채점축과 다른
말을 한다.** 실측(니체 문단): 학생이 "니체가 본 삶과 가치의 관계"만 썼는데 영역 판정은
`주제만`인 반면 명제 3개가 ◐였다. `scope`의 정의가 "화제만 지목"이므로 정의상 어떤 명제의
*내용*도 뒷받침할 수 없다.

- 판별은 질의의 **층위 라벨이 아니라 `evidenceRole`**로 한다(N2-e와 같은 이유). scope 질의에
  답하면서 관계를 진술했다면 그 증거는 `relation`이므로 명제를 뒷받침한다.
- **모순은 역할과 무관하게 전파**한다 — 잘못된 이해를 가리면 안 된다.
- 채점축(`regionSemanticVerdict`)은 영향받지 않는다. 회귀 3세트 수치 불변으로 확인.
- 부작용: scope 질의에만 앵커된 명제는 항상 ○가 된다. 그 명제를 건드리는 질의가 "이 영역은
  무엇에 관한 것인가"뿐이라면 학생은 그 내용을 보인 적이 없으므로 옳은 표시다.

### 4.1.1 결과 화면은 **영역 주도**다 (2026-08-07 확정)

§4.1의 오버레이만으로 화면을 구성하면 **주종이 뒤집힌다.** 명제 10~15줄이 화면을 채우고
채점축인 영역 판정은 헤더 한 줄로 밀린다. 니체 문단 실측에서 드러났다 — 학생이 세 영역을
정확히 나눠 짚었는데(`주제만` ×2) 화면은 ○ 12개로 덮여 **성취가 하나도 보이지 않았다.**

**화면의 주인공은 영역 박스다.**

| | 규칙 |
|---|---|
| 문단 구조 | 영역 개수만큼 박스를 놓아 "이 문단은 N개로 나뉜다"를 먼저 전달 |
| **명제 공개** | **관계보존 영역에만** 하단에 표시한다 |
| 미달 영역 | 정답 **미공개**. 위치와 판정만 |
| 응답 매핑 | 학생 응답의 어느 조각이 어느 영역에 닿았는지 표시 |

**명제를 성공 영역에만 공개하는 것이 핵심이다.** ○이 화면에 등장하지 않으므로 결손표 문제가
우회가 아니라 **소멸**한다. 원안 규칙("충족된 것은 간략화된 정답 공개 / 미충족은 위치만,
내용 비공개")과도 일치한다. 명제 오버레이는 **성취 표시 전용**이고 미달 표시로는 쓰지 않는다.

응답↔영역 매핑은 **추가 데이터가 필요 없다** — `query-eval`이 이미 `viaItem`(학생 항목)과
`evidence`(인용 구절)를 반환하고, 질의는 영역에 속한다. 실측: `viaItem="전통 형이상학의 문제"`
→ q5·q6·q7 → r2.

### 4.1.2 색·기호 체계 (2026-08-07 확정)

| 판정 | 채움색 | 기호 | 흰배경 대비 |
|---|---|---|---|
| `relation_preserved` | `#22C55E` 녹색 | ● | 2.28:1 |
| `partial_relation_preservation` | `#5EEAD4` teal | ◐ | 1.48:1 |
| `topic_only` · `region_not_evidenced` | `#9CA3AF` 회색 | ○ | 2.54:1 |
| `contradicted` | `#B91C1C` 진한 적색 | ✗ | 6.47:1 |
| **수정 확인** | 채움색 아님 — `#B2FFFF` celeste **테두리 + 뱃지** | | |

**주제만과 미포착을 같은 색으로 병합한다.** 색은 §4.2에서 **보상 장치**이므로,
`미포착 → 주제만`을 색으로 보상하면 학생은 **화제어를 갖다 붙이면 화면이 반응한다**는 것을
학습한다. 그것은 관계 이해가 아니라 "채점기가 원하는 요소를 넣는 훈련"이다.
**색은 관계를 잡았을 때만 움직인다.** 두 판정의 구분은 **힌트 문구**가 진다:

```
미포착  → "이 부분을 다시 읽으세요"          (통째로 빠뜨림)
주제만  → "이미 쓴 것에 관계를 더하세요"      (읽었으나 관계를 못 봄)
```

**수정 확인을 채움색에서 뺀 이유.** 5개 상태를 5개 채움색으로 표현하면 무리가 온다. 이것은
사실 직교하는 **두 축**이다 — 채움 = 도달 수준, 테두리 = 정답을 확인했는가. 분리하면
`● + celeste 테두리`(수정으로 도달)와 `● + 테두리 없음`(처음부터 도달)이 자연스럽게 구분되면서
**최종 상태의 가치에는 차등이 없다**(§4.2 S8 요구사항).

또한 "수정 실패"를 별도 채움색으로 두면 **시도한 학생이 안 한 학생보다 나쁘게 보여** 유인이
역전된다. 테두리는 "확인 완료"라는 **획득 상태**이므로 `회색 → celeste 테두리 → ●` 순서가
정상 방향이다.

**색만으로는 부족하다 — 기호를 반드시 병행한다.** 적록색맹(한국 남성 5~6%)에서 실측:

```
관계보존 ↔ 모순     정상 244 → 적록색맹 130    (진한 적색 채택 전에는 54였다)
부분관계 ↔ 회색     정상  92 → 적록색맹  75    ← 가장 가까운 쌍
```

색상은 적록색맹에서 수렴하므로 **명도차로만 가를 수 있다.** `#EF4444` 대신 `#B91C1C`를 쓴
이유다(대비 3.76:1 → 6.47:1). 그래도 부분관계·회색이 75로 가깝고 teal·celeste는 흰 배경 대비가
1.5 안팎이라, `● ◐ ○ ✗` 기호가 없으면 정보가 전달되지 않는다.

### 4.1.3 3단 레이아웃과 선택 연동 (2026-08-07 확정)

```
┌────────────────┬────────────────┬──────────────────────┐
│  원문           │  내 요약        │  평가                 │
└────────────────┴────────────────┴──────────────────────┘
```

**세 패널이 같은 좌표계를 공유한다.** 영역을 선택하면 세 곳이 함께 켜진다.

| 상태 | 원문 | 내 요약 | 평가 |
|---|---|---|---|
| 기본 | 표시 없음 | 표시 없음 | 박스만 |
| 영역 선택 | 해당 문장 **배경 틴트** | 해당 조각 배경 틴트 | 박스 선택 표시 |
| 다른 영역 선택 | 이전 것 해제 → 새 영역만 | 〃 | 〃 |

**배타적 단일 선택이다.** 한 번에 한 영역만 켜지고 기본 상태는 깨끗하다. 이 모델이 세 문제를
동시에 푼다:

- **문장 중복**: 실측상 영역들이 문장을 겹쳐 쓰는 경우가 있다(8개 문단 중 2개에서 1문장씩 —
  광합성 P3의 S4, P5의 S2). 배타적으로 칠하면 어느 색을 줄지 정할 수 없는데, 한 번에 하나만
  켜면 충돌 자체가 없다.
- **원문 가독성**: 영역 4개를 동시에 다른 색으로 칠하면 원문이 알록달록해져 정독을 방해한다.
- **집중**: §2.1이 "한 번에 한 영역 수정"이므로 선택 상태와 수정 단위가 일치한다.

**전체 조망은 박스 패널이 진다.** 박스 개수가 문단 분할을, 박스 색이 커버리지를 전달하므로
원문 위에 중복해서 그릴 필요가 없다.

**관계보존 영역도 선택할 수 있다.** 수정 버튼만 없다. 잘한 부분을 원문에서 짚어보는 것은
정독 훈련에 부합하고 §4.2의 시각적 확인 보상과 같은 성격이다.

**회색 글자가 아니라 배경 틴트다.** 텍스트에 회색을 입히면 "비활성"으로 읽혀 의도(선택됨)와
충돌한다. 글자색은 유지하고 배경에 옅은 음영을 깐다.

**미포착 영역을 선택하면 내 요약 패널에 아무것도 안 켜진다.** 그 영역에 대해 쓴 것이 없기
때문이며, 이것이 정확한 신호다 — "이 부분에 대해 나는 아무것도 쓰지 않았다"가 한눈에 보인다.

#### 박스 제목 — 미달 영역에서는 골드를 노출하지 않는다

| | 관계보존 | 미달 (부분관계·주제만·미포착) |
|---|---|---|
| 박스 제목 | 영역 `label` | **원문 문장 위치** (하이라이트로 지시) |
| 명제 | `shortForm` 목록 공개 | 미표시 |
| 골드 노출 | 허용 | **0** |

**영역 `label`을 미달 영역에 쓰면 안 된다.** label이 관계를 그대로 진술하기 때문이다:

```
"니켈 함량비에 따른 용량 증가와 안정성 저하의 트레이드오프"   ← 완전 노출
"하나의 실이 여러 명으로 지시될 수 있음"                    ← 완전 노출
```

**화제어만 뽑아내는 것은 지금 데이터로 불가능하다.** 콜론 파싱은 27개 영역 중 7개에만
적용되고, 되더라도 "결론: CO₂ 농축을…"처럼 무의미한 값이 나온다. 명제의 `relation.from`
최빈값도 불안정하다(니체 r1·r3가 둘 다 "삶"이 되어 구분 불가). 안정적으로 얻으려면 생성기에
`topicLabel` 필드를 신설해야 하고 이는 `v2` 범프 + 재측정이다.

**그럴 필요가 없다.** 응답↔영역 매핑이 그 자리를 채운다 — 화제어가 골드에서 올 필요 없이
**학생 자신이 쓴 표현**이 박스에 붙는다. 골드 노출이 원천적으로 0이고, 학생에게 인지적으로
더 가깝다.

#### 응답↔영역 매핑은 산문형에서도 작동한다 (검증됨)

`viaItem`·`evidence`가 목록형뿐 아니라 산문형에서도 조각을 잡아낸다. 니체 문단 산문 응답 실측:

```
q1~q4   viaItem="첫 문장"    evidence="삶 자체가 모든 가치의 뿌리이며…"     → r1
q5~q8   viaItem="둘째 문장"  evidence="도덕적 선을 삶보다 위에 두고…"       → r2
q9~q11  viaItem="셋째 문장"  evidence="목적과 수단이 뒤바뀐 사고"           → r3
```

목록형은 항목 제목이, 산문형은 문장 번호가 `viaItem`으로 나오고 `evidence`가 구절 단위로
정확히 인용한다. **추가 데이터·추가 호출이 필요 없다.**

### 4.2 수정 보상은 시각적 전환으로 (S4)

재제출로 판정이 바뀌면 **⚠→●, ✗→●의 하이라이트**가 보상이다. 텍스트 칭찬보다 강력하며,
"재독 → 다듬기" 습관의 강화 장치다. 최종 상태와 **교정 이력을 함께** 긍정적으로 표시한다 —
감점 회수가 아니라 성장 기록으로. (S8)

이 결정이 S7(참고 세부 상한)의 근거다. 보상이 시각 채널에 있으므로 텍스트 채널은 짧아야 한다.

### 4.3 2단계 표제 = focal **후보 집합** 채점 (N3) — **미구현**

교차검증이 H5를 부분 반증한 지점이다. 광합성 지문은 최상위 조직 관계가 **둘**이고, 둘 다
지문이 실제로 조직한 관계다:

- (a) **문제 → 해결**: C3의 한계 때문에 C4를 연구한다 (P4 → P5 → P6 축, 결말부가 닫음)
- (b) **대조 · 기제**: C3와 C4는 광합성 방식이 다르고 그래서 효율이 다르다 (P1 도입 질문 → P3 → P5 축)

`overallCategory(regions, focalId)`는 **focal 단수**를 전제한다(`assessment.ts`). (b)를 고른
정당한 표제가 (a)를 focal로 잡은 채점에서 `region_not_evidenced`로 떨어진다.

**스펙:**
- 후보 중 **하나 이상**에서 관계보존이면 인정.
- **모순은 후보와 무관하게 하드 게이트** — 모순은 어느 축에서 보든 원문 위반이다.
- 대립형은 후보가 1개라 기존 규칙이 특수해로 성립 → **상위 호환 변경**이다.

**선행 작업**: 후보 집합을 골드에서 도출하는 방법이 없다. 현재 골드는 문단 단위 `titleId`
하나뿐이고, **지문 층위 노드(문단 표제들의 상위 조직)가 아직 없다.** 이것부터 만들어야 한다.

## 5. 관계 압축 정책 — N2는 반증됐다 (정정본)

교차검증(07-27)이 제기한 N2는 다음과 같았다:

> ~~과정형 관계는 하위 유형마다 압축 허용도가 다르다(선형=양 끝만 이으면 관계보존 /
> 순환=되먹임 생략 시 부분관계 / 분업=한쪽만이면 부분관계). v0 생성기에 이 구분이 없으니
> 순환·분업에서 **과대평가** 위험이 있다.~~

**실험(07-29) 결과 실증되지 않았다. 과대평가 0건.**

- **분업**: v0가 엽육/유관속초를 각각 핵심 관계로 나눴고, `한쪽공간만` 프로브가 오라클·생성
  3세트 모두 부분관계로 4/4 일치. 프롬프트 수정 불필요.
- **순환**: 가설의 전제부터 틀렸다. v0는 3회 모두 순환을 **진행 축 + 되먹임 축** 두 핵심
  질의로 정확히 분해했다(손 오라클과 동형). 판정이 갈린 원인은 진행 축의 수용 기준으로,
  생성기는 "중간 산물 3탄당 누락 시 미보존"을 3회 모두 명시해 **오라클보다 엄격**했다.
  즉 어긋난 방향은 과대평가가 아니라 **과소평가**다.

**유지되는 관찰**: 분업은 두 항의 병치가 관계 자체다(4/4 일치로 확인).

**진짜 축**은 관계 유형이 아니라 **생략 대상의 종류**였다 — 기제(기공 폐쇄·결합 비율) 생략은
인정, 명명된 물질(3탄당) 생략은 불인정. 대조군 2개 + P4 기존 회귀가 모두 이 패턴이다.
**아무도 정한 적 없는 정책이고 문단마다 답이 다르다**(P4=관대, P3=엄격). → §7 N2-a.

### 5.1 부분관계는 상시 판정이다

`partial_relation_preservation`은 과정형에서 예외가 아니라 **상시 발생**한다(P3 순환·P5 분업
독립 발생). 1차 시뮬레이션 노트가 4값만 나열한 것은 대립형 편향이었다.

구조적 제약 하나를 기록해 둔다: `deriveSemanticVerdict`상 부분관계는 **핵심 질의가 2개
이상**이어야 발생한다. 핵심 질의 1개짜리 영역에서 중간 생략은 `주제만`으로 접힌다.

### 5.2 관계 증거 없이는 부분관계로 올리지 않는다 (원칙 B) — **반영 완료**

N2-b: argument 질의를 `criticalForRelation`으로 지정하면 **명칭 나열만으로 부분관계**가
나왔다(P5 run2 — 세포 이름 2개 나열이 핵심 질의 2개 충족). query-eval의 확립 원칙
("화제어만으로 관계 질의 통과 금지")과 충돌한다. 두 단계로 닫았다:

1. `450e750` — query-eval 프롬프트에 "관계 질의는 대상 목록이 아니라 연결을 요구한다" 명시.
2. **원칙 B** (`query-normalize.ts`) — 영역에 관계 층위 핵심 질의가 있는데 그중 보존된 것이
   0개면 논항이 full이어도 상한은 `topic_only`. `argumentCoverage`는 독립 유지(원칙 A).

관계 층위 핵심 질의가 **애초에 없는** 영역에는 가드가 적용되지 않는다 — 그런 영역에서는
논항 보존이 유일한 관계 증거다.

### 5.3 관계 증거는 질의 라벨이 아니라 증거 종류로 정한다 (N2-e) — **반영 완료**

원칙 B가 생성기의 **층위 라벨을 신뢰한다**는 약점이 있었다. 명칭 질의를 `level: relation` +
critical로 지정하면 이름 나열이 관계 증거로 통과했다(P5 gen1). 이를 `evidenceRole`로 닫았다
(`6aa62ca`, 로그 `docs/experiments/n2e-evidence-role-2026-08-02.md`).

**두 축을 가른다.** `semanticState`는 "질의에 답했는가"이고 질의별 수용 기준을 따른다.
`evidenceRole`은 "그 답이 어떤 종류의 증거인가"이고 수용 기준과 무관하게 정의만 따른다.
`preserved + entity_identification`("답은 했지만 관계 증거는 아니다")이 정상 조합이다.

`semanticState`를 낮추는 방식은 쓸 수 없다 — 학생은 명칭 질의의 답을 실제로 했고, 그 정보는
`argumentCoverage`가 정당하게 집계해야 한다(**원칙 A 위반**).

| 값 | 의미 |
|---|---|
| `relation` | 대상에 역할·방향·조건·인과·대조·순서가 배정됨 — **대상 개수 무관** |
| `entity_identification` | 대상·개수를 지목했을 뿐 연결이 없음 |
| `scope` | 화제만 지목 |
| `none` | preserved가 아닐 때 |

**판별축은 개수가 아니라 역할 배정이다.** `한쪽공간만` 프로브("엽육 세포에서 이산화 탄소를
붙잡아 4탄당의 형태로 저장")는 **대상이 하나인데 관계 증거**이고 기준선 기대값이 부분관계다.

원칙 B는 **"층위 AND 증거" 연언으로 좁혔다**(대체가 아니다) — `argumentQueries`에 있는 q6a는
오늘과 동일하게 동작하므로 §7의 q6a 미결은 그대로 열려 있다.

`relation_preserved` 분기에도 같은 가드를 걸었다. 이 분기는 원칙 B보다 **먼저 반환돼 가드를
전혀 받지 않았고**, 관계 층위 critical이 명칭 질의 하나뿐인 영역에서는 이름 나열이 곧장
관계보존으로 올라갔다. 실험에서는 `rebucketToOracle`이 가려줬을 뿐 production 경로에는
완전 과대평가로 열려 있었다.

## 7. 미결정

### N2-a — 명명된 중간 산물의 조건부 생략 허용 (**결정 + 실측 검증 완료, 2026-08-01**)

> 이 항목은 §7(미결정)에서 나왔다. 정책 결정 후 생성기 프롬프트를 v1으로 올리고
> **재측정으로 효과를 확인했다** — `docs/experiments/n2a-v1-remeasure-2026-08-01.md`.
> 목표 프로브가 오라클과 4/4 일치로 바뀌었고, 과대평가 0건이 유지됐다. 개정 유지 결정.

대상 응답: **"이산화 탄소로 포도당이 만들어지고 그 과정이 반복된다"** — 캘빈 회로의 전체
방향과 반복성은 담았으나 `3탄당`을 생략한다.

**원칙 F (재정의)**: 중간산물은 원문에서 명명되었다는 이유만으로 필수 논항이 되지 않는다. 
시작점·결과·관계 방향이 보존되고, 중간산물의 생략이 분기·조건·대조·인과 또는 순환의 성립 
원리를 제거하지 않는다면 생략을 허용한다. 중간산물의 명칭은 생략할 수 있지만, 그것이 
핵심적인 기능을 수행한다면 그 기능적 역할은 보존되어야 한다.

**판정 기준:**

| 평가 대상 | 판정 |
|----------|------|
| CO₂가 포도당으로 전환되는 전체 흐름 | `preserved` |
| 과정의 순환성 | `preserved` (대체로) |
| 3탄당이라는 명칭 | 생략 허용 |
| 3탄당의 분기·재생 역할 | 요구되는 슬롯이라면 `partial` |
| 모순 여부 | 모순 없음, 하드 게이트 불필요 |

**핵심**: "3탄당을 말했는가?"가 아니라 "3탄당이 담당하는 관계까지 이 요약에서 필요한가?"로 
판단하는 것. 이는 Query-Preservation 원칙과 가장 잘 맞는다.

### 생성기가 명칭 질의를 critical로 만드는 것 자체 (N2-e 잔여)

`evidenceRole`로 **채점은 안전해졌지만**(§5.3), 생성기는 여전히 명칭 질의를
`level: relation` + critical로 만든다. 평가 품질과 설명 가능성 문제로 남아 있다.

- 생성기 프롬프트에 "명칭·개수만 묻는 질의는 층위와 무관하게 critical 금지" 추가
- `GENERATOR_VERSION`을 **v2**로 올리고 P3·P5 재생성 후 재측정

안전장치가 이미 걸려 있으므로 **급하지 않다.** 다만 이걸 하지 않으면 학생이 받는 피드백에
"핵심 관계"로 명칭 질의가 인용되는 부작용이 남는다.

### 힌트가 문답 훈련을 유발하는가 — 관찰 대상

힌트에 질의 `question`을 넣기로 했다(§3.1). 방향이 명확해지는 대신, 학생이 **질문에만 답하고
요약 자체는 안 고칠** 위험이 있다 — 요약 훈련이 아니라 문답 훈련이 된다.

지금은 근거가 없어 결정할 수 없다. **학생 응답을 실제로 받아보기 전에는 판단하지 않는다.**
드러나면 되물음을 더 우회적으로(질의 전문 대신 관계 종류만) 바꾸는 것이 후보다.

### 부당한 강등 — 관찰 대상

재평가 범위는 §2.1에서 결정됐다(전체 재평가 · 단조 유지 없음). 남은 것은 그 결정의 전제가
계속 성립하는지다.

**부당한 강등** = 편집이 그 영역의 증거를 건드리지 않았는데 판정만 내려가는 것.
니체 실행에서 **0건**이었으나 표본이 **수정 2회 · 문단 1개**다. 실제로 나오면 그때
단조 유지를 도입한다. 나오지 않으면 장치를 만들지 않는다.

### 관계 서술어가 있는데 `주제만`이 나오는 경우

니체 실행에서 *"니체는 형이상학에 반대함"*이 `주제만`을 받았다 — **"반대함"이라는 관계
서술어가 있는데도.** 해당 핵심 질의가 *규정 + 반대 + 대조* 셋을 요구하는데 학생은 하나만
썼기 때문이며, 판정 자체는 기준대로다.

다만 **학생 입장에서는 "관계를 썼는데 왜 주제만이지?"** 싶을 수 있다. 힌트 문구가 그 간극을
메우는지는 실제 학생 응답을 받아봐야 안다.

### 모순 반복 실패

모순은 강제인데 학생이 계속 실패하면 무한 루프가 된다. 어느 시점에 원문 근거를 보여줘야
하는데, 그것은 정답 공개라 §3.1의 "정답을 직접 주지 않는다는 원칙은 **전 판정에 공통**"과
충돌한다. **원칙 변경이므로 별도 승인이 필요하다** — 실패 처리 세부로 슬쩍 들어와서는 안 된다.

### 점수 롤업 공식

두 시뮬레이션 모두 **롤업을 흔드는 학생 경로를 구성하지 못했다.** 결정 근거 미확보로 미결
유지. 후보는 `weights.ts`의 `globalWeight` 재사용.

### 오라클 fixture `q6a`의 층위 배치

법인격 지문 오라클의 `q6a`(역할 배정 질의)가 `argumentQueries`에 있어, 원칙 B의 결정적
계층에서는 단순 명칭 질의와 구분되지 않는다. 관계 무게를 유지하려면 관계 층위로 옮기는 것이
맞지만 **검증된 3축 실험 기준선을 건드리므로** 별도 결정 사항으로 남긴다.

### 목적 관계 / 목적 내용

목적 관계(q8)만 보존하고 목적 내용(q9)을 생략해도 좋은 추상으로 인정할지 — q8/q9 분리로
기록만 하고 정책 미결정.

## 8. 바꾸지 말 것

- 질의는 **불안정한 합성 노드가 아니라 문단 층위**에 정의, 원문 span·명제·관계 간선에 앵커링.
- 보존 여부와 암묵성은 **semanticState + expressionMode 두 축**으로 분리. 단일
  `implicitly_preserved` 상태 금지.
- 관계 질의는 **병치만으로 인정**(분리·대조·다르다 같은 표지어 불요). 한쪽 주체만 언급하면 불인정.
- 핵심 채점축은 `regionSemanticVerdict` **하나**. `argumentCoverage`·`expressionProfile`은
  `_debug`(실험 필드, 채점 제외).
- 명제 evidence는 **점수가 아니다** — 골드 명제 앵커링이며 근거·피드백·디버깅용.
- 학생은 요약 시 골드를 보지 못한다. 결과 화면에서 처음 본다.
