## 2026-08-11 · 타이틀의 추상화 보상은 defer한다

### 결정

타이틀 단계에서 **의미 보존과 명백한 누락은 안정적으로 판정할 수 있었으나, 의미 보존
추상화의 질을 일반적으로 평가하는 것은 불안정했다.** 특히 상위 표현이 생략된 세부축을
맥락적으로 포섭하는지 여부는 **사람에게도 해석 가능성이 갈렸다.**

타이틀의 추상화 품질은 progression gate가 아니라 **추가 보상**이므로, 이를 해결하기 위해
새로운 중요도 체계를 도입하는 대신 defer한다. 현재는 false-positive reward보다
**false-negative reward를 허용한다** — 잘 압축한 학생이 보상을 놓치는 것은 받아들이지만,
의미를 실제로 잃은 응답에 보상을 주기 위해 판정을 느슨하게 하지는 않는다.

### 타이틀 단계가 지금 재는 것 (안정 확인됨)

| | 기준 | 예 | 판정 |
|---|---|---|---|
| A | 과대추상 차단 | `광합성에 관한 내용` | 미포착 |
| B | 명백한 핵심 누락 차단 | 암반응 문단에서 `C3 식물 분류`가 사라짐 | 미달 |
| B' | 핵심 관계 제거 (관계형 문단) | 니체·형이상학은 언급하되 `대립`이 사라짐 | 미달 |
| C | 세부 나열은 기본 성공 | `…포도당 생성 과정·환경 조건·C3 식물 분류` | 관계보존 |

`shortForm`은 **"안전하게 의미를 보존한 기본 성공 예시"**다. 학생이 도달해야 하는 상한이
아니며, 다르게 표현했다고 불리하게 평가하지 않는다.

### 하지 않기로 한 것

**1. 중요도/weight 기반 축을 도입하지 않는다.**

`환경 조건`이 `과정`이나 `C3 분류`보다 부가적일 가능성은 있지만, 사례 하나의 결과에 맞춰
그렇게 해석하면 사후 합리화가 된다. 기존 `W`(`weights.ts`), `subsumedByParent`,
`introducesRelation`, hierarchy 구조는 **원래 "타이틀에서 생략 가능한 정보인가"를 판정하려고
만든 값이 아니다.** 이 문제 하나를 풀기 위해 새 중요도 규칙을 추가하지 않는다.

**2. 의미 포섭 판정을 프롬프트 튜닝으로 해결하려 하지 않는다.**

`메커니즘 ⊇ 과정 + 환경 조건`이 성립하는지는 사람 사이에서도 갈린다. 현재 엔진이 신뢰성 있게
측정할 수 있는 축으로 보지 않는다.

### 재본 것 (반복하지 말 것)

`npm run evalcase -- photosynthesis-p3-title-abstraction`으로 측정했다. 프로브는
`good-abstraction`(= `암반응 메커니즘과 C3 식물 분류`, 사용자가 좋은 타이틀로 판단한 응답).

| 시도 | good-abstraction | exemplar(나열) |
|---|---|---|
| 손으로 맞춘 스파이크 | 3/3 통과 | 통과 |
| 생성기 gen1 (기본) | 0/2 | qT3 뒤집힘 1/2 |
| 생성기 gen2 (축 굵기 제약) | 0/3 | 3/3 정상 |
| 생성기 gen3 (입증 책임 전환) | 1/3 | qT3 뒤집힘 2/3 |

**손 스파이크가 통과한 것은 기준에 답을 적어 넣었기 때문이다** —
*"'암반응 메커니즘'은 포도당 생성 과정과 환경 조건을 함께 덮는다"*. 그 힌트가 없으면 모델은
"메커니즘은 작동 원리, 환경 조건은 외부 조건"이라는 방어 가능한 판단으로 반복 수렴한다.
과적합이었고, 이 기록의 핵심이다.

두 시도가 메우지 못했다:
- **축 굵기 제약** — 생성기가 슬롯 세부를 축에 밀어넣어(`순환 절차(CO2+RuBP 결합→3탄당…)와 그
  명명`) 어떤 압축도 불가능해지던 것은 고쳤다. 명사구 하나로 제약하니 축 목록은 정리됐지만
  good-abstraction은 그대로 0/3.
- **입증 책임 전환** — *"덮는가"가 아니라 "빠뜨렸다고 단정할 수 있는가"*로 물었다. 1/3로
  올랐지만 대신 qT3가 흔들려 나열이 보상을 받기 시작했다.

전 구간에서 **안정적이었던 것**은 A·B·B'·C 넷이다. 불안정한 것은 이 한 축뿐이다.

### 구현 상태

- `content/`의 타이틀 질의는 **손으로 검증한 버전**을 유지한다. 생성 결과는
  `packages/pipeline/fixtures/title-queries/*-v2-gen*.json`에만 있고 설치하지 않았다.
- `title-gen.ts`는 새 축(qT2=누락 검사/argument 층위, qT3=보상)으로 두되, qT3에 defer 상태와
  "criticalForRelation을 true로 만들지 말 것"을 명시했다. 새 문단을 생성하면 A·B·C는 선다.
- `qT2`의 층위를 `relation` → `argument`로 옮긴 것은 **되돌리지 않는다.** 원칙 B가 핵심 *관계*
  질의에 `evidenceRole=relation`을 요구하는데 qT2는 커버리지를 묻는 질의라, 층위를 그대로 두면
  나열식 모범 답안조차 통과하지 못한다(3/3 재현). 기준 C가 그것 때문에 깨졌다.
- `good-abstraction` 프로브는 **지우지 않고** `deferred: true`로 남겼다. 실호출은 결과를
  보여주되 실패로 세지 않는다. 지우면 무엇을 미뤘는지가 사라진다.
- 불안정한 축이 기본 판정을 흔들 수 없다는 것을 회귀로 못박았다
  (`eval-case.test.ts` — qT3는 critical이 아니고, 뒤집어도 영역 판정이 변하지 않는다).

### 다시 열 조건

이 축을 다시 보려면 **판정 가능성부터** 확인해야 한다. 기준에 정답을 심어 통과시키는 방식은
검증이 아니다. 골드에서 파생되는 신호로 축의 무게가 정해지는지, 또는 포섭 판정이 힌트 없이
재현되는지가 먼저다.
