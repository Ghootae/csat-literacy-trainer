# 평가 엔진의 영역·질의 구성 프로세스

완성 상태: 2026-08-01  
목적: 위계 구조 → 평가 영역 정의 → 자동 질의 생성하는 **세 번째, 네 번째 단계** 설명

> ⚠️ **예시 데이터는 손으로 구성한 것이다 (미검증).**
> 아래 영역 `region_1~4`, 질의 `Q1~Q12`, 그리고 §6의 학생 요약 평가 예시는 설명을 위해
> **사람이 작성한 것**이며 `generateQuerySet()`이나 `assess()`를 실제로 실행한 출력이 아니다.
> 실제 생성기는 영역을 다르게 나눌 수 있고, 영역당 질의 개수도 3개로 고정되지 않는다
> (실측 예: 광합성 P5는 v0가 `r2`/`r3` 두 영역으로 나눴고 영역별 질의 수가 달랐다).
> **"영역마다 scope·relation·argument 세 층위를 둔다"는 원칙은 프롬프트에 실재하지만,
> "정확히 3개"는 이 문서의 설명용 단순화다.**
> 실제 생성 결과는 `packages/pipeline/fixtures/generated-queries/` 참조.

## 1. 입력: 합성 결과 (c1~c5)

이전 단계에서 만든 위계 구조:

```
타이틀 (c5): 공손룡의 명실론

├─ c1: 물·실·명의 정의
│  ├─ p1, p2, p3
│
├─ c2: 명의 기능
│  ├─ p4, p5, p6
│
├─ c3: 일대일 대응 규칙
│  ├─ p7, p8
│
└─ c4: 규칙 위반의 결과
   ├─ p9, p10, p11
```

## 2. 3단계: 영역 구성 — 학생이 뭘 요약해야 할까?

### 원칙

```
영역 = "학생이 정말 알아야 할 것"

타이틀 바로 아래의 합성 노드(c1~c4)가 각각 하나의 평가 영역이 된다.
```

### 영역 정의

#### **영역 1: 물·실·명의 정의**

| 속성 | 내용 |
|------|------|
| **영역 ID** | region_1 |
| **영역명** | 물·실·명의 기본 정의와 관계 |
| **포함 명제** | p1, p2, p3 |
| **학생이 알아야 할 것** | 물이 실로 분화되고, 명이 그것을 지시하는 구조 |
| **출처 합성 노드** | c1 |

#### **영역 2: 명의 기능**

| 속성 | 내용 |
|------|------|
| **영역 ID** | region_2 |
| **영역명** | 명이 하는 두 가지 기능 |
| **포함 명제** | p4, p5, p6 |
| **학생이 알아야 할 것** | 명은 실들의 차이를 구별하고, 사람들의 소통을 돕는다 |
| **출처 합성 노드** | c2 |

#### **영역 3: 일대일 대응 규칙**

| 속성 | 내용 |
|------|------|
| **영역 ID** | region_3 |
| **영역명** | 명과 실이 가져야 할 대응 관계 |
| **포함 명제** | p7, p8 |
| **학생이 알아야 할 것** | 한 실은 한 명으로만, 한 명은 한 실로만 지시되어야 한다 |
| **출처 합성 노드** | c3 |

#### **영역 4: 규칙 위반의 결과**

| 속성 | 내용 |
|------|------|
| **영역 ID** | region_4 |
| **영역명** | 일대일 대응을 안 지킬 때의 문제 |
| **포함 명제** | p9, p10, p11 |
| **학생이 알아야 할 것** | 규칙을 어기면 실을 구별할 수 없고 명 지시에 혼란이 생긴다 |
| **출처 합성 노드** | c4 |

## 3. 4단계: 질의 생성 — 각 영역의 3가지 질문

### 원칙

```
각 영역마다 정확히 3가지 질문을 만든다:

1. Scope 질문: "이 영역이 무엇에 관한 것인가?"
2. Relation 질문: "이 영역의 핵심 관계·주장이 뭔가?"
3. Argument 질문: "구체적인 요소·조건·결과는 뭔가?"
```

### 3.1 영역 1: 물·실·명의 정의 — 질의 세트

#### **Q1: Scope 질문**

```
질의 ID: q1
레벨: scope
질문: "이 부분은 물, 실, 명이라는 세 개념의 무엇을 설명하는가?"

기대 답변: 
  "물이 분화되어 실이 되는 과정과, 
   명이 그 실을 지시하는 역할"

학생 답변 검사:
  ✅ "명가 사상가가 정의한 물·실·명의 관계"
  ✅ "물에서 분화된 실을 명이 지시한다"
  ❌ "공손룡에 대한 일반적 설명"
     → 주제가 명확하지 않음 (미포착)
```

#### **Q2: Relation 질문**

```
질의 ID: q2
레벨: relation
질문: "물에서 실로, 그리고 명으로의 변화 과정은?"

기대 답변:
  "물은 아직 분화되지 않은 전체 상태이고,
   그것이 분화되어 각각의 개체(실)가 되며,
   명은 그 개체들을 구별하여 지시하는 역할을 한다"

학생 답변 검사:
  ✅ "미분화 상태 → 분화된 개체 → 지시"
  ✅ "물→실→명의 연쇄 과정"
  ⚠️ "물이 실로 변한다"
     → 기본 구조는 맞지만 명의 역할이 빠짐 (부분)
  ❌ "실이 물로부터 분화된다"만 언급
     → 명의 역할을 완전히 누락 (미포착)
```

#### **Q3: Argument 질문**

```
질의 ID: q3
레벨: argument
질문: "물, 실, 명의 구체적인 정의나 예시는?"

기대 답변:
  "물 = 아직 분화되지 않은 천지 만물 (전체)
   실 = 그로부터 분화된 각각의 개체 (흰 말, 검은 말 같은)
   명 = 그 개체를 지시하는 이름의 역할"

학생 답변 검사:
  ✅ "물은 전체, 실은 개체, 명은 지시하는 역할"
  ✅ "흰 말 같은 구체적 예시"
  ⚠️ "물과 실은 구체적인데 명의 예시가 없음"
     → 논항 부분 (부분)
  ❌ "물·실·명을 추상적으로만 설명"
     → 구체성 부족 (미포착)
```

---

### 3.2 영역 2: 명의 기능 — 질의 세트

#### **Q4: Scope 질문**

```
질의 ID: q4
레벨: scope
질문: "이 부분은 명이 하는 무엇에 관한 것인가?"

기대 답변:
  "명이 가지는 두 가지 기능 또는 역할"

학생 답변 검사:
  ✅ "명의 기능"
  ✅ "명이 하는 일"
  ❌ "공손룡의 이론"
     → 너무 광범위 (주제만)
  ❌ "명과 실의 관계"
     → 다른 영역의 주제 (미포착)
```

#### **Q5: Relation 질문**

```
질의 ID: q5
레벨: relation
질문: "명이 하는 두 가지 기능은 무엇이고, 
       그것이 어떻게 연결되어 있는가?"

기대 답변:
  "명은 실들 사이의 차이를 구별하게 하는 기능과
   인간이 사상과 감정을 나누게 하는 기능을 가진다.
   둘 다 명의 '지시 역할'에서 비롯된다"

학생 답변 검사:
  ✅ "명이 차이를 구별하고 소통을 돕는다"
  ⚠️ "명이 두 가지 기능을 한다"만 언급
     → 기능 자체는 맞지만 연결 관계가 부분적 (부분)
  ❌ "명은 소통을 돕는다"만 언급
     → 구별 기능을 완전히 빠뜨림 (미포착)
```

#### **Q6: Argument 질문**

```
질의 ID: q6
레벨: argument
질문: "인간이 사상과 감정을 나눈다는 것은 
       구체적으로 무엇을 의미하는가?"

기대 답변:
  "같은 명(단어)을 공유함으로써 의견을 전달하고
   감정을 표현할 수 있다는 뜻"

학생 답변 검사:
  ✅ "명을 통해 의견과 감정을 나눈다"
  ✅ "같은 단어로 뜻을 통한다"
  ⚠️ "감정을 나눈다"만 언급
     → 의견/사상 부분이 빠짐 (부분)
  ❌ "인간이 소통한다"
     → 너무 추상적 (주제만)
```

### 3.3 영역 3: 일대일 대응 규칙 — 질의 세트

#### **Q7: Scope 질문**

```
질의 ID: q7
레벨: scope
질문: "이 부분에서 공손룡이 주장하는 것의 주제는?"

기대 답변:
  "명과 실 사이의 대응 관계에 관한 규칙"

학생 답변 검사:
  ✅ "명과 실의 대응"
  ✅ "일대일 규칙"
  ❌ "명의 역할"
     → 이전 영역의 주제 (다른 영역 혼동)
```

#### **Q8: Relation 질문**

```
질의 ID: q8
레벨: relation
질문: "공손룡이 주장한 일대일 대응의 구체적인 내용은?"

기대 답변:
  "한 실은 오직 하나의 명으로만 지시되어야 하고,
   한 명은 오직 하나의 실만을 지시해야 한다"

학생 답변 검사:
  ✅ "명과 실이 1:1로 대응되어야 한다"
  ✅ "한 명은 한 실만, 한 실은 한 명만"
  ⚠️ "명과 실이 일대일이어야 한다"만 언급
     → 방향성이 모호 (부분)
  ❌ "명과 실이 다대다로 대응될 수 있다"
     → 반대 주장 (모순)
```

#### **Q9: Argument 질문**

```
질의 ID: q9
레벨: argument
질문: "일대일 대응을 어기는 구체적인 예는 무엇인가?"

기대 답변:
  "같은 명(예: '이것')으로 다른 실(이 사람의 '이것'과 
   저 사람의 '이것')을 지시하는 경우"

학생 답변 검사:
  ✅ "같은 명으로 다른 것을 가리키는 경우"
  ⚠️ "서로 다른 실이 같은 명으로 지시된다"만 언급
     → 한 방향만 설명 (부분)
  ❌ "혼란이 생긴다"만 언급
     → 구체적 상황 설명 없음 (미포착)
```

### 3.4 영역 4: 규칙 위반의 결과 — 질의 세트

#### **Q10: Scope 질문**

```
질의 ID: q10
레벨: scope
질문: "이 부분은 무엇에 관한 것인가?"

기대 답변:
  "일대일 대응 규칙을 안 지켰을 때 나타나는 결과"

학생 답변 검사:
  ✅ "규칙을 어기면 생기는 문제"
  ✅ "명-실 혼란의 결과"
  ⚠️ "공손룡의 주장"
     → 너무 광범위 (주제만)
```

#### **Q11: Relation 질문**

```
질의 ID: q11
레벨: relation
질문: "규칙을 안 지키면 구체적으로 어떤 결과가 생기는가?"

기대 답변:
  "같은 명으로 다른 실을 지시하면
   → 실들을 구별할 수 없게 된다
   → 명이 지시하는 대상이 불명확해진다
   → 혼란이 생긴다"

학생 답변 검사:
  ✅ "실을 구별할 수 없고 혼란이 생긴다"
  ⚠️ "혼란이 생긴다"만 언급
     → 인과 관계가 부분적 (부분)
  ❌ "결과가 안 좋다"
     → 구체적이지 않음 (주제만)
```

#### **Q12: Argument 질문**

```
질의 ID: q12
레벨: argument
질문: "혼란이 구체적으로 어떻게 나타나는가?"

기대 답변:
  "어떤 사람은 '이것'이라는 명으로 이것을 가리키고,
   다른 사람은 '이것'이라는 명으로 저것을 가리킨다면
   의사소통이 불가능해진다"

학생 답변 검사:
  ✅ "같은 명으로 다른 것을 지시해서 오해가 생긴다"
  ⚠️ "사람마다 다르게 해석한다"만 언급
     → 혼란의 결과가 부분적 (부분)
  ❌ "혼란이 생긴다"
     → 너무 추상적 (미포착)
```

## 4. 질의 생성 프로세스 (자동)

### 원칙

```
위의 12개 질의는 사람이 손으로 만든 것이다.

실제 평가 엔진에서는 이것을 자동으로 생성한다.
```

### 4.1 자동 생성 함수

**파일**: `packages/pipeline/src/llm/query-gen.ts` (1~240행)

```typescript
export async function generateQuerySet(
  input: GeneratorInput
): Promise<GeneratedQuerySet>
```

**입력**:
- 원문 문단
- 명제들 (p1~p11)
- 관계 간선들 (evaluationLinks)

**처리**:
1. LLM에 명제들을 전달
2. 각 영역마다 3가지 질의를 생성하도록 지시
3. 각 질의에 다음을 포함:
   - 질문 내용
   - 기대 답변
   - 근거 명제/문장
   - 평가 기준

**출력**:
```typescript
{
  paragraphId: "s1_p4",
  regions: [
    {
      regionId: "region_1",
      label: "물·실·명의 정의",
      queries: [
        { id: "q1", level: "scope", question: "...", expectedAnswer: "..." },
        { id: "q2", level: "relation", question: "...", expectedAnswer: "..." },
        { id: "q3", level: "argument", question: "...", expectedAnswer: "..." }
      ]
    },
    { ... 영역 2, 3, 4 ... }
  ]
}
```

### 4.2 생성 프롬프트 (GENERATOR_VERSION='v0')

**파일**: `packages/pipeline/src/llm/query-gen.ts` (90~130행)

```
원칙 A: 핵심 의미 구별을 평가하는 질의만
  - 의미 영역 찾기
  - 핵심 관계 보존
  - 필수 논항 표현
  - 핵심 관계 왜곡/반대 이해

원칙 B: 합성 노드가 아니라 의미 사실에 앵커링
  - 원문 문장 span / 명제 / 관계 간선 근거

원칙 C: scope·relation·argument 역할 혼동 금지
  - scope: 영역의 주제
  - relation: 핵심 관계
  - argument: 구체 대상·조건·결과

원칙 D: 관계 질의는 최소 충분하게
  - 같은 관계를 표현만 바꿔 중복하지 마라
  - 필수적인 관계는 누락하지 마라

원칙 E: 논항을 지나치게 묶지 마라
  - 서로 다른 정보는 별도 질의로

원칙 F: 명명된 중간산물의 조건부 생략 허용
  - 명칭은 생략 가능하나 기능적 역할은 보존 필요

원칙 G: 수용 기준은 판정 가능하게
  - 학생 응답을 실제로 구분할 수 있어야 함
```

## 5. 영역-질의 매핑 표

학생 요약이 들어올 때, 어디서 뭘 검사할 것인지:

| 영역 | 포함 명제 | Scope 질의 | Relation 질의 | Argument 질의 |
|------|---------|----------|--------------|--------------|
| region_1 | p1, p2, p3 | Q1 (주제) | Q2 (물→실→명) | Q3 (구체적 정의) |
| region_2 | p4, p5, p6 | Q4 (기능) | Q5 (두 기능의 연결) | Q6 (사상·감정) |
| region_3 | p7, p8 | Q7 (규칙) | Q8 (1:1 대응) | Q9 (위반 예시) |
| region_4 | p9, p10, p11 | Q10 (결과) | Q11 (인과) | Q12 (구체적 혼란) |

## 6. 학생 요약 평가 예시

### 학생 요약

```
"공손룡은 미분화된 전체(물)에서 개별 사물(실)이 분화되고, 
그 사물들을 이름(명)이 구별해서 지시한다고 했다. 
명은 사람들의 의사소통도 돕는다. 
그래서 명과 실이 정확히 일대일로 대응되어야 혼란이 없다."
```

### 평가 과정

#### **영역 1 검사**

```
학생 답변: "미분화된 전체(물)에서 개별 사물(실)이 분화되고, 
           명이 구별해서 지시한다"

Q1 (Scope): ✅ 물·실·명의 관계 파악 (명확)
Q2 (Relation): ✅ 물→실→명의 순차적 변화 파악 (올바름)
Q3 (Argument): ✅ "물=미분화 전체, 실=개별 사물" 구체적 (충분)

→ 영역1 판정: ⭐ relation_preserved (관계 잘 보존)
```

#### **영역 2 검사**

```
학생 답변: "명은... 사람들의 의사소통도 돕는다"

Q4 (Scope): ✅ 명의 기능 (주제 맞음)
Q5 (Relation): ⚠️ 소통 기능만 언급, 구별 기능이 위 문장에 숨어있음
               (명이 구별해서 지시 = 구별 기능)
               → 재검토 필요: 실제로는 두 기능 모두 포함
Q6 (Argument): ❌ 의사소통의 구체적 방식 설명 부족

→ 영역2 판정: 🟡 partial_relation_preservation 
   (소통 기능은 명확하나 구별과의 연결이 모호)
```

#### **영역 3 검사**

```
학생 답변: "명과 실이 정확히 일대일로 대응되어야"

Q7 (Scope): ✅ 규칙 (주제 맞음)
Q8 (Relation): ✅ "일대일 대응" 명확 (올바름)
Q9 (Argument): ⚠️ 구체적 위반 예시 없음 (위반 상황이 빠짐)

→ 영역3 판정: 🟡 partial_relation_preservation
   (규칙은 맞지만 위반 상황 예시 부족)
```

#### **영역 4 검사**

```
학생 답변: "[위 요약에서 규칙을 어기면 혼란이 없다는 것을 함축]"

Q10 (Scope): ✅ 결과의 주제 (암묵적으로 제시)
Q11 (Relation): ⚠️ 인과 관계가 암묵적만 있고 명시되지 않음
Q12 (Argument): ❌ 혼란의 구체적 상황 설명 없음

→ 영역4 판정: 🟡 topic_only
   (규칙의 필요성은 알지만 위반 시 결과가 명확하지 않음)
```

### 최종 평가

```
영역별 판정:
  region_1: ⭐ relation_preserved
  region_2: 🟡 partial_relation_preservation
  region_3: 🟡 partial_relation_preservation
  region_4: 🟡 topic_only

종합 판정:
  학생이 기본 구조는 이해했으나,
  영역 4(규칙의 정당화)와 영역 2(기능의 연결)이 부분적
```

## 8. 다음 단계: 5단계 평가

이제 준비가 완료되었다:

```
학생이 요약 제출
  ↓
[질의별 검사]
  영역1의 Q1, Q2, Q3으로 검사
  영역2의 Q4, Q5, Q6으로 검사
  영역3의 Q7, Q8, Q9로 검사
  영역4의 Q10, Q11, Q12로 검사
  ↓
[영역별 판정]
  각 영역에서 3가지 질의 결과로 종합 판정
  → regionSemanticVerdict (5값)
  ↓
[피드백 생성]
  포착한 관계 + 빠진 부분 설명
  ↓
[재제출 안내 (필요시)]
  하드 게이트 (모순): 해당 영역 재작성
  소프트 게이트 (부분/미포착): 선택적 개선 제안
```

## 9. 정리: 영역·질의의 역할

```
합성 노드 c1, c2, c3, c4
  ↓
각각 하나의 "평가 영역"이 됨
  ↓
각 영역마다 "3가지 질의"가 만들어짐
  ↓
학생 요약을 각 질의로 검사
  ↓
검사 결과 → 영역별 판정 (5가지)
  ↓
영역별 판정 → 학생 피드백 + 재제출 안내
```

이것이 평가 엔진의 핵심입니다.
