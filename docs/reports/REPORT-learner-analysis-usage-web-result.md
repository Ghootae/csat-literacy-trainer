# SNS 독해력 진단평가: 결과 화면 방향과 별도 규칙 (결정 기록 초안)

- 상태: **웹 에이전트 논의 결과 (결정 기록 초안)**. 2026-11-05 웹 프로젝트 스레드 "학습자 분석 활용 보고서 논의"에서 사용자와 정한 내용. 코드 에이전트는 이 문서를 바탕으로 결정 기록(D-NNNN)을 만들고 구현 범위를 정한다. "제안"이라고 적은 항목은 사용자가 명시적으로 확정하지 않은 웹 에이전트 제안이다.
- 출발 문서: `docs/reports/REPORT-learner-analysis-usage-desktop.md` (Q1~Q6). 이번 논의는 Q1·Q2·Q4·Q5와 Q3의 SNS용 추천(4-1절)을 다뤘고, Q6과 훈련 서비스용 Q3은 다루지 않았다.
- 범위: **SNS 진단평가 모드에만** 적용한다. 훈련 서비스의 기존 결정은 그대로 둔다.
- 개정(2026-11-06): 첫 판(2026-11-05)의 "교정 대화 없이 판정만", "요약 대화 없이 1회 판정"은 폐기. 문제 풀이·문단 요약 모두 본 서비스 과정을 유지하고 분석은 첫 응답만 쓴다(3절).

## 1. 왜 별도 규칙인가

지금까지의 결정은 실제 훈련 서비스를 전제로 했다. SNS 진단평가는 목적(대규모 자료 수집, 바이럴)과 사용 방식(익명, 한 번 참여, 결과를 바로 기대)이 달라서 몇몇 규칙을 이 모드에 한해 다르게 둔다(Ghootae, 2026-11-05).

## 2. 보는 사람 (Q1)

- 첫 대상은 **SNS 진단평가 참가자**. 참가 동기는 "내가 어느 위치에 있는지 확인하고 싶다"로 본다.
- 교사 시연(D-0198)도 같은 UI를 쓴다. 반 단위 집계는 나중에 붙인다.

## 3. 테스트 구성

- EBS 단추식 진단평가 형식. **4지문, 약 16문항**, 수능 기출로 구성(필요하면 새 지문 세트 마련).
- 문제 풀이는 **메인 서비스의 피드백 과정을 그대로 유지**한다(Ghootae, 2026-11-06). 문항마다 **선택 + 근거 입력**, 이어서 판정 → 교정 질문 → 다시 고르기/코칭.
  - 이유: SNS 진단평가의 진짜 목적은 본 서비스에 대한 실제 사람들의 응답·평가 수집이고, 부차적으로 본 서비스 유입이다. 판정만 하는 일반 진단으로 만들면 서비스의 매력이 크게 준다.
  - **첫 응답 원칙**: 결과 화면의 모든 분석(위치, 정답의 질, 무너진 단계, 걸린 함정)은 **첫 응답(첫 선택 + 첫 근거)에만** 근거한다. 교정 대화 뒤의 답은 분석에 넣지 않고, 교정 결과(`CORRECTED`/`REMAINING` 등)는 서비스 반응 자료로 따로 기록한다.
  - 제안(웹 에이전트, 미확정): **지문 단위 순서**. 같은 지문 안에서 앞 문항의 교정 대화가 뒤 문항의 답을 알려 주면 첫 응답이 오염된다(IRT 위치도 과대). 그래서 지문의 문항을 선택 + 근거로 먼저 다 풀고(첫 응답 확정), 그다음 틀린 문항과 근거가 약한 정답만 교정 대화로 돌아간 뒤 다음 지문으로 넘어간다. 교정 대화에는 "건너뛰기"를 둔다. 메인 서비스가 문항마다 바로 피드백하는 구조라면 진단평가 모드에서만 순서를 바꾸는 작업이 생긴다.
  - 근거를 쓰지 않을 때: CLI 논의에서 (나) "감으로 골랐어요" 버튼 안을 추천받았다(그 문항은 판정·사고 진단 미실행, 결과에 "감으로 고른 문항 수"로 표시, 감으로 맞힌 정답은 근거 있는 정답에서 제외). 사용자 확정 여부는 CLI 쪽 기록을 따른다.
- **문단 요약은 처음부터 선택 사항**. 선택한 경우 **본 서비스의 요약 과정(요약 대화 포함)을 그대로 유지**한다(Ghootae, 2026-11-06). 분석은 문제 풀이와 같이 **첫 요약(문단별 첫 차례)에만** 근거한다. 제안: 지문마다 시작할 때 선택을 묻고, 선택 여부를 기록한다(선택 편향 확인용).
- 시간 제한 없음. 풀이 시간에서 근거 입력 시간을 뺀다(제안: 둘 다 따로 기록).
- 기기: "PC·태블릿 강력 권장" 안내, 모바일 전용 UI는 따로 둔다. 제안: 지문 단위 저장, PC로 이어 하기 링크.
- 보유 자료: 수능 기출 문항별 정답률, 선지별 선택률(Ghootae 보유).

## 4. 결과 화면 (Q2)

순서: ① 내 위치 → ② 문제 풀이 결과 → ③ 독해 패턴(요약을 한 경우).

### ① 내 위치

- IRT로 고3 수험생 모집단 중 위치를 보인다. 지문 하나를 끝낼 때마다 위치를 **범위**로 보이고, 세트를 풀수록 범위가 좁아지는 시각화.
- 제안: 분포 곡선 위에 등급 띠(1등급 4%, 2등급 11% …)를 깐다.
- 주의: 평가원은 문항 모수를 공개하지 않으므로, 보유한 정답률로 Rasch 모형을 근사하고 자체 응답이 쌓이면 다시 보정한다. 시간 압박이 없고 근거를 쓰는 조건이라 "수능 기준 환산 추정"으로 표현한다.

### ② 문제 풀이 결과 (기본 제시)

1. **정답의 질**: 근거 있는 정답과 근거가 약한 정답(운)을 가른다. 판정기 v5 사용.
2. **무너진 단계**: 사고 진단 v0.1(발문 → 선지 해석 → 근거 위치 → 근거 해석 → 대조). 실제 학생으로 검증 전이므로 **개수로 말하는 "경향" 표현**으로 시작한다(예: "틀린 5개 중 3개가 근거 해석 단계에서 어긋났어"). 유형 단정은 하지 않는다.
3. **걸린 함정**: 고른 오답 선지의 비틂 종류(선지 연결 층 14종, 동결 자료). 분포가 아니라 목록으로.
- 문항 카드 예: 전국 정답률, 같은 선지를 고른 전국 비율, 비틂 설명, 내 근거와 원문 대조.
- 출제자 전략 글: 이미 풀이 과정에서 선택 사항으로 보이므로 결과 화면에 따로 두지 않는다.
- 빼는 것: 시간 × 정오(시간 제한 없음), 정답 경로 실패 노드(READ·LINK·APPLY, 2번과 겹침, 개발자용으로만).
- 따라서 학생 화면의 "왜 틀렸나" 분류는 비틂(내용)과 무너진 단계(과정) 두 축이다. D-0181의 두 축 재구성과 방향이 같다.

### ③ 독해 패턴 (문단 요약을 한 경우)

- 기본 제시
  1. **층별 패턴**: 요지는 잡고 세부를 놓침("큰 그림형") vs 세부는 옮기고 요지가 빔("나열형").
  2. **4갈래 강약**: 내용·논증·관점·흐름. 개인 단위는 갈래까지만(18유형은 표본 부족, D-0160 유지). 학생용 갈래 이름은 정해야 한다.
  3. **요약 ↔ 틀린 문항 연결**: 틀린 문항의 정답 근거가 요약에서 놓친 관계였는지. 요약은 잡았는데 틀렸다면 원인은 선지 해석·대조 쪽.
- 더 보기
  - 틀린 이해(`CONTRADICTS`) 실제 사례: 내 문장과 원문 나란히.
  - 문단 순번·분야별 추이.
- 주의: 원문 복사는 포착률 100%로 나오므로 걸러야 한다. 판단에는 포착률보다 오류율을 먼저 쓴다.

## 4-1. 추천 (Q3, SNS 진단평가 모드)

- 목적: 진단평가 뒤 "구독하면 이런 서비스까지 받는구나"라는 인상을 주는 것(Ghootae, 2026-11-05). 정밀한 추천 엔진이 아니다.
- 방식: 진단평가에 쓰인 16문항·약 80선지의 비틂 분석만으로 학생이 자주 걸린 비틂을 고르고, **비슷한 구조의 지문 세트 이름을 추천만** 한다. 예: "너는 대체로 ○○ 비틂에서 함정에 빠지는 경향이 있어. 비슷한 구조를 가진 지문 세트로 '…'를 추천해."
- 추천 대상 세트는 따로 분석하지 않는다. 수능 DB 전체에 선지 연결 층을 넓히지 않는다.
- 제안(웹 에이전트): 비틂 14종 → 추천 세트 1~2개의 작은 대응표를 사람이 직접 고른다. "비슷한 구조"라는 말이 대체로 참이 되게 하는 최소 장치다. 구독 뒤 실제 훈련에서는 이 대응표에 오른 세트(약 14~28개)부터 동결 절차를 밟는다.

## 5. 이 모드에서 기존 결정과 달라지는 점

| 기존 결정 | 훈련 서비스 | SNS 진단평가 모드 |
|---|---|---|
| D-0115 사고 진단 주기 실행 | 묶어서 주기 실행 | 지문을 끝낼 때마다 뒤에서 실행, 결과 화면 전에 완료 (참가자당 약 $0.2) |
| D-0176 학생 노출은 학생 확인 뒤 | 학생 확인 뒤 확대 | 검증 전 분석도 "경향" 표현으로 노출 |
| D-0183 요약 판정 노출 | 학생 확인 단계(2단계)에서, 수형도는 마지막 차례 | 이 모드에서 먼저 노출. 요약 대화는 유지하되 결과 분석은 첫 차례만(수형도 포함) |
| 문제 풀이 교정 흐름(D-0090 등) | 오류 → 교정 질문 → 코칭, 문항마다 | 흐름 유지. 분석은 첫 응답만. 제안: 지문 단위로 다 푼 뒤 교정 |

골드·선지 연결 층을 **판정 입력**으로 쓰지 않는다는 제약(D-0002, D-0003, D-0162)은 그대로다. 이 모드는 그 자료를 **결과 화면 표시**에만 쓴다.

## 6. 남은 일

- 사고 진단 정확도: SNS로 모인 실제 근거 일부를 사람이 검토해 첫 실제 검증으로 삼는다. 맞으면 표현 수위를 올린다.
- 학생용 갈래 이름, 비틂 14종의 학생용 표현.
- 4지문 선정(분야 분산, 비틂 분포), 문항 모수 근사 방법.
- 비틂 → 추천 세트 대응표 작성.
- 훈련 서비스용 추천(Q3), 학생 기록 형태(Q6)는 이번 논의에서 다루지 않았다.
- 개인정보 동의(만 14세 미만 법정대리인)와 근거 원문 저장 범위.
