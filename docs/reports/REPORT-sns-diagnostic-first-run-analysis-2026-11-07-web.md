## 1. 코드 에이전트 판정 엄격성 보고서 검토

### 1.1 보고서 요지
- 대상: 의식과 인지 14·16번(사용자가 처음 지적한 두 문항).
- 14번: 판정기가 v5.8 171행("참인 선지는 선지의 모든 주장이 지지되어야 한다")을 그대로 적용해 `INSUFFICIENT / MISSING_LINK`. 학생이 선지의 (a) "㉠은 지각 이전에 확정된 주체를 전제"를 다시 말하지 않았다는 이유. 지시문 위반은 아니지만 규칙이 지나치게 엄격하다는 해석.
- 16번: 학생의 "해석에 의존해 의미로 전환되는 상태"는 원문 "해석에 의존해서만 의미를 나타내는 상태"의 풀어쓰기인데 `CONTRADICTED`·CONTENT 오류. 선지 조건("막대의 진동은 해석에 의존")을 학생이 다시 말한 것도 UNDETERMINED. 교정 질문은 264-275행(답 표현 넣지 않기, "어떻게 설명" 꼴 금지)을 어겼다. 판정 자체가 틀렸다는 해석.
- M4가 추상적인 원인(가설): layout v2.2 207행이 "드러나지 않았다" 틀을 정하고, 187행(학생 문장 그대로 옮기지 않기)과 인용 검사(학생 근거 문장이 허용 모음에 없음)가 겹쳐 학생 말 인용이 실패·재시도되며 돌려 말하게 된다.
- lab과 같은가: 컨트롤러·판정 지시문·모델·M4 지시문·인용 검사 모두 같다. 차이는 `withoutInstantBubble: true` 하나.
- 제안 P1~P4 (보고서 6절).

### 1.2 [웹 의견]
- 요약: **14번은 규칙이 너무 빡빡해서, 16번은 판정이 틀려서** 생긴 문제다.
- **P2(판정을 바꾸지 않는 낱말 차이는 오류가 아님)**: 바로 해야 한다. "이 차이를 고치면 선지 판정이 달라지는가"라는 시험 기준이 깔끔하다.
- **P4(교정 질문 형식을 서버가 검사)**: 찬성. 규칙이 이미 있는데 어겼으므로 지시문에 문장을 더해서는 막기 어렵다. 프로젝트 원칙("평가자 추론보다 출력 칸 + 서버 검증")과 같은 방향. 표시한 원문 구절과 질문의 겹침, "어떻게 설명" 꼴은 기계로 잡을 수 있다.
- **P3(M4는 내용으로, 학생 말 인용 허용)**: 찬성. 인용 검사는 원문을 지어내지 못하게 하는 장치이므로, 학생이 실제로 쓴 문장은 허용 모음에 넣어도 된다. 화면에서 "네가 쓴 '인지 후'"처럼 출처를 구별하면 된다.
- **P1(선지에 적힌 연결은 다시 말하지 않아도 됨)**: 방향은 맞다. 사용자가 예전부터 "어떤 답은 그냥 통과시켜야 한다"고 지적한 것과도 맞다. 그러나 "정답의 질"의 정의 자체를 바꾸므로 가장 신중해야 한다. "학생 근거가 이 선지만 가르는 원문 사실이면 충분" 같은 조건을 걸고, 너무 관대해지지 않는지 회귀로 본다.
- 순서: 사례 2개에 맞춰 고치면 과적합 위험(회사법 ② 선지 때와 같은 함정). **나머지 지문도 먼저 풀어 사례를 모은 뒤**, 보고서 7절 실험(12회 호출)으로 원인을 가르고, P2·P4 → P3 → P1 순서로 원칙 단위로 고치자고 제안했다. 이후 사용자가 나머지 세 지문을 풀었다(3절).
- SNS 맥락: 정답을 맞혔는데 "근거가 부족해"를 듣는 것이 SNS 참가자에게 가장 나쁜 경험이다. **정답 쪽 거짓 판정을 오답 쪽보다 우선**한다.

## 2. 정답 판정과 오답 판정을 따로 할 것인가

### 2.1 [사용자]
> 정답 판정과 오답 판정을 따로 하는 편이 좋겠다는 생각이 드는데, 어떻게 생각해? 혹시 지금 그렇게 하고 있는지도 확인해줘.

### 2.2 [사실] 지금은 따로 하지 않는다
- 정답이든 오답이든 **같은 판정 지시문 하나**(`source-direct-problem-feedback-v5.8.md`, 41KB)를 쓴다.
- 다른 것은 모델뿐이다. `feedback-evaluator.ts`: `const correct = s.selections.at(-1)?.choiceId === s.source.answerChoiceId;` 로 갈라 정답이면 luna, 오답이면 sol.
- 지시문 안에서 정답·오답이 갈리는 곳은 몇 군데뿐이다.
  - 97행: "정답 선택에서 드러난 읽기 차이는 오류가 아니라 충족 판단에서 다룬다."
  - 158행: "정답 선택의 충족은 다음 순서로 본다. 1) 반박·지지 대상…"
  - 332행: "READING 오류는 … 오답 선택에서만 만든다."
- 나머지 오류 찾기 규칙(CONTENT·TARGET 오류, 오류 가설, sourceCheck)은 양쪽에 똑같이 걸린다.

### 2.3 [웹 의견] 찬성
- 두 판정은 하는 일이 다르다.
  - **오답 판정**: "무엇에 속았나"를 찾는다. 오류를 짚고 교정 질문을 만들어야 하므로 엄격한 것이 맞다.
  - **정답 판정**: "핵심을 짚고 맞혔나"를 확인한다. 기본값이 인정이어야 하고, 판정을 바꾸는 실제 모순이 있을 때만 오류다.
- 지금은 오류 찾기 규칙이 정답 쪽에도 걸려 16번처럼 같은 뜻의 다른 표현까지 오류가 된다. P1·P2는 사실상 정답 쪽 규칙이다. 한 지시문에서 정답 쪽을 느슨하게 고치면 오답 쪽까지 흔들리는데, 나누면 그 위험이 없다.
- 제안 방법
  - 오답 쪽은 v5.8 그대로(회귀 기록 유지).
  - **정답 쪽만 새 지시문.** 기준 둘: (1) 근거가 이 선지만 가르는 원문 사실을 짚었나, (2) 판정을 바꾸는 모순이 있나. 출력 칸도 줄일 수 있다.
  - 자료 경계·근거 기록 같은 공통 규칙은 한 곳에서 공유한다.
  - 정답을 맞혔지만 이유가 틀린 경우(회사법 같은 사례)도 교정으로 보낼 수 있게 **정답 쪽에도 오류 판정은 남긴다.**
  - 검증: lab의 정답 선택 사례(보고서 4.3절 기준 10건) + 세트 E.
- 대가: v5.1~v5.8 회귀 기록은 모두 공용 지시문 기준이라 정답 쪽은 회귀를 새로 쌓아야 한다.
- 3절 자료(사고 진단과 판정기가 5문항에서 갈림)가 이 방향의 근거가 된다.

   - B. 문제 풀이: 문제 5 — 틀린 부분 묻기 "표시한 부분에서 헌법재판소는 여론조사 결과 보도 금지 규정과 관련해 '언론의 자유'를 어떻게 다뤘어?" → 단순 확인만 하면 될 듯. 선지별 설명("선지의 '서로 충돌하는지'는 … 그러므로 ③은 적절하지 않은 선지, 즉 정답이야.") → 개발자 모드에선 지문에 해당 영역을 표시하도록 되어 있지 않나? 확인 필요. 문제 6: 과도하게 보수적으로 근거 판정.
3. 플라스틱의 중합 반응과 물리적 성질
   - 문제 8번: 부정 발문 → 틀린 것 중 하나만 맞으면 됨, 그러나 2개를 요구함. 이 부분은 개발자 모드를 만들 때 검토한 부분인데 적용이 안 된 것 같음. 확인 필요
   - 문제 10번: 근거가 불충분해도 정답 여부는 먼저 확인되어야 함. 근거로부터 이미 선지에 표현된 결론까지 채우길 요구함. 근거가 불충분한 정답 경우, 선택을 늘려야 할 듯
   - 1) 근거 불충분, 오류인 경우 → "정답을 맞췄어. 하지만 네가 제시한 '근거가 불충분했어 / 근거에 오류가 좀 있었어.'" → "네가 제시한 근거를 같이 자세히 검토해볼까?" → 선택(근거 검토 or 다음 문제) → 근거 검토를 한 후 → 정답 확인도 선택: "네가 제시한 근거에서 어느 부분이 보완되어야 할지 같이 검토해봤어. 검토 후에 3번이 정답인 이유가 명확히 파악됐어? 만약 그렇다면 다음으로 넘어가도 좋아. 아직 불충분하다면 3번이 정답인 이유를 '처음부터' 같이 꼼꼼히 따져보자."
4. 오디오 신호의 디지털 저장과 지각 부호화 압축
   - A. 문단 요약: 1) 문단 1 디테일을 확인하는 경향 발견 2) "차폐가 작은 소리를 가리는 점과 임계대역의 범위, 그리고 차폐를 압축에 이용한다는 점은 짚었네. 연결되는 한 가지를 더 확인하고 싶어. 차폐를 고려하면 실제 청각이 감지할 수 있는 최소 소리는 어떤 기준으로 정해질까?" → 굳이 이렇게 질문해야 할까? 답이 정해진 질문은 그에 맞춰서 질문해야 하지 않을까? 3) 문단 5: "임계대역마다 문턱값을 구하고, 그 차이에 따라 비트를 할당하거나 작은 소리를 제거하는 방법은 짚었네. 확인하고 싶은 점이 하나 있어. 이런 압축은 소리의 품질을 어떻게 다루는 기술이라고 했어?" → 필수적이지 않아 보임.
   - B. 문제 풀이: 1) 개발자 모드에선 응답 후에 바로 정답 여부를 코드 베이스로 보여줬던 걸로 기억함 → 동일하게 적용되는지 확인 2) 문제 16: 충분히 추론 가능한 결론을 요구함. 개발자 모드에 비해 근거 분석이나 정답 설명이 짧은 경향이 보임. 같은 판정기를 쓰는지 확인 필요. 3) 문제 17: "표에서 C와 D의 소리 크기와 차폐 문턱값의 차이는 각각 얼마야?" → 너무 디테일을 강요하는 질문, 틀린 부분 묻기 질문이 2단계(계획대로인지 확인 필요)
5. 최종 분석
   - 1) 적절한 근거가 4개밖에 안 돼? 다시 확인 2) "근거를 살펴본 9문항 중 3개가 근거 해석 단계에서 어긋났어." → 근거 쓴 건 13이라고 하고 왜 여기선 9문항이지?
6. 일반적
   - 1) 한 지문 세트에 대한 요약과 풀이 완료 후 분석 → 같은 화면에 후속 설명을 받을 문항을 선택할 수 있게 → 선택한 문항만 후속 피드백을 거칠 수 있도록. 예시: 문제 12(정답, 근거 충분, 선택 안 되게), 문제 13(정답, 근거 불충분, 선택 가능), 문제 14(오답, 근거 오류, 선택 가능), 각 케이스는 색깔로 표시
   - 2) 추천 문항 제시가 필수적(차후 과제)

### 3.3 문제 풀이: 문항별 분석

각 문항의 원문(발문·선지)·근거·판정 이유·사고 진단 메모·대화 전문은 부록 A.

#### 의식 14 — 판정이 지나치게 엄격 (P1)
- 근거: "(나)의 논지는 주체와 대상 분리가 인지 후에 나타난다는 것. 따라서 확장된 인지 이론을 타당하지 않다고 볼 것."
- 판정: INSUFFICIENT / MISSING_LINK. 선지 ①의 (a) "지각 이전에 확정된 주체를 전제"를 학생이 말하지 않았다는 이유.
- 사고 진단: 전 단계 PASS.
- [웹 의견] 학생 근거는 (나)의 핵심 전제(주체·대상은 지각 뒤에 확정)를 정확히 짚었고, 이 사실은 다섯 선지 중 ①만 가른다. (a)는 선지 문장에 이미 있는 연결이다. P1 대상. 다만 (a)가 ㉠의 함의를 추론하는 이 문항의 진짜 어려운 지점일 수 있다는 반론(보고서 5.1)도 있어, P1에 조건을 거는 이유가 된다.
- M4 문장 "…이어지는 설명은 드러나지 않았어"는 A3(추상 문체)의 대표 사례.

#### 의식 16 — 판정 오류 (P2) + 질문 형식 위반 (P4)
- 근거: "막대의 진동은 해석에 의존 그리고 파생적 상태는 해석에 의존해 의미로 전환되는 상태 그러므로 막대 진동은 파생적 상태"
- 판정: ERROR(CONTENT). 교정 질문 "표시한 부분에서 파생적 상태는 주체의 해석에 의존해 의미를 나타내는 상태를 어떻게 설명해?"
- 사고 진단: 전 단계 PASS.
- [웹 의견] "의미로 전환되는"과 "의미를 나타내는"의 차이는 ③의 판정을 바꾸지 않는다(P2). "막대의 진동은 해석에 의존"은 선지 ③이 직접 준 조건이라 원문 대조 대상이 아니다. 교정 질문은 원문의 답 표현을 질문에 넣었고 "어떻게 설명" 꼴이다(v5.8 264-275행 위반). 규칙이 있는데 어겼으므로 서버 검사(P4)가 맞다.

#### 경마 5 — 판정은 맞음, 질문 방식이 무거움
- 근거: "헌법제판소 논의는 언론의 자유와는 상관이 없음."
- [사실] 원문은 헌법재판소가 여론조사 결과 보도 금지 규정이 국민의 알 권리와 언론의 자유를 침해하는지 다뤘다고 한다. **근거가 원문과 실제로 어긋나므로 ERROR 판정은 맞다.** 사고 진단도 ERROR(근거 해석, MISREAD_FACT).
- 교정 질문: "표시한 부분에서 헌법재판소는 여론조사 결과 보도 금지 규정과 관련해 '언론의 자유'를 어떻게 다뤘어?" → 학생 답 "언론의 자유를 다뤘어." → 교정 성공.
- [웹 의견] 사용자 지적대로 확인형("헌법재판소는 이 규정이 언론의 자유를 침해하는지 다뤘어, 다루지 않았어?")이면 충분했다. 현재 질문 규칙(답 표현을 질문에 넣지 않기)과 확인형 질문이 부딪히는지 코드 에이전트가 확인해야 한다. 확인형은 답을 거의 알려 주는 셈이라 규칙상 금지됐을 수 있다. 그렇다면 "어떤 오류는 확인형이 낫다"를 규칙으로 다룰지 논의가 필요하다.
- 선지별 설명에서 "지문에 해당 영역 표시": 대화 기록에는 원문 표시 정보가 없다. 진단 화면이 판정의 `sourceEvidence`/highlights를 지문 표시로 연결하는지 확인 필요(B4).

#### 경마 6 — 판정이 지나치게 엄격 (P1)
- 근거: "a는 제한이 합리적이란 입장. 2번 선지의 케이스는 제한에 의해 불합리가 발생한 경우 그러므로 a의 입장이 약화될 것."
- 판정: INSUFFICIENT. 판정 이유 요지: "불합리한 사례라는 평가를 근거로 되풀이했을 뿐, 이를 뒷받침하는 원문 사실을 별도로 제시하지 않아 판단 근거는 충분하지 않다."
- M4: "선지에서 답을 가르는 말은 '…정치 신인'이 초청받지 못하는 상황이야. 이 구체적인 상황이 왜 제한을 부당하게 보이게 하는지는 원문 사실을 들어 설명해야 해."
- 사고 진단: 전 단계 PASS. note "ⓐ를 제한의 합리성을 인정하는 입장으로 정확히 파악하고, 2번의 사례가 제한의 불합리성을 드러내므로 ⓐ를 약화한다는 연결을 제시했다."
- [웹 의견] 학생은 ⓐ의 입장과 약화 방향이라는 문항의 핵심을 짚었다. 요구된 "구체적 상황"은 선지 문장에 이미 있다. P1 대상.

#### 플라 8 — 판정 UNKNOWN: 원인이 사용자 추정과 조금 다름 (C2)
- 발문: "윗글에서 알 수 있는 내용으로 적절하지 않은 것은?" ④ "불안정한 원자를 가진 에틸렌은 과산화물을 개시제로 쓰면 분해되면서 안정해진다."
- 근거: "과산화물 개시제가 되면 안정적인 분자 구조가 불안정화됨."
- 판정: UNKNOWN. **판정 이유 원문**: "이 말만으로는 그 구조가 에틸렌을 가리키는지, 선지의 에틸렌 관련 주장을 거짓으로 판단한 것인지 확인하기 어렵다. … 학생의 표현과 선지 판단 사이의 대상·관계가 확인되지 않아 전체 판단을 재구성할 수 없다."
- 사고 진단: 전 단계 PASS. note "과산화물 개시제와의 반응으로 에틸렌이 불안정해진다는 근거를 들어 '안정해진다'는 4번 선지를 부적절하다고 판단했다."
- M4: "네 말만으로는 ④의 '불안정한 원자를 가진 에틸렌'이라는 주장까지 판단한 건지 알기 어려워."
- [웹 의견, 수정] 사용자는 "부정 발문인데 2개를 요구했다"고 봤다. 판정 이유를 보면 **UNKNOWN의 직접 원인은 "두 주장 요구"가 아니라 "대상 모호"**다(근거 문장에 주어가 없어 무엇이 불안정화되는지 판정기가 확정하지 못함). 다만 그 결과 M4가 "'불안정한 원자를 가진 에틸렌'이라는 주장까지"라고 말해, 사용자에게는 다른 주장을 요구한 것으로 보였다. 두 가지를 함께 본다.
  - (1) 거짓 선지는 한 지점 반박이면 충분하다는 원리가 지시문에 있는지, 있다면 UNKNOWN 경로에서도 지켜지는지.
  - (2) 근거의 대상이 생략됐을 때 선지·발문 문맥으로 대상을 채워 읽는 관용이 필요한지(사고 진단은 채워 읽었다). 이것도 정답 쪽 판정 기준(P1·P2 계열) 문제다.
- M4가 UNKNOWN 사유(대상 모호)를 학생에게 말하지 않고 다른 주장 이야기를 한 것은 A3(M4 품질) 사례이기도 하다.

#### 플라 9 — 유일한 오답, 정상 동작으로 보임
- 근거: "탄소는 전자 두쌍을 공유." 교정 질문: "\"탄소는 전자 두쌍을 공유.\"라고 했지. 표시한 부분에서 에틸렌의 이중 결합 중 더 약한 결합이 끊어진 뒤, 그 두 탄소 원자가 공유하는 전자쌍은 몇 쌍이야?" → "모르겠어" → 정답 공개·코칭.
- 사용자 코멘트 없음. [웹 의견] 오답 쪽(sol) 동작은 설계대로로 보인다.

#### 플라 10 — 판정이 지나치게 엄격 (P1) + 정오 표시 순서 (B1)
- 근거: "(나)는 결정화된 플라스틱 -> 화학적으로 안정적."
- 판정: INSUFFICIENT. M4: "네가 든 근거는 ㉯가 화학 물질에 덜 민감하다는 데까지야. 선지는 '㉮보다 ㉯로 이루어진 소재를 쓰는 것이 좋겠군'이라고 ㉮와 ㉯를 비교하므로, ㉮보다 ㉯가 더 적합한 이유까지 연결해야 해."
- 사고 진단: 전 단계 PASS.
- [웹 의견] 비교 결론은 선지 문장에 있다. P1 대상.
- 정오 순서 [사실]: 대화 순서가 "네 근거에서 맞는 부분은 살리고, 더 이어야 할 연결은 설명에서 같이 볼게." → "네 근거를 하나씩 같이 볼까?" → "③을 고른 건 맞아."다. 학생은 **맞았다는 말보다 "부족하다"를 먼저 듣는다.** 진단 모드가 즉시 정오 말풍선을 끈 영향이다(B1).

#### 오디오 16 — 판단이 갈릴 수 있는 사례
- 근거: "임계대역은 차폐가 일어나는 범위를 의미."
- 판정: INSUFFICIENT. M4: "⑤는 '주파수 차이가 임계대역의 폭보다 크면' 차폐가 일어나지 않는다고 했어. 네 근거는 … 주파수 차이와 그 범위의 폭을 비교하는 조건까지는 설명하지 않았어."
- 사고 진단: **INSUFFICIENT**(이 문항만 두 분석기가 같은 판단). note "필요한 근거는 정확히 제시했으나, 주파수 차이가 그 폭보다 크면 차폐가 일어나지 않는다는 선지 판단까지 연결하지는 않았다."
- [웹 의견] 근거가 정의만 말하고 선지 판단(정의 → 조건 적용)으로 잇지 않았다는 판단은 가능하다. 사용자는 "충분히 추론 가능한 결론"이라고 봤다. P1을 설계할 때 **경계 사례**로 쓴다(새 지시문이 이 문항을 어떻게 판정해야 하는지 사용자와 정해야 함).
- "개발자 모드보다 근거 분석·정답 설명이 짧다": 판정기·M4 지시문이 같다는 것은 확인됨. 짧게 느껴진 이유는 기록만으로 확정 못 함(B6).

#### 오디오 17 — 판정은 맞음, "2단계 질문"의 정체와 사소한 지적 (C1, A3)
- ⑤ "압축할 때는 C의 소리 크기보다 D의 소리 크기에 더 많은 비트가 할당되겠군."(정답)
- 근거: "C에서 실제 크기와 문턱값 사이의 차이가 더 큼 -> 더 많은 비트 할당"
- [사실] 표에서 C 차이 63−38=25dB, D 차이 55−6=49dB. 근거는 사실과 다르고(C가 더 큼), 근거대로라면 C에 더 많이 할당되므로 ⑤를 고른 것과도 맞지 않는다. **ERROR 판정은 맞다.** 사고 진단도 ERROR(근거 해석 FAIL, 대조 FAIL, 태그 MISREAD_FACT·DIRECTION).
- **[사실] "2단계 질문"의 정체**: `session.errors`에 **오류가 2개** 있다.
  - 오류 1(CONTENT): "C의 차이가 D보다 크다는 주장은 표의 값과 어긋난다." → 질문 "표에서 C와 D의 소리 크기와 차폐 문턱값의 차이는 각각 얼마야?" → 학생 "C: 26, D: 49"
  - 오류 2(CONTENT, 설명 "선택이 뜻하는 판정과 근거에서 도출되는 판정이 다릅니다.") → 질문 "\"C에서 실제 크기와 문턱값 사이의 차이가 더 큼 -> 더 많은 비트 할당\"이라고 했지. 그러면 이 선지는 적절한 설명이야, 적절하지 않은 설명이야?" → 학생 "적절하지 않음"
  - 즉 2단계는 "한 오류를 두 번 묻기"가 아니라 **사실 오류 + 선택·근거 불일치 오류를 차례로 물은 것**이다. 규칙상(오류마다 교정) 설계대로일 수 있다.
- [웹 의견] 그래도 문제다.
  - 두 오류는 **같은 뿌리**(C와 D를 바꿔 본 한 번의 실수)다. 첫 질문에서 학생이 "D가 더 크다"는 수치를 냈으면 불일치도 사실상 풀린 셈인데, 다시 물었다. 같은 뿌리의 오류는 묶거나, 앞 오류가 고쳐지면 뒤 오류를 다시 판정해 건너뛰어야 한다.
  - 두 번째 질문은 발문이 "적절한 것은?"인데 "적절한 설명이야, 적절하지 않은 설명이야?"를 섞어 물어 헷갈리기 쉽다. 학생 답 "적절하지 않음"은 이 혼동일 수 있다.
  - 교정 판정(REPAIR, luna) 이유: "'C: 26, D: 49'라고 답해, C의 차이가 D보다 크다는 기존 판단은 바로잡았습니다. 다만 표에서 C의 차이는 63-38=25이므로 26이라는 새 계산 오류가 확인됩니다." → M4도 "C의 차이를 26dB라고 한 계산은 아직 맞지 않아"라고 짚었다. **1dB 차이는 판정(D가 더 큼)을 바꾸지 않으므로 P2 위반.** 교정 판정에도 P2가 필요하다.
  - 첫 질문 "각각 얼마야?"는 사용자 말대로 계산 세부를 강요한다. "C와 D 중 어느 쪽의 차이가 더 커?"면 충분했다.
