# csat-literacy-trainer

수능 국어 비문학 **정독 훈련** 도구. 학생이 문단을 자유롭게 요약하면, 그 요약이 문단의
**핵심 관계를 어느 수준까지 보존했는지** 판정하고 고칠 곳을 짚어 준다.

개인 프로젝트이고 프로토타입 단계다. 실제 학생 데이터는 아직 없다.

---

## 무엇이 다른가 — 채우기가 아니라 보존

흔한 방식은 정답 슬롯을 만들어 놓고 학생이 몇 개를 채웠는지 세는 것이다. 이 도구는 그렇게
하지 않는다. **좋은 요약은 세부를 버리기 때문이다.**

대신 문단마다 **보존 질의**를 두고, 학생 요약이 그 질의의 답을 담았는지 본다.

```
문단  "이산화 탄소가 RuBP와 결합해 3탄당이 되고, 3탄당이 포도당이 되며,
       남은 화합물은 RuBP로 재생되어 다시 결합한다"

학생  "CO2가 RuBP와 결합해 포도당을 만들고 RuBP가 재생되어 반복된다"
      → 3탄당을 생략했지만 순환 구조는 보존   → 관계보존

학생  "이산화 탄소를 이용해 포도당이 만들어지고 이 과정이 반복된다"
      → 되먹임(RuBP 재생)이 없다             → 부분관계
```

**중간 단계의 필수성은 개수가 아니라 그 단계가 목표 관계를 연결하는지로 정해진다.**
순환에서는 중간산물을 생략해도 되지만, 공간 분업에서는 두 공간을 잇는 운반 과정을 빼면
관계가 무너진다. 이 구분은 회귀 프로브로 고정돼 있다
(`docs/experiments/n2-deconfound-2026-08-10.md`).

## 채점축은 하나다

영역(문단의 의미 단위)마다 다섯 값 중 하나가 나온다.

```
관계보존   핵심 관계를 담았다
부분관계   한 축은 잡았다
주제만     화제는 짚었으나 관계가 없다
미포착     이 영역이 요약에 나타나지 않았다
모순       원문과 어긋난다
```

**명제 단위 표시(●◐○✗)는 점수가 아니다.** 학생에게 근거를 보여주는 용도이고, 채점에
쓰이지 않는다. 두 축을 섞지 않는 것이 설계의 핵심 제약이다.

## 구조

```
packages/core       도메인 타입·골드 검증·가중치
packages/pipeline   골드 생성 → 질의 생성 → 채점         (LLM이 여기에만 있다)
packages/app        학습 UI (서버 + React 클라이언트)
content/            학생이 푸는 문단 8개 — 원문·골드·질의
docs/               설계 문서와 실험 기록
```

**프로세스 경계가 규칙이다.** 클라이언트는 `@csat/pipeline`을 import 하지 않고, 파일시스템
접근은 서버의 두 파일에만 있으며, 미달 영역의 정답은 **애초에 전송되지 않는다**(숨기는 것이
아니라 보내지 않는다). 세 규칙 모두 `packages/app/src/boundary.test.ts`가 소스를 읽어 검사한다.

## 실행

```bash
npm install
npm run build

# .env 에 ANTHROPIC_API_KEY 필요
set -a; . ./.env; set +a

npm run app:server    # 채점 서버 :5174
npm run app:client    # 화면 :5173
```

Node 24. 채점 1건에 약 20초, $0.05가 든다.

## 문서를 어디부터 볼까

| 목적 | 파일 |
|---|---|
| 지금 무엇이 정해졌고 무엇이 미결인가 | `memory/CURRENT_STATE.md` |
| 왜 그렇게 결정했는가 | `memory/DECISIONS.md` |
| 주제별 정책·실험·코드 원문 찾기 | `memory/INDEX.md` |
| 학생이 겪는 흐름과 그 근거 | `docs/STUDENT-LOOP-DESIGN.md` |
| 문단 → 명제 → 합성 → 질의가 만들어지는 과정 | `docs/DECOMPOSITION-PROCESS.md` 외 2편 |
| 판정이 왜 이렇게 정해졌는가 | `docs/experiments/` (26편, 원시 로그 포함) |

`docs/experiments/`가 이 저장소에서 가장 중요한 폴더다. **판정 규칙은 전부 측정으로
정해졌고**, 뒤집힌 판단도 그대로 남아 있다 — 예를 들어 "반복 안정성 100%"라는 초기 보고가
재측정에서 2/9로 뒤집힌 기록(`repeat-stability-nietzsche-2026-08-08.md`)이 그렇다.

## 회귀

```bash
npm run assess -- base    # 법인·과학·인문
npm run assess -- new     # 공시·광합성 P4
npm run assess -- n2      # 광합성 P3·P5 (순환·분업 정책)
```

39개 프로브(12 + 12 + 15)를 **질의 분해 4종**(손 오라클 + 생성 3회)에 각각 돌려, 같은 판정이
나오는지 본다.
가장 중요한 지표는 **과대평가 0건** — 미달 응답에 관계보존을 주는 것이 이 시스템에서 가장
위험한 오류다.

단위 테스트는 `npm test` (197개).

## 알려진 한계

- 실제 학생 응답이 없어 **힌트가 요약 훈련이 아니라 문답 훈련을 유발하는지** 판단되지 않았다.
- 같은 입력에도 영역 판정이 1~2/9 갈린다. 경계 응답(부분관계 ↔ 주제만)에 몰려 있고, 화면은
  겨냥하지 않은 영역의 강등을 가려 이를 완화한다.
- 생성기가 명칭 질의를 관계 질의로 표시하는 습성이 남아 있다. `evidenceRole` 축이 이를
  막고 있지만 원인은 안 고쳤다.
- 단일 사용자·로컬 전용. `ownerId`는 `local` 고정이다.
