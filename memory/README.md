# 프로젝트 메모리 운영 규칙

이 디렉터리는 긴 채팅을 다시 읽지 않고도 현재 프로젝트를 복원하기 위한 정본 계층이다.
대화는 사건 기록이고, 이 디렉터리는 검증된 현재 상태와 결정의 색인이다.

## 문서 역할

| 위치 | 역할 | 갱신 방식 |
|---|---|---|
| [`CURRENT_STATE.md`](./CURRENT_STATE.md) | 지금 참인 상태와 바로 다음 행동 | 기존 내용을 현재 사실에 맞게 갱신 |
| [`DECISIONS.md`](./DECISIONS.md) | 결정 레코드 색인 | 레코드 추가·상태 변경 시 갱신 |
| [`decisions/`](./decisions/) | 결정, 근거, 폐기 대안, 재검토 조건 | 추가형; 과거 결론을 삭제하지 않음 |
| [`OPEN_QUESTIONS.md`](./OPEN_QUESTIONS.md) | 아직 답하지 않은 질문과 닫힌 조건 | 열기·닫기 상태 갱신 |
| [`INDEX.md`](./INDEX.md) | 주제별 코드·정책·실험 출처 지도 | 새 정본이나 중요 보고서가 생길 때 갱신 |
| [`checkpoints/`](./checkpoints/) | 작업 단위의 상태 변화 | 작업 종료 시 delta만 추가 |
| [`templates/`](./templates/) | 결정·체크포인트 작성 틀 | 스키마 변경 때만 갱신 |

`.omc/project-memory.json`은 도구가 생성한 기술 스캔 캐시이며 이 메모리의 정본이 아니다.

## 새 작업을 시작할 때

1. `CURRENT_STATE.md`로 현재 상태와 금지선을 확인한다.
2. `INDEX.md`에서 작업 주제를 찾아 필요한 원문만 연다.
3. 관련된 accepted 결정 레코드를 읽는다.
4. 더 자세한 역사가 필요할 때만 체크포인트와 과거 문서로 내려간다.

전체 대화나 `docs/experiments/` 전체를 처음부터 읽지 않는다.

## 작업을 끝낼 때

다음 중 하나라도 바뀌었을 때만 메모리를 갱신한다.

- 운영 정책이나 아키텍처 결정
- 실험으로 확인된 사실과 증거 수준
- 작업 흐름의 상태, 다음 한 단계, 중단 지점
- 알려진 위험이나 열린 질문

갱신 순서는 다음과 같다.

1. 체크포인트에 이번 작업의 delta와 출처를 기록한다.
2. 현재 사실이 달라졌다면 `CURRENT_STATE.md`를 갱신한다.
3. 선택이 확정·기각·대체됐다면 결정 레코드를 추가한다.
4. 질문 상태와 `INDEX.md` 링크를 갱신한다.
5. `node scripts/validate-memory.mjs`를 실행한다.

## 사실 승격 규칙

메모리에는 아래 근거가 있는 내용만 확정 사실로 올린다.

- 코드와 테스트에서 직접 확인된 결과
- 보존된 실험 입력·출력과 보고서
- 명시적인 사용자 결정
- 버전과 계보가 기록된 운영 정책 또는 자산 원장

LLM 요약만 있는 내용은 `hypothesis` 또는 `unverified`로 남긴다. 모순되는 출처가 있으면 더
새롭다는 이유만으로 자동 선택하지 않고, 원자료·코드·실험 조건을 비교해 해결한다.

## 크기와 이력 규칙

- `CURRENT_STATE.md`는 200줄 이하를 유지하며 현재 사실만 둔다.
- 결정 ID는 `D-0001` 형식으로 한 번만 사용한다.
- 결정 상태는 `proposed`, `accepted`, `rejected`, `superseded`, `deprecated` 중 하나다.
- 결정이 바뀌면 과거 파일을 삭제하지 않고 새 결정에서 `supersedes`로 연결한다.
- 체크포인트는 누적 요약이 아니라 직전 정본에 대한 변경분만 기록한다.
- 원시 로그와 대형 산출물은 기존 `docs/experiments/`에 보존하고 여기에는 복제하지 않는다.

## 도구

새 체크포인트 골격:

```bash
node scripts/new-memory-checkpoint.mjs short-slug
```

구조·ID·링크 검사:

```bash
node scripts/validate-memory.mjs
```
