# 원래 v3에서도 공손룡 지시 대상 설명 혼동 재현

사용자가 원래 v3와 G-error 역전 응답을 지정하고 D-0081에서 외부 전송을 승인했다.
3반복·최초 평가3회+교정 질문3회=6요청 완료, 전송/계약 실패0·재시도0이다.
과거 단가 기준 추정 비용$0.082068, 미확정 예약0. 제품·프롬프트·서버는 수정하지 않았다.

## 조건

`docs/experiments/gongsun-v3-reversed-response-2026-10-02/FROZEN.json`에 원본 v3 해시
`3ba91f7093612560a874304265d510d5d968e3101983aff449152f08301a48ff`를 고정했다.
gpt-5.6-terra/medium, 직전 A/B의 수정된 source를 그대로 사용하고 기존 v3 평가기·스키마·
정답 근거 평가→오류이면 별도 교정 질문 호출 구조를 사용했다.
같은 source 해시와 응답을 유지했지만 v4 후보와 호출 구조/출력 계약은 다르므로 문구만의 인과
효과를 분리하는 A/B가 아니다. 과거 의미 판정 프롬프트를 현재 기호 입력과 결합한 시험이다.

학생 응답은 “d는 빨간 옷만 가리키고, e는 색을 한정하지 않은 일반적인 옷을 가리켜요.
서로 다른 대상을 지시하므로 같다고 한 4번은 틀렸어요.”, 선택은 정답 C4다.
기대값은 에이전트가 고정한 CLEAR_ERROR/ASK_CORRECTIVE 및 d=일반적인 옷/e=빨간 옷의
올바른 설명이며, 독립 사람 정확도 측정이 아니다.

## 반복별 의미 검토

| 반복 | 최초 판정 | 최초 reason 의미 | 교정 질문 단계 |
|---|---|---|---|
| r1 | CLEAR_ERROR | d=일반적인 옷/e=빨간 옷으로 올바르게 설명 | 올바른 설명·대응 교정 질문 |
| r2 | CLEAR_ERROR | d를 ‘일반적인 옷이 전혀 없다는 뜻이 아니라 필요한 빨간 옷이 없다는 뜻’으로 서술하여 전체 발화 의도와 d의 지시 범위를 혼동 | 역전 오류 유지·각각 무엇인지 질문, 잘못된 대응을 반복하지 않음 |
| r3 | CLEAR_ERROR | ‘d는 빨간 옷이 필요하다는 뜻으로 사용되었고 e는 그 빨간 옷을 가리킨다’고 잘못 설명 | d=일반적인 옷/e=빨간 옷으로 다시 설명·교정 질문 |

근거: 위 디렉터리의 `r1.json`, `r2.json`, `r3.json`의 각 steps[].call.result 전문.
최초3/3 CLEAR_ERROR, 질문3/3 ASK_CORRECTIVE다. 최초 설명2건에 혼동이 있으며 r3는 직전
후보 시험에서의 d까지 빨간 옷에 연결하는 오류가 뚜렷하게 재현됐다. 각 최초 판정은 선택 C4가
부적절한 선지라는 점을 유지했다. 직전 후보의 미공개 코칭처럼 ‘④가 적절하다’는 결론 역전까지
이번 v3 출력에서 재현된 것은 아니다.

질문 단계의 오류 대상은3회 모두 학생의 d/e 역전이며 학생이 잘못 말한 대응을 재구성에 보존했다.
r1/r3는 올바른 대응을 명시했고 r2는 잘못된 새 대응 없이 대화 인용과 각각의 대상 질문을 했다.
학생에게 틀린 대응을 직접 제시한 질문은 관측되지 않았다. 질문 목적/명료성의 모든 측면이나
학생 후속 수정 인정까지 검증한 것은 아니다. v3 최초 reason은 다음 입력에 직접 전달하지 않는
원래 구조여서 다음 호출의 정상 설명을 자기 오류를 인지·수정한 증거로 보지 않는다.

## 결론과 한계

이 지시 대상 설명 혼동은 v4 변경 이후에만 생기는 현상이 아니다. 원래 v3로도 오류 판정은
맞으면서 이유가 잘못되는 현상이 발생한다. 따라서 원래 v3 복원만으로 해결된다는 결론은 불가다.
단일 응답3반복이며 v3/v4 중 어느 쪽이 더 안정적인지의 통계적 우열은 판단하지 않는다.

검토 가설: 전체 발화의 의도인 ‘빨간 옷이 필요했다’를 ⓓ가 붙은 ‘옷’ 자체의 뜻으로 옮겨 붙이는
혼동이다. 실제 모델 내부 사고 원인을 확인했다는 뜻은 아니며 프롬프트 수정 제안/실행도 하지 않았다.
Q-0030은 open 유지. 준비 시점의 API0/전송 승인 대기는 해소됐다.

`source.json`, `requests.jsonl`, `RESULTS.json`, `r1.json`~`r3.json`.
