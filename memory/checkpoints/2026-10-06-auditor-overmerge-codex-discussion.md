# 감사기 과병합 해결책 Codex 2라운드 논의

사용자 요청과 명료화 답변(Codex의 실험 폴더 열람과 원문·축 OpenAI 전송 승인, 논의만, 2라운드, 문서+기억 갱신)에 따라
`omc ask codex`로 읽기 전용 논의를 2회 진행했다. 정리는 `docs/experiments/axis-auto-merge-audit-five-passages-2026-10-02/AUDITOR-OVERMERGE-DISCUSSION.md`,
원출력은 같은 폴더의 `codex-overmerge-round1.md`, `codex-overmerge-round2.md`에 있다. 코드·프롬프트·자산 변경과 실험 API 호출은 없었고, 실행 전후 git 상태가 같았다.

- 관측: 감사 추가 병합 10건 중 9건이 문단 전체를 한 축으로 합쳤다. 3축→1축 3건(정보 비대칭3, 표면 장력2·5)은 모두 문제·경계 사례였다.
- 합의 의견(사람 판정 아님): 원인은 '같은 질문' 판별 기준 부족과 문단 단위 통합 기본값이다. 우선 권고는 관계 중심 기준(A)과 원 질문별 통과 요구·손실 대조 계약(B 강화판 5필드)이다. 호출 분리(C)는 조건부 후속 대조로 둔다.
- 감사 프롬프트의 FA 문구가 '축 감소=FA 감소' 전제를 담는다는 데 합의했다. 수정 문구를 제안했지만 사용자 결정 전이다.
- 감사 추가 병합에 대한 검토 표시는 D-0076/D-0077과 양립한다. 적용 전 재확인은 D-0079 실행 방식을 바꾸므로 사용자 결정이 필요하다. 3개 이상 병합 기준은 미검증이다.
- 정정: 도파민2는 감사 추가 병합 실패가 아니라 최초 선택의 결함을 감사가 잡지 못한 것이다. 운영 L1도 흥분/억제를 명시하지 않는다. `OPERATIONAL-VS-AUDIT.md`를 수정했다. 같은 문서의 FA 정의는 미확정(D-0076)이라는 단서를 추가했다.
- 새 결정 기록은 없다. 쟁점별 선택지는 정리 문서 5절에 있다.
