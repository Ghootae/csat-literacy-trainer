# 원문 내 범위 직접 표시만으로 공손룡 혼동 해소되지 않음

D-0082 승인 아래 원래 v3·동일 G-error 역전 응답의 원문 표시 방식만 비교했다.
새 대조군도 함께 각3반복, 최초 평가와 교정 질문을 포함한12요청을 완료했다.
직접 표시 조건의 최초 reason1/3에서 d를 필요한 빨간 옷에 연결하는 같은 오류가 재현됐다.
대조군은 이번 최초 설명3/3 올바르게 구분했다. 개선이나 완전 해결의 근거는 얻지 못했다.

## 방법과 불변 조건

`scripts/test-gongsun-v3-inline-markers-ab.mjs`는 기존 textAnnotations를 사용해 원문에
`〈ⓓ〉옷〈/ⓓ〉`, `〈ⓔ〉빨간 옷〈/ⓔ〉`처럼 시작/끝 표시를 삽입한다.
지문1·보기5의 총6범위에 같은 방법을 적용했다. 겹침·구분자 충돌·범위 불일치는 거부하고,
표시를 제거하면 원래 문자열이 정확히 복원되는지 검사했다. 별도 textAnnotations는 양쪽에
유지하고 직접 표시로 달라진 좌표/앞뒤 문맥만 다시 계산해 스키마로 검증했다.

source의 변경 필드는 passage/scenario/textAnnotations뿐이며 어휘나 해석 정보는 추가하지
않았다. 정답·해설·학생 답변·선지·v3 프롬프트·출력 스키마·호출 구조를 유지했다.
gpt-5.6-terra/medium, 각 반복에서 control→inline 순으로 수행, 자동 재시도0이다.
원본 v3 파일 해시3ba91f…를 고정하고 모든 요청의 trim된 instructions 해시
`cdf891fc7e4ab0a955fd77400c6e64c53b45392a020726219df159a1aad9b79f` 일치를 확인했다.
2번 해석표 생성이나3번 모순 검사는 추가하지 않았다. 제품 fixture/UI/서버도 미변경이다.

근거: `docs/experiments/gongsun-v3-inline-markers-ab-2026-10-03/`의
`FROZEN.json`, `sources.json`, `requests.jsonl`, `RESULTS.json` 및 위 실행 스크립트.

`inline-r1.json` 최초 reason은 “ⓓ는 색을 한정하지 않은 일반적 옷의 부재를 말한 것이 아니라
필요한 빨간 옷을 가리키는 맥락”이라고 설명했다. sourceEvidence에는 직접 표시가 있는 전체
문장을 정확히 인용했다. 표식 정보를 받아 정확히 인용해도 올바른 의미 해석을 보장하지 않는다.
다음 질문 단계에서는 d=일반적인 옷/e=빨간 옷으로 설명했다. 이전 reason을 전달하지 않는
v3 구조이므로 자기 오류를 인지해 고쳤다는 증거로 보지 않는다.

`inline-r2.json`, `inline-r3.json` 최초 reason은 올바른 대응을 명시한다.
그러나 두 질문 단계 reason은 ‘ⓓ는 일반적인 옷의 부재를 뜻하지 않는다’처럼 기호가 붙은
명사와 문장의 부정을 섞은 표현이다. r3의 질문 “각각 무엇이 없다는 뜻으로 사용되었나요?”는
앞절의 부정을 명확히 구별하지 않아 모호할 수 있다. 이를 별도 확정 지시 대상 역전으로
추가 집계하지 않으며 ASK_CORRECTIVE3/3을 질문 품질 전체 통과로 해석하지 않는다.
근거: `control-r1.json`~`control-r3.json`, `inline-r1.json`~`inline-r3.json` 전문.
