# 문단 CAPTURED 사후 검증 역전 원인 확인

- 날짜: 2026-09-11 KST
- 성격: 사용자 직접 사용 실패의 원인 진단

## 관측 사례

- 대상: `gongsun-long-later-mohists-p3`
- 학생의 첫 후속 답변 뒤 1차 모델 원출력은 모든 축을 `captured`, 전체를 `CAPTURED`,
  `targetAxisId: null`로 판정했다.
- 그러나 최종 런타임 결과는 `UNCLEAR`였고 형체와 색에 관한 두 번째 질문을 생성했다.
- 원기록: `.omc/logs/dialogue-experiment/sessions.jsonl`

## 직접 원인

- `packages/pipeline/src/dialogue-experiment/gate.ts`의 사후 검증기는 이전 턴과 상태가 달라진
  축마다 최신 후속 답변의 직접 부분 문자열과 현재 질문 유형에 맞는 source를 요구한다.
- 모델은 AX1을 `partial`에서 `captured`로 갱신하면서 AX1 근거를 `initial`로만 기록했다.
  최신 `diagnostic` 근거가 AX1에 없었으므로 검증기가 AX1을 이전 `partial`로 복원했다.
- 검증기는 복원된 축 상태로 전체 상태를 다시 계산해 `CAPTURED`를 `UNCLEAR`로 바꾸고,
  `targetAxisId`를 AX1로 지정했다.
- `packages/pipeline/src/dialogue-experiment/two-stage-evaluator.ts`는 이 검증 후 결과를 받아
  정상적으로 2차 질문 생성기를 호출했다. 따라서 추가 질문의 직접 원인은 2차 질문 프롬프트가
  아니라 1차 결과의 사후 상태 전이 검증이다.

## 구조적 충돌

- 프롬프트는 누적 응답 전체의 의미를 합성해 판정하도록 하지만, 사후 검증은 각 축의 상태 변경을
  최신 턴의 축별 직접 인용으로만 허용한다.
- 이 때문에 후속 답변이 이전의 압축된 주장을 문맥상 충분하게 만들거나, 여러 축을 함께 명료하게
  하는 경우에도 모델의 누적 의미 판정이 되돌려질 수 있다.
- 반대로 이 보호 장치를 단순 제거하면 새 근거 없는 축 승격을 허용할 수 있으므로, 수정 시에는
  `현재 답변과 누적 문맥에 의한 정당한 재해석`과 `근거 없는 승격`을 구별해야 한다.

## 부가 증상

- 비통과 결과 조립은 게이트의 기존 `decisionSummary`와 질문 생성기의 target 설명을 이어 붙인다.
  그래서 이 사례처럼 상태만 사후 변경되면 “모든 중심축을 포착했다”와 추가 확인 필요가 한 결과에
  함께 기록되는 모순이 생긴다.
