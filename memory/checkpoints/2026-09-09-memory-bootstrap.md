# 프로젝트 메모리 정본 계층 도입

## 새로 확인된 것

- 기존 `docs/WORKSTREAM-STATE.md`가 장기 기억 역할을 했지만 현재 상태와 상세 이력이 593줄에
  함께 누적돼 있었다.
- `docs/NEXT.md`는 2026-08 초 상태를 제목과 전면에 유지해 현재 재개 지점으로 쓰기 어렵다.
- `.omc/project-memory.json`은 기술 스택 스캔 캐시이고 프로젝트 결정의 정본이 아니다.
- 조사 시점의 HEAD는 `6852686`이었으며, 작업 트리에는 그 커밋 이후의 수정·신규 파일이 다수
  남아 있었다. 이 메모리 도입 작업은 그 파일들을 수정하거나 정리하지 않았다.

## 결정된 것

- 기존 문서와 실험 산출물은 이동하거나 덮어쓰지 않고 증거 계층으로 보존한다.
- `memory/CURRENT_STATE.md`를 짧은 현재 상태의 정본으로 사용한다.
- 결정은 ID가 있는 개별 레코드로 추가하고, 상태가 바뀌어도 과거 기록을 삭제하지 않는다.
- 체크포인트는 전체 요약 대신 작업 delta만 기록한다.
- 새 작업이 자동으로 이 규칙을 따르도록 루트 `AGENTS.md`에 시작·종료 절차를 둔다.

## 생성한 것

- 현재 상태, 결정 색인과 6개 초기 결정, 열린 질문, 주제별 출처 지도
- 결정·체크포인트 템플릿
- 새 체크포인트 생성 도구와 구조·ID·링크 검증 도구

## 기존 상태에서 바뀌지 않은 것

- 제품 런타임 코드, 실험 산출물과 운영 정책은 수정하지 않았다.
- 문제 풀이의 원문 직접 정책, 문단 요약 V2, 문단 골드 v1 기준선은 그대로 유지했다.

## 다음 행동

- 다음 실질 작업은 `memory/CURRENT_STATE.md`의 우선순위 1번인 충분한 최초 문단 요약 canary다.
- 앞으로 상태가 바뀌는 작업이 끝날 때 이 디렉터리의 정본과 체크포인트를 함께 갱신한다.
