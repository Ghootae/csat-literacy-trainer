# 세 문제 풀이 후보의 분기·충돌 검토

## 범위와 결론

최신 상태: 아래는 감사 당시 기록이다. 이후 D-0052~D-0059를 거쳐 학습 분기 명료화를 완료했고,
[D-0059](../decisions/D-0059-problem-feedback-clarifications-consolidated.md)와 [수형도](../../docs/review/problem-feedback-policy-tree-2026-10-01.html)에 통합했다. 구현·실모델 검증은 별도다.

사용자 요청에 따라 D-0049·D-0050·D-0051을 합쳐 설계 수준에서 검토했다. 최초/최종 선택,
정오, 근거 유무, 명시적 오류/선택 충돌/충분성, 추론 가능성, 교정 답변 결과의 의미상 분기를
대조했다. 자연어 모든 발화의 전수 검사나 실제 모델·런타임 검증은 아니다.

선택 최대 2회·교정 최대 1회와 정상 종료 흐름은 양립 가능하다. 다만 아래 판정 우선순위와
예외를 명시하지 않으면 충돌 또는 미정의 경로가 남는다. 아래 보완안은 검토 제안이며 사용자
승인된 정책 변경이 아니다. 코드·프롬프트·UI·포인트·기존 결정 내용은 변경하지 않았다.

최초 오답 뒤 근거를 늦게 제출하는 것은 같은 최초 선택을 평가하는 입력이며 새 선택이 아니다.
이때의 근거는 오답 안내 이후 제출됐다는 시점을 보존해야 최초 독립 사고와 혼동하지 않는다.

## 주요 판정 경계

### A. 교정 후 새 근거와 과거 선택의 충돌

후속 상태: 사용자 동의로 [D-0052](../decisions/D-0052-correction-vs-historical-selection-deferred.md)에
설계 원칙을 확정했다. 아래는 감사 당시의 검토이며 구현·회귀 검증은 계속 보류한다.

- D-0049의 선택–근거 일관성 검사를 후속 턴에도 같은 방식으로 적용하면 정상 교정을 막을 수 있다.
- 예: 부정 발문에서 C4를 거짓이라 여겨 선택한 학생이 교정 뒤 C4는 참이라고 바로잡음. 새로운
  근거는 과거 C4 선택이 뜻하는 INVALID와 불일치하지만, 바로 이것이 재선택이 필요한 정상 회복이다.
- 제안: 최초/재선택 제출의 선택–근거 일관성과, 교정 답변의 활성 오류 해소를 별도로 판정한다.
  과거 선택은 이력으로 보존하고 수정된 근거와 불일치한다는 이유만으로 새 실행 오류를 만들지 않는다.

### B. 전체 추론 불가능과 국소 오류의 동시 존재

후속 상태: 사용자는 아래 국소 오류 우선 제안 대신 전체 결론 확인 불가를 우선하도록 결정했다.
[D-0053](../decisions/D-0053-global-unknown-priority-deferred.md)을 따른다. 정답 근거 분기의 적용 범위는 확인 필요하다.

- D-0050은 전체 경로가 확인되기 전 내용 교정을 확정하지 않는다는 표현을 포함한다.
  D-0051은 근거의 명시적 오류가 있으면 교정한다. 전체는 파편적이지만 한 명제는 명백히 틀린
  발화에서 두 원칙이 서로 다른 행동을 지시할 수 있다.
- 제안: 국소적 명시 오류 확인과 전체 선지 결론 도출 가능성을 독립적으로 둔다. 명시 오류가
  확인되면 그것만 교정하고, 전체 결론은 UNKNOWN으로 남길 수 있다. 경로 전체를 꾸며내지 않는다.
- 전체 추론 불가능을 항상 우선하려면 반대로 국소 오류 교정을 생략하는 정책이 필요하다.
  어느 우선순위도 아직 새로 승인하지 않았다.

### C. 읽을 수 있는 근거와 선지 판단에 충분한 근거

후속 상태: ‘참이지만 선지 판단에 불충분한 최초 오답’은 [D-0054](../decisions/D-0054-insufficient-wrong-rationale-exit-deferred.md)로 확인 불가·코칭 종료에 합의했다. 아래 문항 경계 등의 예외까지 합의된 것은 아니다.

- ‘추론 가능’이 단순 문장 이해를 뜻하는지 선지에 대한 판단 경로 확인을 뜻하는지 분명해야 한다.
- 문장이 명료하고 사실도 맞지만 선택을 결정하지 못하는 관련 사실만 있을 수 있다. 이를
  ‘추론 가능 → 반드시 오류 발견’으로 취급하면 오답에서 오류를 역산하게 된다.
- 제안: 명시 오류 없음 + 선지 결론 불충분은 UNKNOWN/불충분으로 처리한다. 최초 오답에서는
  확인 어려움 안내·코칭 종료, 정답에서는 미검증 종료. UNKNOWN과 이진 판정의 차이는 충돌이 아니다.
- 근거가 정말 충분하고 원문상 타당한데 공식 정답과 다르면 학생 오류가 아니라 문항·해설
  한계 또는 평가기 판정 불일치를 검토한다. 현행 v3의 문항 경계 예외를 잃지 않아야 한다.

### D. 교정 성공의 범위

후속 상태: [D-0055](../decisions/D-0055-multiple-error-correction-batch-deferred.md)에서 모든 관련 오류의
실제 수정 확인 원칙과 최초 오답 오류 1·2 순차 질문·누적 최종 판정을 합의했다. 기존 교정 총 1회
제한은 해당 경로에서 변경됐다. 정답 근거 충분성·확장 질문 범위 등 세부까지 해결된 것은 아니다.

- 여러 명시 오류 중 질문한 하나만 고친 경우, 수정 답변에서 새로운 명시 오류가 나온 경우,
  단순 동의·철회만 있고 실제 판단은 확인되지 않는 경우의 성공 조건을 명시해야 한다.
- 제안: 누적 발화에 확인된 관련 오류가 남거나 실제 수정이 확인되지 않으면 성공으로 승격하지
  않고 코칭 종료한다. 확인되지 않은 새 이해 항목을 만들어 추가 시험하지 않는다.
- 최초 정답에서 오류는 고쳤으나 정답을 지지하는 근거의 충분성은 여전히 불확실한 경우,
  ‘교정 성공’만으로 ‘근거 검증 정답’이라고 기록하면 안 된다. 종료는 유지하되 두 판정을 분리한다.
- 최초 정답을 교정하다 답을 바꾸겠다고 말한 경우도 자동 재선택을 만들지 않는다. 이 경로는
  종료 경로이며 현재 근거를 검토해야 한다. 오답 교정 답변 안의 새 선택 번호도 제출 UI의
  재선택과 중복 계산하지 않도록 명시적 제출 경계가 필요하다.

## 입력·종료·운영 경계

후속 상태: 제출/대기 구분은 D-0057, 코칭 종료의 회차 무관 정답 공개·재선택 금지는
[D-0058](../decisions/D-0058-terminal-coaching-answer-reveal-deferred.md)로 설계 합의했다. 아래는 감사 당시 검토이며 다른 예외와 구현 검증은 남는다.

- 근거 요구에 ‘모르겠다/찍었다’고 답하면 발화는 제출됐지만 근거는 충분하지 않은 경우다.
  반면 미제출·연결 종료는 아직 답변이 없으므로 자동으로 교정 실패나 완료로 기록할 수 없다.
  건너뛰기/포기 경로를 제공할지는 미정이다. 자동 반복 요구 없이 대기·중단과 학습 종료를 구분한다.
- 최초/재선택 모두 명시적 답만 제출 선택과 비어 있는 일반 입력을 구별해야 한다. 미래 감점은
  학생의 제출 방식과 오답 사실에 연결하고, 모델의 ‘모호함’ 판정으로 자동 확대하지 않는 것을
  제안한다. 늦은 근거 제출·재시도 요청에서 중복 감점하거나 제출 이력을 덮어쓰지 않아야 한다.
  감점량·실서비스 활성화는 미정이며 개발 실제 차감 금지는 이미 확정된 후보 제약이다.
- 새 후보는 1차 오답에서도 코칭 후 종료하지만 현행 v3는 1·2차 코칭 정답 공개 금지와 최종
  시도 공개 허용을 사용한다. 마지막 시도를 고정 횟수로 판단하면 충돌한다. 제안: 재선택 기회가
  남은 질문/안내는 정답 유도 금지, 불가역적 종료 코칭은 정답·근거 공개 허용. 공개 범위는 미승인이다.
- 자료 누락·발문 정규화 실패·문항 한계·API/계약 실패는 학생 추론 불가능이나 교정 실패가 아니다.
  현행 자료 경계·평가 재개를 별도 예외로 보존하고 선택/질문 예산을 재시도로 증가시키지 않아야 한다.
- 이진 극성 정규화는 해당 문항의 요구와 자료에 대한 적절성 판정이다. 복합 발문이나 단순 참/거짓
  선택으로 정규화할 수 없는 문항을 임의의 극성으로 고정하지 않는 예외가 필요하다.

## 상태 전이 검토

- 정상 분기에는 역방향 전이가 필요 없다: 최초 선택 → 필요 시 근거 보완 → 교정 질문 1회 →
  성공 시 최종 선택 → 종료. 최초 정답·추론 불가능·교정 실패는 더 일찍 종료한다.
- 학생 무응답과 평가 장애를 학습 실패로 치환하지 않는 한, 시간 내 무조건 종료는 보장하지 않는다.
  입력을 기다리는 것과 무한한 질문 루프는 다른 상태다.
- D-0050의 과거 ‘좁은 진단 질문’은 D-0051의 최신 후보에서 대체됨을 이미 명시했으므로
  그 자체는 미해결 충돌이 아니다. 현행 런타임이 선택 3회라는 사실도 구현 보류 상태와 모순되지 않는다.
- 답만 제출 정답을 미검증 종료하면서 오답에는 근거를 요구하는 비대칭은 사용자 의도다.
  포인트 우회 가능성과 학습 효과는 별도 검증 문제이지 논리적 모순의 증거가 아니다.
