# 선지와 다른 대상을 판단한 근거는 대상 오류로 잡아 가장 먼저 묻는다

## 결정

사용자 확정(2026-10-14, UI 메모장 21번, "승인, 진행해줘"). 설계는 [인계 문서](../../docs/handoffs/2026-10-14-v5-choice-target-mismatch.md)에 있다.

- 학생 주장을 판정할 때 대상이 선지와 같은지를 원문 대조보다 먼저 본다.
  - 대상은 선지 문장에 적힌 기호와 짝, 입장, 조건이다.
  - 학생이 선지의 대상 **대신** 다른 대상을 판단한 주장은 `OFF_TARGET`이다.
  - 지문의 다른 정보를 근거로 끌어오는 것은 `OFF_TARGET`이 아니다. 애매하면 쓰지 않는다.
- `OFF_TARGET` 주장들은 대상 오류(`errorType: 'TARGET'`) 하나로 묶는다.
  - 대상 오류는 다른 오류보다 먼저 묻는다.
  - 엉뚱한 대상에 대한 주장으로는 내용 오류를 만들지 않는다.
  - 대상 오류가 있으면 선택 불일치 질문을 내지 않는다.
- 질문은 선지의 실제 대상과 학생이 판단한 대상을 나란히 놓고 묻는다. 지시문 예시는 시험 문항과 겹치지 않는 중립 기호만 쓴다.

## 이유

- 사용자가 직접 푼 공손룡 12번에서 학생은 ②(ⓐ·ⓓ)를 ⓐ·ⓔ로 읽었다. ⓔ에 대한 말은 사실이라 오류가 되지 않았다. 그 대신 ⓐ·ⓔ 관계 오류만 질문으로 나갔다. 그렇게 고친 결과 학생 판단이 틀린 쪽으로 뒤집혔다(UI 메모장 21번).
- 원인: 오류가 원문과 어긋난 주장에서만 생겼다(`feedback-v5-claims.ts`). 다른 대상에 대한 맞는 말은 담을 자리가 없었다.

## 확인

- 빌드, vitest(기존 실패만), e2e 13/13을 통과했다.
- 실모델 12세션([보고서](../../docs/experiments/v5-target-mismatch-2026-10-14/REPORT.md)):
  - 대상 혼동 6/6에서 첫 질문이 대상 오류였다.
  - 대조군 6/6에서 대상 오류는 0이었다.
  - T-G는 교정 뒤 다시 고르기로 이어졌다.
  - 비용은 0.475달러다.

## 감수할 점

- 대상만 바로잡고 끝나면 엉뚱한 대상에 대한 오해는 묻지 않은 채 남는다.
- 대상 오류의 근거가 선지뿐이면 화면에 칠한 곳이 없다. 사용자 결정(2026-10-14): 수정할 필요 없다. 질문에 선지 낱말이 그대로 들어가기 때문이다. 시험 실행기의 `NO_HIGHLIGHT` 검사에서 이 경우는 뺐다.

## 재검토 조건

- 정상 근거를 대상 오류로 잡는 사례가 관찰되면 다시 본다.
- 대상을 바로잡은 뒤에도 같은 오답을 고르는 사례가 반복되면 다시 본다.
