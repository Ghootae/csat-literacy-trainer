# 마지막 설명을 선지별 칸으로 나눠 차례로 보여 준다

## 결정

사용자 확정(2026-10-13, UI 메모장 6번)이다. 상세 표와 문구는 `docs/review/v4-dev-ui-feedback-backlog-2026-10-11.md`의 "6번 상세"에 있다.

1. **구조.** 마지막 설명(luna·sol 모두)은 고른 선지 순서대로 선지마다 이야기를 끝낸 뒤 정답 이유를 다룬다. 같은 선지의 이야기가 둘로 갈라지지 않는다.
   - 모델은 칸을 나눠 쓴다: 첫 선택 / 재선택(없으면 비움) / 정답 이유. 정답 세션은 근거 이야기 / 정답 이유.
   - "정답은 ⑤번이야.", "처음에 고른 ①번부터 볼게." 같은 연결 문장과 버튼은 코드가 붙인다.
   - D-0112 4항(마지막 선지가 답이 아닌 이유 짚기)은 그 선지의 칸 안에서 지킨다.
2. **표시.**
   - 코드 연결 문장은 0.8초 뒤 자동으로 뜬다.
   - 모델 설명 말풍선마다 아래 버튼 줄에 [다음]이 나온다. 정답 이유 뒤에는 "이해됐어? [응] [아니]"가 나온다.
   - 움직임 줄이기 설정이 켜져 있으면 시간차를 두지 않는다.
3. **시작 확인과 생성 시점.**
   - 판정이 끝나면 "정답은 ⑤번이야. 하나씩 같이 볼까? [응] [아니]"를 먼저 보이고, 서버는 뒤에서 설명을 만든다.
   - [아니]를 누르면 설명을 보이지 않고 종료한다. 정답 카드는 보이고, 설명은 내부 기록에만 남는다.
   - 학생이 이미 [코칭 보기]/[설명 보기]를 눌러 끝난 경우에는 시작 확인을 묻지 않는다.
4. **이해 확인.**
   - 세션 결과 `selfReportedUnderstanding`(YES/NO/null)을 원장에 남긴다.
   - 학생이 스스로 답한 값이므로 이해 확인의 증거로 쓰지 않는다.

5. **판단 불가 안내(UI 메모장 2번, 사용자 확정 2026-10-13).** 근거를 알아볼 수 없어 끝난 경우(RATIONALE_UNVERIFIABLE, CORRECT_UNVERIFIED)에는 [응] 직후 첫 연결 문장 앞에 코드가 정해진 문장을 붙인다.
   - 문장 셋은 메모장 "2번 상세"에 있다.
   - 근거 미제출과 재구성 불가를 구분한다.

6. 구현(2026-10-13): 인계 `docs/handoffs/2026-10-13-v5-end-coaching-sequence.md`(1~4항), `2026-10-13-v5-direct-questions-highlight-unverifiable-note.md`(5항). Claude diff 검토를 통과했다. 실모델 확인 전이다.

7. **직접 사용 뒤 보완(2026-10-13, UI 메모장 13~15번, 사용자 확정).**
   - 처음 메시지: 제출하면 판정 전에 코드가 정답 여부를 바로 알린다. 정답 번호는 넣지 않는다. 재선택과 교정 답이 무의미해지지 않게 하기 위해서다.
     - 오답: "정답이 아니야. 어디서 생각이 달라졌는지 살펴볼게."
     - 정답: "정답이야! 근거도 같이 살펴볼게."
     - 판정은 뒤에서 이어 한다.
   - 판단 불가 안내는 [응] 뒤가 아니라 판정 직후, 시작 확인 앞에 둔다. 시작 확인은 "정답은 ⑤번이야. 네 답을 하나씩 같이 볼까?"(오답), "네 근거를 하나씩 같이 볼까?"(정답)다.
   - 판정 뒤 문구에서 정답 여부를 다시 말하지 않는다(정답·근거 정확: "근거도 정확해. 잘 풀었어.").
   - 선지 설명 칸 끝에 "설명이 이해됐으면 다음 설명으로 넘어가 보자."를 붙이고, 버튼은 [다음으로 넘어가기]다.
   - 상세: 메모장 "13~15번 상세".

## 근거

- 사용자 직접 사용(2026-10-12): 마지막 코칭이 너무 길었다. 재선택 세션에서 같은 선지 이야기가 정답 설명을 사이에 두고 갈렸다.
- 원인은 sol 종료 지시문의 내용 종류별 순서(1→4)다.
- [48세션 재검토](../../docs/experiments/v5-diverse-48-2026-10-12/REVIEW-claude.md) 2-E: 코칭 순서가 칸마다 다르고 같은 내용이 반복됐다.

## 8. 정답 칸은 번호를 다시 밝히며 시작하지 않는다 (2026-10-13, 사용자 "진행", UI 메모장 17번)

- 실모델 시험에서 오답 경로 정답 칸 8/8이 "정답은 ⑤야."로 시작해 앞 연결 문장과 겹쳤다([결과](../../docs/experiments/v5-live-check-2026-10-13/REPORT.md)).
- 오답용 설명 지시문(`packages/pipeline/src/problem-solving/feedback-v5-end-explanation.ts`)을 두 군데 고쳤다.
  - 반말 예시를 `"그 부분은 원문과 반대야."`로 바꿨다.
  - answer 칸에 "앞 안내가 이미 정답 번호를 말하므로 … 번호를 다시 밝히며 시작하지 않고, 바로 이유부터 쓴다."를 더했다.
- 재시험: 근거 미제출 오답 6세션에서 겹침이 0/6이었다. 자동 검사 위반은 0건이고 비용은 0.05달러였다(`docs/experiments/v5-live-check-2026-10-13-r4/`).

## 다시 볼 조건

- 실제 학생 사용에서 [다음]을 누르는 부담이나 시작 확인의 [아니] 비율이 높으면 재검토한다.
- 칸 나눔 출력의 실모델 품질이 떨어지면 재검토한다.
