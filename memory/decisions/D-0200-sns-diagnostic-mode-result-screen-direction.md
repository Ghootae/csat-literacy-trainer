# SNS 독해력 진단평가 모드를 따로 두고, 결과 화면에 사고 패턴 분석을 쓴다

## 결정

방향까지만 정한 결정이다. 화면 구성·백엔드 구조의 설계 확정은 별도 단계다(사용자 선택 (가), 2026-11-05).

1. **모드.** 훈련 서비스와 별도로 SNS 독해력 진단평가 모드를 둔다. 목적은 대규모 자료 수집과 바이럴이고, 사용
   방식은 익명·한 번 참여·결과 즉시 확인이다. 아래 규칙은 이 모드에만 적용하며, 훈련 서비스(문단 요약 대화,
   문제 풀이 교정 흐름)의 결정은 바꾸지 않는다.
2. **보는 사람.** 첫 대상은 진단평가 참가자다(참가 동기: 내 위치 확인). 교사 시연([D-0198](./D-0198-teacher-demo-pilot.md))도
   같은 화면을 쓰고, 반 단위 집계는 나중에 붙인다.
3. **테스트 구성.** 수능 기출 4지문·약 16문항, 문항마다 선택과 근거 입력. 교정 대화는 없고 판정은 뒤에서 돌려
   결과 화면에 모은다. 문단 요약은 처음부터 선택 사항이다. 시간 제한은 없다.
4. **결과 화면 순서.** ① 내 위치 → ② 문제 풀이 결과 → ③ 독해 패턴(요약을 한 경우).
   - ① 위치는 범위로 보이고 지문을 끝낼 때마다 좁아진다. "수능 기준 환산 추정"으로 표현한다.
   - ② 기본 제시는 정답의 질(근거 있는 정답과 약한 정답, 판정기 v5), 무너진 단계(사고 진단 v0.1,
     [D-0111](./D-0111-thought-diagnosis-v0-experiment.md)), 걸린 함정(고른 오답 선지의 비틂, 선지 연결 층
     [D-0162](./D-0162-choice-link-layer-direction.md), 분포가 아닌 목록)이다. 무너진 단계는 실제 학생 검증 전이므로
     개수로 말하는 "경향" 표현으로 하고 유형을 단정하지 않는다.
   - ②에서 뺀다: 시간 × 정오, 정답 경로 실패 노드([D-0121](./D-0121-answer-path-layers-and-failed-operation.md), 개발자용으로만).
     출제자 전략 글은 풀이 과정에 이미 있으므로 결과 화면에 따로 두지 않는다.
   - 학생 화면의 "왜 틀렸나"는 비틂(내용)과 무너진 단계(과정) 두 축이다([D-0181](./D-0181-problem-error-taxonomy-two-axes-later.md)과 방향 같음).
   - ③ 기본 제시는 층별 패턴(큰 그림형 / 나열형), 관계 4갈래 강약(개인은 갈래까지, [D-0160](./D-0160-student-fingerprint-aggregation.md)),
     요약과 틀린 문항 연결이다. 더 보기에 틀린 이해 사례와 추이를 둔다. 원문 복사는 걸러 내고, 판단에는
     포착률보다 오류율을 먼저 쓴다.
5. **추천.** "구독하면 이런 것까지 받는다"는 인상을 주는 맛보기다. 진단에 쓴 문항의 비틂 분석으로 자주 걸린
   비틂을 고르고, 비슷한 구조의 지문 세트 이름만 추천한다. 추천 대상 세트는 분석하지 않고, 수능 DB 전체로
   선지 연결 층을 넓히지 않는다.
6. **이 모드에서 기존 결정과 달라지는 점.**

| 기존 결정 | 훈련 서비스 | SNS 진단평가 모드 |
|---|---|---|
| [D-0115](./D-0115-thought-diagnosis-periodic-sol.md) 사고 진단 주기 실행 | 묶어서 주기 실행 | 지문을 끝낼 때마다 뒤에서 실행, 결과 화면 전에 완료 |
| [D-0176](./D-0176-student-switch-roadmap-pilot-before-expansion.md) 학생 노출은 학생 확인 뒤 | 학생 확인 뒤 확대 | 검증 전 분석도 "경향" 표현으로 노출 |
| [D-0183](./D-0183-paragraph-analysis-ui-tree-and-relation-graphs.md) 2단계 요약 직후 판정 | 학생 확인 단계에서 | 이 모드에서 먼저 사용(대화 없이 1회 판정) |
| 문제 풀이 교정 흐름(D-0090 등) | 오류 → 교정 질문 → 코칭 | 교정 대화 없음, 판정만 |

7. **유지하는 제약.** 골드·선지 연결 층을 판정 입력으로 쓰지 않는다([D-0002](./D-0002-problem-source-direct-runtime.md)·
   [D-0003](./D-0003-problem-gold-offline-only.md)·D-0162). 이 모드는 그 자료를 결과 화면 표시에만 쓴다.

## 설계 확정 전에 풀 조건

코드 에이전트 검토(2026-11-05)에서 나온 것으로, 방향은 바꾸지 않고 화면 내용과 규칙을 정하는 문제다.

1. **선택률 자료의 출처와 이용 범위([Q-0042](../OPEN_QUESTIONS.md)).** 웹 에이전트 문서는 정답률·선지별 선택률을
   "보유"로 적었으나, 저장소에 있는 것은 6문항(D-0109)이다. DB 158세트·752문항이 메가스터디 회차와 모두 대응됨을
   확인했을 뿐 수집하지 않았다([확인 기록](../../docs/experiments/megastudy-rate-coverage-2026-11-05/README.md)).
   값은 메가스터디 이용자 집계라 "전국" 정답률로 부를 수 없고, 위치 추정(IRT)도 같은 편향을 물려받는다.
2. **진단 지문 범위([Q-0043](../OPEN_QUESTIONS.md)).** 비틂·분석 지도 동결 자료는 UI 6지문(24문항)에만 있다. 이 안에서
   고르면 추가 동결이 없지만 mRNA는 고2 시험이다. 새 지문은 지문마다 분석 골드(D-0151)·선지 연결 동결·사람 검토가 든다.
3. **위치 범위의 폭.** 16문항이면 Rasch 표준오차가 0.5 logit 안팎이라(코드 에이전트 추정, 미측정) 범위가 등급 여럿에
   걸칠 수 있고, 대부분 맞히는 상위권([D-0125](./D-0125-first-target-top-tier-middle-school.md))일수록 넓어진다.
4. **추천의 최소 근거.** 상위권은 오답이 1~3개라 "자주 걸린 비틂"의 근거가 한두 건일 수 있다. 최소 건수와 모자랄 때의
   문구 규칙이 필요하다.
5. **비용·대기 시간.** 웹 에이전트 문서의 참가자당 약 $0.2는 사고 진단(16 × 약 $0.012)만 센 값이다. 판정기 v5와
   문단 노드 판정(노드마다 1회 호출)을 더한 총비용과 결과 화면까지의 대기 시간을 재야 한다.
6. **개인정보.** 중등 타겟이므로 만 14세 미만 법정대리인 동의와 근거 원문 저장 범위가 출시 전 조건이다.

## 후속 결정: 설계 전 조건에 대한 사용자 답 (2026-11-05)

1. **선택률 자료**: 차후에 일괄 수집한다. 메가스터디 이용자 집단의 편향은 감수하고, 가능하면 전반적인 보정 방법도
   검토한다. 외부 공개 화면에 쓰는 이용 범위(약관·허락)는 답에 없어 Q-0042에 남긴다.
2. **진단 지문 범위**: 현재 UI 6지문이 진단평가 자료로서 넓이와 대표성을 갖는지 먼저 검토한다. 부족하면 다른 세트를
   쓴다(확장 시험 형태도 가능). Q-0043은 이 검토로 바뀐다.
3. **문항 수**: 16문항을 기본으로 하고, 학생이 원하면 문제를 더 풀 수 있게 한다(위치 범위를 더 좁히는 경로).
4. **추천의 최소 근거**, 5. **비용·대기 시간**: 더 생각해 볼 문제로 남긴다(설계 단계에서 다시 본다).

## 확정하지 않은 웹 에이전트 제안

지문마다 요약 선택 여부 기록(선택 편향 확인), 풀이 시간과 근거 입력 시간 따로 기록, 지문 단위 저장과 PC 이어 하기,
분포 곡선 위 등급 띠, 비틂 14종 → 추천 세트 1~2개 대응표(사람이 고름). 설계 단계에서 정한다.

## 다루지 않은 것

훈련 서비스용 추천(Q3), 학생 기록 형태(Q6, [Q-0037](../OPEN_QUESTIONS.md)), 학생용 갈래 이름과 비틂 14종의 학생용 표현.

## 다시 볼 조건

- SNS로 모인 실제 근거 일부를 사람이 검토해 사고 진단이 맞으면 "경향" 표현 수위를 올린다. 틀리면 무너진 단계 표시를 뺀다.
- Q-0042에서 선택률을 쓸 수 없게 되면 ① 내 위치와 문항 카드의 비율 표시를 다시 정한다.
