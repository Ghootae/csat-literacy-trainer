# V4 판정 원칙을 유지한 최소 출력 후보를 오프라인 비교

사용자는 V4의 비용·지연이 상세 기록 출력에서 생기는지 확인하기 위해 테스트 전 과정을 승인했다. 운영 V4는 유지한다.

- V4-light는 중심축 범위, 누적 응답 합성, OK 우선, 누락과 오류 구분을 유지한다.
- 1차 출력은 effectiveResponse와 축별 상태·짧은 이유로 제한한다.
- 첫 단계는 출처가 검증된 자연 응답45시점을 현재 V4와 같은 시점에 비교하는90호출이다.
- 품질 보존이 확인된 경우에만 오류·철회·부분 수정·짧은 후속 답변의 전체 흐름으로 진행한다.
- 속도 차이를 출력 토큰만의 효과로 단정하지 않는다. 지시문과 구조화 출력 계약도 함께 작아진다.

계획·동결 입력은 `docs/experiments/v4-light-output-v1-2026-09-22/`에 있다. 초기 실행은 외부 전송 범위의 명시적 재승인을 기다려 중단됐으나, 사용자가 데이터·수신처·store:false·90호출·USD2 상한을 명시적으로 승인한 뒤 실행했다.

## 실행 결과

90호출·추정 USD1.275944. V4-light는 V4 대비 API 중앙값63.5%, 비용73.6%, 입력 토큰69.6%, 출력 토큰78.3% 감소했다. 그러나 축 상태는30/45시점만 모두 일치했고, V4의 OK를 PASS9축·SERIOUS7축으로 양극화했다. V4가 질문하지 않던5시점을 light가 새 질문 후보로 바꾸고 반대는0건이었다. 따라서 판정 품질 보존 진입 조건을 충족하지 못해 2단계 전체 흐름 시험과 운영 승격은 실시하지 않는다.

V4 원출력2건은 claimLedger 인용 계약에 실패했고 light는45/45 계약 유효였다. 이는 기록 표면 축소의 장점이지만, 개입 경계 손실을 상쇄하는 운영 승격 근거는 아니다. 운영 V4와 D-0014/D-0015 기록 정책을 유지한다.

재검토: 판정 원칙을 다시 단순화하지 않고 후속에 쓰이지 않는 개별 출력 필드만 좁게 제거하는 새 대조안이 생길 때 검토한다. 현재 V4-light는 미승격이며 D-0014/D-0015 기록 계약을 폐기하지 않는다.
