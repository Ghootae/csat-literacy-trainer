# 보여 주기 개발자 모드: 재구성 응답은 effectiveResponse

## 결정

- 피드백에서 학생 응답을 다시 보여 주는 부분(첫 사용 피드백 5·9·10·11번의 "재구성된 응답")은 V4 게이트 결과의 `effectiveResponse`를 그대로 쓴다. 추가 생성 호출은 없다.
- 2차 이후에는 그 시점 판정의 `effectiveResponse`(이전 응답과 합친 내용)를 쓴다. 보여 주기 카드의 "내 요약"도 1차 응답 대신 마지막 판정의 `effectiveResponse`로 바꾼다(11번 도파민 1문단 문제 해소).
- 피드백 메모 그림의 문구는 예시이며 같을 필요가 없다.

## 근거

- 사용자 명시(2026-10-15): "그림에서 쓴 문구는 예시야. 동일할 필요가 없어. effectiveResponse를 사용하면 돼."
- 현재 로그(`.omc/logs/dialogue-experiment/v4-boundary-show/sessions.jsonl`, 7문단)에서 1차·최종 `effectiveResponse`가 모두 있고, 최종 값은 이전 응답과 수정 내용을 합쳐 담는다(예: 공손룡 p5 "…달명·유명·사명의 구분 기준은 명의 외연의 크기라고 답했다.").

## 시험에서 볼 점 (Claude 관찰, 같은 로그)

- 말투: 3인칭 보고체다("학생은 …주장했다", "…라고 답했다"). 반말 피드백 사이에 그대로 놓인다.
- 빠진 내용 언급: 아직 말하지 않은 내용을 적는 경우가 있다(공손룡 p5 1차 "명의 구분 기준이나 … 설명하지 않았다", 도파민 p1 최종 "티로신에서 도파민이 만들어져 … 아직 말하지 않았다"). 질문 전 1차 피드백에서 보이면 질문 대상을 미리 알려 주는 셈이고, 내용 일부가 공개될 수 있다.
- 수정 경위 언급: "처음의 … 설명은 후속 답변에서 수정되었다" 같은 문장이 붙는다(공손룡 p3).
- 게이트 프롬프트는 바꾸지 않으므로(D-0132), 문제가 되면 별도 결정으로 다룬다.

## 포함하지 않는 것

게이트 프롬프트 변경, 재구성 전용 생성 호출, 운영 화면 변경.
