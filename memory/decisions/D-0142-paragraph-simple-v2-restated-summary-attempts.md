# 단순 형식 문단 개발자 모드 v2: 재구성 요약 칸, 반복 시도, 말풍선 분리

## 결정

[D-0140](./D-0140-paragraph-simple-holistic-dev-mode.md) 개발자 모드에 사용감 피드백 1~6(`docs/review/simple-holistic-dev-ui-feedback-2026-10-16/README.md`)을 반영한다. 흐름(행동 표, 질문 최대 2회)은 바꾸지 않는다.

- **재구성된 응답(`restatedSummary`):** 학생이 이 문단에서 한 말 전체(첫 요약, 다시 쓴 요약, 질문에 한 답)를 한 편의 요약으로 다시 쓴 것이다. 학생이 말하지 않은 내용은 원문에서 덧붙이지 않고, 틀린 부분도 고치지 않는다. 바로잡기는 대화에서만 한다.
  - 대화창이 아닌 별도 칸에 보이고, 판정할 때마다 갱신한다.
- **반복 시도:** 문단마다 [새 시도]가 있고, 이전 시도는 보존한다. 진행 중에 새로 시작하면 그 시도는 "중단"으로 기록한다. 메모는 단계, 시도, 문단 전체 세 종류다.
- **말풍선:** CLOSE_ERRORS는 바로잡기(`message`)와 문단 핵심(`coreSummary`)을 서로 다른 말풍선으로 보인다. 모든 말풍선 위에 상태 표시(나의 요약, 다시 쓴 요약, 나의 답, 피드백, 다시 써 보기, 확인하기, 생각해 보기, 빠진 내용, 바로잡기, 문단 핵심)를 둔다.
- **지문 표시:** `sourceQuote`는 해당 내용이 담긴 문장 전체를 인용한다(프롬프트 지시). 서버의 문장 단위 확장은 쓰지 않는다.

## 근거

사용자 지시(2026-10-16, 대화): 피드백 메모 1~6, 재구성 응답의 뜻 확인("네 이해가 맞아"), 갱신 시점("판정할 때 마다"), 6번 처리 방식 선택.

사용자 설명(2026-10-16): "1차 응답 후 질문에 대한 2차 응답이 들어오면 그걸 합쳐서 재구성한 응답을 보여주자는 이야기". 처음에 덧붙인 "문제 풀이에도 같은 논리를 적용"은 문제 풀이 화면에 적용하라는 뜻이 아니었다("문제 풀이 적용은 그냥 무시해도 돼").
