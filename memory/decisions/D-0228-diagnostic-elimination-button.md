# 진단 소거법: 입력창 안 [소거법] 버튼, 판정 없이 '근거 불충분-소거법'으로 기록

## 결정

사용자(2026-11-11). 코드 에이전트가 웹 에이전트 논의용 자료(`docs/reports/DISCUSSION-elimination-rationale-2026-11-11-desktop.md`)를 쓴 뒤, 사용자가 "최대한 단순하게, 입력창 안 버튼에 '소거법'을 추가하고 기록은 '근거 불충분-소거법'으로"를 제안했다. 질문 1~5의 답.

1. **버튼**(질문 1 (가)). 진단 답 입력창 안 버튼에 [소거법]을 더한다(넷: [제출] [근거 미입력(확실)] [근거 미입력(잘 모르겠음)] [소거법]). 누르면 근거 없이 그 문항이 바로 확정된다(D-0226 근거 미입력 버튼과 같은 방식). 판정기를 부르지 않는다. 입력창에 써 둔 글이 있으면 기록에만 남기고 판정·화면에는 쓰지 않는다(코드 에이전트 제안, 사용자 이견 없음).
2. **판정과 기록**(질문 2). 정답이면 '근거 불충분'으로 판정해 학생 화면에는 "근거 약한 정답"(범주 WEAK_CORRECT)으로 보인다. 소거법으로 풀었다는 표시는 따로 기록해 나중에 분석할 수 있게 한다. "소거법" 표시는 개발자 모드(`?dev=1`)에서만 보인다. 2단계 표시(D-0213 (가))로 열면 근거 약한 정답과 함께 "근거 있는 정답"으로 합쳐진다.
3. **정답 뒤 흐름**(질문 3, 정정 뒤 (가′)). 근거 약한 정답과 똑같이 처리한다. 진단에서는 리뷰 대상이 아니므로 검토 버튼 비활성, 마지막 설명 없음, 추가 모델 호출 없음(D-0218 2번). 처음 질문 때 코드 에이전트가 "근거 약한 정답은 마지막 설명으로 끝난다"고 잘못 설명했고(lab·공통 상태기계 기준), 진단 화면 확인 뒤 정정해 다시 결정했다.
4. **오답**(질문 4). 근거 미입력 오답과 똑같다. 근거를 한 번 묻고(진단 문구 `OMITTED_WRONG_RATIONALE_LINE` 그대로, "감점" 문구 없음), 감점 대상 표시(`penaltyEligible`)도 그대로 남는다. 찍고 [소거법]으로 감점을 피하는 길을 막기 위해서다. 소거법 표시는 기록에 남는다.
5. **입력창에 직접 쓴 소거 근거**(질문 5 (가)). 판정 지시문(v5.10)은 바꾸지 않는다. 학생이 버튼 없이 소거 근거를 써서 [제출]하면 지금처럼 판정한다. 그 근거가 다른 선지 판단 때문에 대상 오류(OFF_TARGET)로 잡혀 정답인데 리뷰가 열리는 위험(미측정 추론)은 진단 실사용에서 관찰하고, 사례가 나오면 판정 규칙 개정(v5.11)을 시험한다.

## 이유

- 정답을 낸 학생에게 다시 고치라고 하지 않는다는 기준(D-0213)을 판정 규칙 변경 없이 지킨다.
- 소거 근거 판정 규칙은 판정기가 고른 선지 하나만 보는 구조와 부딪혀 오픈(2026년 11월) 전에 정하기 어렵다(논의 자료 3·4절).
- 판정기 호출이 없어 비용·대기가 없다.

## 다시 볼 조건

- 진단 실사용에서 입력창에 직접 쓴 소거 근거가 정답인데 리뷰로 가는 사례가 나오면 판정 규칙 개정을 시험한다(Q-0047 관찰 항목).
- [소거법] 버튼이 찍기를 감추는 데 쓰이는 정황(소거법 정답 비율이 비정상적으로 높음 등)이 보이면 재검토.
- 근거 약한 정답에도 진단에서 마지막 설명을 보이기로 하면, 소거법 정답도 함께 다시 본다.

## 추가 (2026-11-12, 사용자 결정): 지문 결과 화면 문구를 최종 카드와 맞춤, 소거법 정답 문구

- 결정: ① 근거 약함·판정 불가 정답의 지문 결과 화면 설명을 최종 카드 문구와 같게 한다(2단계 표시면 근거 약함은 "근거가 확인되는 정답이야"). 지문 결과 화면도 표시 단계 설정을 받는다. ② **소거법 정답은 두 화면 모두 "정답이 아닌 선지들을 잘 걸렀어"**(카드는 "정답이야. …"). 근거를 쓰지 않았으므로 근거를 평가하는 말을 쓰지 않는다. 표시 단계와 무관하다.
