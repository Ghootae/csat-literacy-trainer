# 클로드·코덱스 업무 분장

2026-10-14: 챗GPT 계정 종료로 [D-0128](./D-0128-claude-subagent-work-division.md)로 대체. 실행은 executor 하위 에이전트로 옮기고 인계·검토 규칙은 유지.

## 사용자 지시

1. 클로드: 문제 해결의 주된 사고 파트너.
2. 코덱스: 사용자가 코덱스와의 논의를 명시한 경우에만 보조 논의 파트너.
3. 코덱스 사용 한도가 넉넉하므로, 설계가 확정된 작업의 실행은 코덱스에 넘긴다.

## 운용 규칙

- **설계 확정 = 인계 문서 존재.** 실행을 넘길 때 `docs/handoffs/`에 인계 문서를 만든다.
  최소 항목은 목표·범위 밖, 손댈 파일·계약(입출력·스키마), 완료 조건·테스트 명령,
  관련 결정 기록이다. 형식: [`docs/handoffs/TEMPLATE.md`](../../docs/handoffs/TEMPLATE.md).
- **중단·보고.** 실행 중 인계 문서와 충돌하거나 설계 공백이 드러나면 코덱스는 즉흥적으로
  설계를 바꾸지 않고 멈춘 뒤 충돌 내용을 보고한다. 설계 판단은 클로드·사용자 쪽에 남긴다.
- **검토 루프.** 코덱스 실행 결과는 클로드가 인계 문서 대비 diff로 검토하고, 필요하면
  수정 사항을 다시 인계한다.
- **작은 작업 예외.** 인계 비용이 실행 비용보다 큰 작업(한두 줄 수정, 문서 갱신)은 클로드가
  직접 한다. `memory/`의 결정 기록·체크포인트는 클로드가 작성한다.
- **보조 논의의 독립성.** 코덱스에 의견을 물을 때 클로드의 결론을 함께 주지 않고 문제와
  근거 자료만 준다. 결과는 클로드가 종합한다.

- **커밋 확인.** 작업 단위가 검증까지 통과했을 때, 코덱스 실행분은 클로드 diff 검토를 통과했을 때,
  결정 기록·체크포인트를 남긴 직후에 클로드가 커밋 여부를 묻는다. 파일 목록과 메시지 초안을
  보여 주고 사용자 승인 후에만 커밋한다. 테스트 실패·실험 진행 중·인계 충돌 미해결 상태에서는
  묻지 않는다. 그 작업에서 바꾼 파일·변경분만 담고 `git add -A`는 쓰지 않는다. 커밋 승인은
  푸시 승인이 아니다(사용자 동의, 2026-10-07).

## 적용

`AGENTS.md`에 같은 규칙을 추가해 두 에이전트가 공유한다. 이 결정은 제품 판정 규칙·프롬프트
변경이나 외부 전송 승인이 아니다.

## 근거

- 사용자 직접 지시와 제안 동의(2026-10-07).
- 적용 파일: `AGENTS.md`, `docs/handoffs/TEMPLATE.md`.
