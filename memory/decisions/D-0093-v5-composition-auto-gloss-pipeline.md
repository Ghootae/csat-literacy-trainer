# v5 구성과 자동 해석본 파이프라인

## 결정

사용자 결정(2026-10-07)에 따라 운영 후보 v5([D-0090](./D-0090-problem-evaluator-v5-naming.md))를 다음처럼 구성한다.

1. 운영 규칙은 v5 그대로 쓴다.
2. 사람 승인 해석본은 쓰지 않는다. 기호 해석본은 문항마다 미리 자동 생성하고 자동 검사·자동 검수를 통과하면 그대로 쓴다.
   이는 [D-0084](./D-0084-local-marker-gloss-direction.md)의 "문항 검토자가 확인한 해석본"과 재검토 조건의 "제작·검토 절차"를,
   그리고 [D-0091](./D-0091-v3-marker-phase-closed-port-to-v5.md)의 "사람이 만들고 승인한 해석본을 옮긴다"를 대체한다.
   D-0084의 나머지(기호·도표 지칭에 한한 국소 해석본, 기호 해석만 판정기에 전달, 원문 결속)는 유지한다.
3. v3에서 만든 판정 방법(학생 주장 분리 기록, 인용 형식 규칙, 해석본 사용 규칙)을 옮긴다.

자동 해석본 세부:
- 형식은 중간안(대상과, 같은 자료 안에서 그 범위에 드는 구체 사례만; 허용·오류 예시 없음).
- 생성 → 코드 검사 → 독립 재도출(같은 OpenAI 모델, 생성본을 보지 않음) → 기호별 대조. 문항당 최대 3회차이며 코드 검사 실패도 1회차로 센다.
  불일치하면 생성과 재도출을 모두 새로 하고, 끝까지 불일치한 기호만 뺀다. 생성기에 재도출 내용을 주지 않는다.
- 3회차 모두 코드 검사를 통과하지 못하면 해석본 없이 판정하고 생성 실패를 기록한다.

검증 순서: 1단계 해석본 파이프라인(검수 레이어 오류 검출 시험 + 파이프라인 실행) → 2단계 v5 검증(v5 원본 / +판정 방법 / +자동 해석본).

## 근거

- 사용자 '그러니까 내가 생각하는 v5는 이런거야. 1. 운영 규칙은 기존의 v5의 것을 기본으로. 2. 사람 승인 해석은 고려하지 않음.
  앞으로는 모두 자동승인을 전제로. 3. 지금까지 v3에서 작업한 판정 방법을 이식.', '중간안으로 하자', '해석본 없이 판정하고 실패 기록하는 걸로.
  해석본 생성 후 의미를 자동 검수 및 수정하는 레이어를 추가하는 건 어떨까?', '같은 OpenAI 모델로 하자', '최대 3회로 하자', '그 순서로 진행.' (2026-10-07).
- 자동 생성 실험: [작업 기록](../checkpoints/2026-10-07-gongsun-auto-gloss-generation.md). 검사는 통과했지만 뜻이 틀린 문장이 판정에 쓰인 사례(v2 중간안 slot1 ⓐ)가 있었다.
- [이식 설계안](../../docs/review/v5-marker-port-design-2026-10-07.md), `scripts/lib/marker-gloss-pipeline.mjs`.

## 재검토 조건

- 1단계 검수 레이어 시험에서 심은 오류를 많이 놓치거나 정상 해석본을 자주 막으면 검수 방식(다른 회사 모델 포함)을 다시 정한다.
- 생성 실패·기호 제외가 운영 문항에서 자주 나오면 생성 지시나 회차 수를 다시 정한다.

## 후속 결정(2026-10-07, 1단계 결과 뒤)

- 1단계 결과([요약](../../docs/experiments/marker-gloss-pipeline-gongsun-2026-10-07/REVIEW-SUMMARY.json))를 보고 사용자가 대조 규칙을 먼저 고친 파이프라인 v2로
  해석본을 새로 만든 뒤 2단계를 하기로 했다. 1단계 채택본은 비교 기준으로 보존한다.
- v2 규칙: 대조를 대상·화자·사례로 나눠 판정하고 기호 일치는 코드가 합친다. 설명 생략(같은 범위)과 범위 변경을 구별한다.
  사례는 대상 칸에서 떼어 목록으로 받고 틀린 사례는 그 사례만 지운다. 재도출·생성 모두 대상을 문맥의 일부 구체물로 좁히지 않는다.
  불일치 때 원문이 어느 쪽을 뒷받침하는지 기록만 한다.
- 허용하는 사례는 원문에 등장하는 구체 개체뿐이다. 하위 범주와 대상 전체와 같은 것(같은 대상을 가리키는 다른 기호 포함)은 사례가 아니다(사용자 '㉮만 허용하는 걸로').
- 구현은 [D-0092](./D-0092-claude-codex-work-division.md)에 따라 [인계 문서](../../docs/handoffs/2026-10-07-marker-gloss-pipeline-v2.md)로 Codex에 넘긴다(사용자 'Codex에 넘기는 걸로 진행').

## 후속 결정(2026-10-07, 2단계 준비 전 설계안 5절)

사용자가 네 권고에 모두 동의했다.
1. 학생 주장 분리는 처음 근거 판정(SELECTION)에만 넣고 교정 답 판정(REPAIR)에는 이번에 넣지 않는다.
2. 학생 결론 독립 확인(CONCLUSION_AUDIT)에는 해석본을 주지 않는다.
3. 코칭·질문 등 학생에게 나가는 문장에 해석본 표현을 쓰지 않는다(해석본 사용 규칙 유지). 2단계에서 해석본 문구 노출을 따로 센다.
4. 학생 주장 분리·인용 형식 규칙은 모든 문항에, 해석본은 기호 문항에만 쓴다. 기호 없는 문항에서의 효과는 아직 확인하지 않았다.
- 1단계 채택본은 파이프라인 v2 실행 1~3의 채택본을 고치지 않고 2단계 반복 1~3에 쓴다([v2 결과](../../docs/experiments/marker-gloss-pipeline-v2-gongsun-2026-10-07/REVIEW-SUMMARY.json)).
