# 세션 안 모델 배정: 선택은 정오로, REPAIR는 luna, 코칭은 세션 모델

[D-0104](./D-0104-problem-evaluator-model-routing-by-choice.md)(첫 선택의 정오 라우팅)를 세션 전체로 넓힌다.

## 결정

| 판정 | 모델 |
|---|---|
| 모든 선택 판정(첫 선택·재선택) | 그 선택의 정오로 고른다. 정답 `gpt-6-luna`, 오답 `gpt-6.1-sol` |
| 교정 답변 판정(REPAIR) | `gpt-6-luna`로 고정 |
| 학생에게 보이는 코칭·설명 | 세션의 정오 모델과 연동. 정답 세션은 luna, 오답 세션은 sol |

- 오답 세션의 교정 실패 종료 코칭과 [코칭 보기] ([D-0106](./D-0106-post-repair-choice-reselect-or-coaching.md)) 설명, 재선택도 오답일 때의 종료 설명은 sol이 쓴다.
- 정답 세션의 [설명 보기]와 교정 실패 설명은 luna가 쓴다.
- 오답 세션은 REPAIR 판정(luna)과 공개 코칭(sol)의 모델이 다르다. 현재 구조에서는 REPAIR 호출이 coaching도 함께 만들므로,
  오답 세션이 끝날 때 sol에게 코칭만 따로 쓰게 하는 호출이 필요하다(판정기의 COACHING 요청 종류를 활용할 수 있음).

## 근거

- 사용자 결정(2026-10-10): "교정 답변 판정(REPAIR): 일단 루나로 고정", "일단 정오로 모델을 선택하고, 코칭 답변도 해당 모델로 연동.
  정답: 루나. 이미 정답을 맞춘 상태이므로 코칭의 퀄리티는 덜 중요하다고 지각될 것. 오답: 솔. 오답의 경우 코칭이 중요."
- [v5 다문항 의미 검토](../../docs/experiments/v5-multi-item-luna-sol-review-2026-10-08/REVIEW-SUMMARY.json): luna의 학생 노출 코칭 결함
  (판단 방향 뒤집힘 B21, '반비례' 강화 D21·D22, 내부 선지 번호)은 오답 세션의 종료 코칭에서 나왔다.
- [REPAIR 탁상 점검](../../docs/experiments/v5-repair-desk-check-2026-10-10/): 세 모델의 REPAIR 판정이 거의 같았고, 첫 판정 분석을 입력에 더해도 판정이 바뀌지 않았다.
  luna는 정답 세션의 수정 후 근거 충분을 후하게 판정했으나 D-0104 후속 판단으로 실패로 세지 않는다.

## 범위와 미검증

- 구현(모델 선택, 오답 세션 종료 시 sol 코칭 호출, D-0106 버튼 흐름)은 별도 설계·승인 대상이다.
- REPAIR에서 luna 판정 품질과, 오답 세션의 sol 코칭 품질은 REPAIR API 시험으로 확인한다. 첫 판정 분석 추가 입력은 채택하지 않는다(점검에서 효과 없음).
- 오답 세션이 끝날 때 sol 코칭 호출만큼 학생 대기 시간이 늘어난다(칸 중앙값 약 20초대, 종료 시점 1회).

## 재검토 조건

- REPAIR API 시험에서 luna가 미수정 답을 수정으로 판정하거나 명확한 오류를 놓칠 때
- 오답 세션 종료 대기 시간이 실제 사용에서 이탈 요인이 될 때
