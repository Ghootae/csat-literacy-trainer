# 두 단계 생성 v2: 개관·요약 문장을 CONNECTIVE로, 보강 제한 강화

## 결정

[D-0095](./D-0095-central-story-two-stage-generation.md)의 두 단계 생성 1단계를 다음과 같이 고쳐 v2로 25문단 전체를 다시 생성한다. 2단계 지침, 덧붙이기만 허용하는 검사, 최소 축 수 계산, 별도 실험 원칙은 그대로 둔다.

1. **CONNECTIVE 정의 확장:** 기존(예고·도입·연결)에 두 종류를 더한다.
   - 개관 문장: 새 관계를 더하지 않고 뒤 설명의 화제·범위만 미리 제시한다.
   - 요약 문장: 앞 설명을 다시 정리하거나 결론짓기만 한다.

   "확실하지 않으면 설명 단위에 배정한다"는 보수적 기본값은 유지한다.
2. **보강 제한:**
   - CONNECTIVE로 배정한 문장의 내용은 중심 이야기에 보충하지 않는다.
   - 용어 정의는 그 정의 자체가 문단의 핵심 관계일 때만 보충한다.
   - 코드 검사: 보충의 근거 인용이 CONNECTIVE로 배정된 문장에만 있으면 계약 위반으로 처리한다(정의 제한은 의미 판단이므로 사람 검토 대상).
3. **출력 스키마:** 입력을 그대로 돌려주던 `centralStory` 필드를 1단계 출력에서 없앤다.

진행 순서는 [D-0092](./D-0092-claude-codex-work-division.md)를 따른다: 인계 문서 → Codex 구현·사전 검증 → Claude diff 검토 → 별도 전송 승인 → 실행. v1 결과(`docs/experiments/central-story-two-stage-2026-10-07/`)는 보존하고 v2는 새 폴더에 저장한다.

## 근거

사용자 판정 4건이 모두 같은 방향이다. 실질 설명 하나에 도입·연결·개관·요약 문장이 붙은 문단은 1축이 적당하다.

| 문단 | 판정 | 기록 |
|---|---|---|
| 표면 장력3 | 1축 적당 | `docs/experiments/axis-audit-v2-min-two-2026-10-06/HUMAN-REVIEW.md` |
| 정보 비대칭2 | 1축 적당 | 위와 같음 |
| 도파민4 AX1(개관 문장) | 잉여 | `docs/experiments/central-story-two-stage-2026-10-07/HUMAN-REVIEW.md` |
| 표면 장력6 AX2(요약 문장) | 잉여 | 위와 같음 |

v1 결과(`docs/experiments/central-story-two-stage-2026-10-07/REPORT.md`, Claude 의견)도 근거로 삼는다.

- 표면 장력2: 도입 문장이 보강으로 들어가 계면 활성제 축의 요구 범위가 넓어졌다.
- 표면 장력5: '점도는 끈적거림의 정도'라는 부수 정의가 보강됐다.
- 1단계 계약 실패 3건 가운데 2건(도파민3, 정보 비대칭2)이 `centralStory` 필드에 보강 문장을 쓴 형식 오류였다.

사용자 승인: "그 방향대로 진행."(2026-10-07). 승인 범위는 정의 확장, 보강 제한, 스키마 정리, 25문단 전체 재실행이다.

## 폐기한 대안

- 실패 3문단과 문제 4문단만 재실행(14회): 지침이 바뀌면 다른 문단(예: 정보 비대칭5의 '되새길 필요' 축)에도 영향이 있어, 버전이 섞이면 비교가 흐려진다.
- 보수적 기본값을 반대로 바꿈(불확실하면 CONNECTIVE): 사람 판정 4건은 모두 판단이 분명한 사례여서 기본값을 바꿀 근거가 되지 않는다.
- 덧붙이기 검사 완화: 표면 장력1의 실제 문구 변경을 잡아낸 검사다.

## 재검토 조건

- v2에서 실질 설명 문장을 CONNECTIVE로 잘못 배정해 핵심 관계가 축에서 사라지는 사례가 사람 검토에서 나올 때
- 1축 문단이 늘어 "1축은 도입·정리 정도로 제한적"이라는 사용자 원칙과 어긋날 때
