# 근거 기본 제출·교정 1회·재선택 1회 흐름을 구현 후보로 기록

## 결정 범위

후속 갱신: [D-0055](./D-0055-multiple-error-correction-batch-deferred.md)는 최초 오답 복수 오류에서
아래 ‘교정 질문 총 1회’와 ‘중간 실패 즉시 종료’를 오류별 순차 질문·누적 최종 판정으로 대체한다.
아래 본문은 당시 후보 이력으로 보존하며 현재 설계는 후속 결정과 함께 읽는다. 운영은 미변경이다.

사용자가 논의하고 명확화한 아래 흐름을 후속 구현 후보로 보존한다. `accepted`는 후보 기록과
구현 보류에 대한 승인이지 운영 승격이 아니다. 현재 v3 프롬프트·상태 머신·UI·포인트는 변경하지
않는다. D-0049·D-0050과 함께 사용자가 나중에 구현을 요청할 때 검토한다.

## 제출 원칙

- 최초 선택과 재선택 모두 기본적으로 근거를 제시한다.
- 너무 명백한 판단에 대한 작성 부담을 피할 수 있도록 모든 선택에 명시적인 ‘정답만 입력’
  (답만 제출) 선택을 제공한다.
- 답만 제출하여 틀린 경우 포인트 감점 리스크를 부담한다. 개발에서는 실제 포인트 차감을
  구현하지 않는다. 감점 대상 안내와 실제 차감을 혼동하지 않게 한다.
- 최초 오답에 근거가 없으면 오답임을 명시하고 근거를 요구한다. 뒤늦게 제출된 근거를 아래
  최초 오답 분기로 보내며, 근거 제출 자체는 새로운 선지 선택이나 교정 질문으로 세지 않는다.
- 마지막 재선택에는 근거 요구보다 종료 규칙이 우선한다. 근거 없는 재선택 오답도 다시
  근거를 요구하지 않고 상세 코칭 후 종료한다.

## 최초 정답

| 근거 상태 | 처리 |
|---|---|
| 없음 | 근거 미검증 정답으로 종료 |
| 타당하고 충분함 | 근거 검증 정답으로 종료 |
| 불충분·모호하지만 명시적 오류 없음 | 추가 질문 없이 근거 미검증 정답으로 종료 |
| 명시적 오류 또는 발문 극성을 고려한 선택–근거 충돌 | 교정 질문 1회 → 실제 수정 성공이면 종료, 실패·수정 확인 불가이면 상세 코칭 후 종료 |

## 최초 오답

1. 근거에서 오류가 명확하면 해당 오류를 겨냥한 교정 질문을 1회 제시한다.
2. 근거가 불명확하면 내부 추론 가능성 게이트를 거친다.
   - 이미 제출된 발화에서 추론하여 오류를 확인할 수 있음: 같은 교정 질문 1회 경로로 간다.
   - 추론 불가능: 제출된 설명으로 판단을 확인하기 어렵다고 알리고 상세 코칭 후 종료한다.
3. 교정 질문에 대한 학생 답변에서 실제 수정이 확인되면 재선택을 1회 제공한다.
4. 교정에 실패하거나 실제 수정 여부를 확인할 수 없으면 상세 코칭 후 종료한다.

게이트는 학생에게 추가 진단 질문을 하는 단계가 아니다. 학생이 말하지 않은 핵심 전제·관계·
결론을 만들어 오류를 확정하지 않는다. 추론 불가능을 ‘학생의 사고가 비논리적임’으로 단정하지
않으며, 상세 코칭은 추정한 학생 사고가 아니라 원문에 근거한 선지 판단을 설명한다. 짧다는
이유만으로 불명확 판정을 하지 않는다.

## 마지막 재선택

| 선택·근거 상태 | 처리 |
|---|---|
| 정답 + 타당하고 충분한 근거 | 근거 검증 정답으로 종료 |
| 정답 + 근거 없음 또는 불충분·모호하나 명시적 오류 없음 | 근거 미검증 정답으로 종료 |
| 정답 + 명시적 근거 오류 또는 선택–근거 충돌 | 추가 교정 질문 없이 상세 코칭 후 종료 |
| 오답 | 근거 유무·내용에 관계없이 상세 코칭 후 종료 |

전체 한도는 최초 포함 선택 최대 2회, 교정 질문 최대 1회다. 별도 진단 질문으로 대화를
늘리지 않는다. 코칭 확인만으로 재선택을 허용하거나 수정 성공으로 기록하지 않는다.

## 기존 후보 및 현행 정책과의 관계

- [D-0049](./D-0049-stem-polarity-normalization-deferred.md)의 발문 극성 정규화·선택 의미와
  근거 파생 결론 분리·실제 내용 수정 확인 원칙을 유지한다.
- [D-0050](./D-0050-reasoning-reconstructability-gate-deferred.md)의 추론 가능성 확인과
  과잉 재구성 금지는 유지한다. 다만 후속 후보에서 추론 불가능 이후 행동은 기존의 ‘좁은 진단
  질문’ 대신 ‘확인 어려움 안내 + 상세 코칭 + 종료’를 적용한다. D-0050의 역사적 본문은 보존한다.
- D-0008의 운영 v3와 현행 선택 3회·오답별 질문 2회 구현은 아직 대체하지 않는다.
- [정책·구현 불일치 기록](../checkpoints/2026-10-01-problem-feedback-policy-runtime-discrepancy.md)의
  코칭 확인 후 재선택 경로는 이 후보에 포함되지 않는다. 구현 시 별도로 제거·검증할 대상이다.

## 구현 시 검증할 항목

- 최초 정답 4분기, 최초 오답의 근거 없음·명확한 오류·게이트 성공·게이트 실패를 고정 사례로 검증한다.
- 교정 성공과 실패·불명확을 분리하고, 실제 수정 없는 재선택과 코칭 뒤 재선택을 차단한다.
- 마지막 재선택의 모든 종료 분기에서 추가 근거 요구·진단·교정 질문이 생기지 않게 한다.
- 짧지만 일관된 근거를 추론 불가능으로 오분류하지 않고, 모호한 근거에 오류를 만들어 넣지 않는다.
- 정보 비대칭 13번의 발문 극성 실패를 D-0049와 함께 재현·검증한다.
- 개발 환경에서 실제 포인트 잔액이 변경되지 않음을 확인한다. 감점량과 실서비스 적용 시점은 미정이다.
