# SNS 진단평가도 본 서비스 피드백을 유지하고, 지문 단위로 다 답한 뒤 하나씩 피드백하며, 분석은 첫 응답만 쓴다

## 결정

[D-0200](./D-0200-sns-diagnostic-mode-result-screen-direction.md)의 "교정 대화 없음, 판정만"과 "요약 대화 없이 1회 판정"을
대체한다. D-0200의 다른 내용(결과 화면 순서, 경향 표현, 골드를 판정 입력으로 쓰지 않음 등)은 그대로다.

1. **피드백 유지.** 문제 풀이(판정 → 교정 질문 → 다시 고르기·코칭 → 마지막 설명)와 문단 요약(요약 대화)을 본 서비스와
   거의 같게 둔다. 판정기·지시문·모델 배분은 바꾸지 않는다.
2. **지문 단위 순서.** 한 지문은 (요약 대화) → 문항 답 모두 입력 → 지문 결과 정리 → 문항별 피드백 → 다음 지문이다.
   정오와 교정 질문은 그 지문의 답 입력이 끝날 때까지 숨긴다. 세트 전체(16문항)를 먼저 답하는 방식은 쓰지 않는다.
3. **첫 응답 원칙.** 결과 화면의 분석(위치, 정답의 질, 무너진 단계, 걸린 함정, 독해 패턴·수형도)은 첫 응답만 쓴다.
   문항은 첫 선택 + 첫 근거, 요약은 문단별 첫 차례다. 교정 뒤의 답과 교정 결과는 분석에 넣지 않는다.
4. **문단 요약.** 지문마다 "문단별 요약" / "요약 안 하기"를 고르고 기록한다. 요약 도중 다음 문단으로 넘어갈 수 있다.
   요약 대화는 문항보다 먼저 한다. 그래서 요약을 고른 참가자의 문항 첫 응답에는 요약 피드백이 섞인다(사용자가 알고 고름).
   요약 선택 여부로 두 집단의 위치를 나눠 볼 수 있게 기록한다.
5. **근거 생략.** 문항마다 근거를 쓰지 않을 수 있다("근거 생략", 너무 쉬운 문항 등). 이를 "감"으로 해석하지 않는다.
   그 문항은 첫 응답 판정·사고 진단을 부르지 않고, 정답이면 "근거 생략" 정답으로 따로 센다.
6. **지문 결과 정리.** 정답 수는 첫 선택 기준. 근거는 쓴 문항만 분모로, 판정 `SUPPORTED`만 적절. 근거 생략 수는 따로
   말한다. 판정 실패 문항은 분모에서 빼고 "확인 중", 오답 + `SUPPORTED`는 적절로 세지 않고 개발자 검토 목록에 올린다.
   예: "이 지문의 4문항 중 3개를 맞혔어. 근거를 쓴 3개 중 2개가 적절했어(1개는 근거 생략)."
7. **건너뛰기.** 문항 피드백마다 "이 문항 건너뛰기"를 둔다. 누르면 교정을 그만두고 마지막 설명 확인으로 가며, 건너뛴 사실을
   기록한다. 지문 전체 건너뛰기는 두지 않는다.
8. **교정 결과 표시.** 결과 화면 문항 카드 안에 "피드백으로 고쳤어요" / "건너뜀"을 작게 보인다. 집계 칸은 두지 않는다.
   교정 결과는 서비스 반응 자료로 따로 기록한다.

D-0200 6 표에서 바뀌는 두 줄:

| 기존 결정 | 훈련 서비스 | SNS 진단평가 모드(D-0204) |
|---|---|---|
| D-0183 요약 판정·수형도 | 학생 확인 단계, 수형도는 마지막 차례 | 요약 대화 유지, 분석·수형도는 첫 차례 |
| 문제 풀이 교정 흐름(D-0090 등) | 문항마다 바로 피드백 | 흐름 유지, 지문의 답을 다 입력한 뒤 하나씩 피드백 |

## 근거

- 사용자(2026-11-06, 웹 에이전트 대화를 붙여 넣음): "sns 진단 평가의 진짜 목적은 본 서비스에 대한 진짜 사람들의 응답과
  평가 수집이야. 부차적으로 진짜 서비스로의 유입이고. 그래서 일반적인 진단만을 목적으로 구현하면 우리 서비스의 매력이
  많이 줄 것 같아." "후자로 가는 경우, 분석의 결과는 첫 응답에 국한해서 제시한다는 원칙이 필요할 것 같아."
- 웹 에이전트 제안: 같은 지문 안 앞 문항의 교정이 뒤 문항 답을 알려 주면 첫 응답이 오염되고 IRT 위치가 과대해진다 →
  지문 단위로 다 풀고 교정. 개정 문서: `docs/reports/REPORT-learner-analysis-usage-web-result.md`(2026-11-06 개정).
- 사용자 선택(2026-11-06, 코드 에이전트 질문에 대한 답): 요약 대화 (가) 먼저 유지(코드 에이전트 권고는 첫 요약만 먼저,
  대화는 문항 뒤), "지문 단위야", 근거 입력 여부를 문항마다 선택(사용자 안), 지문 결과 정리(사용자 안, 기준은 코드 에이전트
  제안에 "그 기준으로 동의"), 건너뛰기 (나) 문항마다, 교정 결과 표시 (나) 카드 안 표시만.
- 코드 확인(2026-11-06): 판정 함수는 컨트롤러 없이 부를 수 있고(`packages/pipeline/src/problem-solving/feedback.ts`
  `createFeedbackSession`·`submitFeedbackCommand`·`applyFeedbackAssessment`), 판정 뒤 상태는 교정 질문 대기로 멈춰 나중에
  이어 갈 수 있다(`feedback.ts:523`). 지금은 제출 즉시 정오를 알리고(`packages/app/src/server/problem-feedback.ts:139`),
  교정 도중 빠져나갈 명령이 없다(`feedback.ts:13`). 요약 대화는 문단 사이 이동이 이미 된다(`packages/app/src/server/dialogue-simple.ts:85`).

## 다시 볼 조건

- 요약을 고른 집단과 고르지 않은 집단의 위치 차이가 커서 위치 표시가 왜곡되면 요약 대화를 문항 뒤로 옮기는 안
  (코드 에이전트 권고안)을 다시 본다.
- 피드백 때문에 지문 중간 이탈이 많으면 지문 전체 건너뛰기를 더한다.
