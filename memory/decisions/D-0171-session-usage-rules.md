# 사용량 절감 규칙: 과제 종료 절차·모델 배분·긴 산출물 검토 위임·기억 문서 읽기

## 결정

코드 에이전트의 사용량을 줄이기 위해 다음 다섯 규칙을 둔다. 구현을 DeepSeek 등 외부 모델로 옮기는 안은 채택하지 않는다.

1. **과제 종료 절차**: 과제 한 단위가 끝나면 코드 에이전트가 판단해 (1) 변경이 있으면 커밋 여부를 묻고(기존 커밋 규칙대로 파일 목록·메시지 초안 제시), (2) 세션 재시작 여부를 묻는다. 맥락이 많이 쌓였거나 다음 과제가 지금 맥락과 관련이 적으면 재시작을 권하고, 이어지는 과제면 계속을 권한다. 재시작하기로 하면 체크포인트·`CURRENT_STATE.md`에 다음 할 일을 적은 뒤 사용자에게 `/clear` 입력을 안내한다. 코드 에이전트는 세션을 직접 재시작하지 못한다.
2. **모델 배분**: 하위 에이전트 모델은 코드 에이전트가 과제 종류로 고른다. 구현·인계 문서 실행은 sonnet, 단순 조회·파일 수집은 haiku, 독립 검토·까다로운 디버깅은 opus. 메인 세션 모델은 사용자가 `/model`로 바꾸므로 코드 에이전트는 과제 시작 때 한 줄로 권고만 한다(일상 작업: 커밋·기록 갱신·단순 확인은 Sonnet, 설계·실험 해석은 Opus 유지).
3. **긴 산출물 검토 위임**: 대량 생성 결과·긴 로그·긴 실험 출력의 검토는 하위 에이전트에 맡기고 요약·판정·문제 사례만 돌려받아 원문을 메인 맥락에 쌓지 않는다. 사용자가 직접 판정해야 하는 경우(예: 학생용 설명의 이해 용이성)에는 원문을 보여 준다.
4. **기억 문서 읽기**: 과제 시작 때 `INDEX.md`를 통째로 읽지 않는다. 소제목 목록을 먼저 읽고 과제와 관련된 구역 전체를 읽은 뒤 낱말 검색으로 보충한다.
5. **CURRENT_STATE 크기**: `CURRENT_STATE.md`는 지금 참인 것만 담고 20KB 이하로 유지한다(`scripts/validate-memory.mjs`가 검사). 2026-10-24 정리에서 뺀 원문은 `memory/CURRENT_STATE-ARCHIVE-2026-10-24.md`에 보존한다.

## 근거

- 측정(2026-10-24, 코드 에이전트가 `~/.claude/projects/*csat*`의 최근 30일 대화 기록을 집계): 메인 세션 Opus 5.5 캐시 쓰기 37.7M·캐시 읽기 1,467M·출력 5.9M(5,397호출), 하위 에이전트 Sonnet 5.5 캐시 쓰기 6.8M·캐시 읽기 75M·출력 0.27M(910호출). 공개 단가 비율로 환산한 Sonnet 구현 몫은 약 4~5%(Opus와 같은 무게로 쳐도 약 7%). 비용의 약 2/3는 메인 세션 캐시 읽기, 즉 긴 맥락의 반복 읽기다. 구독 한도의 실제 계산 방식은 공개 단가와 다를 수 있어 근사값이다.
- 과제 시작 때 읽는 문서: `WORK_TREE.md` 9KB, `CURRENT_STATE.md` 63KB(199줄로 줄 수 한도 200은 지키지만 줄이 길어짐), `INDEX.md` 66KB, 합계 약 138KB.
- 사용자(2026-10-24): "한 단위의 과제가 끝날 때마다 네가 적절히 판단해서 커밋 여부를 묻고, 세션 재시작 여부를 물어줘", "네가 과제의 종류에 따라 적절히 모델을 배분해줘", 긴 산출물 검토 위임을 규칙으로 만들기(가), 범위 확인에 "오케이", 정리 계획에 "승인".

## 폐기한 대안

- 구현을 DeepSeek API로 옮기기: 구현 몫이 약 4~5%라 절감 효과가 작고, 별도 실행 도구 설정·외부 전송(지문 포함 자료)·검토 비용 증가가 따른다.
- 보관본을 하위 폴더에 두기: 문서 안 상대 링크가 깨진다.

## 재검토 조건

- 같은 집계 방법으로 다시 쟀을 때 하위 에이전트 몫이 전체의 20% 이상이 되면 구현 외부 모델 시험을 다시 검토한다.
- INDEX 구역 읽기로 관련 기록을 놓친 사례가 나오면 읽기 규칙을 다시 정한다.
