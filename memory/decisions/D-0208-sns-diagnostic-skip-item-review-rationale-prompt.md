# SNS 진단평가: 건너뛰기는 새 종료 사유 SKIPPED, 문항 검토 문항은 고정 문장 뒤 넘어감·결과에서도 정답 비공개, 근거 요청 문구에서 감점 안내 제거, 지문 끝까지 답 고치기 가능

## 결정

백엔드 인계 문서(`docs/handoffs/2026-11-06-sns-diagnostic-backend.md`)를 쓰며 코드와 대조하다 찾은, 설계 초안
(`docs/SNS-DIAGNOSTIC-DESIGN-DRAFT-2026-11-06.md`)의 빈칸이다. 1~3은 코드 대조에서, 4~5는 인계 문서에 대한 웹 에이전트 검토에서 나왔다. [D-0204](./D-0204-sns-diagnostic-keeps-service-feedback.md)를 보충한다.

1. **건너뛰기(`SKIP`)의 종료 사유(사용자 선택 (가)).**
   - 새 종료 사유 `SKIPPED`를 만들고, 마지막 설명 지시문의 종료 사유 정의에 한 문장("SKIPPED는 학생이 질문에 답하지 않고 이 문항을
     건너뛴 것이다")을 더한다. 마지막 설명 앞 안내 문장은 없다.
   - 결과 분류는 정답이면 `UNVERIFIED_CORRECT`, 오답이면 `COACHING_TERMINATED`.
   - 받는 단계는 근거 요청(`AWAITING_RATIONALE`)·교정 질문(`AWAITING_CORRECTION`)·다시 고르기(`AWAITING_RESELECTION`) 셋이다.
     교정 뒤 선택 단계는 [설명 보기]가 같은 일을 하므로 뺀다.
   - 실제 모델의 설명 품질은 비용·대기 시간 측정 때 확인한다.
2. **문항 검토(`ITEM_REVIEW`) 문항(사용자 선택 (가)).**
   - 피드백 차례에는 "이 문항은 우리가 한 번 더 확인해 볼게. 다음 문항으로 넘어갈게."를 보이고 다음 문항으로 간다.
     정답은 공개하지 않고 개발자 검토 목록에 올린다.
   - 판정기가 원자료 부족이나 정답 충돌(`boundary ≠ NONE`)을 표시한 문항은 지문 결과 정리에서 판정 실패와 같이 근거 분모에서
     빼고 "확인 중"으로 센다. 정답 수는 첫 선택 기준으로 그대로 센다. 결과 카드의 정답의 질 칸은 "확인 중"으로 둔다.
3. **근거 요청 문구(사용자 선택 (가)).** 근거를 생략한 오답에 근거를 물을 때, 진단평가 화면에서는 본 서비스의 감점 안내 대신
   "정답이 아니야. 어떻게 판단했는지 적어 주면 같이 볼게. 적기 어려우면 [근거 미제출]을 눌러 줘."를 보인다. 상태기계 문구는
   그대로 두고 진단평가 컨트롤러가 화면 문구만 바꾼다.
4. **지문 안 답 고치기(웹 에이전트 검토 1, 사용자 동의).** 지문을 다 풀었다고 낼 때(`answers-done`)까지는 답을 고칠 수 있고,
   선택 판정은 그때 한꺼번에 시작한다. 첫 응답은 그 시점의 답이다. 설계 초안 2-1 (2)·(4)의 "근거를 쓴 문항은 제출 즉시 판정"을 바꾼다.
5. **결과 화면에서도 정답 비공개(웹 에이전트 검토 3, 사용자 동의).** 문항 검토 문항(원자료 부족·정답 충돌 표시, 오답 + `SUPPORTED`)은
   결과 화면에서도 정답 위치·근거 원문·함정·사고 진단을 보이지 않는다. 첫 선택 기준 정오는 남긴다.

## 근거

- 코드 확인(2026-11-06):
  - 종료 사유 여섯 가지와 정의 문장: `packages/pipeline/src/problem-solving/feedback.ts:48`, `feedback-end-explanation.ts:14`·`:35`.
    기존 사유를 빌리면 모델에 사실과 다른 대화 결말을 준다(예: REPAIR_FAILED = 고치려다 실패).
  - `ITEM_REVIEW`는 어떤 명령도 받지 않는다(`submitFeedbackCommand`). 판정 지시문의 boundary 정의: "판정에 필요한 원자료 누락은
    MISSING_SOURCE, 충분히 타당한 판단과 공식 정답의 실제 충돌은 KEY_CONFLICT". 이 문구는 v5 이전 연결 후보 판의 지시문
    (`docs/experiments/v5-lead-sentence-2026-10-14/requests/`)에서 읽었고, 현행 v5 문구와는 대조하지 않았다.
  - 근거 생략 오답의 감점 문구: `feedback.ts`의 `SELECT` 처리.
- 사용자 답(2026-11-06): 1 "(가)에 동의. 누를 수 있는 단계에도 동의", 2 "(가)로 하자", 3 "(가)로 하자".
- 4·5: 웹 에이전트 검토 `docs/review/sns-diagnostic-backend-handoff-review-2026-11-06.md` 1·3에 사용자 "나도 동의해"(2026-11-06).
  같은 검토의 2(참가자 파일 직렬 저장)·4(RESUME 성공 시 첫 판정 갱신)·5(시간 정의는 인계 B)·6(문단 판정 259회를 측정 때 먼저 봄)은
  설계 판단이 아닌 구현 계약으로 인계 문서에 반영했다.

## 이후 변경

- 4번(답 고치기 허용, 판정은 지문 끝에 한꺼번에)은 [D-0221](./D-0221-diagnostic-confirm-each-item-judge-immediately.md)로 대체됐다(2026-11-10): 문항마다 답을 내면 확정·바로 판정, 답 고치기 없음.

- 측정에서 `SKIPPED` 마지막 설명이 어색하면 지시문 문장을 다시 본다.
- 실제 참가자에서 문항 검토 문항이 자주 나오면 그 문항의 묶음 자료·정답 기준을 점검한다.
