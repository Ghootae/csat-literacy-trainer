# 학생에게 보이는 문장은 반말로 통일

## 결정

1. 학생이 보는 문장의 말투를 친근한 반말로 통일한다(사용자 결정 2026-10-12). 범위는 세 출처 모두다.
   - 서버 고정 문구
   - 판정 모델이 쓰는 교정 질문(v5 판정 지시문)
   - luna·sol 종료 설명
   [D-0110](./D-0110-public-coaching-format-haeyo-and-markdown.md)의 '해요체'만 이 결정으로 대체한다. 3인칭 금지, 마크다운 유지 같은 나머지 항목은 그대로다.
2. 서버 고정 문구는 아래로 바꾼다(사용자 동의 "둘 다 동의").

   | 상황 | 문구 |
   |---|---|
   | 시작 | 답을 고르고, 그렇게 판단한 근거를 적어 줘. 근거 없이 답만 내도 돼. |
   | 근거 없는 오답 | 정답이 아니야. 근거 없이 고른 오답은 감점돼(개발 버전에서는 실제로 깎지 않아). 어떻게 판단했는지 적어 주거나, [근거 미제출]을 눌러 줘. |
   | 교정 성공(오답 세션) | 핵심 오류를 잘 고쳤어. 처음에 ①번을 고르게 된 생각 중 어디가 잘못됐는지 알 것 같으면 다시 골라 볼래? |
   | 교정 성공(정답 세션) | 근거의 핵심 오류를 잘 고쳤어. 처음 근거에서 어디가 잘못됐는지 정리한 설명을 볼래? |
   | [다시 선택] 뒤 | 답과 근거를 한 번 더 내 줘. 이번이 마지막 선택이야. |
   | 정답·근거 확인 | 정답이야. 근거도 정확해. |
   | 정답·근거 없음 | 정답이야. 근거를 안 적어서 어떻게 풀었는지는 확인하지 않았어. |
   | 평가 실패 | 피드백을 만들지 못했어. 제출한 내용은 저장돼 있으니 다시 시도해 줘. |

3. 선지 번호 뒤 조사는 '번'을 붙여 "①번을"로 쓴다. D-0112 3항의 "'를' 고정"을 대체한다. "①를"·"③를"은 읽는 소리(일·삼)와 맞지 않는다.
4. 문항 검토(ITEM_REVIEW) 문구 2개는 개발자 확인 상황이라 이번 범위 밖이다.
5. 판정 지시문을 바꾸므로, 반영 뒤 소규모 실모델 확인을 한다. 예상 비용은 0.1~0.2달러이고 실행 전에 따로 승인을 받는다.

6. 종료 설명의 금지 표현(사용자 동의 2026-10-13, UI 메모장 9·11번):
   - luna·sol 지시문 공통으로 학생을 3인칭으로 부르지 않는다. 예: "학생이 고친 답변" 대신 "네가 고친 답".
     지금 3인칭 금지 문장은 luna 지시문에만 있다.
   - 내부 용어(교정 질문, 판정, 종료 사유)를 쓰지 않고 대화 말로 쓴다. 예: "아까 내 질문에 '아니요'라고 답하면서".
     지시문의 endReason 설명 문장도 이 용어가 그대로 따라 나오지 않게 고친다.
   - 서버가 "교정 질문"이 들어간 종료 설명을 거부하고 다시 생성하게 한다. 내부 식별자 검사와 같은 방식이다.
     3인칭은 서버에서 검사하지 않는다. 원문 발문에 "학생이"가 있어(공손룡) 정상 문장을 막을 수 있다.
   "오류"는 금지어에서 뺐다(인계 작성 때 Claude 보정). 서버 문구 "핵심 오류를 잘 고쳤어"처럼 일반 단어로도 쓰기 때문이다.
   인계: `docs/handoffs/2026-10-13-v5-tone-and-correct-unverified.md`.
   근거: [48세션 재검토](../../docs/experiments/v5-diverse-48-2026-10-12/REVIEW-claude.md) 2-C, 3절.
   "교정 질문" 노출 6/30, 3인칭 1/30.

7. 구현(2026-10-13): 코덱스가 인계 `docs/handoffs/2026-10-13-v5-tone-and-correct-unverified.md`대로 반영했다. Claude diff 검토를 통과했고 테스트는 355/355다. 실모델 확인 전이다.
