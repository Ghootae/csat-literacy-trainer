# 마지막 설명 선지 칸의 첫 판정 문장은 코드가 쓴다

## 결정

사용자 확정(2026-10-14, UI 메모장 19번). 설계는 [인계 문서](../../docs/handoffs/2026-10-14-v5-section-lead-sentence.md)에 있다.

- `firstChoice`·`reselection` 칸의 첫 문장은 `feedbackSectionLead()`가 정해진 틀로 쓴다. 화면에서는 이 문장이 모델이 쓴 칸 내용 앞에 붙는다. 모델은 이 문장을 입력(`sectionLeads`)으로 받고 다음 문장부터 쓰며, 다시 판정하지 않는다.
- 틀:
  - 정답: "②를 고른 건 맞아."
  - 오답이고, 그 선택의 마지막 비교가 `CONSISTENT`: "②가 틀렸다고/맞다고 봤지만, ②는 답이 아니야." 틀렸다/맞다는 문항 극성으로 정한다.
  - 그 밖의 오답: "②는 답이 아니야."
  - 조사는 번호를 읽는 소리를 따른다(①·③은 을/이/은).
- `answer` 칸은 그대로다.

## 이유

- 재선택 시험의 P3-G에서 판정·재구성·질문은 정확했다. 그런데 첫 문장이 "처음에 ②가 틀렸다고 본 건 아니야."로 꼬여 학생 말을 뒤집은 것처럼 읽혔다(18개 중 1개). 출처: [재선택 시험](../../docs/experiments/v5-reselection-sections-2026-10-14/REPORT.md).
- 학생 말을 거꾸로 전하는 문장은 드물어도 피드백 전체의 신뢰를 깎는다. 이 문장에 필요한 사실은 코드가 이미 안다.
- 사용자는 "코드가 기본 문장을 쓰고 모델이 자연스럽게 고치는" 방안을 제안했다. 그러나 모델이 판정을 다시 옮기는 단계가 남으면 같은 실수가 생길 수 있다. 그래서 판정 문장은 고정하고, 자연스러움은 모델이 다음 문장을 이어 쓰는 방식으로 얻기로 했다.

## 확인

- 단위 시험으로 표의 모든 경우를 확인했다. 빌드, vitest(실패는 기존 2건만), e2e 13/13을 통과했다.
- 실모델 4세션 1회 확인: 판정 문장은 표와 같았고, 다시 판정한 문장은 0건, 이음은 자연스러웠다. 비용은 0.169달러다. 출처: [보고서](../../docs/experiments/v5-lead-sentence-2026-10-14/REPORT.md).

## 감수할 점

- 칸 첫 문장의 표현이 틀에 박힌다.
- 변경 전에 설명이 만들어진 개발용 세션은 판정이 두 번 보일 수 있다.

## 재검토 조건

- 학생 화면에서 첫 문장이 반복적으로 딱딱하다는 피드백이 나오면 다시 본다.
- 판정 문장과 모델 문장이 서로 맞지 않는 이음이 관찰되면 다시 본다.
