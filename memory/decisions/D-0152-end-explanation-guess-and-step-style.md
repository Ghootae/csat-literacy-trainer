# 마지막 설명: 추정 오류는 짐작이라고 밝히고 직접 말하며, 한 단계씩 쓰고, 칸 끝 문구는 칸이 다룬 내용으로 고른다 (D-0150 설명 표현 보완)

## 결정

사용자 동의(2026-10-20 "권고대로 진행해줘", "권고대로 설계안 고치고 진행해줘", UI 메모장 27번). 설계는
[인계 문서](../../docs/handoffs/2026-10-20-v5-end-explanation-style.md)에 있다.

- 추정 오류(basis INFERRED)는 근거만으로는 학생 생각을 다 알기 어려웠다는 점과 짐작이라는 점을 먼저 밝히고, 학생이 했을 법한
  생각을 큰따옴표로 풀어 보인 뒤 원문으로 짚는다. [D-0150](./D-0150-error-hypothesis-first-for-wrong-choice.md)의 "가정으로만
  쓴다"를 바꾼다. 짐작이라고 밝히지 않은 단정은 계속 쓰지 않는다.
- 설명은 한 단계씩, 원문 구절 → 그 뜻으로 잇는다. 원문에 없는 개념을 끌어와 "…가 아니라"로 부정하지 않는다.
- 정답 칸은 선지 판정과 문제 목표를 잇는 문장으로 끝낸다(예: "그러므로 ②는 적절하지 않은 선지, 즉 정답이야.").
- 선지 칸 끝 고정 문구(코드, `feedbackSectionClosing`)는 정답·오답이 아니라 그 칸이 다룬 내용으로 고른다: 학생의 잘못된 생각 /
  학생 근거의 빈 곳 / 선지 내용만. 다음 칸이 다시 고른 선지면 "다음 설명으로 넘어가 보자."로 끝낸다.

## 이유

- [2026-10-19 판정 기록](../../docs/experiments/v5-hypothesis-user-2026-10-19/REVIEW.md)의 고칠 점 4개가 모두 문체였고,
  사용자 수정안(P2·P3·P5)에서 문항 내용을 뺀 원리만 옮겼다.
- 끝 문구를 정답·오답으로만 가르면 정답 선택 칸(P9·P10)에 맞지 않았다(예시 검토, 2026-10-20).

  `DevPartNav.tsx`가 "문제" 버튼을 하나 더 만들어 선택자가 둘에 걸림(이 변경과 무관).

  적절 8, 고칠 점 8, 부적절 0. 정답 칸·단계 설명·새 끝 문구 세 종류는 지적 없음. 고칠 점은 오답 칸 첫 문장(UI 메모장 20번)
  6개, 짐작 도입 말투, 원문에 있어도 불필요한 대비(27번 상세)다.
