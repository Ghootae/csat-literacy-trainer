# 문단 게이트의 상태 전이 충돌을 계약 재시도로 처리

## 결정

1차 문단 게이트가 누적 의미 판정으로 축 상태를 바꿨지만 최신 학생 근거 또는 명시적 철회
근거를 해당 축에 기록하지 않은 경우, 사후 코드가 이전 상태로 조용히 되돌리지 않는다.

대신 학생의 최초 응답과 누적 문답을 그대로 보존한 채 계약 오류를 한 번 자동 재시도한다.
재시도 출력은 다음 중 하나를 선택해야 한다.

- 상태 변경을 뒷받침하는 최신 학생 답변의 짧은 직접 근거와 올바른 source를 해당 축에 기록한다.
- 최신 근거가 없다면 이전 축 상태를 유지한다.

축 상태와 전체 status가 충돌하는 출력도 같은 계약 오류로 취급한다. 존재하지 않는 축이나
captured 축을 질문 대상으로 고른 경우의 결정론적 후보 보정과, 최초 응답으로 잘못 표기한 철회
근거 제거는 기존대로 유지한다.

## 감사와 실패 처리

- 최종 성공 출력의 원출력과 검증 결과를 계속 기록한다.
- 재시도 전 계약 실패의 오류, 시도 번호, 원출력도 `decisionAudit.contractFailures`에 보존한다.
- 재시도에도 계약이 맞지 않으면 질문 생성 단계로 넘기지 않고 오류로 종료한다.

## 이유

사용자 직접 수행의 공손룡 3문단에서 모델은 첫 후속 답변 뒤 모든 축을 포착했다고 판정했지만,
사후 검증이 한 축을 이전 `partial`로 복원해 불필요한 질문을 생성했다. 누적 의미 판단과 축별 최신
인용 계약의 충돌을 상태 역전으로 숨기지 않고, 모델이 근거 귀속 또는 상태를 명시적으로 바로잡게
해야 판정과 질문이 일치한다.
