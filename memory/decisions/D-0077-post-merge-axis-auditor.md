# L2 의심 자동 병합 뒤에 전체 축 감사 추가

## 결정

사용자는 D-0076의 자동 병합 다음에 감사기를 붙이기로 했다. 다음 후보 흐름은 다음과 같다.

후보 생성 → JEV 선택(근소 점수 규칙 적용) → L2 생성 → L2 중복 의심 그룹 자동 병합 → 변경된 L1/L2 생성 → 전체 축 감사 → 필요한 수정.

감사기는 원문과 병합 후 전체 L1/L2를 보고 남은 과분해, 독립적으로 평가할 필요가 없는 소개·연결 축, 문구의 누락·왜곡·원문에 없는 추가를 점검한다. 앞서 논의한 유지·추가 병합·불필요한 축 삭제·문구 수정의 역할을 이 위치에 둔다. 축 삭제는 독립 평가 단위를 없애는 것이며 원문 자료 삭제를 뜻하지 않는다.

D-0076의 의심 그룹 자동 병합은 그대로 실행한다. 감사기를 병합 전 승인·거절 단계로 되돌리지 않는다. 사용자가 명시한 FA 회피 우선 원칙을 따른다.

## 기존 의미 기준과의 정합성

D-0039에 따라 L2는 L1의 모든 세부와 비교 방향을 반복할 필요가 없다. L2에서 방향이 생략된 사실만으로 오류를 확정하거나 L1 요구를 다시 넣지 않는다. 허용된 추상화와 원문에 없는 추가·명시적 왜곡을 구분한다. 5지문 비교의 L2 방향 약화 지적은 관측·검토 의견이며 자동 수정 조건으로 승격하지 않는다.

## 범위

이번에는 감사기의 위치와 역할을 기록했다. 구체 프롬프트·출력 계약·수정 실행 코드는 아직 구현하지 않았고 API 호출이나 기존 골드/UI 변경은 없다. D-0075의 기존 시험 결과는 보존한다.
