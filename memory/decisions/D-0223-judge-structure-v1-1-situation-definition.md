# 구조 판정 기준표 v1.1: `onItemSituation`의 '상황'은 구체적 사례·현상으로 좁힌다

## 결정

사용자(2026-11-10, "(가)로 결정", 수정안 확인 뒤 "진행").

1. 기준표·판정 지시문을 v1.1로 올린다.
   - `docs/experiments/principle-application-structure-2026-11-09/JUDGE-STRUCTURE-v1.1.md`
   - `judge/JUDGE-INSTRUCTIONS-v1.1.md`
2. 3절의 '상황'은 특정 대상이 조건이나 값을 가진 구체적 사례·현상이다.
   - 다음은 상황이 아니다.
     - 지문의 개념·용어·밑줄 대목을 가리키는 발문
     - 지문 전체나 중심 대상을 가리키는 발문
     - 개념 틀만 주고 지문 내용을 옮기게 하는 〈보기〉
   - 예시는 모두 지어낸 진자 지문에서 가져왔다. 평가 문항은 예시로 쓰지 않았다.
3. 6절에 대비 예시를 한 줄 더한다. 상황 없는 발문이면, 같은 선지라도 모두 `false`다.
4. 나머지(`basis` 정의·순서, 출력 형식)는 v1과 같다.
5. 개발자 화면 4지문은 판정자 2명이 v1.1로 처음부터 다시 판정한다(`judge/out-v1.1/`).
   - v1 결과(`judge/out/`)는 기록으로 남긴다.
   - E1 4지문과 P1은 처음부터 v1.1로 판정한다.

## 근거

- v1 판정자 간 불일치(개발자 화면 4지문, 선지 85개):
  - `basis` 불일치 2개: 도파민, STATED/COMBINED 경계. `APPLIED` 관련 불일치는 0이다.
  - `onItemSituation` 불일치 10개: 문항 2개에서 선지 전부가 갈렸다.
    - mRNA 01: 발문 "mRNA 백신에 대해 이해한 내용으로 적절한 것은?"
    - 공손룡 03: 기표·기의 개념 틀을 주는 〈보기〉
- 두 판정자가 일치한 문항에서도 "㉠을 설명한 내용" 같은 개념 발문을 '상황 위'로 봤다.
  - 그래서 v1의 이 표시는 사실상 "발문이 가리킨 대상에 대한 선지인가"로 쓰였다.
- 이대로면 P1 통과 조건 (다)(같은 상황 위 선지 4개 이상, D-0215 12)가 a 문항에서 거의 자동으로 충족된다.
  - (다)의 의도는 표면 장력 15번처럼 오답까지 상황 하나 위에 모였는지를 보는 것이다. 기준표 예시의 'STATED + 상황 위' 선지가 그 의도를 보여 준다.
- 방안 나(`situationScope`로 대체)는 이 의도를 잃어 채택하지 않았다.

## 다시 볼 조건

- v1.1에서도 `onItemSituation` 불일치가 문항 단위로 남으면 정의를 다시 본다.
