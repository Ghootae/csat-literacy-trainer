# 감사기 v2: 일반 문단 최소 2축과 병합 기록 계약

## 결정

사용자는 직접 검토한 결과로 "실제로 한 축으로 정리될 문단은 지문의 도입이나 정리 부분 정도로 매우 제한적"이라고 보았다. 그래서 도입·정리 기능이 아닌 문단은 최소 축 수를 2로 고정하자고 제안하고, Claude·Codex 논의의 권고 해결책도 받아들였다. 명료화 답변으로 확정한 규칙은 다음과 같다.

1. **문단 기능 판정:** 감사기가 지문 전체 맥락으로 대상 문단을 도입(introduction), 정리(conclusion), 일반(general) 중 하나로 판정한다. 도입·정리로 판정하려면 원문 구절을 그대로 인용해야 하고, 확실하지 않으면 일반 문단으로 처리한다.
2. **최소 2축(감사기에만 적용):** 일반 문단에서 감사 입력 축이 2개 이상이면, 감사기는 병합이든 삭제든 최종 축을 2개 미만으로 만들 수 없다. 예외는 없다. 1축이 맞다고 판단하면 그 의견과 근거만 기록한다. D-0076 자동 병합, JEV 선택, 후보 생성에는 적용하지 않는다. 감사 전에 이미 1축인 문단은 감사기가 분할할 수 없으므로 그대로 둔다.
3. **감사 프롬프트의 FA 문구:** FA 회피 우선 원칙은 유지한다. 다만 "경계적인 평가 단위를 무리하게 독립 축으로 유지하지 마세요"를 다음으로 바꾼다: "축 수 감소만으로 FA 감소를 추정하지 마세요. 병합이 서로 다른 핵심 질문의 답을 하나의 필수 요구 묶음으로 확대하는지 점검하세요."
4. **관계 중심 병합 기준(A):** 같은 질문인지는 공통 소재, 같은 대상, 서술 연속성이 아니라 학생이 답해야 하는 '무엇의 어떤 관계'로 판단한다. 주장–이유–예시는 병합하고, 서로 다른 원인·결과·조건·대상의 관계는 분리한다. 최소 2축 안에서 사례별로 판단한다.
5. **병합 기록 계약(B):** 감사기가 추가로 병합한 축마다 다음을 기록한다: 원 `centralQuestion` 정확 인용, 원 L1의 최소 핵심 관계와 그 인용, 질문 관계 유형, 최종 L1의 대응 구절·제외 사유·새 요구, 병합에 가장 불리한 학생 응답 예시. 최소 요구는 핵심 관계로 한정하고 부수 세부를 L1에 덧붙이지 않는다. 학생 응답 예시의 예상 판정은 검토 자료일 뿐 통과 근거가 아니다.
6. **검토 신호:** 문단 전체 병합 여부와 병합한 축 수를 기록하되 검토 표시로만 쓴다. 감사 수정은 D-0079처럼 직접 반영한다. 적용 전 재확인 단계는 두지 않는다.
7. **시험 순서:** A+B를 먼저 시험한다. 병합 판단과 문구 작성을 나누는 호출 분리(C)는 A+B 뒤에도 자기 정당화가 남을 때의 후속 대조로 둔다.

이번 범위는 결정 기록과 구현 준비다. `scripts/test-axis-audit-v2.mjs`는 v1 실험의 자동 병합 결과(`--merged.json`)를 그대로 입력으로 쓰고 감사 단계만 바꾼다. 사전 검증만 했고 API 호출은 0회다. 실제 실행에는 원문·축을 OpenAI로 보내는 것에 대한 별도 명시 승인이 필요하다. 운영 골드·UI·기존 실험 결과는 바꾸지 않는다.

## 근거

- 사용자 제안(2026-10-06): "도입이나 정리 기능이 아닌 문단의 최소 축의 수는 2로 고정", "네가 권고하는 해결책도 받아들이고".
- 사용자 명료화 답변(2026-10-06): 모델 판정과 보수적 기본값, 감사기에만 적용, 예외 없이 고정, 권고 전체와 우려 2개 수용, 결정 기록과 구현 준비까지.
- `docs/experiments/axis-auto-merge-audit-five-passages-2026-10-02/AUDITOR-OVERMERGE-DISCUSSION.md`: 감사 추가 병합 10건 중 9건이 문단 전체 병합이었고, 3축→1축 3건은 모두 문제·경계 사례였다.
- `docs/experiments/axis-auto-merge-audit-five-passages-2026-10-02/OPERATIONAL-VS-AUDIT.md`: 감사 후 단일 축 문단은 12/25였다.

## 폐기한 대안

- 최소 2축을 전 단계(JEV 선택, D-0076 자동 병합)에 적용: 사용자가 감사기에만 적용하기로 했다. D-0076은 바꾸지 않는다.
- 근거를 대면 1축 예외 허용: '하나의 연속된 설명' 같은 자기 정당화가 통과할 수 있어 예외 없이 고정했다.
- 위치(첫·마지막 문단) 기반 도입·정리 판별, 사람의 사전 지정: 모델 판정과 보수적 기본값을 택했다.
- 표시된 추가 병합을 적용 전에 재확인하는 단계: 검토 표시만 두기로 했다.

## 재검토 조건

- v2 실행 결과에서 일반 문단의 2축 유지가 같은 질문의 반복이나 불필요한 분해를 체계적으로 만든다는 사람 검토 근거가 나올 때
- `singleAxisOpinion` 기록이 일반 문단에서 반복적으로 타당하다고 사람이 판단할 때
- 문단 기능 판정이 사람 판정과 반복해서 어긋날 때
- A+B 뒤에도 병합 기록이 자기 정당화에 그칠 때(C 대조를 연다)
