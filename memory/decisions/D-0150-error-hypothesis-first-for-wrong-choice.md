# 오답 첫 선택에서 오류 가설을 먼저 세우고, 그 가설로 질문한다 (D-0120 정리 보완)

## 결정

사용자 제안·승인(2026-10-19, UI 메모장 26번). 설계는 [인계 문서](../../docs/handoffs/2026-10-19-v5-error-hypothesis-first.md)에 있다.

- 오답을 고른 첫 선택에서 학생이 밝힌 주장에 오류(CONTRADICTED·OFF_TARGET)가 없으면, 판정기는 학생이 밝힌 주장에서 학생의 선택까지 가는 가장 그럴듯한 생각 하나를 오류 가설(`errorHypothesis`)로 세운다.
- 가설은 학생이 밝힌 주장에 학생이 말하지 않은 한 단계를 더한 것이다. 그 단계가 원문과 어긋나면 추정 오류(`basis: 'INFERRED'`) 하나로 기록하고 두 갈래 질문을 한다. 이후 교정·다시 고르기·설명 흐름은 기존과 같다.
- 가설 후보가 둘 이상이거나, 느낌만 있거나, 선지와 관계없는 근거는 지금처럼 확인 불가다. 정답 선택과 두 번째 선택에는 가설을 세우지 않는다.
- 추정 오류만 있었던 교정 성공 뒤 안내는 "맞아, 거기가 ①을 판단하는 열쇠야. 그걸 생각하면서 다시 골라 볼래?"다(코드).
- [D-0120](./D-0120-omitted-conclusion-reconstruction.md) 정리의 "사실만 쓴 근거는 질문 없이 끝낸다", "오류는 명시 주장에서만 만든다"는 오답 첫 선택에 한해 이 결정이 보완한다. 정답 선택 쪽은 그대로다.

## 이유

- 사용자 세션(도파민 13번 ①, "지문에서 약물로 유입된 도파민은 장벽을 통과할 수 없다고 했음."): 판정기는 학생의 혼동(도파민 사실을 레보도파에 옮김)을 알면서도 확인 불가로 처리했고, 학생은 질문·다시 고르기 없이 정답을 들었다. 화면에서는 "다 알기 어려웠어" 다음 칸이 그 혼동을 설명해 앞뒤가 맞지 않았다.
- Claude 첫 제안(옆 대상 사실을 옮긴 경우만 대상 오류)은 한 유형만 다뤄 일반화가 약했다. 사용자 제안(오류를 먼저 적극적으로 설명하고 그것으로 판정)을 채택했다.

## 확인

- 테스트: 빌드·클라이언트 타입 검사 통과, e2e 13/13. vitest 1313 중 실패 3(기존 2, 다른 세션 문단 대화 코드의 `dialogue-simple.test.ts` 1). 지시문 충돌 문장 보정 뒤 문제 풀이 시험 382/382.
- 반자동 사용자 시험([판정 기록](../../docs/experiments/v5-hypothesis-user-2026-10-19/REVIEW.md), 도파민 13번 10경로, 0.36달러): 판정·질문·안내 15단계 모두 적절. 설명 칸 12개 중 4개 고칠 점(문체·표현).
- 대조군([기록](../../docs/experiments/v5-hypothesis-user-2026-10-19-controls/), 0.24달러): 6개 중 5개 이전과 같다. V-S(선지 앞부분만 되풀이)는 가설 질문으로 바뀌었고 사용자 판정 적절. 대조군 기준을 넓힌 것으로 본다.

## 재검토 조건

- 학생이 하지 않은 생각을 가설로 세워 질문이 빗나가는 사례가 반복되면 조건을 좁힌다.
- 정답 선택에도 같은 방식을 쓸지는 UI 메모장 25번 설계에서 다룬다.
