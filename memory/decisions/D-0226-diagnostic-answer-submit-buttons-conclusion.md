# 진단 답 입력: 입력창 안 제출·근거 미입력 버튼으로 확정, 마지막 문항의 "답 다 냈어", 결론 버튼

## 결정

사용자(2026-11-10), 진단 v5.10 첫 사용 메모 1~4(`memory/checkpoints/2026-11-10-diagnostic-v510-use-notes.md`)를 논의한 결과다. 질문 1~4의 답.

1. **입력창 안 작은 버튼 셋으로 확정**(메모 1·4, 4번 문구가 1번을 대체). [제출] [근거 미입력(확실)] [근거 미입력(잘 모르겠음)]. 셋 중 하나를 누르면 그 문항 답이 바로 확정되어 잠긴다(D-0221의 확정 순간). 근거 미입력 두 버튼은 켜 두는 토글이 아니라 누르면 곧 확정이다. 확신 구분 `SURE`/`UNSURE`의 뜻은 그대로다.
2. **이동 버튼**(질문 1). 제출 전에도 "이전 문항"은 켜 둔다(앞 문항은 읽기 전용, 지금 문항 답은 임시 저장). "다음 문항"은 그 문항을 제출한 뒤에만 켜지고 이동만 한다.
3. **마지막 문항**(메모 2, 질문 2 (가)). 마지막 문항에서는 "다음 문항" 자리에 "이 지문 답 다 냈어"가 대신 나온다. [제출]로 확정한 뒤 켜지고 따로 누른다. [제출]은 어느 문항에서나 "이 문항 확정"만 뜻한다.
4. **결론 버튼**(메모 3, 질문 3). lab의 "결론" 버튼을 진단의 답 입력 화면, 피드백의 다시 고르기 근거, 피드백의 근거 다시 묻기(이미 고른 선지 기준)에 넣는다. 교정 질문 답에는 넣지 않는다. 위치는 기호 줄 끝(lab과 같음).
5. **소거법 근거 판정(메모 5)은 이번에 다루지 않는다**(질문 4). 차후 논의. 코드 에이전트 권고는 지금 v5.10의 판정을 먼저 실측한 뒤 규칙을 논의하는 것이다(미승인).

- 코드 에이전트 정리(사용자 이견 없음): 피드백 화면의 "근거 미제출" 버튼은 이번 대상이 아니라 그대로 둔다. 확정한 앞 문항에 돌아가면 입력창 안 세 버튼은 비활성이고 "이미 낸 답이야"가 뜬다.

## 근거

- 메모 원문과 코드 위치: `memory/checkpoints/2026-11-10-diagnostic-v510-use-notes.md` 1~4절.
- 결론 버튼은 진단 화면에 연결된 적이 없었다(같은 체크포인트 3절, 커밋 996c38c7은 lab만).
