# 학생용 전환 순서: 작은 실제 학생 확인을 대량 확대보다 앞에 둔다

## 결정

학생용 전환(문단 단순 형식 v4.7, 문제 v5)은 다음 순서로 한다.

1. **1′ 개발자 경로 정리**: 지금 있는 6지문으로 개발자 경로(`/dialogue/lab`, `/problem/lab`)의 알려진 문제를 0건으로 만든다. 지문 확대는 하지 않는다. 첫 과제는 문제 판정 출력의 쓰이지 않는 `coaching` 필드와 지시문 제목 정리 뒤 48세션 회귀 1회다([작동 순서 문서](../../docs/PROBLEM-LAB-FLOW-2026-10-24.md) 6절 1·6·7번).
2. **얇은 학생판 준비**: 내부 정보 숨김, 로그 저장, 최소 인증, 서버 상시 실행. 섭외가 되면 바로 시작할 수 있게 미리 만든다. 범위는 별도 승인.
3. **방식과 무관한 확대만 먼저**: 원자료(원문·문항·선지·정답·공식 해설·이미지) 수집·정리는 진행한다. 문제 판정은 원문 직접 방식이고 문단 v4.7은 골드를 쓰지 않으므로 운영 방식이 바뀌어도 다시 쓸 수 있다. 지문별 부가 자산(출제자 전략 피드백, 선지 연결, 분석 지도)은 방식 확정 뒤로 미룬다.
4. **2′ 실제 학생 확인 → 3′ 운영 방식 확정 → 4′ 부가 자산 확대 → 5′ 학생용 정식 전환.**
5. 학생 섭외처가 아직 없다(2026-10-25). 섭외는 사용자 몫으로 병행한다. 대리 테스터(정답을 모르는 고등학생·대학생·지인 자녀)는 1명이라도 쓴다. "현실적인 학생 행동" 가상 답변 묶음은 판정기 스트레스 회귀로만 쓰고 학생 검증으로 세지 않는다.

## 근거

- 사용자 원안(2026-10-25): ① 개발자 모드로 제품 완성(지문·문제 대량 확대, 모든 운영 방식 확정) ② 개발자 직접 충분히 테스트 후 전환 결정 ③ UI만 다소 수정해 학생용 완성. 객관적 검토를 요청했다.
- 코드 에이전트 검토: 개발자 경로 정본·학생용 일괄 전환은 [D-0031](./D-0031-developer-ui-url-only.md)과 맞다. 그러나 (가) 판정 규칙이 가상 답변과 사용자의 학생 역할로만 다듬어져 실제 학생 없이 "확정"의 근거가 없고, 늦게 발견한 문제의 비용이 확대량에 비례한다. (나) "모든 운영 방식 확정"에 완료 기준이 없다. (다) 학생용 전환은 UI 수정이 아니라 운영 준비다: 학생용 `/dialogue`와 `/dialogue/lab`은 다른 컴포넌트, 단순 형식은 학생 상태 원장 미연결([D-0174](./D-0174-paragraph-simple-v47-operating-candidate.md)), 인증·재시작 복원·상시 서버 미완료(`memory/CURRENT_STATE.md` 웹 흐름·서버 절).
- 사용자: "일단 네 의견에 동의. 하지만 실제 학생은 아직 섭외처가 없는 상태야." 섭외처 없음을 반영한 수정안(위 1~5)에 "응, 맞아. 기록하고 A 진행해"(2026-10-25).

## 다시 볼 조건

- 1′과 얇은 학생판을 마친 뒤에도 실제 학생 섭외가 안 되면, 대리 테스터 결과를 근거로 제한된 규모의 확대(예: 고1 학평 몇 회분)를 시작할지 다시 정한다.
- 축 기반 쪽 폐기 여부([D-0174](./D-0174-paragraph-simple-v47-operating-candidate.md), Q-0036)는 5′ 정식 전환 때 정한다.
