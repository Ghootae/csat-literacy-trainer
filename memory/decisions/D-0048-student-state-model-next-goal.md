# 학생 상태 모델과 정기 피드백을 다음 개발 목표로 설정

> 폐기(2026-10-27): [D-0180](./D-0180-student-state-model-v1-discarded.md)으로 대체. 논의에서 제외한다.

사용자는 핵심 기능을 개발자 단계에서 캘리브레이션하는 동안 부가 기능축을 논의한 뒤,
학생 상태 모델과 정기 피드백을 다음 개발 목표로 설정했다.

초기 상태 모델은 현재 문단 요약과 문제 풀이가 실제로 저장하는 행동·평가 기록을 재사용한다.
난이도 보정과 실제 학생 종단 자료가 없으므로 단일 독해력 점수나 학생의 실제 내적 상태를
확정하지 않는다. 관측 증거, 도움 수준, 표본 수, 콘텐츠 범위, 평가기 버전과 불확실성을 함께
보존하는 다차원 프로필을 우선한다.

첫 설계 범위는 다음과 같다.

- 문단 최초 축 포착·부분 이해·명시적 오류와 최초→최종 관계 상태 전이
- 질문 유형과 도움 단계, 학생의 선택적 보완·진행, 미해결·건너뜀
- 문제 최초 선택, 정답 여부, 근거 판정, 개입 경로, 재선택·회복 단계와 정답 공개 여부
- 선택 입력인 확신도와 실제 정답·근거 판정의 관계
- 위 증거를 독립 이해, 근거 기반 문제 해결, 교정·회복, 자기 점검으로 집계한 정기 피드백

보상 시스템, 콘텐츠 난이도 추정·적응형 제시, 선택형 배경지식은 연계 후보로 남기되 이번 결정의
구현 범위로 자동 포함하지 않는다. D-0036의 JEV 보류를 뒤집거나 MR coverage를 학생 상태 점수로
재도입하지 않는다.

## 재검토 조건

상태 차원·집계 규칙·피드백 주기와 문구는 별도 설계 및 실제 로그 감사 뒤 확정한다. 콘텐츠
난이도가 보정되고 여러 지문·학생의 반복 자료가 쌓이기 전에는 단일 능력 점수나 적응형 난이도
정책으로 승격하지 않는다.

## 구현 상태

2026-10-01 V1 코어 1단계를 구현했다. 문단·문제 기록의 공통 증거 변환, 중복/충돌 보호,
다차원 누적 프로필과 결정론적 정기 피드백 생성기가 타입 검사와 신규 단위 테스트를 통과했다.
이어 실제 문단 handoff와 완료 문제 세션의 JSONL 영속화 및 개발자 조회 API를 연결했다.
기존 로그 감사에서 학생/실험 출처가 없음을 확인해 백필을 금지하고, 새 증거에 학생/개발자
맥락 분리와 혼합 거부를 추가했다. 개발자 리포트 UI·새 실제 로그 감사와 학생용 피드백 승인은
후속 단계다. 같은 날 개발자 리포트 UI와 7·30·90일 관측 창까지 구현·브라우저 검증했다.
과거 직접 사용 문제 6세션의 읽기 전용 감사에서 알려진 결과를 재구성하고, 잠정 패턴을 반복
확인처럼 표현한 문구를 정정했다. 미해결을 도움 단계에서 제거하고 질문 뒤 지속된 미확인 관계를
불확정 회복 증거로 보존했다. 새 형식 실제 로그 감사와 학생용 피드백 노출·주기 승인은 아직
후속 단계다. 학생용 `/progress` 프리뷰도 같은 날 구현했지만 기본 비활성으로 두고, 개발자
내부 정보 없이 불확실성·표본 수·다음 행동만 표시하도록 제한했다. 불확정 증거가 확정 패턴의
신뢰도를 높이지 않도록 판단 가능한 증거와 그 콘텐츠 범위로 신뢰도를 계산한다. 관련 단위/컨트롤러 40테스트,
서버·클라이언트 타입 검사와 브라우저 5경로가 통과했다. 실제 기본 노출과 피드백 주기는 여전히
사용자 승인 및 새 형식 실제 로그 검토 전에는 활성화하지 않는다. 플래그를 켠 환경에서는 공개
capability 계약에 따라 학생 학습 화면의 `/progress` 진입점이 함께 나타나도록 연결했으며,
기본 비활성 환경에서는 링크와 데이터 API가 모두 닫힌다. 문단 증거는 연결 문제 클릭에
의존하지 않고 전체 지문 완료 즉시 한 번 저장하도록 수집 경계를 바로잡았다.
원장 입력에서는 관측 종류–상태 차원–출처 결합과 확신도 파생값을 검증해 손상되거나 잘못
백필된 레코드가 프로필 집계에 들어가지 못하게 했다.
브라우저에서 실제 학생 지문 4문단을 완료하고 연결 문제를 열지 않은 채 API 집계와 `/progress`
표시가 함께 증가하는 전 구간도 검증했다. 이는 모의 평가기를 사용한 배선 검증이며 실제 학생
문구 수용성 증거로 보지는 않는다.
학생 피드백 활성 플래그만으로 인증 없는 고정 터널에 개인 학습 기록이 열리지 않도록 기본
접근 범위를 loopback Host로 제한했다. 공개 Host 노출은 별도 `CSAT_STUDENT_FEEDBACK_PUBLIC=1`과
사용자 승인이 모두 필요한 경계로 남겼다.
확신도 비교만 충분한 프로필에서 자기 점검 피드백과 자료 부족 헤드라인이 동시에 나오던
문구 모순도 제거하고, 수행 증거 수와 확신도 비교 수를 헤드라인에서 구분했다.
연습 후보 설명을 정규식으로 잘라 다음 행동으로 재사용하던 방식도 제거했다. 각 차원이 직접
행동 제안을 제공하며, 자기 점검 연습 후보는 근거 재확인 뒤 확신도 기록을 제안한다.
개발자 상태 API의 `context=student`가 공개 Host 차단을 우회할 수 있던 경로도 같은 로컬 전용
경계로 닫았다. `context=developer` 캘리브레이션 집계만 기존 개발자 공개 범위에 남긴다.
