# 마지막 설명을 요점 문단 단위로 넘겨 보이고, 문단마다 지문·〈보기〉 한 곳을 칠한다

## 결정

문제 풀이 마지막 설명(M4)의 방향으로 다음 화면을 채택한다. 지금은 개발자 미리보기(FIXTURE)에서만 동작하고, 모델이 문단·칠할 곳을 직접 쓰게 하는 일은 다음 단계다.

- 문단 단위는 "요점 하나". 요점이 하나인 칸(예: 오네소르게 수 정답 칸 약 300자)은 나누지 않는다. 줄바꿈만으로는 나누지 않는다.
- 문단 하나가 말풍선 하나, 문단 사이와 칸 끝에서 [다음으로 넘어가기].
- 칸 첫 문장은 첫 문단 앞, 마무리 문장은 마지막 문단 뒤에 붙인다.
- 문단마다 칠할 곳은 지문 또는 〈보기〉의 한 구간(선지는 칠하지 않음). 원문에 정확히 한 번 나올 때만 칠한다.
- 칠할 곳이 없는 문단(짐작·정리 문단)은 칠하지 않고 앞 문단 칠하기를 지운다.

## 근거

- 사용자 메모 1·2와 질문 1~4 답(2026-10-30): "2-3개 정도. 요점 별로", "(ㄴ) 지문 + 보기로", "(ㄱ)로, 앞 문단 칠하기는 지우는 걸로", 칸 첫·마무리 문장 "(ㄱ)으로".
- 순서: 사용자 제안("사용감이 별로라면 할 이유가 없잖아")에 따라 지시문 변경 전에 기존 글로 화면만 먼저 만들었다. 기존 글(`end-explanation-layout-2026-10-28` S-A1·KF-r1·QP-r2)을 문장 경계에서만 나누고 칠할 곳은 코드 에이전트가 골랐다(`docs/experiments/end-explanation-paragraph-preview-2026-10-30/FIXTURE.json`). 인계 `docs/handoffs/2026-10-30-end-explanation-paragraph-preview.md`.
- 사용자 사용 판정(2026-10-30): "사용감이 매우 좋아졌어."

## 한계

- 칠할 곳은 사람이 고른 최선의 경우다. 모델이 요점 문단과 핵심 구간을 그만큼 고르는지는 미측정이다.

## 다시 볼 조건

- 모델 생성 시험에서 문단 나누기나 칠할 곳 품질이 사용자 판정을 통과하지 못하면 방식을 다시 정한다.
