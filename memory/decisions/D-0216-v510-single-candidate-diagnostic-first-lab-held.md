# 판정 지시문 채택 후보는 v5.10 하나, 진단평가부터 적용, lab은 보류

## 결정

사용자 결정(2026-11-09, "v5.10 하나로 결정. lab은 일단 보류. 진단 평가 사용 후 lab을 진단 평가 방식으로 고칠 생각", 확인 질문에 "(나)").

1. **v5.9를 따로 채택하지 않는다.** v5.10은 v5.9의 질문 규칙(D-0212)을 그대로 포함하고 171행 판정 기준(D-0213 추가, D-0214)을 더한 버전이다. v5.9는 판정 변화와 질문 변화를 가르는 시험용이었고 그 역할은 끝났다(v5.9 판정 v5.8과 같음).
2. **질문 품질 사용자 블라인드 판정을 거친 뒤 진단평가 기본값을 v5.10으로 바꾼다.** 블라인드 판정은 저장된 v5.8·v5.9 질문 출력으로 한다(질문 규칙이 v5.10과 같으므로 결과가 v5.10에 그대로 적용됨, 새 외부 전송 없음).
3. **lab(`/problem/lab`)은 v5.8로 둔다(보류).** 진단평가를 실제로 써 본 뒤 lab을 진단평가 방식(판정 흐름·모델 배정, D-0213)으로 고친다. lab 정답 세션의 luna가 v5.10에서도 짠지(Q-0044)는 그때 함께 본다.

## 근거

- [v5.9·v5.10 시험 보고](../../docs/reports/REPORT-v59-v510-run-human.md): v5.10 기대 판정 통과(관대 오판 0/18), v5.9는 판정 불변·질문 모양만 바뀜, lab 회귀 18세션 둘 다 v5.8과 같음(원래 흔들리던 세션 제외).
- 지시문 차이: `packages/pipeline/experiments/problem-solving/source-direct-problem-feedback-v5.10.md`는 v5.9에 171행·근거 형태 규칙만 더함.
- 진단평가의 정답 판정은 sol(D-0213)이라, v5.10 시험(sol 중심)의 결과가 그대로 해당한다.

## 영향

- 지금 기본값은 여전히 v5.8이다(진단·lab 모두). 진단평가 전환은 블라인드 판정 뒤 코드 기본값(옵션 `judgmentRules`) 변경으로 한다.
- v5.9 지시문은 재현용으로 남긴다.

## 다시 볼 조건

- 블라인드 판정에서 v5.9 질문이 v5.8보다 나쁘다고 나오면 질문 규칙을 고친 v5.10 개정판을 다시 시험한다.
- 진단평가 사용에서 v5.10의 관대 오판(충분이면 안 되는 근거가 충분)이 실제 사례로 나오면 채택을 다시 본다.
