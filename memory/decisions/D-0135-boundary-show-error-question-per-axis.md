# 보여 주기 개발자 모드: 오류 축마다 질문 한 번

## 결정

[D-0134](./D-0134-boundary-show-dev-mode-central-object.md)의 "문단당 질문 최대 1회"를 다음으로 바꾼다. 나머지(보여 주기 화면·연결 자산·고쳐 쓰기 기록만)는 유지한다.

- **질문 상한:** 1차 응답에서 ERROR인 축 수로 고정한다. 2차 이후 새로 생긴 오류는 상한을 늘리지 않고 보여 주기로 넘긴다.
- **오류 축마다 질문은 한 번:** 같은 축은 다시 묻지 않는다. 아직 묻지 않은 오류 축 가운데 아직 ERROR인 축만 다음 질문 대상이 된다. 앞선 답에서 스스로 고쳐진 오류 축은 묻지 않는다.
- **수정 실패 알림:** 질문한 오류가 다음 답에서도 ERROR이면 간단히 알리고 다음 오류 축으로 넘어간다. 문구는 코드 고정 반말(예: "이 부분은 아직 원문과 조금 다른 것 같아. 마지막에 표시해 줄게." — 문구 미확정).
- **종료:** 물을 오류 축이 더 없으면 중심 대상을 공개하고, 마지막 판정에서 남은 ERROR·SERIOUS 축 구간을 모두 표시한다. 오류가 모두 고쳐지고 SERIOUS만 남아도 질문 없이 보여 주기로 끝낸다.
- **오류 없는 경우는 그대로:** 1차에 ERROR 없이 모든 축 SERIOUS(1축 문단 포함)이면 질문 1회, 일부 SERIOUS면 바로 보여 주기, OK만·PASS면 통과.

예: 1차에 A·B 오류 → A 질문 → A 수정 실패 알림 → B 질문 → B도 실패면 A·B 모두 표시, B 성공이면 A만 표시.

## 근거

- 사용자 명시(2026-10-15): "오류가 다수인 경우, 질문은 오류의 갯수만큼 하기로", 상한은 "1차 응답에서 판정된 ERROR 축 수로 고정", 흐름 "A에 대한 질문-응답-수정 실패 -> 수정 실패를 간단히 알림 -> B에 대한 오류 … 1) B 오류 -> 중심 대상 내용 공개 2) B 성공 -> 중심 대상 내용 공개 + 오류남은 부분 밑줄", 1)에서 "둘 다 표시", 오류 해소 후 SERIOUS 남음은 "보여 주기로 끝내".
- 계기: 질문 1회 상한에서는 묻지 않은 오류가 교정 기회 없이 남는다. 누락은 보여 주기로 충분하지만 오류는 틀린 이해가 남는다.

## 구현 메모

- 질문 대상 축은 현재 게이트 모델이 고른다. "묻지 않은 오류 축만"은 코드가 대상 축을 바꿔 넣어 지킨다(`packages/pipeline/src/dialogue-experiment/gate.ts`의 대상 축 보정과 같은 방식). 게이트 프롬프트는 바꾸지 않는다.
- 1차 오류 축 목록과 물은 축 목록을 문단 기록에 보관해야 한다.

## 포함하지 않는 것

운영 V4·학생 화면 변경, 게이트·피드백 프롬프트 변경(질문 말투 반말화는 별도 결정), 수정 실패 알림 문구 확정.
