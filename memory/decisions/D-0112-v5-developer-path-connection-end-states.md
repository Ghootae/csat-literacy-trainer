# v5 개발자 경로 연결: 종료 상태와 종료 설명 호출 범위

## 결정

D-0104·D-0106·D-0107·D-0108·D-0110을 개발자 v4 경로(`/problem/dev/v4`)에 연결한다(학생용 v3 경로는 그대로, D-0065).
그때 남은 설계 공백을 사용자 확인(2026-10-10)으로 다음처럼 정한다.

1. 정답 선택·근거 교정 실패: 결과는 '정답, 근거 미확인'(UNVERIFIED_CORRECT). 화면에는 luna 설명(D-0110)만 보이고 "정답은 N번입니다"와 공식 해설은 붙이지 않는다.
2. 오답 세션의 모든 종료 지점(교정 실패, [코칭 보기], 재선택도 오답(근거 있음·없음), 근거 확인 불가)에서 sol 해요체 종료 코칭을 따로 호출한다.
   종료 사유로 구분하고, 공식 해설은 모든 경우 학생에게 보이지 않는다. "정답은 N번입니다"는 남긴다.
   근거가 없거나 확인 불가인 경우 지시문에 "학생 근거가 없거나 확인할 수 없으면 1)을 건너뛰고 학생 생각을 오류로 단정하지 않는다"를 더한다(미시험, 연결 뒤 확인 시험 대상).

3. 인계 문서 작성 중 Claude가 정하고 사용자가 동의한 규칙(2026-10-10, "네가 정한 4가지 규칙에 동의"):
   - 정답/오답 세션은 마지막 선택의 정오로 정한다(첫 선택 오답 → 재선택 정답이면 정답 세션 규칙).
   - 재선택이 정답이지만 근거 오류면 교정 질문 없이 luna 설명으로 끝낸다(종료 사유 `NO_CORRECTION`, 정답·근거 미확인).
   - 마크다운 렌더러는 의존성 설치 없이 저장소 안에 작게 작성한다(문단·줄바꿈·굵게·목록, HTML은 글자 그대로). 기울임(`*…*`)은 원문 각주 별표("정관*")를 그대로 인용한 문장을 잘못 바꿀 수 있어 diff 검토 때 뺐다.
   - 교정 성공 뒤 안내 문구는 D-0106 그대로, 선지 번호 뒤 조사는 '를'로 고정한다.
   인계 문서: `docs/handoffs/2026-10-10-v5-developer-path-connection.md`.

4. 오답 종료 코칭은 학생이 마지막으로 고른 선지가 왜 답이 아닌지 원문에 근거해 짚는다. 학생 근거가 없거나 확인할 수 없어도 생략하지 않는다(사용자 결정 2026-10-11).
   근거: 실모델 확인 시험에서 근거 없음·확인 불가로 끝난 5칸이 고른 선지를 언급하지 않았다([작업 기록](../checkpoints/2026-10-11-v5-live-connection-test.md)).
   sol 종료 지시문 `INCORRECT_END_INSTRUCTIONS`에 "4) …" 한 줄을 더했다(`packages/pipeline/src/problem-solving/feedback-v5-end-explanation.ts`).

5. 서버가 오답 종료 메시지에 붙이던 "정답은 N번입니다." 줄을 뺀다(사용자 결정 2026-10-11, 1번의 "정답 번호 유지"를 대체).
   근거: 실모델 확인 시험에서 모든 오답 종료가 코칭의 "정답은 ③이에요" 뒤에 서버 줄을 또 붙여 중복되고 말투가 합니다체로 바뀌었다. 정답 번호는 화면의 정답 카드(`answerRevealed`)에 남는다.
   `finish()`(`packages/pipeline/src/problem-solving/feedback-v4.ts`)는 종료 설명만 메시지로 쓴다.

6. 정답 선택에서 근거가 부족하거나 확인할 수 없을 때도 한 줄 종료("정답입니다. 다만 근거는 검증되지 않았습니다.") 대신 luna 설명으로 끝낸다. 결과는 그대로 '정답, 근거 미확인'(UNVERIFIED_CORRECT)이다(사용자 결정 2026-10-12: "근거 부족·확인 불가의 경우에도 'luna 설명으로 끝남'으로 수정하자. 직접 해보니까 좀 사용감이 이상해." → "기록해두기").
   교정 질문을 더하는 것이 아니라 종료 메시지만 바꾼다. 따라서 D-0104의 관대함(과도한 개입 대신)은 유지된다.
   범위 세부(사용자 확인 2026-10-12):
   - 근거 미제출로 정답을 고른 경우는 **제외**한다. 확실해서 근거를 안 적었을 수 있다. 첫 선택·재선택 모두 지금처럼 한 줄로 끝낸다.
   - 재선택이 정답이고 근거가 부족하거나 확인할 수 없는 경우는 **포함**한다.
   - 종료 사유 이름은 `CORRECT_UNVERIFIED`(Claude가 정함, 사용자 위임). 오답 세션의 `RATIONALE_UNVERIFIABLE`과 구별한다.
   - luna 지시문은 이 종료 사유에서 "틀린 곳 짚기"를 하지 않는다. 학생 생각을 오류로 단정하지 않고, 학생이 말한 내용 중 맞는 것은 인정한 뒤 빠진 연결을 원문으로 채워 답까지 잇는다(동의).
   구현(2026-10-13, 인계 `docs/handoffs/2026-10-13-v5-tone-and-correct-unverified.md`, Claude diff 검토 통과, 테스트 355/355). 실모델 확인 전이다.
   관련 코드: `packages/pipeline/src/problem-solving/feedback-v4.ts`의 `unknown()`, SELECTION 정답·INSUFFICIENT 분기.
   근거: [48세션 기록](../../docs/experiments/v5-diverse-48-2026-10-12/REVIEW-claude.md)에서 정답 사례 12/12가 한 줄로 끝났다. 메모장 8번.

## 근거

- 사용자 확인(2026-10-10): 1번 "오케이", 2번 "오케이".
- 현행 `finish()`(`packages/pipeline/src/problem-solving/feedback-v4.ts`)는 정답·오답 구분 없이 COACHING_TERMINATED에서 정답 번호와 공식 해설을 붙이며, 오답 종료 지점마다 설명 출처가 다르다.
