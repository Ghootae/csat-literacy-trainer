# 교정 실패·다시 고른 답 오답으로 끝날 때도 정답 공개 앞에 안내 문장을 둔다 (D-0117 5항 확장)

## 결정

사용자 발견·승인(2026-10-21, UI 메모장 28번, "권고대로 진행해줘"). [D-0117](./D-0117-end-coaching-sectioned-sequence.md) 5항은
판단 불가(RATIONALE_UNVERIFIABLE, CORRECT_UNVERIFIED)에만 시작 확인 앞 안내 문장을 뒀다. 같은 자리(코드, `appendCoach`)에 두 경우를 더한다.

- REPAIR_FAILED, 오답 선택: "네 답과 근거에 고쳐야 할 부분이 있어서 질문했는데, 방금 답도 정확하지 않았어. 더 묻지 않고 정답을 먼저 알려 줄게."
- REPAIR_FAILED, 정답 선택: "네 근거에 고쳐야 할 부분이 있어서 질문했는데, 방금 답도 정확하지 않았어. 더 묻지 않고 근거를 같이 정리해 볼게."
- RESELECTION_WRONG: "다시 고른 답도 정답이 아니야. 더 묻지 않고 정답을 먼저 알려 줄게."

## 이유

- 반자동 재시험 P2([판정 기록](../../docs/experiments/v5-lead-user-2026-10-21/REVIEW.md)): 교정 질문에 학생이 틀리게 답했는데 피드백
  없이 "정답은 ②번이야."로 넘어갔다. 사용자: 교정 질문을 하고 답을 받았으면 그 답에 대한 피드백이 있어야 한다. 문구는 사용자 예를
  바탕으로 정답 선택(공개할 정답 없음)을 갈랐다.
- 다시 고른 답이 오답일 때도 "어디서 생각이 달라졌는지 살펴볼게." 뒤에 바로 정답을 공개해 같은 끊김이 있었다(Claude 권고).

## 확인

- 서버 시험: REPAIR_FAILED 오답·정답 선택 두 경우의 안내 문장 순서. e2e: 다시 고른 답 오답 안내 문장.
- 빌드·클라이언트 타입 검사 통과, vitest 1328 중 1326(실패 2 기존), e2e 13 중 12(실패 1은 다른 세션 `DevPartNav.tsx` 버튼 중복).
- 고정 문장이라 실모델 확인은 하지 않았다.
