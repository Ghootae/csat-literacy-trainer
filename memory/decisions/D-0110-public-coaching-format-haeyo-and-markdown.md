# 공개 설명 형식: 정답 세션 설명은 해요체 지시문으로 따로 생성, 마크다운은 유지하고 화면에서 렌더링

## 결정

1. 정답 세션(정답 선택·근거 오류)의 마지막 설명은 REPAIR 판정이 함께 쓴 coaching을 쓰지 않고, luna가 별도 지시문으로 생성한다(사용자 확인 2026-10-10).
   지시문: 해요체·학생에게 직접 말함(3인칭 금지) → 선택이 맞았다고 짧게 인정 → 근거 중 틀린 부분을 학생 발화 인용으로 짚기 → 원문으로 맞는 내용과 답 잇기.
   공식 해설을 인용·전달한다고 말하지 않고, 내부 식별자를 쓰지 않는다. 전문은 `scripts/test-v5-coaching-fix.mjs`의 `LUNA_COACHING`.
2. 코칭의 마크다운(`**` 등)은 지우지 않는다. 운영에서 마크다운 형식을 쓸 것이므로 학생 화면이 마크다운을 렌더링한다(사용자 결정 2026-10-10).
   구현 때 원시 HTML 렌더링은 끄고, 서버의 공개 코칭 인용 검사·복원이 `**`와 충돌하지 않는지 확인한다.

## 근거

- [종료 코칭 의미 검토](../checkpoints/2026-10-10-v5-repair-coaching-review.md): REPAIR 판정이 쓴 luna 정답 세션 설명은 내용은 맞지만 내부 번호 14/57, 3인칭·합니다체로 학생용 형식 미달.
- [수정 확인 시험](../checkpoints/2026-10-10-v5-coaching-fix-test.md): 위 지시문으로 같은 12유형 36칸을 다시 만들자 내용·형식 문제 0(Claude·GPT 블라인드 일치).
- `**`는 sol 교정 실패 코칭 71칸 중 9칸에서만, 학생이 거꾸로 생각한 핵심과 정답 번호 강조에 쓰였다([요약](../../docs/experiments/v5-repair-test-2026-10-10-review/REVIEW-SUMMARY.json)). 현재 학생 클라이언트에는 마크다운 렌더링이 없다.

## 다시 볼 조건

- 운영 연결 뒤 렌더링된 화면에서 강조가 과하거나 인용 검사와 충돌하면 재검토한다.
