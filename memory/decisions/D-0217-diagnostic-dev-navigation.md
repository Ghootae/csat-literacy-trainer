# 진단평가 개발자 이동 지도: 개발자 전용, 앞으로 건너뛰기, 돌아가면 읽기 전용, 흐름 한 줄 이동, 위치와 상태 표시

## 결정

사용자가 진단평가를 직접 써 보며 검증하는 단계에 쓰는 이동 장치(사용자 2026-11-10, "지문, 문단, 문항, 화면을 자유롭게 이동할 수 있는 맵과 같은 장치가 필요해. 이전, 다음 화면 이동도 가능하도록"). 질문 다섯에 대한 사용자 답:

1. 개발자에게만 보인다: 화면 `/diagnostic?dev=1`, 서버 개발자 API는 `CSAT_DIAGNOSTIC_DEV=1`일 때만.
2. 아직 가지 않은 단계·지문으로도 건너뛴다(안 나). 건너뛴 단계는 비워 둔다(요약 생략, 답 없는 문항은 판정·피드백 없음). 가짜 답·판정은 채우지 않는다.
3. 지나온 화면은 읽기 전용(안 가). 고치려면 개발자 "지문 초기화"로 처음부터 다시 한다.
4. 이전·다음 화면은 전체 흐름을 한 줄로 놓고 한 칸씩(안 가).
5. 지도는 위치와 칸마다 상태(미진행·진행 중·완료·판정 중·판정 실패·건너뜀), 지문마다 초기화 버튼(안 나).

## 근거

- 서버는 지문마다 상태(NOT_STARTED→SUMMARY→ANSWERING→AWAITING_JUDGMENT→FEEDBACK→DONE)와 피드백 커서로 순서를 강제한다(`packages/app/src/server/diagnostic/controller.ts`). 그래서 앞으로 건너뛰기는 서버의 개발자 전용 경로가 필요하고, 되돌리기는 상태 역행 경로가 많아 지문 초기화 하나로 대신한다(코드 에이전트 권고, 사용자 수용).
- 가짜 판정 채우기는 v5.10 판정 검증 목적과 맞지 않는다.

## 영향

- 인계: `docs/handoffs/2026-11-10-diagnostic-dev-navigation.md`.
- 학생 흐름(`?dev=1` 없음)은 바뀌지 않는다. 답 없는 문항을 다루기 위한 집계 변경은 모든 문항에 답한 경우의 결과를 바꾸지 않아야 한다.

## 다시 볼 조건

- 학생용 공개 전에 개발자 API가 공개 서버에서 꺼져 있는지 확인한다(`CSAT_DIAGNOSTIC_DEV` 미설정).
