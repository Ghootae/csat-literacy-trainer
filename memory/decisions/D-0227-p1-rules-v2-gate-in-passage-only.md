# P1 1차 실행이 관문에서 멈춤 → RULES 지시문 v2(규칙별 열린 자리) + 관문은 a 문항만 막음, `runs-v2/`로 처음부터

## 결정

사용자(2026-11-10): "C로 가자".

1. **RULES 지시문 v2** (`docs/experiments/principle-application-pilot-2026-11-09/RULES-PROMPT-v2.md`)
   - 대상마다 규칙별로 따로 본다.
   - 다른 규칙의 `statedApplications`에 들어 있는 대상이라도, 이 규칙을 적용한 결과가 지문에 없으면 이 규칙의 `openSlots`에 넣는다.
   - 나머지는 v1과 같다. SITUATION·WRITE 지시문은 그대로 둔다.
2. **관문**
   - 쓸 수 있는 열린 자리가 0개인 지문이 2개 이상이면, **IN_PASSAGE(a) 문항만** 모두 보내지 않는다.
   - BOGI(b) 문항은 열린 자리를 쓰지 않으므로 그대로 진행한다.
   - `RUN.json`의 `stop`은 null로 두고, `gate.inPassageBlocked`로 기록한다.
   - 0개인 지문이 하나면 그 지문의 a만 건너뛴다(기존과 같음).
3. **실행 폴더**
   - 새 실행은 `runs-v2/`에서 처음부터(단계 1 포함) 한다. `--runs` 옵션을 쓴다.
   - 1차 실행 `runs/`는 기록으로 남긴다.

## 근거

- 1차 실행 `runs/RUN.json`: 요청 4개, $0.111. 열린 자리는 법인 0, 표면 장력 3(그중 2개는 제외할 기포 합체 상황), 오디오 0, 플라스틱 1이었고, 관문에서 멈췄다.
- 법인의 0개는 모델이 놓친 것이다.
  - 지문은 무상 증자가 "주식을 추가로 발행"한다고 말하고, 자본금은 "발행된 총 주식 수 × 액면가"라고 정의한다. 그러나 무상 증자 뒤 자본금이 어떻게 되는지는 말하지 않는다.
  - 모델은 무상 증자를 R6(외부 유출 여부)의 `statedApplications`로만 적고, R3(자본금 정의)의 열린 자리로는 적지 않았다.
  - 기출 법인 12번 ①이 이 자리를 썼다.
- 오디오는 지문 속 사례(1,000~10,000 Hz)를 지문이 결과까지 말했다. 재료가 실제로 없는 쪽일 수 있다.
- 관문이 b까지 막은 것은 설계의 불일치였다. 지문 하나만 0개일 때는 a만 건너뛰는데, 2개일 때는 b까지 멈췄다.
- 과적합 위험:
  - v2 문장은 법인 사례를 보고 넣었지만, 특정 지문과 무관한 일반 원리다.
  - 기출 문항 텍스트는 여전히 생성 요청에 들어가지 않는다(dry-run 시험).
- 시험: `node --test scripts/run-principle-pilot.test.mjs scripts/check-exam-overlap.test.mjs scripts/build-structure-judge-bundle.test.mjs` 34 통과(관문 시험 갱신, 실행 폴더·v2 지시문 시험 추가).
- dry-run(`--runs runs-v2`): 20요청, 예약 상한 $3.62. 출력은 `dry-run-runs-v2/`.

## 다시 볼 조건

- v2에서도 법인의 열린 자리가 0개이면, 모델 누락이 아니라 단계 1 설계(규칙 단위 추출)의 한계로 보고 다시 설계한다.

## 보완 (2026-11-11, 사용자 "승인")

- 2차 실행 `runs-v2/` 결과
  - 단계 1은 4지문 모두 성공했다. 열린 자리는 법인 1(R3-S1 무상 증자 × 자본금), 표면 장력 3, 오디오 0, 플라스틱 5였다. 관문에는 걸리지 않았고, 오디오는 a만 건너뛴다.
  - 법인 a는 상황 단계까지 성공했다.
  - 법인 a 집필 요청은 21분 동안 걸려 있다가 시간 초과로 끝났다. 이어서 7요청이 즉시 "Connection error"로 실패했다(일시적 연결 끊김, 이후 연결 확인됨).
  - 장부 합계는 $0.34다. 시간 초과 1건은 예약액 $0.19를 비용으로 잡았다.
- **재사용 옵션 `--reuse-from <run dir>`**
  - 앞선 실행에서 파싱에 성공한 출력을 요청 없이 가져온다.
  - 그 실행의 장부에 있는 요청 해시가 지금 요청과 같을 때만 가져오고, 다르면 `REUSE_MISMATCH`로 멈춘다(D-0168).
  - dry-run도 재사용분을 빼고 센다.
- **요청 시간 한도 `P1_TIMEOUT_MS`를 5분으로 둔다.**
  - 지금까지 완료된 요청 가운데 가장 오래 걸린 것은 99초였다(E1 v3 최대 55초, P1 1·2차 최대 99초).
- 3차 실행은 `runs-v2b/`로, `runs-v2/`를 재사용한다.
  - 재사용 5개: 규칙 4, 법인 상황 a
  - 새 요청 13개, 예약 상한 $2.44, `--usd-cap 3`
- 시험: 세 스크립트 35 통과(재사용 시험 추가)
