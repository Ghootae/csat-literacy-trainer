# 깊은 〈보기〉 문항 생성 = 골드 지도 탐색 → 선별 → 〈보기〉 조립, 출제 양식 3갈래

## 결정

사용자(2026-11-11, 웹 스레드에서 정리해 코드 에이전트에 전달).

1. **생성 절차**: 깊은 〈보기〉 문항은 다음 세 단계로 만든다.
   1. 골드 지도 탐색: 지문 명제 쌍을 훑어 헷갈리는 인근 지점(후보 진술)을 찾는다.
   2. 선별: 후보 진술 중 쓸 것을 고른다. 선별도 모델이 할 수 있다.
   3. 〈보기〉 조립: 고른 진술로 〈보기〉와 선지를 만든다.
2. **규칙 추가**
   - 〈보기〉는 짧게 쓴다.
   - 용어 풀어쓰기는 핵심 개념에만 한다. 모든 용어를 바꾸지 않는다.
3. **출제 양식**
   - 개념 연결+적용: 범용
   - 계산: 과학
   - 관점 비교: 인문 후보

## 근거

- **API 생성과 비교** (`docs/experiments/gold-search-api-2026-11-11/KEY.md`)
  - API(gpt-6.1-sol, 선별도 모델)로 법인 지문 문항 2개(가·다)를 만들었다.
  - 웹 하위 에이전트(사람 선별)의 문항 2개(나·라)와 함께 블라인드로 판정했다.
  - 사용자 순위는 라 > 다 > 가 > 나이다. 출처로 바꾸면 웹 V1 > API V2 > API V1 > 웹 V2이다. 두 방식 사이의 차이보다 같은 방식 안 문항 사이의 차이가 크다. 그래서 방식 간 차이는 없다고 판단했다.
  - 사용자 총평: 4문항 모두 쓸 만하다.
  - 규칙의 근거는 가 < 다로 매긴 이유다. 가는 상황 서술이 장황하지만 선지는 비교적 단순하게 풀린다. 깊이는 〈보기〉를 해독하는 데서가 아니라 선지의 개념 연결에서 나와야 한다.
- **출제 양식** (`docs/experiments/item-format-taxonomy-2026-11-11/SUMMARY.md`)
  - 표본: 15세트 69문항. 코드 에이전트 혼자 한 번 판정했다.
  - 세 분야 모두 A(개념 연결+적용)가 가장 많다(25/69).
  - B(계산·대입)는 과학에 몰려 있다(주 양식 기준 4문항 중 3문항).
  - C(관점 비교)는 인문에 몰려 있다(9문항 중 7문항).
- **탐색 결과**: `docs/experiments/gold-search-corporate-law-2026-11-11/result.md`
- **출제 규칙 후보**: `docs/handoffs/2026-11-11-examiner-simulation-corporate-law-rules.md`

## 한계와 재검토 조건

- 생성은 법인 지문 하나에서만 확인했다. 과학형·인문형 지문으로 다시 확인해야 한다.
- 양식 분류는 판정자 한 명이 한 번 한 결과다. E/A, A/C 경계의 일치도는 재지 않았다.
- 인문의 관점 비교 양식은 아직 후보다.
- API 실행은 첫 시도에서 시간 초과가 3회 났다. 그 요청이 과금됐을 수 있다.
  - 이후 `run.mjs`를 스트리밍 수신, 재시도 0회로 바꿨다.
