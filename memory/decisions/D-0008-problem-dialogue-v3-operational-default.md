# 문제 풀이 v3를 운영 기본값으로 고정

## 결정

`source-direct-problem-dialogue-prompt-v3`를 문제 풀이 원문 직접 evaluator의 운영 기본값으로
승인하고 고정한다. v2는 과거 회귀와 명시적 비교 실행을 위한 호환 버전으로만 보존한다.

전체 회귀에서 확인된 과잉 복원 경계와 진단 질문 표현의 실행 간 변동은 알려진 한계로 기록하되,
운영 승격을 계속 차단하는 사유로 사용하지 않는다. 개별 불편 하나마다 프롬프트를 수정하지 않고,
여러 지문에서 반복되거나 실제 학습 흐름을 방해하는 문제가 확인될 때 일반적인 수정으로 묶는다.

## 운영 검증 방향

다음 검증의 중심은 준비된 모범 응답의 판정 일치율이 아니라 학생 관점의 전체 경험이다.

- 문단 이해에서 문제 풀이까지 직접 사용한다.
- 질문을 학생이 알아들을 수 있는지 확인한다.
- 피드백이 학생의 실제 생각을 제대로 짚는지 확인한다.
- 학생이 답한 뒤 흐름이 자연스럽게 이어지는지 확인한다.
- 짧고 불완전한 자연 응답을 우선 관찰한다.
- 지문·문제 세트를 확장해 반복되는 실패와 실제 학습 방해를 구분한다.

## 실패 복구

원문 인용 또는 상태 머신 계약 오류로 모델 출력이 차단돼도 이미 저장된 학생 선택·근거·후속
답변을 되돌리지 않는다. 세션을 `EVALUATION_ERROR`로 노출하고 같은 저장 상태에서 evaluator를
다시 실행할 수 있어야 한다. 클라이언트는 한 번 자동 재개하고, 이후에도 사용자가 `다시 진행`을
누를 수 있다. 정답 근거 평가의 계약 오류도 같은 방식으로 재개한다. 전송 실패가 제한 재시도 뒤
계속되는 경우 정답 선택은 기존 정책대로 미검증 정답으로 안전 종료할 수 있다.

## 알려진 한계

- “두 개념을 구분해야 한다” 같은 메타 판단을 실제 구별 방향까지 이해한 것으로 보충할 수 있다.
- 모호한 관계 응답의 진단 질문이 아직 확인되지 않은 술어를 전제할 수 있다.
- 동일 프롬프트·모델·응답도 경계 판정과 질문 표현이 실행마다 달라질 수 있다.
- 합성 응답과 같은 모델 계열 평가가 대부분이며 실제 학생 사용성 증거는 아직 없다.
