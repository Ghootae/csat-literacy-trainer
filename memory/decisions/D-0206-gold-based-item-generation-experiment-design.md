# 골드 기반 문항 생성(E1)·지문 대체 생성(E2) 실험 설계 확정

## 결정

설계는 `docs/handoffs/2026-11-06-gold-based-generation-experiment.md`(1차 수정 뒤, 이 결정을 반영해 2차 수정)를 따른다. 확정한 항목은 다음과 같다.

### E1 골드 기반 문항 생성 (기출 지문 위)

1. **대상 4지문**: 법인(`corporate-law`), 표면 장력(`surface-tension-laplace`), 오디오 지각 부호화(`audio-perceptual-coding`), 플라스틱 중합(`plastic-polymerization`).
2. **문항 수와 발문 틀**: 조건마다 그 지문의 〈보기〉 없는 기출 수만큼 만든다. 법인 10~12, 표면 장력 14·15, 오디오 14~16, 플라스틱 8·9로 합계 10문항이다.
   - 문항 자리마다 기출의 극성(적절한/적절하지 않은)과 범위만 준다. 범위는 지문 전체 또는 특정 개념이다.
   - 특정 개념 자리에서 어느 개념을 물을지는 생성 조건이 고른다. 기출의 개념명·㉠ 표시는 주지 않는다.
3. **조건 세 가지**:
   - A안: 지문만 주고 바로 생성. 품질 요구(단일 정답, 원문에서 짚을 수 있는 오답, 지문 없이 풀리지 않음)는 지시문에 넣는다.
   - A′안: 지문만 주고 설계표를 만든 뒤 집필. 비틂 14종 목록은 주지 않는다.
   - B안: 동결 지도·입장·관계 유형과 다른 지문의 비틂 분포로 설계표를 만든 뒤 집필.
   - 그 지문의 실제 기출 문항과 선지 연결 동결본은 생성 입력에서 뺀다.
   - 주 비교는 A′ 대 B다.
4. **모델**: 생성은 `gpt-6.1-sol`. 풀이 검사는 `gpt-6-luna`, `gemini-3.8-flash`(medium), `deepseek-v4-pro`(high) 셋이다(생성기와 다른 모델, 다른 공급자 포함).
5. **단일 정답 검사**: 정답 번호만 고르게 하지 않는다. 지문을 보고 선지마다 정/오와 근거 원문 구절을 판정하게 한다.
   - 결함 후보: 판정이 생성 정답과 다르거나, 복수 정답이거나 정답이 없게 나온 경우. 그리고 근거 구절이 원문 부분 문자열이 아닌 오답.
6. **지문 없이 풀림 검사**: 같은 세 모델이 지문 없이 푼다. 기준선은 같은 4지문의 〈보기〉 없는 기출 10문항을 같은 방식으로 푼 정답률이다. 세 모델이 모두 지문 없이 맞힌 문항은 결함 후보로 표시한다.
7. **역연결**: `run-choice-link.mjs`(v5) 결과는 관찰 지표다. 비틂 종류 복원, 비틂 분포, `readingGap`·`OUTSIDE` 비율을 기록하되 성립 기준에서는 뺀다.
8. **사용자 블라인드 판정**: 생성 30 + 기출 10 = 40문항. 문항마다 정답 유일성(유일/복수/없음), 오답 근거 명확성, 수능다움(1~4)을 판정한다. 출처 추측(기출/생성)은 하지 않는다.
9. **성립 기준**: 아래 셋을 모두 만족해야 한다. 결함은 5·6의 결함 후보와 사용자 "복수/없음" 판정을 합친 것이다.
   - B안 결함률 < A′안 결함률
   - B안 결함 ≤ 1문항(10문항 중)
   - B안 수능다움 평균 > A′안 평균
   - 미달이면 E2로 넘어가기 전에 보고한다.

### E2 지문 대체 생성 (E1 결과 뒤 별도 인계)

10. **관문 기준은 범위 비교로 한다.** 생성 지문도 지도를 3회 만든다. "원 뼈대 ↔ 새 지도" 일치가 같은 원문 회차 간 일치 범위 안에 드는지 본다.
    - 노드 대응: 사상표 기준
    - 관계 재현: 방향 반대·끝 범위 차이 허용. 원문 천장은 81~91%다.
    - 재현 쌍의 유형 일치
    - 선지 고리 보존: 분할·병합 인정, 100%
    - 근거: `docs/experiments/map-run-agreement-2026-11-06/REPORT-desktop.md`
11. **T1 예시**: 법인 → 조합. 재단은 원문 2문단에 있어 주제 이동이 아니다.
12. **사실 출처는 출처 묶음 먼저 만든다.** 코드 에이전트가 공공 백과·정부·학회 자료를 URL과 함께 파일로 모으고, 집필은 그 문장 안에서만 한다. 모델이 출처를 제시하게 하지 않는다. 수집 단계의 외부 조회는 E2 인계에서 승인받는다.

### 공통

13. **문서 정리**:
    - 회사법 13번 ②는 원 초안대로 "결함 선지"로 둔다(D-0196). 정정: 채팅 권고 13은 D-0182만 보고 "논란이 있는 선지"로 낮추자고 했으나, 더 새 결정 D-0196(2026-11-03, 사용자 판단)이 선지 결함으로 정했으므로 따르지 않는다. 이 문항(13번)은 〈보기〉 문항이라 E1 대상 밖이다.
    - 작성 주체는 "웹 에이전트"로 표기한다(D-0169).
    - 상업적 사용 전 저작권 확인을 한계에 적는다.
    - 문체 지표에서 한자어 비율은 뺀다.
14. **생성 문항을 SNS 테스트에 쓰는 기준**은 E1 결과 뒤 별도로 결정한다.
14′. **〈보기〉 문항 생성**은 E1·E2 범위 밖이다. E1 결과를 본 뒤 별도로 설계한다(사용자 확인 2026-11-06). 이유: 새 사례 제작·정합 검증이 따로 필요해, 함께 넣으면 실패 원인을 가를 수 없다. 한계: E1이 성공해도 지문의 고난도 〈보기〉 문항(대상 4지문의 법인 13·표면 장력 16·오디오 17·플라스틱 10)은 대체하지 못한다.
15. **외부 전송**은 단계마다 dry-run 뒤 모델·요청 수·상한을 적어 따로 승인받는다. 이 결정은 전송을 승인하지 않는다.

## 근거

- 사용자(2026-11-06): "권고대로 진행". 권고 내용은 코드 에이전트가 채팅에서 표로 제시한 14항목이다(이 결정 1~14).
- 설계 검토: A안과 B안의 원인 혼재, 블라인드 누설(사용자가 대상 기출을 이미 봄), 볼록 렌즈 근거 오인용(`docs/PROBLEM-GOLD-ASSET-REGISTER-2026-09-09.md` 217~221행).
- 지도 회차 간 천장: `docs/experiments/map-run-agreement-2026-11-06/REPORT-desktop.md`(커밋 `b322269f`).
- 〈보기〉 없는 기출 수: 선지 연결 동결본의 `extraSegments`와 수능 DB `prompt_blocks`로 확인했다.
  - 정정(같은 날): 채팅 권고에서는 플라스틱을 3문항(합계 11, 검토 44)으로 셌다. 그러나 플라스틱 10번은 〈보기〉가 발문 블록 안에 있어 `extraSegments`에 잡히지 않았을 뿐 〈보기〉 문항이다. 그래서 2문항(합계 10, 검토 40)으로 바로잡았다.
- 공급자: `scripts/lib/provider-adapter.mjs`(gemini-3.8-flash, deepseek-flash), `scripts/run-v58-deepseek-p1.mjs`(deepseek-v4-pro). 이전 전송 선례는 D-0192다.

## 다시 볼 조건

- E1 결과에서 B안이 A′안보다 낫지 않으면 E2를 보류할지 다시 정한다.
- 풀이 검사 세 모델의 기출 판정이 기출 정답과 자주 어긋나면(기출 10문항 중 2문항 이상) 단일 정답 검사의 신뢰도를 다시 본다.
