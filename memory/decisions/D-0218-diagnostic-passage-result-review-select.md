# 진단 지문 결과 화면: 결과 가려 두고 하나씩 공개, 리뷰 대상만 골라 검토, 결과를 다 보면 확률 최대 등급 공개

## 결정

사용자(2026-11-10, 진단 직접 사용 중 메모 6, 시안 `docs/review/diagnostic-passage-result-mock-2026-11-10/`). 시안의 배치·색은 설명용이며 사용성·심미성에 맞게 다듬어도 된다(사용자).

1. 지문 결과 화면은 문항 줄 목록이다. 결과 설명은 가려 두고 문제 버튼을 누르면 공개한다. 문제 버튼은 정오·근거 강도로 색을 나눈다.
2. 리뷰 대상(D-0213: 오답, 근거가 틀린 정답)만 검토 버튼이 활성이다. 나머지는 칭찬 문구로 비활성(아무 동작 없음). 검토를 마치면(건너뛰기 포함) "검토 완료했어. 수고했어"로 비활성. 다음 검토 문항은 학생이 고른다.
3. 잘 모르겠지만 정답(범주 5)은 힌트 흐름이 구현되기 전까지 리뷰 대상이 아니다(사용자 (가)). 힌트 흐름 구현 때 대상으로 바꾼다.
4. 등급은 지문의 모든 문항 결과를 공개한 뒤 보인다(검토 완료는 조건 아님). 범위가 아니라 확률이 가장 높은 등급 하나로 쓰고, 1~9등급 띠에 등급별 확률을 진하기로 칠한다.
5. 내부 범주 표기는 개발자 모드에서만 보인다.
6. "다음 지문" 버튼은 오른쪽 아래, 리뷰 대상을 모두 검토하고 판정 중 문항이 없을 때 활성.
7. 판정이 끝나지 않은 문항은 "정답(n%). 아직 분석 중이야" 형식.

## 근거

- 사용자 원문은 `memory/checkpoints/2026-11-10-diagnostic-v510-use-notes.md` 6·6-1절.
- 등급 확률은 기존 위치 추정의 격자 사후분포(`packages/pipeline/src/diagnostic-position/position.ts` `estimateAbility`)로 새 외부 자료 없이 계산한다. 두 선택과목 분포는 산술 평균(코드 에이전트 결정, 기존 백분위 평균과 같은 취지).
- D-0213 7번의 "문항별 피드백 열기"는 대기 줄이기였고 문항을 고르는 형식은 결정된 적이 없었다(코드 에이전트 확인, 사용자에게 정정 보고).

## 영향

- 인계: `docs/handoffs/2026-11-10-diagnostic-passage-result-review-select.md`.
- 학생 흐름의 피드백 커서(문항 순서 강제)를 쓰지 않는다. 개발자 이동 지도(D-0217)의 피드백 칸은 리뷰 대상 문항만 둔다.
- 최종 결과 화면의 위치 표시(범위)는 이번에 바꾸지 않는다.
