# 판정기 형식 실수 두 종류는 재작성 대신 서버가 기계적으로 고친다

## 결정

판정 결과를 `validateClaims`로 검사하기 전에 서버의 기계적 정리 단계에서 다음 둘을 고친다. 고칠 때마다 시도 기록(`attempt.normalized`)에 메모를 남긴다.

- 결론 문장 옮기기(`normalizeCells`): 학생 말 항목이 아래를 모두 만족하면 `CHOICE_READING`으로 옮긴다.
  - 표시가 `CONTRADICTED`다.
  - 겹치는 오류 항목이 없다.
  - 문장이 선지 번호와 맞다/틀리다 계열 서술만으로 된 결론이다(예: "그래서 5번이 틀렸어").
- 인용 바로잡기(`snapQuotes`): 선지 읽기 인용이나 근거 인용이 학생 말에 그대로 없으면 원문 구간으로 바꾼다. 조건은 넷이다.
  - 인용이 12자 이상이다.
  - 인용의 앞 6자와 뒤 6자가 학생 말에서 각각 한 번씩만, 앞이 먼저 나온다.
  - 바꿀 원문 구간의 길이가 인용 길이의 0.7~1.5배다.
  - 이 가운데 하나라도 어긋나면 고치지 않고 재작성으로 보낸다.

판단이 필요한 실수(건드림·인용 없음, 판단 대상 번호 오류)는 지금처럼 재작성한다. 판정 지시문 v5.8 문구는 바꾸지 않는다.

## 근거

- 저장된 v5.8 판정 86회 중 재작성 5회, 최종 실패 0회였다. 사용자 직접 풀이 28회 중 4회, 실험 58회 중 1회다. 5회 모두 재작성 전후 판단이 같았다(재작성은 대기 시간 문제).
- 재생 검증(`scripts/replay-judge-normalization.mjs`, 외부 전송 없음): SELECTION 시도 71건 중 원래 ERROR 5건에서 3건이 통과했다(`97a9de5f`, `206a362f`, `9924082b`). 판단은 실제 2차 답안과 같았다. 원래 SUCCESS 66건은 결과 변화 0건이었다.
- 사용자 승인: 2026-11-02 방안 (ㄱ), 2026-11-03 설계 초안 "승인, 하위 에이전트에 맡겨 진행해". 인계 문서: `docs/handoffs/2026-11-03-judge-format-slip-normalization.md`.

## 한계

- 결론 문장은 "선지 번호가 먼저 오는" 꼴만 인정한다("정답은 5번이야"는 옮기지 않음).
- 표본이 작다. 실제 풀이에서 재작성이 줄어드는 정도는 앞으로 기록으로 확인한다.

## 다시 볼 조건

- 기계적 정리 뒤 판단이 바뀐 사례나 잘못 옮긴 사례가 나오면 되돌리거나 조건을 좁힌다.
