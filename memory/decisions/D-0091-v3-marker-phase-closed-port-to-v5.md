# v3 기호 실험 단계를 마무리하고 v5로 옮긴다

## 결정

사용자 결정(2026-10-07)에 따라 v3를 기준선으로 한 공손룡 12번 기호 실험 단계를 마무리한다. 이후 개선과 검증은
운영 후보 v5([D-0090](./D-0090-problem-evaluator-v5-naming.md))에서 한다.

v5로 옮길 구성 요소:
- 학생 주장 분리 기록(학생 판단을 의미 단위로 나눠 원문 대조 결과를 따로 적은 뒤 판정)
- 인용 형식 규칙(학생 판단은 학생 발화를 그대로 인용하고 평가자 판단과 분리)
- 기호 해석본(기호 해석만, 사람이 만들고 승인한 것, [D-0084](./D-0084-local-marker-gloss-direction.md))

v3에서 더 다루지 않고 v5로 넘기는 미해결 과제: 해석본 자동 생성, S5처럼 범위 안 사례를 지시 대상으로 말한 응답의
허용 기준(보류한 두 후보 포함), 교정 질문 품질(정답 노출·표면 답 가능).

이식 방법은 [설계안](../../docs/review/v5-marker-port-design-2026-10-07.md)으로 작성했으며 아직 승인되지 않았다.
v5 프롬프트·코드·서버·UI는 바꾸지 않았다.

## 근거

- 사용자 'v3 기반 v4 후보가 최종적인 운영 모델이 될거야. 일단은 진행하던 v3 실험을 확정하고 v3 기반 v4로 옮기면 되겠지?',
  'v3 실험 정리하고 v5 이식 설계안 작성 진행' (2026-10-07).
- [기호 해석본·인용 형식 기록](../checkpoints/2026-10-06-gongsun-marker-gloss-and-quote-format.md),
  [자동 생성 기록](../checkpoints/2026-10-07-gongsun-auto-gloss-generation.md).
- v3 실험 근거: 주장 분리 3/5 → 5/5, 인용 규칙 귀속 대체 4/8 → 0/8, 해석본 S5 과잉 교정 2/3 → 1/14.
  모두 공손룡 12번 한 문항의 탐색 결과다.

## 재검토 조건

v5 이식 검증에서 세 구성 요소가 v5 원본보다 과잉 교정·오류 누락·귀속 대체를 줄이지 못하거나, 오류 목록·교정 질문과
한 출력에 묶인 v5 구조에서 새 실패(주장과 오류 목록 불일치 등)가 반복되면 이식 범위를 다시 정한다.

## 후속 결정

같은 날 [D-0093](./D-0093-v5-composition-auto-gloss-pipeline.md)에서 사람 승인 해석본 대신 자동 생성·자동 검수 해석본(중간안)을 쓰기로 했다. 위 '사람이 만들고 승인한 것'은 당시 기록이다.
