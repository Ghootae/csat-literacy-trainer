# 현재 주장과 수정·철회 이력 분리

사용자 ‘2번도 이어서 수정’에 따라 이전에 수정한 내용을 현재 주장으로 계속 저장하는
기록 불일치를 다룬다. 판정 기준·개입 정책의 변경은 아니다.

- 1차 모델은 claimLedger에서 주장별 current/superseded/retracted와 직접 근거,
  응답 번호 및 후속 변경 근거를 반환한다.
- 현재 expressedClaims는 current 항목에서만 코드로 생성하여 저장·2차 입력에 사용한다.
- 원래 학생 발화, 전체 변경 이력, 실패 원출력은 보존한다. 임의 문자열 추론으로 지우지 않는다.
- 부분 수정은 해당 의미만 갱신하고 다른 미수정 주장까지 해소된 것으로 만들지 않는다.
- 코드의 인용·시간 순서 검증과 모델의 의미적 상태 분류를 구별한다. 후자는 실모델 검증 필요.

## 범위와 검증

`docs/experiments/dialogue-current-claims-fix-2026-09-19/REPORT.md`에 구현·118테스트·빌드
및 검증 한계를 기록했다. 기존 V4 원본 프롬프트는 보존하고 기록 보충 지시를 결합한다.
새 유료 호출과 공개 서버 재시작은 실시하지 않았다. 정확한 오류 인용 저장(1번)은 미완성이다.

## 재검토 조건

실제 모델이 수정 상태를 잘못 분류하거나 이력 출력 때문에 계약 실패·지연이 늘면
표적 입력으로 확인한다. 학생의 충분한 응답을 더 엄격하게 판정하는 변경과 혼동하지 않는다.
