# 단순 형식 문단 개발자 모드: 사용자 직접 사용감 기록

## 결정

[D-0139](./D-0139-paragraph-simple-format-question-rules.md) 단순 형식의 검증을 엄밀한 실험 대신 사용자가 직접 참가자로 써 보며 사용감을 기록하는 방식으로 한다. 이를 위해 웹앱에 개발자 전용 모드 `simple-holistic`을 만든다.

- **위치:** 웹앱 개발자 모드. 운영 V4·보여 주기 모드·학생용 화면은 그대로 둔다.
- **지문:** 기존 6지문 30문단(V4와 사용감 비교, 문제 연결). 필요하면 나중에 새 지문 하나를 추가한다.
- **입력:** 지문과 학생 대화만. 골드·축을 쓰지 않는다.
- **흐름:**

| 첫 응답 | 행동 | 그다음 |
|---|---|---|
| 핵심을 잡음 | 짧게 칭찬, 다음 문단 | – |
| 무관한 응답·원문 복사 | 코멘트 후 다시 쓰기 권유(1회) | 다시 쓴 응답을 새로 판정. 두 번째도 같으면 핵심 내용 공개 후 다음("응답 없음으로 넘어감" 기록) |
| 구멍 | 구멍 질문 1회 | 해결 → 칭찬 · 미해결 → 빠진 내용 한두 문장 + 해당 구절 미색 표시 |
| 오류 1개(구멍 동반 포함) | 교정 질문 1회 | 교정·충분 → 칭찬 · 교정·구멍 남음 → 구멍 질문 사이클 · 교정 실패 → 오류 바로잡기(미색) + 핵심 내용 공개 |
| 오류 2개 이상 | 질문 없음 | 모든 오류 바로잡기(미색) + 핵심 내용 공개 |

  - 오류는 핵심 관계를 뒤집거나 왜곡하는 것만 센다. 사소한 세부 오류는 질문하지 않고 개수에도 넣지 않는다.
  - 질문 중에는 지문을 표시하지 않는다(답 누출). 표시는 마무리 공개에서만 한다.
  - 질문은 문단당 최대 두 번이다.
- **말투:** 문제 풀이 v5와 같은 [D-0116](./D-0116-student-facing-tone-banmal.md) 규칙(반말, 3인칭·내부 용어 금지).
- **기록:** 세션 로그 자동 저장(모드 전용 폴더). 개발자 서랍에 단계마다 판정·이유와 인상 메모칸, 문단마다 전체 인상 메모칸. 메모는 자동 저장하고 수정 이력을 남긴다.
- **연결 차단:** 학생 상태 원장과 문제 판정에 문단 기록을 넘기지 않는다([Q-0037](../OPEN_QUESTIONS.md)). 지문을 마치면 문제 개발자 화면으로 넘어갈 수 있다.

## 근거

사용자 지시(2026-10-16): "엄밀한 실험을 할 필요는 없으니까, 그냥 내가 직접 참가자가 돼서 사용감을 기록하는 방식으로", "웹앱 개발자 모드로 하자", 기존 자료 사용("V4 버전과 사용감을 비교하려면 기존 자료를 기반으로"), 흐름 표(대화로 전달, 3-1~3-5 확정), "말투 레이어는 문제풀이 v5와 동일하게 유지", "개발자 서랍에 각 단계에 대한 인상을 메모할 수 있도록", "문단 전체 인상 칸도 하나 추가".
