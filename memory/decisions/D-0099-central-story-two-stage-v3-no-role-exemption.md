# 두 단계 생성 v3: 최소 축 수에서 도입·정리 문단 면제 제거

## 결정

최소 축 수를 문단 기능과 관계없이 정한다. 1단계 설명 단위가 2개 이상이면 2, 아니면 1이다. 그동안 도입(introduction)·정리(conclusion) 문단은 최소 축 수가 항상 1이었는데, 이 면제를 없앤다. 문단 기능 판정은 참고 정보로만 남긴다.

**실행 범위:** v2의 1단계 결과를 그대로 재사용하고, 최소 축 수가 바뀌는 문단만 2단계를 다시 호출한다. v2 결과로 계산하면 법인1·도파민1·정보 비대칭1·표면 장력1의 4문단이며, 모두 도입 문단이다. 나머지 20문단은 2단계 입력까지 v2와 같으므로 v2 결과를 그대로 쓴다. v2에서 1단계가 실패한 법인2는 실패로 남긴다.

**바꾸지 않는 것:** 1단계·2단계 지침. 2단계 지침은 v2와 바이트 단위로 같다.

**진행:** 인계 → Codex 구현 → Claude 검토 → 별도 전송 승인 → 실행([D-0092](./D-0092-claude-codex-work-division.md))

## 근거

- 사용자 결정(2026-10-07): "도입 문단 면제 없애는 방향으로 진행". 정리 문단 면제도 함께 없애자는 권고에 "권고대로 진행", 4문단 2단계 재실행 범위에 "승인".
- v2 결과(`docs/experiments/central-story-two-stage-v2-2026-10-07/REPORT.md`, Claude 의견): 도입 문단 면제로 2단계 묶음 규칙이 그대로 작동해 도파민1(설명 단위 5개)과 정보 비대칭1이 한 축으로 뭉쳤다.
- 사용자가 1축이 적당하다고 판정한 4건(표면 장력3, 정보 비대칭2, 도파민4, 표면 장력6)은 모두 소개·연결·개관·요약 문장을 걸러 내서 1축이 된 사례다. 문단 기능 면제 덕분에 1축이 된 경우는 없다.

## 폐기한 대안

- 도입 문단만 면제 제거(정리 문단은 유지): 같은 근거가 적용되고 규칙이 단순해지지 않는다.
- 25문단 전체 재실행: 1단계가 다시 실행되면 결과 차이를 규칙 변경과 실행 간 변동으로 나눌 수 없다. v1→v2에서 도파민1이 3축에서 1축으로 흔들린 사례가 있다.

## 재검토 조건

- 면제를 없앤 뒤 도입·정리 문단이 개관·요약만으로 억지 2축이 되는 사례가 사람 검토에서 나올 때
