# 감사기 최소 2축을 실질 설명 축 기준으로 수정

## 결정

D-0086의 규칙 2(일반 문단에서 입력 축이 2개 이상이면 감사 후 최소 2축, 예외 없음)를 다음과 같이 바꾼다. D-0086의 나머지 규칙(문단 기능 판정과 보수적 기본값, 감사기에만 적용, FA 문구 수정, 관계 중심 기준, 병합 기록 계약, 검토 표시만, A+B 먼저)은 그대로 유지한다.

- 최소 2축은 축의 개수가 아니라 **실질 설명 축의 개수**에 적용한다. 일반 문단에서 실질 설명 축이 2개 이상이면, 실질 설명을 담은 최종 축을 2개 아래로 줄일 수 없다(병합·삭제 모두). 소개·연결 축만으로 된 최종 축은 이 수에 넣지 않는다.
- 소개·연결 축은 다음 조건을 모두 갖춘 입력 축이다: 원문 한 문장이고, 이 문단에서 학생이 따로 답해야 할 관계를 제시하지 않으며, 화제를 예고·도입하거나 다른 문단으로 연결만 한다. 감사기는 이런 축을 근거 인용과 함께 표시하고, 인접 축에 흡수하거나 삭제할 수 있다. 표시한 축은 실질 설명 수에서 뺀다. 관계·주장·근거·사례 적용·정의를 담은 축은 한 문장이어도 소개·연결 축이 아니다.
- **코드 검사(사용자 선택):** 소개·연결로 표시한 축의 원문 구간이 정확히 한 문장인지, 근거가 그 축 원문의 정확한 인용인지 검사한다. 위반하면 계약 실패로 처리한다.
- 이 수정은 D-0086의 "예외 없이 고정"을 바꾼다. 실질 설명이 둘 이상인 문단을 1축으로 줄이는 것은 여전히 금지된다.

이번 범위는 결정 기록과 구현 준비다. `scripts/test-axis-audit-v3.mjs`는 v1·v2와 같은 자동 병합 결과를 입력으로 쓴다. 사전 검증만 했고 API 호출은 0회다. 실행에는 별도의 전송 승인이 필요하다.

## 근거

- 사용자 판정(2026-10-06, `docs/experiments/axis-audit-v2-min-two-2026-10-06/HUMAN-REVIEW.md`): 표면 장력3과 정보 비대칭2는 "1축이 적당", 공손룡3은 "경계". 앞의 두 문단은 실질 설명 하나에 도입 또는 연결 문장 하나가 붙은 구조이며, D-0086 규칙과 어긋났다.
- Claude 권고와 사용자 승인(2026-10-07): "이 방향으로 D-0086을 수정 승인." 명료화 답변: 한 문장 코드 검사 포함.
- `docs/experiments/axis-audit-v2-min-two-2026-10-06/REPORT.md`: 최소 2축 때문에 소개·연결 축이 남은 사례(표면 장력3 AX1, 정보 비대칭2 AX2)

## 폐기한 대안

- D-0086 현행 유지: 사용자 판정 2건과 어긋난다.
- 소개·연결 판단을 감사기에만 맡기고 문장 수 검사를 하지 않음: v1처럼 넓게 해석할 위험이 있어 사용자가 코드 검사를 택했다.

## 재검토 조건

- 감사기가 실질 설명 축을 소개·연결 축으로 표시해 실질 설명을 흡수하는 사례가 사람 검토에서 반복될 때(한 문장 검사는 필요조건일 뿐 충분조건이 아니다)
- 두 문장 이상의 소개·연결 구간을 흡수해야 한다는 사람 판정이 반복될 때
