# 문제 풀이 화면: 선지는 가운데 문제 칸에서 직접 눌러 고른다

## 결정

개발자 문제 화면(`/problem/dev/v4`)에서 선지를 고르는 조작을 제출 칸의 ①~⑤ 번호 버튼에서 **가운데 문제 칸의 선지 문장을 직접 누르는 방식**으로 바꾼다. 풀이 첫 선택, 재선택, 풀이가 끝난 뒤 출제자 전략을 볼 선지 고르기(D-0170)까지 모든 단계에서 같은 조작을 쓴다.

세부 화면 설계는 따로 확정한다. 포함할 것은 좁은 화면의 탭 문제 보완, 고를 수 있음 표시, 고를 수 없는 단계 처리, 접근성, 제출 칸 버튼 정리다.

## 근거

- 사용자(2026-10-24): 긍정 발문 문항에서 정답을 맞힌 뒤 [출제자 전략 보기]를 누르면 첫 오답이 자동으로 열려 원하는 오답을 고를 수 없다고 지적했다. 그리고 "선지 선택을 중간의 선지에서 선택하도록 하는 건 어떨까?", "선지 고르기(모든 단계에서 동일하게 유지)를 … 중간의 선지에서 고르도록"을 제안했다.
- 코드 에이전트 검토:
  - 읽는 곳과 고르는 곳이 같아진다.
  - 단계마다 조작이 하나로 통일되어 버튼 위치가 갑자기 바뀌지 않는다.
  - 제출 칸이 단순해진다.
  - 걸리는 점은 좁은 화면의 탭 분리(문제 탭에서 고르고 대화 탭에서 근거 쓰기)이고, 제출 칸 위 상태 줄로 보완을 권했다.
- 사용자 질문 "유사한 UI의 앱들은 어떤 것을 취하지?"에 코드 에이전트가 일반적 사례로 답했다(조사하지 않음). 학습형 앱은 선지를 직접 누르고, 시험 재현형 앱은 별도 답안 칸을 쓴다. 이 앱은 학습형이다. 사용자 결정: "선지 직접 누르기로 하자".

## 영향

- 화면 조작만 바뀐다. 판정·서버 흐름은 그대로다.
- 기존 e2e 가운데 번호 버튼으로 고르는 시험은 새 방식으로 바꾼다.
- 학생용 경로(v3)는 이번 범위가 아니다.

## 화면 설계 확정 (2026-10-24, 사용자 "오케이. 구현 시작.")

모형: `docs/handoffs/2026-10-24-choice-direct-mock-{1..4}.png`(+`.html`). 인계: `docs/handoffs/2026-10-24-choice-direct-select-ui.md`.

- 제출 칸에서 ①~⑤ 번호 버튼과 [학습 맵으로 돌아가기]를 없앤다(상단 [학습 맵]이 같은 기능).
- 위 줄: 왼쪽 상태("②번을 골랐어 · 문제에서 바꾸기" 등), 오른쪽 [정답만 입력].
- 아래 줄 오른쪽: 작은 버튼. 주 버튼 자리 하나는 문구만 단계별로 바뀐다([제출] → [전략 보기] → [다음] → [전략 보기]). 풀이가 끝나면 [다시 풀기]가 그 옆에 고정된다. 버튼 위치는 바뀌지 않는다.
- 가운데 문제 칸 맨 위에 단계별 한 줄 안내를 둔다. 풀이가 끝난 뒤에는 전략이 없는 선지를 흐리게 하고 누를 수 없게 한다. 본 선지에는 "봤음" 표시를 붙이되 다시 누를 수 있다.
- 풀이 시작 말풍선은 "문제에서 답을 고르고, 그렇게 판단한 근거를 적어 줘. 근거 없이 답만 내도 돼."로 한다. 전략 안내 말풍선 끝에 "보고 싶은 선지를 문제에서 눌러 봐."를 더한다.

## 사용자 수정 (2026-10-24, 직접 사용 뒤)

- 부정 발문은 전략을 볼 선지가 정답 하나뿐이라 고를 것이 없다. 안내 말풍선을 "선지를 누르면 출제자가 어떤 전략으로 정답 선지에 함정을 만들었는지 검토할 수 있어."로 바꾼다(사용자 문구). 같은 이유로, 전략을 볼 선지가 하나뿐인 문항에서는 읽는 중의 문제 칸 안내("다른 선지를 누르면 …")를 비운다(코드 에이전트, 사용자에게 알림).
