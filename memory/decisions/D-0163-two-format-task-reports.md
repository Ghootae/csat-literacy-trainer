# 과제 결과 보고: 두 형식

## 결정

아래 경우의 결과 보고는 두 형식으로 한다. 둘 다 파일로 남기고, 채팅에는 인간 보고서를 출력한다.

- 실험이나 생성을 실행하고 결과를 해석할 때.
- 결과를 보고 설계 판단(방안 선택 등)이 필요할 때.
- Desktop Claude와 논의할 거리가 생긴 큰 작업 단위를 마쳤을 때.

문서·규칙 기록, 커밋, 작은 코드 수정, 설명 요청에 대한 답, 진행 알림은 채팅에 짧게만 보고한다.


1. **Desktop 보고서 (논의 목적).** 정확성과 빠짐없음이 우선이다.
   - 측정과 해석을 나누어 적는다.
   - 실행 조건, 수치 표, 사례, 정정 사항, 제안, 열린 질문, 파일 경로를 담는다.
   - 파일 이름: `REPORT-<작업>-desktop.md`
2. **인간 보고서 (이해와 판단 목적).** 파일 이름: `REPORT-<작업>-human.md`
   - **1. 개요:** 1) 작업의 목적, 2) 작업의 결과, 3) 다음 스텝. 분량에 제한이 없고, 사례와 예시로 직관적으로 설명한다.
   - **2. 본문:** 분량에 제한이 없다.
     - 문제마다 구체적인 사례로 "어떤 문제가 → 어떤 과정을 거쳐 → 어떤 결과(해결/미해결)"를 적는다.
     - 소제목에 (해결)·(미해결)·(판단 필요)를 표시한다.
     - 다음 스텝을 제안한다.
     - 사람의 판단이 필요하면 원문과 사례를 질문 바로 앞에 보여 준다. 방안을 표로 비교하고, 추천과 그 이유를 적는다.
     - 마지막에 다음 스텝 표(할 일·외부 전송·사용자 판단)를 둔다.
   - 앞선 보고를 고치는 내용이 있으면 개요의 결과에 "정정"으로 밝힌다.
3. **파일 위치.** 실험이면 해당 실험 폴더에 둔다. 아니면 `docs/reports/`에 둔다.
4. **본보기.** `docs/experiments/choice-link-2026-10-22/REPORT-v2-run-human.md`와 `REPORT-v2-run-desktop.md`.

## 근거

사용자(2026-10-22):

- "보고는 항상 두가지 형식으로 해줘. 1. 데스크탑에게 보고할 형식(논의 목적): 정확성과 comprehensiveness이 중요(파일 남기기) 2. 인간에게 보고할 형식: 인간의 이해와 판단의 용이성이 목적(파일 남기기)". 개요(목적·결과·다음 스텝)와 본문 형식도 함께 지정했다.
- "앞으로 모든 과제에 대한 결과 보고는 위의 예시와 같은 형식으로 보고. 이 내용을 다른 세션에도 적용할 수 있도록 문서에 기록해줘."
- 범위 조정: "모든 과제에 대해 이런 식으로 보고를 할 필요는 없을 것 같은데". 이어 Claude가 제안한 기준(실험·생성 결과 해석, 설계 판단 필요, 큰 작업 단위 종료일 때만 두 형식)에 "오케이 그 기준으로 수정".

## 적용

- `AGENTS.md`의 "결과 보고 형식" 절에 넣어, 이 저장소에서 일하는 모든 세션이 시작할 때 읽게 한다.
- 다른 작업 폴더(worktree)의 세션은 각자의 브랜치에 있는 `AGENTS.md`를 읽는다. 그래서 그 브랜치에 이 절이 합쳐지기 전에는 이 결정을 보지 못한다.
