# v3 기반 후보 프롬프트를 먼저 검토

## 승인 범위

사용자는 v4에 지침을 보충하는 방식 대신 v3의 판정·질문 지침을 기반으로 합의한 v4 규칙을
반영하는 방식을 선택했다. 이어 실제 적용 전에 후보 초안을 먼저 검토하기로 했다.
전달 내용은 검토가 필요한 중요한 포인트만 추리도록 요청했다.

승인은 후보 작성과 변경 검토 자료 준비까지다. 후보 문구 자체의 최종 승인, 실제 런타임 교체,
유료 재평가나 서버 재시작 승인이 아니다. D-0059의 운영 정책과 D-0063의 실패 보완은 유지한다.

## 산출물

- `packages/pipeline/experiments/problem-solving/source-direct-problem-feedback-v4-v3-based-candidate.md`
- `docs/review/problem-v3-based-v4-candidate-review-2026-10-02.md`

학생이 이미 말한 내용을 질문에서 되짚는 범위, 질문에 대한 정답과 오류 수정의 연결,
최초의 타당한 근거와 후속 수정의 누적 평가를 사용자 검토 대상으로 구분했다.
이 후보를 승인된 운영 프롬프트로 취급하지 않는다.

## 근거

- 사용자 직접 결정: 2번(v3 기반) 선택 후 ‘v3를 바탕으로 새 프롬프트 초안을 만들고 변경한 부분을 내가 확인’.
- 위 두 산출물과 `memory/checkpoints/2026-10-02-problem-v3-v4-prompt-comparison.md`.

## 후속 승인

사용자는 이후 후보 검토 완료·추가 수정 없음 및 소규모 시험을 요청했다.
[D-0072](./D-0072-v3-based-problem-candidate-accepted-test-requested.md)에 기록했다.
위 초안 검토 단계의 미승인 문구는 당시 범위이며, 현재 후보 문구는 승인된 상태다.
