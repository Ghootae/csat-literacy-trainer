# 학생 추론 가능성 게이트를 후속 구현 후보로 채택하고 구현은 보류

## 결정

학생이 근거를 제출했다는 사실만으로 하나의 논리적 추론 경로가 존재한다고 가정하지 않는다.
향후 문제 풀이 판정기 수정 시, 학생 발화에서 선지 결론을 도출하기 전에 주장·관계·충돌과
추론 가능성을 별도로 확인하는 게이트를 구현 후보로 둔다.

후보 흐름은 다음과 같다.

1. 학생 발화에서 명시적 주장과 학생이 직접 표현한 관계를 분리한다.
2. 서로 충돌하는 주장, 끊긴 연결, 불명확한 지시 대상과 복수 해석을 보존한다.
3. 하나의 판단 경로로 재구성 가능한지 먼저 판정한다.
4. 충분히 일관된 경우에만 `reconstructedPath`와 근거가 함의하는 선지 판정을 생성한다.
5. 파편적·모순적·과소결정된 경우에는 파생 결론을 `UNKNOWN`으로 두고 선택–근거 충돌과
   내용 교정을 확정하지 않은 채 좁은 진단 질문을 제시한다.

`COHERENT`, `FRAGMENTED`, `CONTRADICTORY`, `UNDERDETERMINED` 같은 상태명은 구현 후보이며
최종 스키마로 확정하지 않는다. 핵심 계약은 판정기가 학생보다 더 논리적인 경로를 대신 만들지
않고, 추론 가능성이 확인되기 전에는 선지 참·거짓 결론을 학생 이해로 귀속하지 않는 것이다.

## D-0049와의 관계

[D-0049](./D-0049-stem-polarity-normalization-deferred.md)는 발문 극성·선택 의미와 학생 근거의
파생 결론을 분리한다. 이 결정은 그보다 앞에서 “학생 근거로부터 파생 결론 자체를 만들 수
있는가”를 확인하는 게이트다. 두 사안은 별개로 기록하되, 나중에 같은 문제 풀이 판정기 수정
묶음에서 함께 설계·검증한다.

## 구현 상태

후속 후보 갱신(2026-10-01): [D-0051](./D-0051-bounded-problem-feedback-flow-deferred.md)은 위 게이트와
과잉 재구성 금지를 유지하되, 추론 불가능 이후 ‘좁은 진단 질문’은 ‘확인 어려움 안내·상세 코칭 후
종료’로 변경한다. 위 본문과 아래 검증 항목은 당시 후보 이력으로 보존하며 후속 구현에는 두 기록을
함께 읽는다. 현재 운영은 어느 후보로도 변경하지 않았다.

현재 프롬프트, 스키마, 상태 머신, UI와 테스트는 변경하지 않는다. 사용자가 다른 문제 풀이 수정
사안과 함께 구현을 요청할 때 D-0049와 묶어 진행한다.

## 구현 시 검증 조건

- 사실 나열, 결론 없는 연상, 명시적 모순, 대상 전환, 복수 해석의 고정 fixture를 각각 둔다.
- 추론 불가능 응답에서 `rationaleImpliedVerdict`를 임의로 `VALID`/`INVALID`로 채우지 않아야 한다.
- `UNKNOWN`은 오류 없음이나 정답 근거 충분으로 승격되지 않아야 한다.
- 진단 질문은 한 번에 하나의 불명확한 관계를 확인하고 정답 방향을 학생 주장으로 선제하지 않는다.
- 일관된 짧은 근거와 실제 선택–근거 충돌의 기존 정상 경로는 유지해야 한다.
