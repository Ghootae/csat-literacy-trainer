# 선택 불일치 질문은 한 칸만 묻고, 원문상 참·거짓과 같게 답하면 교정 성공

## 결정

사용자 확정(2026-10-14, UI 메모장 22번). 설계는 [인계 문서](../../docs/handoffs/2026-10-14-v5-selection-mismatch-repair.md)에 있다.

- 선택 불일치 질문은 학생 결론을 인용하고, 선지가 적절한 설명인지만 묻는다. 목표와 비교하라는 요구는 넣지 않는다.
- 교정 판정은 학생이 선지를 원문상 실제 참·거짓과 같게 판단했는지로 정한다.
  - 같게 판단하면 REPAIRED, 반대로 판단하면 REMAINING, 판단을 밝히지 않으면 UNCONFIRMED다.
  - 오답을 고른 경우와 정답을 고른 경우를 이 한 규칙으로 함께 다룬다.
- 오답을 골랐고 남은 오류가 선택 불일치뿐이며 교정 답변에 새 오류가 없으면, 다시 고르기 안내를 코드가 쓴다. 예: "네 근거대로면 ⑤는 적절한 설명이야. 이 문제는 적절하지 않은 것을 고르는 문제니까, 다시 골라 볼래?"
- 학생이 이미 정답을 골랐으면, 질문에 정답 번호가 들어가도 정답 노출로 보지 않는다. "정답은 …" 선언, 정답 선지 문장 전체, 내부 ID는 계속 막는다.

## 이유

- 사용자가 직접 푼 공손룡 ⑤ 세션이 근거다. 질문이 "맞는 설명이야?"와 "목표와 비교해 봐" 두 가지를 함께 물었다. 학생은 첫 칸에 바르게 답했지만 판정기가 둘째 칸까지 요구해 코칭 종료로 끝났다.
- 기존 실모델 시험에는 이 길을 거친 기록이 없었다.
- 정답을 골랐는데 근거 결론이 반대인 경우도 있다. 이때 학생 말을 인용하면 기존 정답 노출 검사에 항상 막혔다.

## 확인

- vitest는 기존 실패 2건만 남았다. e2e는 13/13이다.
- 실모델 결과([보고서](../../docs/experiments/v5-mismatch-repair-2026-10-14/REPORT.md)):
  - 오답 2세션은 모두 한 칸 질문 → 교정 성공 → 새 다시 고르기 안내로 갔다.
  - 정답 1세션은 검사를 고친 뒤 교정 성공 → 정답 경로 안내로 갔다.
  - 비용은 약 0.08달러다.

## 재검토 조건

- 학생이 "적절한/적절하지 않은"이 아닌 말로 답해 판정이 갈리는 사례가 나오면 다시 본다.
